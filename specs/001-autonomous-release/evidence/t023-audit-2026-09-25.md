## What this slice added

- **Readings** (`source-readings-v1`, 3 routes): `GET|HEAD /api/v1/source-readings/{work_id}`,
  `POST …/{work_id}` (`source-reading-command-v1`), `GET|HEAD …/{work_id}/{source_id}`.
  Sealed `extraction` records (`source-reading-v1`, parents = source + artifact), kept text
  ≤ 60,000 UTF-8 bytes, `ingestion.completed` / `ingestion.failed` events, replay by command
  id through the shared owner-material journal, index table `source_readings_v1`
  (backed up as `records_and_lineage`). Text read from an original the owner later deleted
  is no longer shown or sent to a model (the sealed record itself remains; see open items).
- **Conversation** (`conversations-v1`, 5 routes): read; `messages`; `proposals`;
  `challenges`; `approvals`. Messages are `chat_message` records bound to the current
  revision and exact same-work references (revision, source, reading, work model, earlier
  message); proposals are versioned `proposed_command` records (proposed → approved →
  executed/failed); challenges are one-time tokens stored as digests, bound to the session,
  5-minute expiry, revoked on reissue, excluded from backups (`pending_challenges`). The
  executed command is `PersistentWorkModels.confirm` under a command id derived from the
  proposal: the chat and the panel buttons make one decision, never two. Refusal envelopes
  carry `reason` (`approval_ambiguous`, `reader_unavailable`) because the shell's closed
  error partition maps unknown codes by status.
- **Budgets** (`budget-policies-v1`, 2 routes) as above.
- Route composition: 104 → **114** installed (pins updated in `test_first_party.py` (115 with
  the example), `test_web_owner_integration.py` (ids and order), `test_runs_api.py`,
  `test_works_api.py`, `test_provider_source_startup.py`).
- Served assets: `source-reading.mjs`, `budget-policy.mjs` (pinned in `test_web_shell_assets.py`).

## 2026-09-25 follow-up: reading text erased with its original (open item 5)

- `source-reading-v2` keeps the read text as its own content-addressed blob
  (`text_blob_ref`), never inside the `extraction` record.
- The T073 deletion preview lists every reading of each chosen original, the other readings
  that share its text, and the work-model drafts made from them. These are in
  `affected_refs` and so bound into the preview digest. The preview also states what backups
  made before and after the deletion hold.
- Consent tombstones each reading text per content address (`former_kind:
  source_reading_text`) and removes the bytes after the commit.
- After that, the reading records answer `text_state: deleted`, and the text route answers
  410 `deleted`. Drafts get the source as `not_read`, and later backups no longer carry the
  text.
- Tests:

    database, WAL and blob directories, and in backup archives before and after.
  - `test_source_readings.py`: 11 passed. The deleted-original case now expects metadata
    plus 410.
  - `source-deletion.test.mjs` and `work-conversation.test.mjs`: new cases.

    the fixture data directory.
