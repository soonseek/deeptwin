# T048 — run creation from the work page (2026-09-26)

Status: **the work page has a `실행 시작` section: it lists the owner's prepared environment
versions usable for this work (from the store), shows exactly what a run will use, records the
owner's consent through `run-consents-v1` and starts the run through `runs-v1`, then links to the
observation page, which selects that run.** Without a prepared environment — production today —
it says exactly why and offers no start. Exercised in real Chrome both ways; the prepared case is
TEST-ACTOR with a SIMULATED critic qualification, labelled on the page (decisions.md 2026-09-25:
never a release qualification). T048 stays unticked (see Open).

## What landed

- **`GET|HEAD /api/v1/run-environments/{work_id}`** (`runs.environments`, `work.read`, in the
  `runs-v1` contribution; `app/services/run_environments.py`). For each `environment` record it
  binds the version back to the vault and offers it only when every link agrees:
  - environment record → its own head record → the owner's design approval record, whose digest
    must equal the version's `approval_sha` (the approval names the model choice, the tool
    permission grant, the observation contract and the critic qualification);
  - the approved design → the stored `graph` record at that identity, admitted by
    `GraphVersion.from_untrusted`, whose `graph_digest` must equal the design hash — that record is
    the run's `graph_ref` (this closes, for offering, the "environment ⇄ graph" gap noted in
    `run_consents.py`: the design hash is now resolved to a store reference and verified);
  - the graph's work model → the stored `work_model` → the work revision it was designed for,
    which must belong to this work; the run names that revision, and the view says whether a newer
    one exists (`revision_current`).
  - Unresolvable versions are never offered; they are counted by reason (`unresolved`, e.g.
    `graph_not_in_vault` for an environment approved over a design outside this vault — exercised
    with `browser_grant_chain.approved_environment`).
  - `runs.available` (a run executor is host wiring), `usable`, and — when nothing is offered —
    `absence: {code: no_prepared_environment, reason: no_approved_design, critic_qualifiable}`
    (`critic_qualifiable` is `bool(V3_VERIFYING_DESIGN_IDS)`: false in production).
  - The critic qualification is shown with `simulated: true` when its design id is not a release
    design (test-actor).
- **`app/static/run-start.mjs`** mounted on `work.html` (`#work-run`), reloaded after each save:
  - environment and budget pickers (budgets from `GET /api/v1/budget-policies`, the owner's own);
  - `이 실행이 쓰는 것`: environment version (prepared, not activated), graph (ref, nodes), work
    revision (current or not), model bindings, tool bindings with their grants, the approved
    bindings (model choice, tool permissions, observation contract), extension binding revisions,
    the critic qualification (simulation labelled), the budget limits, and the consent scope
    (`위 그래프·작업 수정본·환경 버전·예산 정책 네 기록에만, 실행 한 번에만 … 외부 쓰기·결제
    변경·승격은 포함하지 않습니다`);
  - a consent checkbox gates `동의하고 실행 시작`, which posts `run-consent-command-v1` over the
    exact four refs, then `POST /api/v1/runs` with that `consent_ref`; the outcome links to
    `./observe.html#run=<id>` (an asset takes no query string);
  - blockers are stated: no executor, no budget, an unusable version; refusals are shown by code.
  - production absence text: `준비된 실행 환경이 없어 실행을 시작할 수 없습니다. 승인된 설계가
    없습니다: 설계를 승인하려면 평가자(critic) 구성과 렌즈의 자격이 필요한데, 이 인스턴스에는
    자격을 얻을 수 있는 평가자 구성이 없습니다 (V3 오류 독립성 미검증).`
- `observe.mjs` selects the run named by `#run=` if the list holds it (`run-list.mjs` `select`).
- Asset catalogue: `run-start.mjs`. Routes 134 → 137 (with T038's two design routes).

## Observed

- `test_run_environments.py`: 2 passed — the exact absence (no executor, no environment,
  `critic_qualifiable: false`, 404/400/401); a SIMULATED prepared environment offered exactly
  (graph digest, revision, bindings, `simulated: true`), a foreign-design environment counted as
  `graph_not_in_vault`, the offered inputs accepted by the consent and run routes (a run started),
  and `revision_current: false` after the work is revised.
- `run-start.test.mjs`: 4 passed (absence without a start; the usage rows; consent then start with
  the exact bodies and the observe link; blockers and a refused start).
- **`browser-run-start-t048.test.mjs`: 2 passed in real Chrome** against
  `app/tests/fixtures/design_arc_server.py`:
  1. production state (`--unqualified --no-executor`): a real work, the arc generates three
     candidates, preparation is refused with `the critic configuration is not qualified (unknown:
     no_suite_record)`, the run section shows the absence text and no start button; the read says
     `critic_qualifiable: false`, no runs exist;
  2. SIMULATED: the owner generates, prepares candidate 1 (environment version 1), authors a budget
     through the budget route, sees every usage row (simulation labelled), consents, starts (run
     `awaiting_human` at the design's `owner-gate`), follows the link to `observe.html#run=…`, the
     run is selected, the owner approves `owner-gate/artifact.publish` on the approval screen,
     resumes, and the run completes. No page errors.
- The run executor in the browser fixture is the code-owned test executor (compiles under the
  design request's authority; handlers forward one synthetic artifact). No model, tool or paid
  call.

## Open (why T048 stays unticked)

- In production no environment can be prepared (no qualified critic/lens; V3 unverified; T077), and
  no production path registers a design request with the owner's model turns — so run creation
  from the work page can only ever show the absence in production today.
- T049's browser case (its Codex half) stays with T049.
- The environment record still stores the design as a hash; the binding to the graph record is
  verified at read time, not by the record itself.
