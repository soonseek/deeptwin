# T073 slice — work export: actual preview, bound consent, sealed bundle (2026-09-23)

Status: **the export slice landed; T073 stays open**. The logs, backup and retention GUI screens
are not built yet.

## What landed

### Server (`app/services/work_exports.py`)

The export routes live in the `works-v1` contribution, `app/api/works.py`. The installed route
count went from 43 to 46.

- **`preview`** reads what the export would actually contain right now.
  - Originals: every revision of the work. The raw text is included only when the owner asks for
    it explicitly; otherwise only metadata (revision, time, character count) goes in.
  - History: the work's revision history.
  - Attachments: the list of sources its revisions name.
  - Every selected category the server does not collect yet is stated as `unavailable`, every
    unselected one as `not_selected`, and "no attachments" as `not_recorded`.
  - It stores nothing. `preview_sha` digests the request id, the selection and the exact bytes of
    every item.
- **`confirm`**:
  - Consent must be explicit: it requires `confirmed: true` and the exact `preview_sha`.
  - It recomputes the preview, inside the writer transaction as well. A work revised after the
    preview gets `conflict`.
  - It seals these records:
    - a `run_consent` record with `export_consent` bound to the digest
    - one raw-inclusion `artifact` per raw original
    - a manifest built through `operations.export`, so it never carries the bundle's own hash
    - a bundle blob plus its `artifact` record
    - an `export_manifest` record holding the receipt; the manifest is kept as canonical text,
      because its `export_ref` names an entry, not a record
  - One bundle per request id.
- **`download`** is owner-only. The store verifies the blob on read, and its sha must equal the
  receipt's.

### GUI (`app/static/work-export.mjs`)

The panel is mounted on the work page as `#work-records`. The mount is optional, so pages without
it still boot.

- It says export is optional (UX-AC08). Before a work is saved, it asks the owner to save first.
- Category checkboxes cover the closed set only. Raw inclusion is a separate checkbox, off by
  default.
- The preview is shown as each item with its content mode and size, plus each omission with its
  reason, before any consent.
- Consent is a separate unchecked box, and it is bound to the digest through
  `records.mjs exportConsent`.
- A stale preview is refused and cleared. When there is nothing to export, no consent control is
  offered.
- The bundle is offered as a same-origin download link next to its SHA-256.
- Server text reaches the DOM through textContent or attributes only.

## Observed

- `test_work_exports_api.py`: **4 passed**. It covers the actual preview and its gaps, raw
  inclusion only by choice, digest binding, refusal of implicit and wrong-digest consent, bundle
  hash equal to the receipt, zip members equal to the manifest items, the consent record, refusal
  of a stale preview, a closed wire (`credentials`, raw inclusion without originals, extra keys),
  404 for an unknown work or bundle, and refusal without a session.
- `work-export.test.mjs`: **7 passed**. The existing `work.test.mjs` also passes.
- The route-count tests (works, runs, web_owner_integration, provider_source_startup and
  first_party), `test_server`, `test_web_shell_assets` and the records mirror: 213 passed.
- The 8 browser-*.test.mjs files (79 failing cases) fail the same way without this change; they
  need a real browser environment and are tracked under the regression task.

## Not yet met

- The logs, backup and retention screens are not built. Backup needs the T070 worker to be
  connected, and retention/deletion needs a persistent ledger service.
- `model_final_responses`, `tool_observations`, `alternatives` and `evaluation_evidence` are
  honestly stated as `unavailable`: this server does not collect them yet.
