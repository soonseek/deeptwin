# Experience contract — 독립 프레임워크의 전체 사용자 여정

작성일: 2026-09-07 · 계약 ID: UX-001 · 상태: 자율 설계 위임에 따른 상세 설계, 구현·사용성 수용 증거 아님

## 1. 적용 범위와 정본

이 계약은 오픈소스 웹 인스턴스 배포/최초 소유자 설정 → 업무 설명·자료·실시간 음성 → 업무 이해 → 실제 환경 그래프 제안·검토 → 구성·실행 → 역할별 산출물 → 자기 대안 → 탐구 → 이전 업무 큐 재평가 → 사람의 환경 버전 승인까지, 사용자에게 무엇이 보이고 어떤 행위가 무엇을 변경하는지 정의한다. 기록 추출·제작자 전달은 이 순서 밖의 선택 경로다.

사용자 직접 정정이 우선한다. 아래 문서는 근거와 과거 상태를 보존하며, 옛 문서의 당시 미결·구현 불허를 이번 자율 진행 위임의 철회로 읽거나 과거 짧은 응답을 새 세부 UI 승인으로 확대하지 않는다.

**제공자 요구 변경(2026-09-07):** 사용자는 “클로드는 사전 승인 안받고 그냥 api 방식으로만 하는걸로 할게.”라고 정정했다. 현재 계약은 **Claude는 API-only, Codex는 구독 기본과 사용자가 명시 선택하는 추가 API 경로**다. 과거 양쪽 구독 필수 문장과 Claude 구독 사전 승인 문제는 역사적 기록이며 현재 요구·출시 차단 조건으로 적용하지 않는다. 프레임워크의 독립 UI·도구·전체 여정·에이전트별 모델 관리와 자동 과금 전환 금지는 유지한다. 제품에 유료 API 선택지를 구현하라는 결정은 개발 중 실제 유료 API 호출·크레딧 구매·과금 한도의 승인과 다르다.

- [통합 제품 설계](../../../docs/superpowers/specs/2026-09-06-deeptwin-integrated-product-design.md): 제품 정체성, 세 모드, 렌즈 세 경로, 증거·권한 경계.
- [관제 UI 구조](../../../docs/superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md): 특히 §8, §10.3–10.7의 도구·수행/시도·다형식·동일 초점 비교.
- [첫 사용 경험](../../../docs/ui/2026-09-07-first-use-experience.md): 입력하던 같은 공간에서 그래프가 나타나고 운영 관제로 이어지는 흐름. 기존 관제 상세보다 이 첫 사용 우선순위가 앞선다. 이 문서의 ADR-009 이전 네이티브 설치물 표현은 현재 배포 경계가 아니며 상호작용 의도만 참조한다.
- [모델·음성 요구](../../../docs/ui/2026-09-07-model-control-and-voice.md), [실제 업무 이해 기록](../../../docs/ui/2026-09-07-live-understanding.md), [현재 브라우저 개발 슬라이스](../../../app/README.md).
- [의도·수용 출처 추적표](../source-traceability.md): 비공개 원 checkout의 제품 의도
  INT-001–035와 수용·거부 AC-001–037을 내용 해시·요약으로 연결한다. 직접 발언 원본은
  publishable worktree에 복제하지 않으며 배포 런타임 입력도 아니다.
- [성장 계약](growth.md): 품질 하한, 유의미한 개선, 비교 가능성, 최선 후보·patience, 최종 검증·승격의 알고리즘 정본. 이 문서는 같은 상태를 사용자 경험으로 표현한다.

새 사용자 요구인 **일정 수준에서 3회 이상 큰 개선이 없을 때 종료**는 배포된 DeepTwin 인스턴스의 **이전 업무 큐 반복 평가 루프**에 적용한다. 개발 작업·전체 구축·세션의 조기 종료 조건이 아니며, 환경의 자동 운영 승격 조건도 아니다.

최신 크리틱 구현 범위는 해당 구현 기록에서 판정한다. README의 넓은 미구현 목록이나 오래된 시험 수치를 최신 상태로 덮어 읽지 않는다. 어떤 행의 개발 기반도 오른쪽 요구의 완료를 뜻하지 않는다. 시제품의 고정 점수·렌즈·파일 사례를 새 입력의 실제 생성 결과로 붙이지 않는다.

## 3. 자율 결정한 경험 원칙

아래 `UX-D`는 기존 의도를 충족하기 위해 이번 **설계 위임으로 선택한 추천안**이다. 사용자가 각 문구·간격·배치를 개별 승인했다는 기록이 아니다. 이후 변경은 영향·근거·회귀 항목과 함께 버전화한다.

| 결정 | 채택 내용 | 이유·경계 |
| --- | --- | --- |
| UX-D01 | 신규 환경의 기본 화면은 업무 입력 중심 작업공간. 기존 환경은 마지막 안전한 읽기 위치 복원 | 빈 그래프 조립·내부 객체 학습을 첫 과제로 만들지 않음. 모드 선택 설문 없음 |
| UX-D02 | 넓은 화면은 환경/업무 탐색 + 한 주작업면 + 선택 상세. 좁은 화면은 같은 맥락의 전환형 상세 | 세 패널을 항상 펼쳐 과밀하게 만들지 않음. 그래프·원본은 필요하면 확대하고 정확한 위치로 복귀 |
| UX-D03 | 설계 비교는 권장안의 읽을 수 있는 전체 그래프와 같은 초점의 후보 요약, 후보 전환/넓은 병렬 보기 | 세 그래프를 작은 카드에 끼워 넣지 않음. 구조 자체를 비교하며 요약·점수는 보조 |
| UX-D04 | 편집은 로컬 초안 자동 보존, 서버 확인 뒤 저장 표시, 명시적인 작업 시작은 저장본 고정 후 실행 | 저장/열람/침묵을 추론·실험·승인 권한으로 읽지 않음. 내부 단계마다 제출 버튼을 만들지 않음 |
| UX-D05 | 기본 자동화 권한은 업무별로 한 번 설정한 범위·모델·자료 전송·사용량·시간 안에서만 유효 | 매 내부 호출 승인도, 무제한 자율 실행도 피함. 권한 없는 외부 쓰기·과금 전환은 별도 |
| UX-D06 | 최초 사용의 주행동 문구는 `업무 이해하기` → `환경 제안받기` → `이 설계로 준비` → `업무 시작` | 제품의 구분되는 실제 행위다. 고정 단계 마법사·모든 필드 승인 절차를 뜻하지 않음 |
| UX-D07 | 산출물의 `내 버전` 작업면에서 작성·파일 제공. 최초에는 범위가 제한된 `차이 살펴보기`로 탐구 시작 | 자기 산출물과 설명을 구분. 별도 개선 메뉴를 찾아 원인을 해설하지 않아도 됨. 해당 환경의 허용된 반복 정책이 있으면 이후 내부 진행은 묶음으로 수행 |
| UX-D08 | 실제 실행/성장 진행률은 단계·완료 업무 수와 함께 추정치로만 표시. 소요 자료가 없으면 남은 시간 미산정 | 시간을 흘려 99%에 고정하지 않음. 실제 생성 개수·큐 분모 변경·대기 원인을 표시. 개발 진척률과 별개 |

## 4. 공통 화면 맥락과 세 보기

공통 맥락은 `환경 → 환경 버전/후보 → 업무/입력 수정본 → 실행 → 역할 수행 → 시도 → 산출물 버전/선택 범위`이며, 필요할 때 `대안 버전 → 탐구 → 실험/회차 → 평가/승인`이 연결된다. 아직 없는 대상은 없음으로 둔다. 화면 선택을 위해 실행·대안·승인을 생성하지 않는다.

상단에는 사람이 읽을 업무·환경 이름과 **운영 / 설계 검토 / 격리 실험 / 과거 기록** 표식을 둔다. 긴 내부 ID·해시·프로필은 상세에 둔다. 후보 화면에서도 현재 운영 버전을 확인할 수 있다. 새 환경에는 운영 버전 없음이 정상이다.

| 보기 | 기본 주작업 | 공통 연결 |
| --- | --- | --- |
| 작업공간 | 원 자료·실제 산출물·자기 버전·비교를 형식에 맞게 읽고 작성 | 선택한 수행/시도, 원본 전체, 그래프의 생성·전달 위치, 관련 대화 |
| 대화 | 같은 업무와 명시된 참조를 바탕으로 설명·조정·탐구 | 참조 칩에서 정확한 자료/산출물/범위를 열기. 일반 요청·이유·실제 자기 대안을 서로 구별 |
| 그래프 | 실제 역할·분기·반복·제어·도구·모델·기억·평가 관계와 실행 상태 탐색 | 노드에서 수행/시도별 입력·다중 출력, 선에서 실제 전달된 산출물 버전과 수신 수행 |

보기 변경은 같은 권한과 저장 상태를 사용한다. 작성 중 내용·선택 범위·회차·그래프 확대/스크롤을 보존하고 대상이 달라진 경우 이전 선택을 새 대상의 기록으로 표시하지 않는다. 세 보기는 세 자동화 모드가 아니며 전환은 새 실행·학습·승인·버전업이 아니다.

## 5. 웹 배포·연결·첫 입력

### 5.1 외부 배포와 브라우저 시작

오픈소스 배포물은 지원 host/container runtime·브라우저·필수 image/component의 실제 준비 검사를 제공한다. 지원 조합의 최종 목록은 릴리스의 플랫폼 계약과 실제 시험표를 따른다. 없는 플랫폼 지원을 문구로 약속하지 않는다.

1. 외부 배포 authority가 image/container/volume을 준비한 뒤 DeepTwin control-plane이 처음
   기동해 기록할 수 있는 시점부터 setup/검사/실패 사건을 남긴다. Docker Desktop/Portainer 설치나
   image pull처럼 그 전에 관측하지 못한 사건을 소급 생성하지 않는다. DeepTwin 네이티브 런처는
   존재하지 않으며 사용자 자료·마이크·모델을 자동 시작하지 않는다.
2. 외부 배포 보조물과 Docker/Portainer 운영자 화면은 정확한 인스턴스 주소와 최초 소유권 전달
   재료를 준비할 뿐, DeepTwin 제품 런처나 일상 업무 화면이 아니다. 사용자는 준비된 인스턴스를
   지원 브라우저에서 직접 연다.
3. 아직 소유자가 없는 인스턴스의 첫 DeepTwin 브라우저 화면은 동일 출처의 최초 소유자 설정
   양식을 보여 준다. 사용자는 URL에 포함되지 않은 일회용 capability를 직접 입력하고 소유자
   비밀번호를 만든다. 서버가 capability를 소비하고 소유자·인증 수단을 원자적으로 만든 경우에만
   인증된 브라우저 세션을 발급한다. 기존 소유자는 같은 제품의 로그인 화면에서 다시 인증한다.
4. 인증된 세션이 만들어진 뒤에만 일반 업무 화면으로 이어진다. 이 첫 업무 화면에서 로컬 보관
   범위, 외부 모델 전송이 발생하는 시점, 제작자에게 자동 전송하지 않음을 짧게 안내하고 상세로
   연결한다.
5. `어떤 일을 맡기고 싶으세요?` 아래 설명, `자료 추가`, 마이크, 저장 상태를 제공한다. 모델·도구 설정은 관련 시점에 접어 보여 준다.
6. 연결 없이도 초안과 자료를 보존한다. 모델이 필요한 시점에만 선택한 제공자의 준비·인증·모델 확인을 안내하고 같은 입력 위치로 돌아온다.
7. 배포·소유자 설정·연결 실패는 DeepTwin UI의 실제 관측 범위와 Portainer/운영자 화면에서 해야 할 조치를
   구별하고, 진단 기록 내보내기와 지원 범위를 안내한다. CLI 명령이나 개발자 설정 파일 편집을
   비개발자 프로필의 사용자에게 해결 과제로 넘기지 않는다.

제공자 선택은 `Codex 구독으로 연결`, `Claude API 연결`, 별도 상세의 `Codex API 연결`로 실제 경로를 구별한다. Claude API 연결에는 **“Claude 구독과 별도인 API 사용료가 발생합니다”**라는 안내, DeepTwin 웹 UI의 API 키 입력·교체/삭제, 적용할 모델과 업무/에이전트 범위·사용량/비용 한도 설정을 제공한다. Codex API를 고를 때에도 구독에서 API 과금 경로로 바뀐다는 사실과 적용 범위를 명시한다. Claude 구독 로그인·구독 연결 신청을 요구하지 않는다.

연결 삭제는 먼저 DeepTwin의 사용을 즉시 중지하고 로컬 암호문 정리 상태를 보여 준다.
`로컬 제거 완료`를 Anthropic/OpenAI에서 그 API 키가 폐기된 것으로 표현하지 않으며, 원격 키
무효화가 필요하면 제공자 관리 화면의 별도 행위와 확인 상태를 구분해 안내한다.

API 키는 일시적인 입력 필드에서만 다루고 저장 후에는 마스킹된 연결 참조만 표시한다. 키를 브라우저 localStorage·일반 설정·업무 자료·프롬프트·로그·내보내기에 넣지 않으며 보호된 서버 측 비밀 저장 경로를 사용한다. 설정 저장이나 기존 키 발견만으로 추론을 시작하지 않는다. 연결 확인, 모델 목록 확인과 유료 추론은 구분하고 검증된 실제 경로·한도 안에서만 실행한다. 잔액·크레딧·예상 비용을 제공자가 확인해 주지 않으면 미확인으로 표시하며 자동 충전·구매하지 않는다.

기존 환경의 Codex 구독 설정과 이력은 유지한다. 과거 Claude 구독 설정이 있으면 `이전 연결 방식·재설정 필요`로 보존하고 명시적인 Claude API 설정 전에는 실행하지 않는다. 키가 저장되어 있다는 이유만으로 예전 환경을 API로 자동 마이그레이션하거나 새 과금 동의를 만든 것으로 처리하지 않는다.

인스턴스 업데이트는 새 버전·데이터 마이그레이션·복구 가능성과 외부 배포 authority로 넘길 exact
request를 보여 준다. 제품이 container/image를 직접 교체하지 않고 활성 외부 행동 중 자동 업데이트하지
않는다. 백업 성공과 새 버전의 열기 검증 없이 기존 저장소를 삭제/초기화하지 않는다. stack 제거와
named-volume 업무 데이터 삭제를 구분한다.

### 5.2 파일과 업무 이해

- 파일마다 `받는 중 / 원본 보관됨 / 읽는 중 / 전체 또는 일부 읽음 / 읽기 실패 / 형식 미지원`을 표시한다. 원본 저장 성공과 내용 이해를 구분한다.
- 읽은 페이지·시트·문자 범위, 누락 이미지·OCR·표·변환 손실은 자료 상세에 명시한다. 못 읽은 부분을 전체 반영한 것으로 요약하지 않는다.
- 문서의 지시는 자료이며 사용자 권한이 아니다. HTML·SVG·문서 매크로·링크는 원본 열람만으로 실행하지 않는다.
- 설명·파일 추가·STT 확정은 입력 수정본 변경이다. 업무 설명을 대안·선호 프로필·학습 정답으로 재분류하지 않는다.
- 모델 전송 전 대상 제공자·모델·구독/API 경로와 전송 자료·제외 범위를 표시한다. 이미 설정된 동일 범위의 전송 정책 안에서는 반복 확인을 생략할 수 있지만 자료나 권한 확대는 묵시 승인하지 않는다.
- `업무 이해하기`는 고정된 입력/모델 수정본으로 실행한다. 결과에는 이해한 업무·예상 산출물·원문 출처·중요 빈칸·추정을 구분해 보여 준다. 충분한 정보가 있으면 모든 필드의 승인 클릭을 요구하지 않는다.
- `수정`은 원 설명/자료 또는 명시된 해석 수정본을 새 버전으로 보존한다. 어느 경로로 변경했는지 기록하며 원 사용자 문장을 시스템 요약으로 덮어쓰지 않는다.
- 입력을 바꾸면 과거 이해·설계는 이전 저장본 표시로 남긴다. 새 입력으로 재검토되기 전 과거 승인·점수를 최신 입력에 적용하지 않는다.

### 5.3 실시간 STT

마이크는 명시 시작과 OS/브라우저 권한 후에만 켠다. 녹음 중임과 `정지`를 명확히 표시한다.
`stt-local-ko-v1`은 배포물에 고정된 networkless PCM-only `deeptwin-faster-whisper` worker이며
runtime model download·파일 디코딩·VAD·외부 전사 fallback이 없다.
component가 빠졌다면 deployment request로 안내하고 외부 STT는 별도 전송·비용 profile 없이는 쓰지 않는다.

말하는 중의 잠정 전사와 확정 글자를 다르게 표시한다. 잠정 결과의 재작성은 중복 삽입되지 않으며 한글 IME·동시 타이핑·사용자 수정·커서를 덮지 않는다. 확정 전사는 사용자가 수정 가능한 인식 결과이지 승인된 정답이 아니다. v1 원음은 application-level durable storage 없이 browser memory/container tmpfs에만 있으며 worker 재시작 시 사라진다. host/swap/crash capture는 이 보장 밖임을 과장 없이 설명한다.

업무 이동·명시 취소·탭/브라우저 종료에는 캡처를 중단하고 늦은 전사를 다른 입력에 삽입하지 않는다.
server/worker 재시작이 마이크를 다시 켜거나 tmpfs에서 잃은 미확정 원음을 재구성했다고 하지 않는다.
권한 거절·장치 부재·준비 실패·무음·network/local server 단절·queue 초과는 text/file 입력과 독립적으로
복구한다. 실제 한국어 정확도·긴 발화·소음·지연 시험 전 지원 품질을 주장하지 않는다.

## 6. 실제 설계 그래프·모델·도구·승인

### 6.1 생성과 비교

`환경 제안받기`는 업무 모델·자료·제약·사용량 정책을 고정한 후 렌즈 단독/하이브리드의 실제 설계 판단 → 역할·산출물·전달·기억·권한·도구·평가 그래프 → 별도 크리틱 → 선별의 실행을 시작한다. 고정 템플릿 선택을 렌즈 생성으로 표시하지 않는다.

기본 비교 초점은 **누가 무엇을 만들어 누구에게 전달하는가**다. `검토·승인`, `자료·기억`, `도구·모델`, `비용·위험`을 고르면 후보별 같은 기능이 어디에 있는지 함께 강조한다. 분산/부재/미대응 구성은 그대로 나타내며 노드를 강제로 일대일 정렬하지 않는다. 일반 화면의 설명은 업무 언어이고 철학·렌즈·철학자 이름은 감사 상세에만 둔다.

통과한 구조적으로 다른 기본 3안을 제시한다. 적합 후보가 0–2개면 실제 수·탈락/근거 부족 이유와 추가 탐색 가능 범위를 보인다. 생성 중인 그래프에는 미검토 표시를 하며 선택·승인 가능한 통과 후보처럼 표시하지 않는다. 높은 총점으로 필수 결함을 숨기지 않는다.

`이 안 선택`, 자연어 수정, 다른 후보의 설계 요소 병합은 새 설계 버전을 만든다. 수정 전후 그래프와 영향받는 계약을 함께 보이고 필수 재검토를 수행한다. 원 후보의 점수·승인은 병합본에 상속하지 않는다. 노드 직접 편집·코드·YAML 작성은 필수가 아니다. 다시 생성해도 이전 후보·평가·제시 순서·선택 이력은 남는다.

### 6.2 모델과 도구 관리

환경 기본 모델, 업무 이해/설계 모델, 모든 개별 역할의 provider/model/지원 설정을 구별한다. 생성·크리틱·탐구·평가의 내부 에이전트도 `모델 관리` 상세에 포함한다. 첫 사용에 모든 역할 설정을 요구하지 않으며 적용되는 기본값과 개별 재정의를 확인·변경할 수 있게 한다.

모델 목록은 선택한 Claude API·Codex 구독·명시 선택 Codex API 연결 경로의 실제 조회 결과와 확인 시각·실행기 호환성을 따른다. 공개 모델명을 가짜 계정 목록으로 만들지 않는다. 조회됨·접근 가능·실제 실행 준비·과금 확인을 구분하고 모르는 사용량·요금을 0으로 표시하지 않는다. 선택값과 실제 실행/응답 모델이 다르면 조용히 성공 처리하지 않는다. API의 비용 추정·확인 사용량·실제 청구 확인 상태를 구분하며, 구독 사용량을 API 요금표로 환산해 실제 청구액처럼 표시하지 않는다.

실행 중 변경은 이미 시작된 호출을 다시 쓰지 않고 다음 실행/새 시도의 버전과 적용 범위를 표시한다. 운영 구성의 모델 변경은 새 후보와 재검증 필요로 연결한다. 구독/API 인증 오류·한도·크레딧 부족·모델 종료 시 다른 제공자·모델·과금 경로로 자동 전환하지 않는다. 사용자가 전환을 명시 선택하면 대상·모델·경로·비용 한도·적용할 다음 실행/새 시도와 실제 선택을 기록한다. 연결 변경 후에도 기존 환경·파일·이력은 유지하며 권한·호환성·재검증 상태만 새 버전으로 다룬다.

역할의 도구 상세는 필요한 기능, 자료/사이트/파일 범위, 산출물 형식, 읽기/쓰기/외부 전송 권한과 `준비됨 / 미연결 / 권한 부족 / 미지원 / 검증 전`을 구분한다. 모든 계정을 설계 전에 연결시키지 않는다. 인증은 공식 UI로 안내하며 복귀 후 실제 상태를 재조회한다. 인증 성공은 외부 행동 허가가 아니다.

### 6.3 설계·실행·지속 운영의 승인

| 행위 | 화면에서 고정할 대상·효력 | 자동으로 포함하지 않는 것 |
| --- | --- | --- |
| `이 설계로 준비` | 정확한 설계 버전과 구성할 역할·도구·모델·관측 계약 승인, 실제 구성 검증 | 업무 시작, 미허용 계정/자료 접근, 외부 발송·게시, 이후 변경의 운영 승격 |
| `업무 시작` | 입력/환경 버전, 이번 실행의 허용된 행동·사용량·모델 경로 | 범위 밖 외부 쓰기·자동 과금 전환·후보 개선의 지속 반영 |
| 외부 행동 승인 | 실제 대상·내용/산출물 버전·행동·횟수/유효 범위 | 다른 수신처/다른 파일/다른 시도의 새로운 행동 |
| `이 버전 적용 승인` | 최종 검증된 정확한 변경 묶음·범위·운영 버전과 되돌릴 버전 | 검증되지 않은 추가 변경, 실제 적용 성공의 선결 주장 |

상호 다른 효력이 반드시 네 개 화면·네 개 클릭이어야 한다는 뜻은 아니다. 같은 화면에서 묶을 때에도 각 효과·버전·범위를 명시하고 서버가 독립 검증한다. 기본 권한자는 로컬 보관함의 사용자이며 공유 배포는 실제 인증된 권한자만 승인한다. 표시 이름만으로 권한이 생기지 않는다.

### 6.4 설정 > 확장

일반 사용자는 첫 업무를 시작하기 위해 확장 시스템을 먼저 배울 필요가 없다. 환경이나 역할이
요구하는 기능이 없을 때 `준비 필요`에서 필요한 확장 종류·기능·현재 상태로 연결하고, 전체 관리는
`설정 > 확장`에서 제공한다. 목록과 상세에는 사람이 읽을 이름과 함께 정확한 source, version,
digest, license expression, kind/port-contract version, trust tier, 지원 platform/runtime, 설치·검증·
qualification 만료/실패, 요청 scope/grant/credential 종류, active/superseded/disabled binding과 이를
사용하는 환경 버전을 보여 준다. 서명된 staging receipt와 실제 service handshake/qualification은
서로 다른 상태이며 receipt만으로 `사용 가능`이라 표시하지 않는다.

Binding은 포트 이름으로 한 줄에 합치지 않는다. 각 행은 사람이 이해할 logical slot(어느 환경/
graph node의 어떤 기능인지), port contract version, core-owned capability selector, target scope/purpose, 현재 extension
candidate와 head revision을 보여 준다. 같은 port/scope/purpose라도 다른 slot/selector는 함께 활성화될
수 있고, 정확히 같은 slot의 후보만 `현재/교체 후보`로 경쟁한다. bind/disable/rollback 확인에는 exact
server-supplied five-field `BindingSlotKeyV1`+digest와 expected head를 그대로 보내며 UI label에서
key를 재구성하지 않는다. Stale-head이면 다른 slot을 끄거나 전체 extension을
disable하지 않고 현재 상태를 다시 읽게 한다. 과거 binding 이력과 현재 rollback
적격성을 한 상태로 합치지 않는다. 각 superseded binding에 `롤백 보존중/해제됨/
사용됨`과 exact retention head를 보여 준다.

인증된 owner는 크기·형식이 제한된 code-free lens/evaluator definition을 가져오고, 이미 외부
운영자가 staging하여 현재 qualification을 통과한 runtime extension을 허용 scope 안에서 bind,
disable 또는 rollback할 수 있다. rollback은 현재 자격·권한을 다시 확인한다. 실행 코드·OCI image,
storage/vault adapter를 브라우저 upload로 설치하지 않는다. 실행형 확장이 필요하면 UI는 exact
digest의 immutable deployment request와 현재 `운영자 준비 중 / receipt 대기 / handshake 실패 /
qualification 필요` 상태를 보여 주지만 Docker/Portainer를 제어하거나 터미널 명령을 제품 단계로
가장하지 않는다. 사용자는 확장을 사용하지 않아도 지원 built-in만으로 가능한 업무를 계속할 수 있다.

현재 installation과 교체 뒤 남은 superseded service를 한 행/상태로 합치지 않는다. Current 행은
`현재 설치 제거`가 active binding을 먼저 disable하고 그 때 만든 retained target을
해제하여 binding/rollback/environment dependency가 모두 0인 때만 새 uninstall tombstone/head를
만든다는 점을, superseded 행은 exact ancestor와
그 service tuple, 현재 descendant head, active binding/rollback/environment dependency를 보여 준다.
롤백 보존중인 행에서 owner는 `롤백 보존 해제`를 별도로 확인할 수 있다. 확인문은
현재 binding head와 해제할 target revision을 정확히 표시하고, 이력은 계속 보이지만 해당
target으로는 다시 rollback할 수 없으며 이 행위 자체가 service를 제거하지 않는다고 고지한다.
성공 후 retention head만 `released`로 전진하고 binding/installation head는 그대로이며,
stale/cross-slot/current-target/repeated release는 각각의 blocker로 보여 준다. 모든 retained target이 해제/
consume되고 세 dependency 집합이 모두 비었을 때만 `교체된 서비스 정리 요청 준비`를 허용하고, 실제 host
제거는 외부 운영자에게 맡긴다. 성공 뒤 current head가 그대로이고 target retirement head만
전진했음을 표시한다. Non-ancestor/stale head/남은 dependency/현재 서비스 handshake 실패는
모호한 `제거 실패`가 아니라 각각의 blocker와 재조회 상태로 보인다.

재시작 뒤에도 installation, service retirement, qualifications, bindings와 실패 이력이 복원되어야 한다. 만료·runtime/
framework/platform 변경은 verified artifact를 삭제하지 않고 영향받은 qualification/binding만
중지하며 `다시 자격 확인 필요`와 영향을 받은 환경을 표시한다. 새 qualification과 binding
supersession은 이전 기록을 보존하고, 경합·실패 시 활성 head와 실제 실행 상태를 모순되게 보여
주지 않는다.

## 7. 실행 관제와 실제 산출물

실행 시작 후 같은 그래프가 실제 관제가 된다. 설계 연결은 예정선, 실제 전달은 사건 근거가 있는 선으로 구별한다. 실시간·과거 선택·기록 재생·격리 실험을 명시한다. 사용자 일반 브라우저나 다른 앱을 임의로 감시하지 않는다.

- 기본 노드는 역할과 현재 수행 상태다. 선택하면 검토 후 재방문한 **수행**과 실패 재시도의 **시도**를 별도로 고른다. 선택한 과거 시도에 최신 산출물을 붙이지 않는다.
- `입력 / 산출물 / 전달 / 도구 작업 / 기록` 상세는 동일 수행/시도 기준이다. 입력은 앞선 완결 산출물 전체와 정확한 버전을 열 수 있다. 출력 0개·복수·생성 중·실패·미보존을 정상적으로 표현한다.
- 전달 상세는 보낸 산출물 버전, 수신 수행/시도, 수신 확인을 연결한다. 전달됨, 명시적 활용 근거, 개입으로 지지된 영향은 서로 다른 주장이다.
- 역할의 실제 도구 호출·입출력·시간·오류·재시도·결과 파일을 연결한다. 지원하는 브라우저 작업은 당시 스냅샷/현재 세션/기록 재생을 구별하며 계정·세션의 허용 범위를 넘지 않는다.
- 전체 업무 완료 전에도 완료한 역할의 실물을 열 수 있다. 생성 완료 문구나 파일명 카드만 있고 파일 bytes가 없으면 산출물 완료가 아니다.
- 실패·사람 대기는 관련 역할/의존 노드와 함께 보인다. 안전한 독립 작업은 계속할 수 있으나 오염/공유 자원 문제가 있으면 근거에 맞게 보류 범위를 넓힌다.

### 7.1 다형식 작업면의 지원 계약

아래는 **첫 릴리스에서 구현·검증할 기본 조합에 대한 위임 결정**이다. 무제한 편집기·모든 파일 형식 지원을 주장하지 않는다. 내장 편집이 없는 형식도 원본과 대안 파일을 받을 수 있으며, 미지원 비교는 해당 범위에서 명시적으로 보류한다.

| 형식 | 원본/파생 열람 | 자기 버전·부분 범위 | 비교·접근성 경계 |
| --- | --- | --- | --- |
| TXT/Markdown | 안전한 원문/렌더링 전환, 원문 다운로드 | 내장 텍스트 편집, 원본 해시+문자/문단 범위에 연결된 대안 | 단어/문단·구조 차이. 렌더링 차이와 원문 차이 분리, 스크린리더 원문 |
| CSV/구조화 표 | 행·열·값을 보존한 표, 원본 다운로드 | 셀/범위 편집 또는 대안 파일, 원본 버전+시트/표/범위 | 행 정렬·키 대응 불명확이면 사용자에게 대응만 확인. 수식은 실행하지 않음 |
| PDF | 격리된 페이지 렌더링과 원본, 추출 텍스트 별도 | 페이지/영역 선택, 대안 텍스트·이미지·PDF 파일 연결 | OCR/추출/레이아웃 손실 표시. 스캔본을 읽었다고 하지 않음. 페이지 이미지 대체 설명/추출은 한계를 함께 제공 |
| DOCX | 격리 변환 미리보기와 원본, 본문/표 구조 추출 구분 | 대안 파일 또는 선택 문단/표의 대안 내용 | 변환 결과는 파생물. 원본 조판을 동일 재현했다고 주장하지 않음 |
| PNG/JPEG 및 안전 변환 SVG | 이미지 확대·원본 다운로드, SVG는 스크립트 없는 파생 렌더링 | 전체 대안 이미지 또는 사각 영역+대안 이미지/내용 | 영역 좌표+원본 크기/버전 고정. 시각 차이를 의미 개선 점수로 사용하지 않음 |
| 기타 파일/오디오/영상 | 확인된 MIME·크기·해시·원본 다운로드, 안전한 지원 미리보기만 | 대안 파일을 원본에 연결; 지원되는 시간/영역 대응만 사용 | 자동 내용 이해·편집·부분 비교가 없으면 각각 미지원. 확장자로 실행하지 않음 |

PDF를 포함한 기본 업무 산출물은 DeepTwin 웹 작업면에서 생성·열람·대안 내용 제공까지 가능해야 한다. 모든 형식의 복잡한 원본 조판 편집기를 프레임워크가 전부 내장한다는 뜻은 아니다. 사용자가 이미 만든 파일 업로드는 선택 경로이고 외부 프로그램 사용을 핵심 여정의 필수로 삼지 않는다.

미리보기 실패해도 원본·메타데이터·관련 맥락·다운로드를 유지한다. 다운로드는 실행이나 제작자 전송이 아니다. 악성/실행 가능한 파일은 경고와 제한된 원본 접근을 제공하고 브라우저 출처/네트워크 권한을 부여하지 않는다. 미리보기·부분 대응·편집·자동 비교의 준비 상태를 분리한다.

## 8. 자기 대안과 차이 탐구

`내 버전`은 선택한 원본을 유지한 별도 작업면이다. 사용자는 전체 또는 일부에 자신의 실제 내용을 쓰거나 파일을 올린다. 이유·수정 명령·원인 해설·점수는 필요하지 않다. 일반 대화에서 실제 자기 버전을 제공하면 원본/범위가 명확할 때 해당 대안에 연결하고, 모호하면 연결 대상만 확인한다. 시스템이 대신 만든 내용을 사용자가 만든 대안으로 기록하지 않는다.

대안은 원본 산출물·입력·역할/수행/시도·환경·모델 버전, 작성자/시각, 전체/부분 범위, 원본 노출/독립 수행의 확인 상태를 가진다. 선택 영역만 있거나 빈 초안이면 실제 대안 없음이다. 부분 밖을 원본으로 채운 합성 미리보기는 시스템 파생물이며 사용자가 전체를 작성·검토한 것으로 표시하지 않는다.

초안 보존과 분석 시작은 구별한다. `차이 살펴보기` 또는 대상이 명확한 대화 요청은 저장본과 허용된 분석 범위를 고정한다. 이미 허용된 분석/실험 정책이 있으면 같은 범위의 후속 내부 작업을 매번 승인받지 않는다. **‘이 정도만 보고 다시’라는 별도 필수 버튼, 전체 대안 완료, 모든 질문 답변을 선행 조건으로 만들지 않는다.** 침묵·단순 열람·초안 자동 저장도 신규 실행 권한이 아니다.

탐구의 첫 화면은 관찰 차이와 관련 실행 구간이다. 차이 선택 시 원본/대안 부분과 전체 문맥, 실제 입력/전달/도구 근거, 경쟁 설명이 함께 따라온다. 조사 강조를 원인 확정 또는 책임 점수로 표시하지 않는다.

시스템 결손, 조건부 판단 차이, 양자의 공존, 일회성 예외, 대안 오류, 일반화 없음, 관찰/원인 미확정을 유지한다. 필요한 경우 한 조건을 바꾼 업무 사례·새 수행·판별 질문을 제시하며 목적을 업무 언어로 설명한다. 고정 철학 설문이나 사용자 철학/성격 프로필을 만들지 않는다.

일반 화면에는 관찰, 가설, 새 증거, 시험할 변경을 구별한다. 감사 상세에는 렌즈 출처/정의/버전/혼합/기권/탈락, 새 응답 전에 고정한 질문·예측, 실제 결과를 연결한다. 철학 해석을 운영 규칙에 직접 주입하거나 대안 원문 복사로 흡수 성공을 판정하지 않는다.

질문 거절·보류·새 증거 부족은 해당 탐구에만 반영한다. 원본/대안이 없는 상태에서 비교 결과를 만들지 않는다. 새 대안이 들어오면 기존 탐구·평가를 덮지 않고 새 증거/후보 버전과 재검증 범위를 남긴다.

## 9. 이전 업무 큐 재평가와 사람의 환경 버전 승인

`변경 시험`은 복원·새 지식/절차·보호의 변경 묶음, 기준/후보 환경, 관련 과거 업무 큐, 비교 조건, 평가 기준과 권한·사용량·시간 한도를 보여 준다. 세부 실행은 [성장 계약](growth.md)에 따른다. 대안의 작은 범위가 영향·시험 범위를 가두지 않으며 무관한 모든 개선 과제 완료를 요구하지 않는다.

실험 화면은 큐 전체 요약에서 **업무·회차의 기준/후보 실행 쌍**으로 내려간다. 두 그래프의 수행·시도·산출물을 함께 열고 추가·제거·미대응 수행은 그대로 표시한다. 원 대안의 출발점인 과거 실행과 비교용 기준 재실행은 다른 참조다. 실행하지 않은 기준 결과를 꾸미지 않는다.

각 회차에 품질/개선/악화/필수 실패/미측정, 모델·도구 응답·평가기·데이터 조건의 차이, 소요/사용량, 최선 유효 후보와 관련 근거를 남긴다. 최고 회차만 보여 주거나 튜닝 자료를 미관측 자료로 재명명하지 않는다.

### 9.1 조기 종료를 보여 주는 방식

- 사용자가 이해할 설명: **“정한 품질 수준에 도달한 뒤, 비교 가능한 평가에서 큰 개선이 이어지지 않으면 반복을 멈춥니다.”** 구체 횟수·품질 하한·개선 기준은 고정된 실험 정책을 함께 연다.
- 기본 추천은 유효하고 비교 가능한 연속 평가에 대한 patience 3이다. 품질 하한에 처음 도달한 회차는 카운터 0이며, 이후 비교의 상세 조건·진전 기준·reset·동률·악화 처리는 성장 계약을 따른다. UI 자체가 카운터를 독립 계산하지 않는다.
- 진행 중에는 실제 `개선 정체 1/3` 등의 근거 있는 카운터와 최선 후보·마지막 평가 상태를 표시한다. 실제 최고 후보와 마지막 유의미한 개선의 비교 기준은 구분해 열 수 있다. 작은 개선의 누적도 고정 기준에 따라 처리한다. 정상적으로 완료한 비교에서 확인된 업무 실패/회귀는 유효한 비개선일 수 있지만 실행기·평가기 장애, 취소, 근거 없음, 조건 불일치를 유효 평가인 척 횟수에 넣지 않는다.
- 종료 이유는 `개선 정체로 반복 종료`(`plateau_reached`), `사용량/시간 한도`(`budget_exhausted`), `품질 수준 미달·한도 종료`(`below_floor_exhausted`), `사용자 중단`(`human_stop`), `안전 문제`(`safety_stop`), `추가 근거 필요`(`evidence_blocked`), `비교 조건 변경`(`lineage_changed`)으로 구분한다. 품질 하한 미달에서 예산이 끝난 것을 개선 정체 합격으로 표시하지 않는다.
- 정체 종료는 최적해·최종 검증 통과·자동 버전업을 뜻하지 않는다. 최선 유효 후보가 있으면 해당 근거와 남은 검사를 제시한다. 적합 후보가 없으면 없다고 표시한다.
- 새 자료/대안/평가 기준/허용 예산으로 다시 시험할 때 원 기록은 보존하고 새 평가 묶음의 조건을 표시한다. 같은 정체 정책을 몰래 초기화하며 무한 반복하지 않는다.
- 이 표시는 **제품 업무 환경의 개선 루프**에만 속한다. 개발 진행률, 개발 목표의 완료/중단, 전체 세션 수명과 연결하지 않는다.

### 9.2 최종 검증·승인·적용·롤백

반복이 종료되거나 허용된 후보 고정이 이루어지면 별도 최종 증거를 검사한다. 고정 후보와 미관측/전향 자료·경계·회귀·출처·안전의 결과 및 결손을 표시한다. 후보가 바뀌면 이전 합격을 복사하지 않는다. 관찰 전용은 실제 출력에 영향 없음으로 표시한다.

권한 있는 사람에게 정확한 변경 묶음·후보 버전, 개선과 악화, 검증 범위·한계, 적용 범위·현재/되돌릴 버전을 제시한다. `이 버전 적용 승인` 전에는 운영 기준을 바꾸지 않는다. 개발자의 자동 의사결정 위임이 제품 사용자의 최종 승인 행위를 대체하지 않는다.

승인 뒤 `적용 중 / 적용 확인 / 적용 실패 / 상태 확인 필요`를 구별하고 실제 적용된 버전이 승인본과 일치할 때만 새 운영 버전으로 표시한다. 작은 변경도 버전화할 수 있으며 매번 전체 환경 재설계를 요구하지 않는다. 롤백은 대상 버전·재개 영향·권한을 확인하며, 이미 발생한 외부 발송 등을 되돌렸다고 주장하지 않는다.

일시적인 읽기 요청은 기존 정책의 제한된 자동 재시도를 허용한다. 모델·외부 쓰기의 결과가 불명확하면 먼저 소유 요청과 외부 상태를 확인한다. 서버/worker 재시작은 요청 idempotency·실행 소유권·보존 경계 재조정 후에만 재개하며, 가능한 정상 재개와 신규 비용을 발생시키는 재실행을 구분한다.

## 11. 기록·선택적 추출·개인정보

어느 업무 화면에서도 `기록 내보내기`로 관련 환경·기간·업무·실행·설계/렌즈/실험·승인 범위를 선택한다. UI는 관련 계보를 제안하되 선택 범위를 자동 확대해 원문을 외부에 보내지 않는다. 기본은 로컬 파일 생성이며 제작자 전송과 별도다.

1. 관련 기록 범위와 포함할 원문/산출물·파생 자료를 선택한다. 비밀정보는 선택 가능 항목 자체에 두지 않는다.
2. 미리보기에서 실제 포함 파일·민감 내용·가림·제외·접근권한/재배포 제한·빠진 근거와 진단/재현 한계를 확인한다.
3. `파일로 추출`은 선택한 정확한 묶음과 manifest를 만든다. 추출 실패·취소는 원 기록을 지우지 않는다. 해시만 있는 자료를 복원 가능하다고 표시하지 않는다.
4. 사용자는 추출 파일과 자신의 의견을 전달할 수 있다. 웹 제품 내 전송 기능을 제공할 때에도 수신자·파일·전송 범위 확인을 별도로 받는다. 자동 업로드·제작자 학습 동의·전체 로그 상시 전송은 없다.

배포 뒤 최초 웹 설정·자료/요청·설계 후보 전체·렌즈 조합/탈락·모델/도구·실행·대안·탐구·변경·평가·중단·승인·실제 적용은 하나의 계보로 조회할 수 있다. 감사 설명과 관찰 가능한 동작은 기록하지만 자격증명·인증 URL·토큰·숨은 사고과정·다른 앱 활동·키로깅은 수집하지 않는다. DeepTwin이 기동되기 전 Docker/Portainer의 호스트 작업은 관측한 것처럼 소급 기록하지 않는다.

원문 보관과 메타데이터 사건을 분리하고 UI에서 같이 열 수 있다는 이유로 운영 에이전트가 대안/진단/미승격 자료를 검색할 수 없게 한다. 자료 삭제·보존 기간 변경은 영향·복구 가능성을 안내하며, 이미 추출/전송한 복사본까지 삭제되었다고 주장하지 않는다. 저장소 잠금/권한 변화 뒤 상세 화면과 다운로드에도 서버 접근 검사를 적용한다.

## 12. 접근성·문구·검증 수용 연결

키보드로 입력·후보 비교·노드/선 선택·산출물·대안·승인에 도달한다. 그래프에는 같은 관계를 읽는 접근 가능한 역할/입출력 목록을 제공하되 시각 그래프를 제거하는 대체 제품으로 만들지 않는다. 상태는 색만으로 구분하지 않고 이름·아이콘·텍스트로 보이며 단계 알림은 스크린리더를 과도하게 반복하지 않는다.

모달/확장 보기의 초점과 닫기·복귀를 보존한다. 360px 이상 좁은 화면, 1024px·넓은 데스크톱, 확대/키보드·밝은/어두운 테마에서 중요 행동·정확한 원본 접근이 가능해야 한다. 그래프·표 내부 탐색을 페이지 전체 넘침이나 글자 축소로 대신하지 않는다. 오류 메시지는 사용자 자료를 HTML로 실행하거나 인증 비밀을 노출하지 않는다.
