These are format facts, not authentic observations or authorization.

All shapes below are closed; all listed fields required, `?T` means required T-or-null. JSON bool is never int. `U`=canonical nonnil UUID; `H`=lowercase SHA256 hex64; `N`=integer0..9007199254740991; `P`=N>=1; `R`=existing EntityRef; `B`=existing BlobRef with purpose=operational; `T`=canonical port UTC millisecond timestamp; `DT`=existing domain UTC microsecond timestamp. `I`=canonical port identifier; `S`=NFC short-text1..512; `E`=exact effort string1..80; `L`=bounded existing ObjectRef locator, never authority. All record refs must resolve to their named kind/variant, same vault and exact bytes/hash under existing purpose/grant rules (common bootstrap roots retain their existing bootstrap purpose). New content records are operational; no generic ref is accepted merely because its syntax is valid.

`F[X]` preserves native optional fields as `{state:absent|null|value,value:?X}`; absent/null require value=null, value requires non-null X. Arrays are ordered unless explicitly sorted. `Canon` is unchanged domain canonical_json; every metadata record must pass its real 1MiB/depth32/10k-item/string65536 bounds. Port payloads also pass existing stricter port bounds. Raw upstream JSON uses UTF-8, duplicate-key/nonfinite/BOM rejection, depth32, 65536 recursive members/elements, string65536 bytes, numeric token128 bytes; known integer fields use N/P. Raw unknown numeric fields may be finite decimals; retain their original bytes, never cast them into domain authority.

## 3. Ownership, replay and concrete interfaces

`provider_semantic_records` owns `seal_frozen(store,*,command_id,turn,execution_envelope_ref,purpose_ref,grant_refs,artifact_input_bindings,messages,max_output_tokens,instruction_projection)->R`, `load_operation(store,request_id)->ImmutableRecord|None`, `seal_operation(store,*,config_ref,request,core_boot_id,reservation_ref)->R`, and `seal_terminal(store,*,operation_ref,result,response_ref)->R`. They use existing DomainStore transactions/record graph, not new tables. Deterministic lookup uses exact `(vault_id,kind,id,version=1)` domain_records identity, loads stored sha256, then DomainStore's exact load/graph checks; never trust the index alone.

Compute semantic key exactly as canonical ports §2.2; hash input and existing schema bytes never change. **F1 correction requires explicit approval of [scoped read/cancel amendment](post46-read-observation-amendment-draft.md), not silent implementation reinterpretation.** Every operation anchor remains uniquely addressed by request_id; compare exact Canon(request) bytes and config_ref before any fresh admission. Same ID/bytes/config returns the immutable terminal or retained pending/unknown state with zero new worker/gateway/upstream action; changed bytes/config under that ID conflict. Historical owner/purpose authorization still applies.

Only model_step creates the semantic-key index: tag `provider-semantic-idempotency-v1`, owner_uuid=uuid5(NAMESPACE_URL,semantic_key), ordinal0, content `{schema_version:"provider-semantic-idempotency-v1",request_id:U,request_sha256:H,operation_ref:R}`. Insert operation and index atomically in the existing domain_records writer transaction. Different request_id under an already owned model key conflicts; unknown never resends. Fresh capabilities/catalog/status IDs create independent immutable observations under the same unchanged semantic key after fresh admission/currentness checks; they create no semantic-key index. Fresh catalog may read upstream again, never Messages. Fresh cancel IDs use the target-scoped cancellation-intent rules below, not model-step effect keys. No second registry/table is introduced.

Cancellation intent uses validation_report tag `provider-semantic-cancel-intent-v1`, owner_uuid=target operation's request_id, ordinal0, closed content `{schema_version:"provider-semantic-cancel-intent-v1",target_operation_ref:R,first_cancel_operation_ref:R,first_request_sha256:H,reason_class:canonical-cancel-reason,core_boot_id:U}`. Under the actual target's core operation mutex, check authoritative terminal first; otherwise verify live cancellability, atomically insert intent plus first cancel operation, then set the target's one-way cancel Event before acknowledging accepted. Forward at most one best-effort gateway cancellation control, never a provider remote-cancel request. New cancel ID observing terminal returns already_terminal regardless of prior intent; existing live intent with set latch returns accepted without forwarding again; owner loss/no live cancellable target or an intent whose latch was not set returns not_cancellable, never reconstructs/resends. Same cancel ID replays its original acknowledgement even if the target later changes. Later reasons do not escalate/rewrite the first intent. The amendment freezes race/error details and approval gate.

Historical replay still requires the authenticated owner/purpose read authority; only native/live eligibility checks are skipped. Conflict maps to canonical failed/invalid_request/validation/never with the request's exact identity and empty outputs/artifacts, not a fabricated copy of the old success. It does not replace the canonical terminal of the earlier operation.

No terminal record means pending only while the same owner process actually has a pre-send operation; if any committed send-intent exists after owner loss, result is unknown through existing ledger reconciliation. Do not infer unsent merely from absent terminal. Terminal sealing is deterministic; blobs may be sealed before transaction but are not authorized outputs until result acceptance. Existing ledger acceptance remains the final runtime authority.

`provider_semantic_context.load_semantic_context(store,*,config_ref,request_ref,now_utc)->ProviderSemanticContext` uses concrete scoped owner dependencies set at construction, not request-supplied Mapping/callback authority. Context carries detached config/request, exact resolved refs/records, validated time, immutable connection/credential pins, profile/capability/reservation evidence and the actual authenticated channel/session observations. `provider_attempt_transport.ProviderAttemptTransport.__call__(permit,request,window)->AttemptTransportResult` stays the existing dispatcher callable.

The missing genuine C/binding/current-head issuer is **not** implemented as a test-mode branch in this loader. Offline harness under tests builds real temporary records and a concrete test-owned semantic owner using the existing private trusted-context projection seam; validates all exact joins through the same loader/port validator. Its qualification/head facts are labelled synthetic in fixture ownership, not claimed as native results. No production factory imports/registers that owner or accepts a fixture selector. Future genuine owner must supply the same immutable interface; its actual permission/C issuer is a separate activation gate, not an arbitrary passed callback. In-process code owners remain trusted, not Python-sandboxed.

## 4. Exact Models projection and traversal

Raw pages require `{data,first_id,last_id,has_more}`; additional root fields retained, not used for decisions. data<=100. Each native model requires type="model",id:I,display_name:S,created_at RFC3339 string<=64; optional nullable capabilities/max_input_tokens/max_tokens use F. Invalid known fields refuse; preserve raw unknown ordinary fields but do not give them capability meaning. RFC3339 admits Z or signed HH:MM offset and 0..9 fractional digits; real calendar required; no leap second. Parse exact instant for ordering, retain original string.

`ModelProjection={id:I,display_name:S,created_at:str,capabilities:F[Capabilities],max_input_tokens:F[P],max_tokens:F[P]}`. Known nested capability objects reject unknown fields (a future decision-bearing shape requires review), while raw native record bytes remain retained.

Traversal is exact:

Reject duplicate model IDs within/across pages, repeated requested cursor, returned last_id equal to requested cursor, a previously seen last_id, or has_more=true with empty data.
3. Retain API order exactly; do not sort model rows by name. Across known non-epoch created_at values require non-increasing release time; epoch marks unknown order metadata and does not authorize a guessed date. This stricter ordering check may refuse future upstream behavior and is a project rule, not a claimed API snapshot guarantee.
4. Stop successfully only at has_more=false within all caps. Retain already received pages as private evidence.
5. Empty complete native catalog is valid but admits no model. Exhausted/refused traversal may retain private incomplete evidence but returns no successful catalog output.

Text modality is not a native ModelInfo flag. `text-policy` source URL is only provenance text: activation must supply an authorized reviewed policy with retained exact source bytes/hash, explicit scope_model_ids and review/effective window. Require retrieved_at<=reviewed_at<=now<valid_until, valid_until-reviewed_at<=7days (chosen project freshness), and model ID in that exact reviewed scope. The observation ref points to retained exact-profile evidence, not private B, a model-name guess or merely non-null Models capabilities. Omission of thinking/effort does not prove default output is text-only. The genuine observation issuer is outside this offline tranche; synthetic evidence is explicitly test-owned. Live owner must authenticate its provenance before constructing the same immutable context. This is a consumer seam, not a new C/source registry.

## 5. Request, SSE and usage codec

API-key-only production selector is HTTPS api.anthropic.com:443. Required nonsecret headers exactly `anthropic-version:2023-06-01` and `content-type:application/json`; gateway adds x-api-key. No Authorization/workspace/beta/proxy/cookie/cache/sampling/tool/effort overrides. Tests route the same selector to an explicit loopback endpoint in the test-owned constructor, not a config/environment field or supported production factory. No redirects; legacy raw SDK path never runs.

HTTP framing headers Host and Content-Length are gateway-generated from the pinned endpoint/body, never projected caller headers; omit automatic Accept-Encoding via the connection's explicit request construction. Do not follow proxies, compressed-body transformations or redirects. Gateway checks response media type application/json for models or text/event-stream for messages, allowing only absent parameters or charset=utf-8; unsupported content encoding/media refuses normalization after recording possible send. The descriptor repeats that checked media type. Response headers/errors are not blindly reflected into worker/core logs.

New text serializer, isolated from accepted B, constructs exactly `{model,max_tokens,messages,stream:true}` plus `system` iff the frozen first system input exists. System value is its exact UTF-8 text. Remaining messages are `{role:user|assistant,content:[{type:"text",text:exact-input-text}]}` in frozen order. No unknown request keys. Recompute expected body independently in core and require equality to worker proposal before gateway prepare. Actual body<=1MiB and all input bytes/ref digests agree. This closed body excludes all cache_control and tools; it does not assert an upstream named effort default.

New response accumulator may reuse pure SSE framing/duplicate-JSON primitives but **must not reuse old private Catalog/Text acceptance logic unchanged**. Raw full upstream bytes are retained separately from canonical metadata. Known SSE types require payload.type equal event name. message_start requires message `{id:string1..200,type:"message",role:"assistant",model:I,content:[],stop_reason:null,stop_sequence:null,usage:Usage}`; additional ordinary fields retained. Require one start; model exactly equals selected resolved catalog ID. No alias substitution.

For text blocks require increasing contiguous index0..3, exactly one active block, start `{type:"text",text:string}` (initial text may be empty), deltas `{type:"text_delta",text:string}`, then stop same index. Retain initial text+deltas exactly, not normalized. Other content/delta types are outside this profile and prevent success. Require all blocks closed before message_delta terminal reason; message_stop exactly once and only after non-null known stop reason; reject later non-ping known lifecycle events. Only end_turn is successful in this narrow profile; max_tokens/stop_sequence/refusal/tool_use/pause_turn/model_context_window_exceeded/unknown reasons do not become successful partial text. Preserve all raw evidence and classify uncertain-effect outcomes per main draft.

Allow multiple message_delta updates; output_tokens is cumulative and cannot decrease. Other known numeric cumulative categories cannot decrease when a new non-null value appears. Pings/unknown named events are bounded, retained and skipped without changing block/terminal/usage state. Unknown content/delta types are not treated as unknown informational events. error event, missing required start/delta usage, incomplete framing or no coherent message_stop prevents success. Unknown ordinary JSON fields stay raw; unknown fields inside usage objects are recorded as unknown_categories and never financially interpreted.

## 8. State machines and cancellation

Worker model path: IDLE → BEGIN_VALIDATED → INPUTS_RECEIVED → PROPOSAL_SENT → WAIT_UPSTREAM → RESPONSE_RECEIVED → NORMALIZED → FINAL_SENT → CLOSED. Core independently reconstructs proposal before gateway prepare. For catalog, WAIT_UPSTREAM/RESPONSE_RECEIVED cycles up to20 with cursor checks before the next proposal. Idle capabilities/status/cancel can complete without HTTP. No second model dialogue is admitted while active.

Gateway path: IDLE → PREPARE_VALIDATED → BODY_RECEIVED → READY → COMMITTED → DELIVERY_CLAIMED → WRITE_MAY_START → RESPONSE_COLLECTING → RESULT_SENT → CLOSED. Only READY accepts one matching commit. Deadline/disconnect before COMMITTED cannot send. Immediately before handing header/body bytes to HTTP mark WRITE_MAY_START, conservatively treating exceptions after that as may_have_sent. No restart/resume/automatic resend. A cancel before WRITE_MAY_START wins a local cancellation latch; after it cancellation only stops local work and retains possible effect.

Application cancel acknowledgement is succeeded/failed query semantics, not original call success. Original model_step: before possible write → cancelled/none/null/not_applicable; after possible write without a proved terminal → cancelled/unknown/null/unconfirmed if the cancellation was observed, otherwise unknown/unknown/null/unknown. All non-success artifacts empty. Complete valid end_turn yields succeeded/committed/effect-ref/confirmed; malformed/truncated/unsupported response after possible write yields unknown, never failed with committed/unknown effect. Non-2xx Messages response is conservatively unknown unless future contract proves non-effect; catalog non-2xx is failed read.

Cancellation/deadline sets a per-exchange Event and shuts down/closes the owned HTTP socket; stream reader uses the original remaining deadline, not an unbounded read. Joins and resource cleanup consume only remaining deadline; a failed prompt interruption makes the exchange unknown and closes the gateway instance, not a cancelled remote success. Native scheduling/DNS/HTTP interruption fit is not established by the design; controlled-server tests must demonstrate bounded cleanup on supported CI, and production platform activation must refuse a profile whose real interruption behavior is unproved. No new PID/native workaround is authorized.

### 9.1 Optional shared custody budget (F2 correction)
