# Feature Specification: DeepTwin 전체 설계와 오픈소스 웹 프레임워크 배포 후보

**Feature Branch**: `codex/ui-structure`

**Created**: 2026-09-07

**Status**: ADR-009–013의 웹 프레임워크·배포·음성·비밀·Codex 경계에 대한 이전 V1
교차 검토는 2026-09-08 확장 프레임워크 감사에서 다시 열렸다. ADR-014가 종류별 의미 포트,
내구적 확장 수명주기, 외부 운영자 staging, 브라우저 관리, 배포 가능한 SDK/클라이언트와
재귀 의존성 경계를 보정했다. 독립 검토는 revision 1–6을 기각했고, exact 35-entry manifest의
revision 7을 P1=0/P2=0으로 승인하여 T086 설계 게이트를 닫았다. 이는 구현·배포·효과 검증
완료 판정이 아니다.
이전 V0 네이티브 검토와 최초 T086 판정은 역사 자료이며 구현·배포·효과 검증 완료가 아니다.
현재 저장소에는 프로젝트 라이선스가 없어 아직 법적으로 오픈소스 릴리스가 아니며, T084의
copyright-owner 명시 승인 전 LICENSE 추가·공개·재배포 완료를 주장하지 않는다.

**최신 요구 변경**: 2026-09-08 사용자가 제품을 네이티브 설치형 앱이 아닌 **웹 기반
오픈소스 멀티에이전트 프레임워크**로 명확히 정정했다. 브라우저가 제품 UI이며, 자체 호스팅 배포와 최초 웹
온보딩을 구분한다. 기존 macOS 앱·DMG·내장 WebView·제품 런처 전제는 현재 요구가 아니다.
2026-09-07의 Claude API 전용, Codex 구독과 선택적 API 요구는 그대로 유지한다.

**Input**: 전체 설계를 먼저 완성하고, 변경은 전체 맥락을 고려한 추천안으로 자동 결정하여
자체 호스팅 가능한 웹 프레임워크 배포 후보와 검증 보고서까지 진행한다. 제품의 이전 업무 큐 재평가는 일정 품질
수준에서 큰 개선이 없는 평가가 3회 이상이면 조기 종료한다. 개발 진행의 종료 규칙이 아니다.
대략적인 전체 진척률과 근거가 생긴 뒤 남은 시간 범위를 보고한다.

## 제품 경계

- **프레임워크**: 목표 릴리스에서 멀티에이전트 그래프 실행, 권한, 증거, 예산, 기록과 DeepTwin 성장 루프는 자체 호스팅
  서버의 재사용 가능한 오픈소스 코어다.
- **공식 제품 표면**: 함께 배포되는 브라우저 UI가 지원되는 최종사용자 제품·관제면이자
  첫 번째 참조 클라이언트다. 참조 구현이라는 표현은 이 UI가 선택 사항이라는 뜻이 아니다.
- **배포 표면**: Docker Engine/Desktop, Compose와 Portainer는 인스턴스 운영자가 쓰는 외부
  배포·운영 수단이다. 이를 제품 UI, 설치 런처 또는 사용자 업무 화면으로 취급하지 않는다.
- **모델 표면**: Claude는 API 연결만 지원한다. Codex 구독은 서버가 소유·격리하는 관리형
  어댑터/실행기로 연결하며 Codex API는 별도 선택이다. 사용자가 제공자 앱이나 CLI 안에서
  DeepTwin을 사용하도록 요구하지 않는다.
- **도구·산출물 표면**: 에이전트의 브라우저·외부 도구 사용과 PDF 등 다양한 원형 산출물
  생성은 서버 측 프레임워크가 권한·실패·부작용·계보를 통제한다. 브라우저 UI는 일반 텍스트로
  평탄화하지 않고 지원 형식의 실제 파일·미리보기·전달 관계를 다룬다.
- **확장 표면**: 공통 worker transport는 의미 포트가 아니다. 제공자·모델 런타임·도구·산출물
  코덱·렌즈·평가자·저장소·비밀 저장소·내보내기는 각각 코어가 소유한 버전 포트 계약을 따른다.
  실행형 제3자 확장은 외부 배포 운영자가 digest로 고정한 OCI 서비스와 서명된 배포 receipt로
  staging하며 제품이 코드·이미지를 내려받거나 컨테이너를 조작하지 않는다. 브라우저의
  `설정 > 확장`은 상태·근거·binding을 관찰·통제하되 실행형 staging authority를 얻지 않는다.

## User Scenarios & Testing

전체 제품의 정체성은 **멀티에이전트 관제 그래프 기반 LLMOps + 철학 렌즈 기반 DeepTwin**이다.
아래 여정은 각각 시험할 수 있지만, 일부 구현만으로 전체 제품을 완성했다고 부르지 않는다.
모의 자료를 이용한 시험, 실제 제공자 실행, 실제 사용자의 만족·업무 효과를 구별한다.

### User Story 1 — 웹 인스턴스에 접속해 자신의 업무를 설명한다 (Priority: P1)

인스턴스 운영자는 지원되는 비개발자용 경로로 오픈소스 DeepTwin 웹 인스턴스를 배포한다.
사용자는 브라우저에서 최초 설정을 마치고 Codex 구독 또는 Claude API를 연결한 뒤, 말·글·자료 중
편한 방식으로 업무를 설명한다. 자신의 입력과 시스템 해석이 구별되며 짧은 업무 이해 결과를 확인한다.

**Why this priority**: 최초 오해가 모든 설계에 전파되는 것을 막는 진입점이다.

**Independent Test**: 빈 지원 호스트에서 공식 비-CLI 배포 경로로 인스턴스를 시작하고, 새 사용자
상태의 브라우저 UI만으로 최초 설정·연결·입력·수정·재개를 수행한다. 네이티브 앱 창은 요구하지 않는다.

**Acceptance Scenarios**:

1. **Given** 설명만 또는 자료만 있는 상태, **When** 업무를 시작하면, **Then** 불필요한
   철학 설문이나 모든 외부 계정 연결을 요구하지 않고 목적·완료 조건·자료·위험·미확정을 제시한다.
2. **Given** 여러 파일 중 일부를 읽을 수 없음, **When** 읽기를 끝내면, **Then** 파일별 원본과
   읽은 범위·실패를 보존하고 읽지 못한 내용을 이해했다고 주장하지 않는다.
3. **Given** 음성 입력 중 키보드로 수정함, **When** 전사 결과가 갱신되면, **Then** 직접 수정한
   내용을 덮어쓰지 않으며 임시·확정 전사를 구별하고 마이크 중단·거부를 처리한다.
4. **Given** 기존 업무의 입력 또는 모델을 바꿈, **When** 새 이해를 요청하면, **Then** 과거
   이해·그래프를 보존하고 새 입력 버전의 결과로 구별한다.
5. **Given** 배포된 인스턴스의 URL, **When** 지원 브라우저로 접속하면, **Then** 설치용
   데스크톱 셸·내장 WebView·제공자 CLI 화면으로 이동하지 않고 DeepTwin의 웹 작업공간에서 계속한다.

### User Story 2 — 같은 업무를 수행할 실제 그래프를 비교한다 (Priority: P1)

확인한 업무에서 여러 구조를 제안받고, 그래프와 실제 역할·산출물·도구·승인 차이를 비교한다.
하나를 선택하거나 일부를 결합·수정한 뒤 정확한 설계 버전을 승인한다.

**Why this priority**: 일반적인 대화·문서 작성 앱이 아닌 환경 구성 프레임워크의 핵심이다.

**Independent Test**: 같은 업무에서 구조적으로 다른 후보와 검토 근거를 보고 수정·승인한다.

**Acceptance Scenarios**:

1. **Given** 공통 업무 모델, **When** 후보를 생성하면, **Then** 단독·혼합 미세렌즈의 설계
   판단이 역할·연결·기억·권한·평가 구조에 반영되고, 별도 크리틱이 후보를 개별 검토한다.
2. **Given** 필수 조건을 통과한 충분한 후보, **When** 비교하면, **Then** 최소 두 구조 축에서
   구별되는 상위 세 안을 실제 그래프로 보여준다. 이름만 바꾼 고정 세 템플릿은 불합격이다.
3. **Given** 통과 후보 부족, **When** 생성 한도에 도달하면, **Then** 통과한 안과 부족 이유를
   보여주며 점수 높은 불량 후보로 숫자를 채우지 않는다.
4. **Given** 노드별 모델·도구·연결을 수정함, **When** 승인하면, **Then** 수정 버전을 재검토하고
   실행 구성과 일치시킨다. 이전 승인을 새 후보에 재사용하지 않는다.

### User Story 3 — 실행을 관제하고 단계별 실제 산출물을 본다 (Priority: P1)

승인한 환경이 업무를 실행한다. 사용자는 현재 진행, 각 에이전트의 모델과 도구 작업,
역할별 산출물, 다음 역할에게 전달한 자료와 실패·재시도를 확인한다.

**Why this priority**: 설계 화면을 실제 업무 시스템으로 연결한다.

**Independent Test**: 실제 브라우저 조회와 파일 생성을 포함한 분기·합류 실행에서 역할의
완성 산출물과 다음 역할이 사용한 원형 파일을 추적한다.

**Acceptance Scenarios**:

1. **Given** 도구 권한을 가진 승인 환경, **When** 수행하면, **Then** 브라우저가 실제 조회하고
   PDF 등 실제 파일이 생성된다. 완료 문구만으로 산출물을 생성했다고 표시하지 않는다.
2. **Given** 초안 파일이 다음 역할의 입력, **When** 후속 역할이 수행하면, **Then** 입력 버전·
   전달 검증·수신과 후속 산출물 계보를 확인한다. 전달 사실과 적절한 활용 증거를 구별한다.
3. **Given** 일부 역할의 권한 부족 또는 실패, **When** 복구하면, **Then** 영향받는 작업과
   독립 작업을 구별하고 결과 미확인의 외부 변경을 무작정 재시도하지 않는다.
4. **Given** 실행 중 브라우저 새로고침·닫기 또는 서버/작업자 재시작·중단 요청, **When**
   복원하면, **Then** 실제 저장 상태와 소유 실행의 상태를 대조하고 복원 불가·원격 종료
   미확인을 숨기지 않는다.

### User Story 4 — 전체 또는 일부에 자기 산출물을 남긴다 (Priority: P1)

사용자는 특정 역할·시점의 산출물을 보며 자신의 전체 또는 부분 버전을 남긴다. 문제 원인,
수정 지시 또는 자신의 판단에 대한 설명은 필수가 아니다.

**Why this priority**: DeepTwin의 입력은 해설이 덧씌워진 지시가 아니라 비교 가능한 대안 수행이다.

**Independent Test**: 실제 선행 산출물 뒤에 부분 대안을 작성·업로드하고 나머지 영역을 미검토로
유지한 채 탐구·후속 평가를 이어간다.

**Acceptance Scenarios**:

1. **Given** 봉인된 원 수행과 산출물, **When** 자기 버전을 남기면, **Then** 원본·대안·범위·
   생성 순서를 보존하며 후속 해석과 분리한다. 설명 칸을 채워야 진행되는 흐름은 불합격이다.
2. **Given** 부분 대안만 있음, **When** 변경 후보를 평가하면, **Then** 관련 다른 단락·역할·
   업무에 미친 영향을 함께 확인한다. 대안 범위를 영향 범위로 제한하지 않는다.
3. **Given** 최초 업무 설명만 있음, **When** 학습 근거를 조회하면, **Then** 이를 대안이나
   선호 정답으로 소급 표시하지 않는다.

### User Story 5 — 차이의 원인을 탐구하고 근거 있는 변경을 만든다 (Priority: P1)

DeepTwin은 두 수행의 차이에서 관련 기록을 추적하고, 시스템 결함·새 조건부 판단·예외·
대안 오류 등의 경쟁 설명을 검토한다. 필요한 경우 렌즈가 구별 질문과 새 증거 확보를 돕는다.

**Why this priority**: 단순 재작성이나 사용자 문장 복사를 개선 엔진으로 오인하지 않게 한다.

**Independent Test**: 전달 결손과 새로운 판단이 함께 가능한 사례에서 다른 개입의 예측과
근거를 보존하고, 증거 부족·렌즈 기권 경로도 실행한다.

**Acceptance Scenarios**:

1. **Given** 관찰 차이, **When** 탐구하면, **Then** 기록된 사실과 가능 가설을 구분하고
   정상·일회성·대안 오류·관찰 불충분 설명을 임의로 제거하지 않는다.
2. **Given** 판단 차이에 렌즈가 적합함, **When** 추가 탐구하면, **Then** 질문·예측을 새 증거보다
   먼저 고정하고 새 업무 증거로 판단 가설을 갱신한다. 철학 해석을 운영 규칙으로 직접 넣지 않는다.
3. **Given** 변경 후보, **When** 시험 환경으로 보내면, **Then** 복원·학습·보호 개입을 구분하고
   대상·범위·근거·변경 외 고정 조건을 명시한다. 현재 대안의 문장·사례값 복사는 누출로 검사한다.

### User Story 6 — 이전 업무를 반복 평가하고 환경을 버전업한다 (Priority: P1)

관련 이전 업무 큐로 원 환경과 후보 환경을 비교한다. 자동 또는 사람 개입 반복을 지원하고,
충분한 품질에서 큰 개선이 지속되지 않으면 반복을 종료한다. 별도 검증 결과를 사람이 검토해
정확한 환경 버전을 승인한 뒤 운영에 적용한다.

**Why this priority**: 대안 흡수를 실제 개선·악화 증거와 운영 버전으로 연결한다.

**Independent Test**: 개선·작은 개선·악화·무효 평가가 섞인 반복과 재시작을 수행하고,
조기 종료·예산 소진·최종 승인·적용·롤백을 서로 다른 상태로 확인한다.

**Acceptance Scenarios**:

1. **Given** 사전에 고정한 평가 기준과 충분한 품질 수준, **When** 유효하고 비교 가능한
   평가에서 큰 개선이 없는 상태가 기본 세 회 연속되면, **Then** 제품의 반복 평가를 종료하고
   최선 유효 후보와 전 회차 기록을 보존한다. 이것은 개발 종료 조건이 아니다.
2. **Given** 평가 오류·누락 또는 변경된 평가 기준, **When** 다음 회차를 처리하면, **Then**
   이를 기존 연속 정체 횟수로 세지 않고 오류 복구 또는 새 비교 계열로 분리한다.
3. **Given** 반복에 사용한 큐에서 개선, **When** 최종 검증하면, **Then** 튜닝에 사용하지 않은
   자료·경계·회귀·출처·안전 조건을 별도로 확인한다. 이미 본 사례를 미관측으로 재사용하지 않는다.
4. **Given** 평가 종료 또는 검증 통과, **When** 사람의 승인이 아직 없으면, **Then** 자동으로
   운영 버전을 바꾸지 않는다. 승인한 후보와 실제 적용한 버전의 일치를 검증한다.

### User Story 7 — 필요할 때 기록을 추출해 제작자에게 전달한다 (Priority: P1)

첫 프레임워크 제어 사건부터 쌓인 기록 중 관련 범위를 선택하고 내용·민감정보·빠진 근거를 확인해 파일로 추출한다.
사용자가 원할 때 자신의 피드백과 함께 제작자에게 전달한다.

**Why this priority**: 사용자 환경의 성장과 프레임워크 자체의 개선을 연결하되 통제를 유지한다.

**Independent Test**: 배포 확인·최초 설정·요청·탈락 후보·렌즈 조합·실행·대안·평가 사건이 있는 상태에서
선택적 추출을 만들고, 재현 가능한 부분과 제외된 자료를 구별한다.

**Acceptance Scenarios**:

1. **Given** 새 배포의 최초 설정 상태, **When** 사용하면, **Then** 설계나 실행 기능을 쓰기 전부터
   배포 확인·최초 설정·연결 실패·요청 등 프레임워크가 실제 관찰한 사건 기록이 시작된다.
2. **Given** 민감한 자료를 포함한 기록, **When** 추출하면, **Then** 범위·가림·제외·재현 제한을
   미리 확인한다. 인증정보나 숨은 추론을 넣지 않고 외부 자동 전송하지 않는다.
3. **Given** 피드백을 보내지 않음, **When** 다음 업무를 수행하면, **Then** 정상 사용할 수 있다.
   추출·전달은 매 업무의 필수 마지막 단계가 아니다.

### Edge Cases

- 계정 만료·구독 한도·모델 제거: 명시적 재선택 전 과금 경로나 모델을 자동 교체하지 않는다.
- 읽을 수 없는 자료·지원하지 않는 형식: 원본 보존·지원 범위 표시·다운로드를 제공한다.
- 업로드/웹 콘텐츠에 포함된 명령: 업무 자료로 취급하며 권한·설계 기준을 변경할 지시가 아니다.
- 저장 공간 부족·이벤트 기록 실패: 미기록 외부 동작을 정상 완료로 표시하지 않는다.
- 중복 요청·늦은 응답·취소 경쟁: 과거 버전 응답이 현재 설계/실행/승인을 덮어쓰지 않는다.
- 평가 중 외부 쓰기·결과 미확인: 격리하거나 정지하며 동일 작업을 중복 실행하지 않는다.
- 대안 없음·차이 없음·근거 부족: 학습 사건이나 철학 성향을 만들어내지 않는다.
- 렌즈 미적합·기권·사용자 거절: 기본 진단과 안전한 검증은 계속하되 렌즈 효과를 주장하지 않는다.
- 후보 간 비교 불가·정체 전 품질 미달: 미확정·부적합 종료와 품질 달성 후 정체 종료를 구별한다.
- 정책·모델·도구 버전 변경: 관련 검증·승인 효력을 점검하고 과거 증거를 그대로 재사용하지 않는다.
- 브라우저 종료 또는 서버/작업자 재시작 뒤 외부 실행 상태 미확인: 자동 성공/자동 재시도 대신 확인 필요 상태를 유지한다.

  precondition으로 삼거나 request→receipt→postcondition→record/head→consumption/event digest 순서를
  거꾸로 참조하지 않는다. 52개 port-qualified operation의 terminal 조합과 result artifact
  cardinality와 role/media/omissions/effect tuple은 core가 닫으며 cancelled codec을 포함한 모든
  non-success result는 `artifacts=[]`다. Result effect는 유일한 outcome 정본이고 error가 이를
  중복하지 않으며 성공한 외부 변경의 unknown/unconfirmed나 failed+unknown+retryable 조합을
  허용하지 않는다. 별도 request 행렬은 같은 52개를 전수 분류해 11개만 frozen/tool/codec/storage/
  export 프로필에 따른 artifact input을 허용하고 나머지 41개는 정확히 `artifact_inputs=[]`로 고정한다.
  입력의 수·role·media·selector·frozen-ref/ToolDefinition 관계와 총 byte 한도를 코어가 검증하며
  codec/storage/tool input 안의 경쟁 artifact ref는 금지한다. Export prepare/transmit은 exact
  snapshot/prepared artifact list를 반복하여 bounded IPC로 bytes를 받고 ref나 shared store mount로
  전달을 가장하지 않는다. 검증된 설치 bytes,
  반복 가능한 qualification, 원자적 binding supersession/rollback과 사건은 재시작·경합에서도
  내구적이어야 한다. 불변 binding history와 실제 rollback 가능성은 분리한다. Supersession/disable은
  대상 binding별 rollback-retention head를 만들고, owner의 exact-head release가 이를 해제한 뒤에만
  그 설치가 zero-retained-rollback retirement precondition을 만족할 수 있다. Release는 binding/
  installation history를 삭제하지 않지만 이후 해당 target rollback을 금지한다. 모든 config,
  binding record/head, command/result/event와 retention은 exact five-field
  `BindingSlotKeyV1={port_contract_version,target_scope_fingerprint,purpose,binding_slot_id,
  capability_selector_digest}`와 같은 canonical digest를 쓴다. 다른 port version/slot/selector는
  공존하고 byte-identical key의 후보만 경쟁한다. 브라우저 UI는 이 수명주기와 현재 제거/이전 서비스 은퇴를 구분해
  권한을 관찰·통제하고, 별도 설치 가능한 extension-author SDK와 HTTP/OpenAPI client가 실제 서버의
  같은 명령/이벤트 계약을 사용해야 한다. 특정 제공자 세션·화면 상태·코어 image가 프레임워크의
  유일한 진실이 되어서는 안 된다. (INT-034/035, ADR-014, 2026-09-08 프레임워크 감사)
- **FR-033**: 개발자는 전체 설계를 먼저 교차 검토하고 일반 권고안을 자동 결정하며 전체 맥락의 변경 영향·근거를 보존해야 한다. (최신 자동 진행 위임)
- **FR-034**: 개발 진척은 전체 작업 기준의 대략적 비율로 보고하고 근거가 생긴 뒤 잔여시간 범위를 제시해야 한다. 정체 종료는 FR-024의 제품 동작에만 적용한다. (최신 진척/확인 요구)

### Key Entities

- **Work / WorkRevision / Source**: 업무의 원 설명·자료·읽기 결과·수정 버전과 해석 결과.
- **WorkModel / DesignCandidate / GraphVersion**: 공통 업무 기준, 구조 후보, 정확한 역할/연결/권한/산출물 계약.
- **ProviderConnection / ModelChoice / ToolGrant**: 사용자 연결과 실행 경로, 역할별 모델 설정, 범위가 정해진 권한.
- **Run / Attempt / Artifact / Handoff / Event**: 실제 실행·시도·원형 결과·역할 간 전달·시간순 기록.
- **Alternative / Discrepancy / Hypothesis / LensInquiry**: 자기 버전과 관찰 차이, 서로 다른 가설과 새 증거 탐구.
- **Intervention / EvaluationSeries / EvaluationRound**: 근거 있는 변경과 고정된 비교 기준·큐·반복 결과.
- **KnowledgeCandidate / Validation / Approval / EnvironmentVersion**: 조건부 지식, 검증 결과, 사람 승인, 운영 구성·롤백.
- **ExportBundle / RetentionPolicy**: 사용자가 선택한 공유 범위·가림·자료 결손과 로컬 기록 관리.
- **OwnerAccount / BrowserSession / ServiceClient+CredentialRevision**: 최초 소유권, 브라우저 세션,
  사람 권한을 가장하지 않는 제한된 외부 클라이언트의 내구 principal·회전/만료/revoke 인증.
- **OriginProfile / DeploymentRequest+Lifecycle / DeploymentReceipt+Consumption /
  PlatformSupportManifest**: 정확한 웹 origin과 제품이 제안한 immutable 배포 변경, 외부 운영면의
  서명된 진술·별도 one-use 적용 기록, 실제 시험한 자체 호스팅 범위.
- **CredentialEnvelope / SpeechSession / SpeechUtterance / SpeechChunk / SpeechSegment**: 서버 측 비밀 봉투와
  겹치지 않는 음성 입력·잠정/확정 전사·사용자 편집 fence.
- **ExtensionPortContract / ExtensionServiceDescriptor / ExtensionInstallation+Head /
  ExtensionServiceRetirement+Head / ExtensionQualification / ExtensionBindingRevision+Head /
  ExtensionRollbackRetentionRevision+Head**:
  종류별 의미 포트, 외부 운영자가 staging한 실행 서비스, 재자격 가능한 immutable 설치, current
  head를 보존하는 superseded-service retirement, slot/selector 단위 원자적 binding
  supersession/rollback과 불변 이력에서 분리된 rollback-retention/release.

## Success Criteria

### Measurable Outcomes

- **SC-001**: `local-no-terminal-v1`과 `portable-compose-v1` 각각의 빈 호스트에서 동일한 고정
  소스·Compose schema·DeepTwin core/built-in 서비스별 `image_locks[]`를 공유해 공식 배포를 완료한다. 각 core lock은 해당
  image ID의 멀티아키텍처 OCI index 또는 Docker manifest list와 호스트별 고정
  platform-manifest/config/layer 각각의 media type·digest·byte size를
  가진다. 비개발자 프로필의 사용자는 CLI 없이, 두 프로필의
  일반 사용자는 지원 브라우저만으로 US1–US7을 수행할 수 있어야 하며 Codex 구독과 Claude API
  각각의 실제 실행 증거를 확보한다. core lock과 분리된 하나의 private multi-platform descriptor를
  사용하는 저장소 밖 대표 tool OCI
  extension을 core image 재빌드 없이 외부 운영자가 staging하고, 실제 broker 호출·재시작·재qualification·
  binding rollback과 브라우저 관찰을 검증한다. 어느 필수 프로필·제공자 경로·대표 확장 경로가
  미지원이면 전체 완료가 아니다.
- **SC-002**: FR-001–034 각각에 설계 위치·실행 작업·수용 시험·결과/미확인 상태가 연결된다. 누락된 필수 요구를 조용히 후순위로 이동하지 않는다.
- **SC-003**: 충분한 후보가 있는 시험에서 실제 구조 두 축 이상이 다른 세 안을 보여주고, 부족/실패 사례에서는 허위 통과·허위 세 안을 만들지 않는다.
- **SC-004**: 브라우저와 실제 PDF·구조화 표·문서·이미지를 포함한 지원 형식 시험에서 생산 역할→전달→소비 역할→최종 결과의 계보가 유지된다. 모든 임의 형식을 완벽히 해석한다는 주장은 하지 않는다.
- **SC-005**: 동일 모델 조건의 크리틱 시험에서 판정 경로의 정보 격리·원자료 대조·필수 결함·유효 대안·기권·공동 실패를 각각 검사하며, 그 결과가 실제 보장 범위를 벗어나지 않는다.
- **SC-006**: 전체/부분 대안, 원본 없는 입력, 대안 누출, 새로운 증거, 범위 밖 영향의 시험에서 FR-016–022를 충족한다. 개발 대화나 합성 대안을 실제 사용자 학습으로 보고하지 않는다.
- **SC-007**: 적정 품질 후 세 번의 연속 정체, 중간의 의미 있는 개선, 누적 작은 개선, 오류/결손, 기준 변경, 재시작, 품질 미달 예산 소진의 경우를 구별하며 허위 조기 종료/승격이 없다.
- **SC-008**: 고정 후보→별도 검증→정확한 사람 승인→적용→롤백의 버전 일치가 확인된다. 튜닝 자료를 미관측으로 표시하거나 운영 부작용을 평가 중 반복하지 않는다.
- **SC-009**: 최초 프레임워크 제어 사건 이후 필수 기록 범주를 추출할 수 있고 비밀 유출 검사·사용자 범위 선택·가림·결손 표시를 통과하며 자동 외부 전송이 없다.
- **SC-010**: 최종 보고서가 구현/실제 시험/실사용 평가/렌즈·성장 효과/외부 승인 상태를 구별한다. 필수 외부 승인·기능·시험의 미완료가 있으면 전체 배포 후보 준비 완료를 주장하지 않는다.

## Assumptions

- 첫 배포 단위는 한 운영자가 관리하는 자체 호스팅 단일 인스턴스다. 첫 릴리스는 같은 컨테이너
  구조를 `local-no-terminal-v1`(macOS arm64 Docker Desktop+Portainer CE)과
  `portable-compose-v1`(Linux amd64 Docker Engine/Compose+pinned HTTPS edge와 operator TLS secrets)에서 각각 검증한다.
  외부 배포 도구는 DeepTwin 제품이나 네이티브 런처가 아니며, 검증하지 않은 조합을 지원한다고
  표시하지 않는다.
- 최초 수용 시험의 업무·파일·도구 폭은 유한한 대표 집합으로 고정하되 실제 전체 순환을 생략하지 않는다. 향후 임의 도구는 등록·권한·형식 계약을 통해 확장한다.
- 사용자는 선택한 Codex 구독 또는 Claude API의 유효한 계정/권한과 연결을 제공한다. Claude 구독 제3자 승인은 해당 경로 제거로 현재 배포 선행 조건이 아니다. 다른 실행 경로의 공식 지원·권한·실제 작동 검증은 유지한다.
- 품질 하한·큰 개선 폭·평가 가중치 등은 업무별 사전 고정 프로필로 정의한다. 보편적인 업무 품질 또는 사용자의 실제 선호를 임의 수치로 확정하지 않는다.
- 최종 사용자 만족, 실제 사용자가 제출한 대안의 타당성, 외부 제공자 승인과 실제 공개는 개발 에이전트가 대신 완료했다고 선언할 수 없다. 이 상태를 구현된 기능/검증 범위와 분리해 보고한다.
- 목표는 OSI 라이선스의 오픈소스 릴리스지만 현재 저장소에는 프로젝트 라이선스가 없다. T084에서 copyright owner가 명시 승인하기 전 공개·재배포 가능한 오픈소스 상태로 표시하지 않는다.
- 기존 코드·시제품·729개 회귀 통과는 재사용 근거이지만 아직 구현하지 않은 그래프 실행·DeepTwin 효과의 근거는 아니다.
