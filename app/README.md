# DeepTwin — 실제 첫 사용 입력 기반

DeepTwin은 공식 브라우저 UI를 포함한 **자체 호스팅 가능한 웹 기반 오픈소스 멀티에이전트
프레임워크**로 공개하는 것을 목표로 개발 중이다. 현재 저장소에는 프로젝트 라이선스가 아직
추가되지 않아 공개·재배포 가능한 오픈소스 릴리스 상태가 아니다. 사용자가 CLI를 조작하는
제품이 아니며, 이 문서의 명령은 **개발자용**이다.
지원되는 최종 웹 배포물과 브라우저 최초 설정 여정은 아직 구현되지 않았다. 사전 출시
호스트-로컬 Codex 계정 연결 실험 UI만 구현했다.
`control-prototype/`의 고정 합성 업무와 DB/브라우저 상태를 공유하지 않는다.

## 제품 경계

- 공식 제품 화면은 DeepTwin이 제공하는 브라우저 UI다. 네이티브 런처·DMG·WKWebView나
  최종사용자 CLI를 제품 사용 경로로 두지 않는다.
- Docker·Compose·Portainer는 운영자가 웹 인스턴스를 배포·업데이트·복구하는 수단이며,
  최종사용자가 업무를 입력하거나 에이전트를 조작하는 화면이 아니다.
- Claude는 공식 API 전용이다. Codex 구독 연결은 DeepTwin 서버가 소유하는 격리된 관리형
  실행기와 전용 인증 볼륨을 사용하고, Codex API는 사용자가 명시 선택할 때만 사용한다.
- 에이전트는 서버가 통제하는 도구 실행 경계를 통해 브라우저·외부 도구를 사용하고 PDF를
  포함한 여러 형식의 산출물을 만들 수 있어야 한다. 공급자 CLI 자체가 제품 표면은 아니다.
- 재사용 가능한 코어는 API/static/server presentation을 직접 의존하지 않고 종류별 semantic
  extension port를 제공한다. 실행형 확장은 외부 운영자가 OCI service로 staging하며, 제품의
  `설정 > 확장`은 code-free import와 이미 qualified된 binding만 통제한다. 현재 source-tree
  helper는 설치 가능한 SDK/client나 durable extension framework의 완료 증거가 아니다.

현재 `app/`는 ADR-009 이전에 시작한 **사전 출시 loopback 개발 슬라이스**를 웹 제품으로
이행하는 중이다. 아래의 macOS Keychain, 개발 호스트의 기존 Codex 자격 증명, 호스트-로컬
실행기와 STT 기록은 구현 가능성을 확인한 역사 자료이지 최종 웹 배포 계약이 아니다. 릴리스
경로는 T018/T025/ADR-010–012에 따라 브라우저 최초 소유자 설정, 서버 소유 격리 worker와
별도 Codex auth volume을 구현·검증해야 한다.

## 현재 사전 출시 개발 슬라이스에서 동작

- 빈 업무 공간에서 설명 입력, 여러 파일 추가, 파일별 결과 확인.
- 서버 응답을 받은 뒤에만 저장됨을 표시한다. 입력 문자열은 정규화/요약하지 않는다.
- 개발 인스턴스에 지정된 데이터 디렉터리의 SQLite에 설명, 원본 bytes, 읽기 결과,
  불변 수정본, 메타데이터 이벤트를 보관한다. 브라우저 기기의 개인 폴더를 뜻하지 않는다.
- TXT/MD/CSV/JSON의 UTF-8 원문, DOCX 본문/표 일부를 읽는다. 파일 추가만으로 모델에 보내지 않는다.
- PDF는 `pdftotext`가 있을 때 앞 50쪽의 제한된 텍스트만 읽는다. 없으면 원본만 보관한다.
- 그림/OCR/조판을 해석하지 않는다. HTML/SVG는 실행·미리보기하지 않고 원본으로만 보관한다.
- 설명 20,000자, 추출 결과 20,000자, 파일 각 10MiB, 업무당 20개 제한.
- 명시 선택한 모델과 정확한 저장본에 연결된 설계 요청을 보관한다.
  **설계 엔진이 없어 요청은 blocked**다. 가짜 후보·대기 작업·승인을 만들지 않는다.
- 업무 저장과 독립적인 Codex 연결 확인, 공식 ChatGPT 로그인 시작·완료 확인·취소,
  API 계정 구분, 제공되는 사용 한도 조회. 이메일·토큰·로그인 URL은 일반 로그에 넣지 않는다.
- 사용자가 전송할 내용을 확인한 뒤 `업무 이해하기`를 누르면 해당 저장본으로
  업무 이해 초안을 요청하는 서비스·UI를 구현했다. 역사적 호스트-로컬 타당성 실험에서는
  Codex 0.144.4로 실행 환경을 붙이지 않는 별도 구독 generation 프로세스와 실패폐쇄 점검을
  확인했다. 합성 입력 2건(직접 연결 1건, UI+파일 1건)이 성공했지만, 이는 서버 소유 관리형
  실행기가 구현된 웹 릴리스나 제품 품질·사용자 업무 처리 완료를 증명하지 않는다.
  설명·읽은 글자·파일명·읽기 한계만 전송하며 원본 bytes는 보내지 않는다.
- 같은 입력 공간에서 이해한 업무·요청 산출물 형식·명시 제약·중요 빈칸·추정을 구분한다.
  인용문은 원문 일치를 검사하지만 의미적 정확성을 보증하지 않는다. 수정은 원 업무 설명에서 한다.
- 이해 요청의 정확한 입력/프롬프트/출력 스키마/결과, 저장본과 상태 이력을 개발 인스턴스의
  업무 저장소에 보존한다.
  같은 요청의 중복 호출 방지, 취소·늦은 응답 제외, 이전 저장본 표시, GET 재열람을 지원한다.
  서버 재시작은 진행 중 요청을 자동으로 다시 모델에 보내지 않는다.
- Codex가 실제 반환한 모델 목록과 지원 추론 수준을 조회하고 업무별로 선택을 저장한다.
  입력과 별개인 모델 설정 버전을 이해 요청에 고정하며 실제 응답 모델도 대조한다.
  목록 조회 성공은 실제 추론 준비나 과금 포함의 증명이 아니다. API/다른 모델 자동 대체는 없다.
- 입력 옆의 명시 마이크 조작으로 브라우저가 음성을 캡처하고 개발 인스턴스의 전사 worker로
  보낸다. 말하는 중의 잠정 전사와 확정된 글자를 구분하며 기존 입력을 덮어쓰지 않는다.
  역사적 Apple Silicon 개발 호스트에 whisper.cpp/base를 준비했다. 원음은 worker 메모리에서만
  처리하고 전사 결과·수정·종료 이력은 개발 인스턴스의 업무 저장소에 보관한다.

## 아직 동작하지 않음

Claude API 연결·실제 모델 조회/선택·에이전트별 모델/설정 관리,
일반 사용자 UI에서 검증된 Codex 업무 이해 실행, 철학 렌즈·크리틱,
그래프 후보 생성, 설계 수정/승인,
환경 실행, 타입별 산출물 뷰어, 사용자 대안, 재평가, 버전 승격, 로그 내보내기/공유,
최종 웹 배포물과 배포 업데이트·복구, ADR-014의 semantic extension ports·durable
qualification/binding·operator-staged OCI service·확장 설정 UI·별도 설치 SDK/HTTP client.
이 입력 기반의 테스트를 이 기능들의 검증으로 해석하지 않는다.

모델 선택·관제·음성 입력의 후속 직접 요구와 구축 순서는
[추가 요구 기록](../docs/ui/2026-09-07-model-control-and-voice.md)에 보존했다.

2026-09-07 사용자의 명시 변경으로 **Claude는 공식 API 전용**, Codex는 구독 연결과
명시 선택 API를 지원하는 제품으로 확정했다. Claude CLI 설치·구독 연결·제3자 구독
사전 승인은 현재 요구가 아니다. 현재 코드에는 오프라인 fake-server로 검증한 Claude
API 어댑터가 있으나, 브라우저 제품의 자격증명 gateway·지속 실행·실계정 경로는 아직
통합되지 않았다. 따라서 연결·목록 조회·실행 완료로 표시하지 않는다. Codex의 합성 업무 이해 2건 확인을
멀티에이전트 환경 전체의 완료로 확대하지 않는다. API로 자동 전환하지 않으며 키를
브라우저에 저장하지 않는다. 최신 정본은 `specs/001-autonomous-release/`의 명세와
ADR-007·ADR-009–014이며,
기존 `docs/ui/2026-09-07-provider-integration-findings.md`는 당시의 조사 이력이다.

### 사전 출시 Codex 계정 연결 실험의 범위

- 다음 항목은 호스트-로컬 구현 가능성을 검증한 개발 어댑터의 동작이다. 웹 릴리스의 지원
  계약은 서버 소유 관리형 Codex 실행기와 격리된 인증 볼륨으로 대체해야 한다.
- 현재 개발 슬라이스의 `연결` → `연결 확인`은 개발 호스트에서 발견한 공식
  `codex app-server`에 계정을 조회한다. 기존 Codex 자격 증명은 공식 프로세스가 관리하며
  DeepTwin이 토큰 파일을 읽거나 복사하지 않는다.
- 로그인은 `ChatGPT로 로그인`을 눌렀을 때만 시작한다. 반환된 HTTPS 공식 주소를
  사용자가 열어 완료한다. DeepTwin이 OAuth 콜백이나 토큰 교환을 흉내 내지 않는다.
- 이 사전 출시 어댑터는 **개발 호스트의 기존 Codex 로그인과 공유되는 방식**이라 명시 로그인
  완료가 같은 호스트의 다른 Codex 도구에도 영향을 줄 수 있다. 이는 릴리스 계약이 아니다.
  웹 릴리스는 브라우저 기기나 호스트 도구의 자격 증명을 자동 공유하지 않는다. 인증 방식 강제
  설정, 자동 로그아웃, API 키 로그인/자동 전환은 하지 않는다.
- 로그인 성공 알림만 믿지 않고 요청 ID의 일치와 공식 계정 재조회로 ChatGPT 여부를 확인한다.
  취소 `notFound`는 완료와 경합할 수 있으므로 계정을 다시 읽으며 자격 증명 롤백을 주장하지 않는다.
- 한도에 값이 없으면 미확인이다. 크레딧 구매/사용량 리셋/유료 API 호출은 제공하지 않는다.
- 기본 화면/업로드는 공급자 프로세스를 시작하지 않는다. 계정 동작은 첫 명시 확인/로그인에 시작한다.
  인증/메타데이터 RPC 허용목록에는 계정 확인/로그인/취소/한도와 모델 목록 조회만 있다.
  업무 이해용 실행 연결은 별도다.
- 프로세스별 analytics/OTEL 전송을 비활성화하며 API 키/외부 토큰 환경변수를 전달하지 않는다.
  사전 출시 어댑터에서는 개발 호스트의 Codex 설정과 인증 저장소를 공식 프로세스가 사용한다.
  웹 릴리스에서는 이를 서버 소유 실행기의 전용 인증 볼륨으로 격리해야 한다.
  상속된 앱 범위 MCP의 시작 부작용까지 격리됐다고 검증하지는 않았다.
- 로그인 URL/ID는 메모리에만 둔다. UI는 대기 중에만 제한적으로 조회한다. 600초 만료는
  **다음 상태 조회 시 처리**되며 정시 백그라운드 취소가 아니다. 서버 종료 시 소유한 프로세스는 닫는다.
- 계정 연결 확인 자체는 모델 추론 검증이 아니다. 별도의 격리된 generation 경로에서만
  합성 입력 2건을 확인했으며 도구 권한·그래프 생성·멀티에이전트 실행 검증은 아니다.
  현재 `capabilities.execution`과 `design_generation`은 계속 false다.

### 업무 이해 연결의 범위

- `app/understanding.py`는 명시 전송 동의·불변 입력·모델 응답 검사·요청 수명주기를 담당한다.
  일반 이벤트에는 원문을 넣지 않는다. 감사용 입력/프롬프트/응답은 개발 인스턴스의 원본
  업무 저장소와 같은 DB에 있다.
- `app/codex_understanding.py`는 인증 연결과 분리된 generation 프로세스다. 사용자 설정 파일을
  변경하거나 토큰을 복사하지 않는다. 모델 제공자·도구·스킬·지시 상속을 검사하고 실패폐쇄한다.
- 읽기 전용 샌드박스만으로 모든 도구가 사라진다고 주장하지 않는다. 이는 이번 Codex 버전의
  검증 중인 텍스트 이해 경로이며 최종 프레임워크 도구 실행기·모든 OS/버전의 보안 인증이 아니다.
- 0.144.4 공식 소스에서 실행 환경이 있으면 `view_image`가 등록되며 이를 끄는 설정이 없음을
  확인했다. 효과 없는 `tools.view_image=false` 대신 thread와 turn 모두 `environments: []`를
  사용해 shell·apply_patch·view_image를 등록 전에 제외한다. MCP·skills·plugins·검색·협업은
  별도 설정과 재조회로 차단한다. 내부 `update_plan`까지 0개라고 주장하지 않으며 예상 밖
  tool item이나 서버 요청은 결과를 실패시킨다.
- 실제 합성 확인과 소스 근거는
  [실제 업무 이해 확인 기록](../docs/ui/2026-09-07-live-understanding.md)에 분리했다.
  `understanding=true`는 서비스 구현 여부이고, `understanding_provider_ready`는 사전 출시
  호스트 어댑터의 버전·환경 설정 호환성 점검이다. 요청마다 계정·설정·스킬·지시를 재검증한다.
  알려지지 않은 버전/환경은 닫히며, UI 준비 상태가 모든 사용자 설정의 실행 성공을 보증하지 않는다.
  실행 프로필 ID·버전·격리 정책을 호출 전에 입력 감사 기록과 요청에 원자 저장한다.
- 모델 전달 글자는 합계 60,000자까지다. 초과/미독해 자료뿐이면 내용을 몰래 자르거나
  가짜 결과를 만들지 않는다. 실패한 요청의 재시도는 사용자가 명시적으로 시작한다.
- 업무 이해는 설계 승인·작업 실행·사용자 대안·DeepTwin 학습으로 분류하지 않는다.
  렌즈/크리틱 상세 정책을 임의 확정해 고정 그래프를 붙이지 않는다.
- 실제 공급자 확인과 통제된 시험의 구분은
  `docs/ui/2026-09-07-work-understanding.md`의 최종 검증 기록을 참고한다.

### 모델 선택·음성 입력의 현재 한계

- 모델 선택은 현재 **업무 이해 호출**의 설정이다. 아직 생성하지 않은 관제 그래프의 모든
  에이전트를 제어하는 화면이 완성된 것은 아니다. 환경 기본값·노드별 배정·실제 실행/변경 기록은
  후속 그래프와 실행기 구축에 반드시 포함한다.
- 역사적 개발 호스트에서 Codex 0.144.4를 실제 조회했을 때 6개 모델을 반환했고 Astra는
  그 목록에 없었다.
  제품/계정 전체에서 지원하지 않는다는 뜻은 아니다. 실제 조회된 모델만 선택 대상으로 삼는다.
- STT의 역사적 타당성 실험은 Apple Silicon macOS에 준비한 whisper.cpp 1.8.7/base로 수행했다.
  최초 엔진 준비는 수초 걸린다. 짧은 합성 한국어 문장의 숫자 구절 오인식이 관찰됐으므로
  한국어 정확도·실제 마이크/소음 성능을 보증하지 않는다. 브라우저 자동 검사는 가짜 오디오 기기와
  통제된 전사 응답을 사용한다. 실제 사용자 마이크는 자동으로 열지 않았다.
- 브라우저가 캡처한 음성은 DeepTwin 개발 인스턴스의 전사 worker에 0.25–8초 PCM 구간으로
  전달한다. 한 세션 128개 요청 제한과
  5분 유휴 만료(다음 요청 시 검사)가 있다. 늦은 응답·중복 요청은 구간별로 관리한다.
- 이 개발 경로 전용 약 199 MB 로컬 엔진/모델 준비를 완료했으나, 지원되는 웹 배포 이미지·
  구성·브라우저 온보딩에 아직 통합되지 않았다. 사용자가 CLI로 설치해야 한다는 의미가 아니다.
- 구현/실측/남은 요구는 [모델·음성 기록](../docs/ui/2026-09-07-model-control-and-voice.md)에 구분한다.

## 개발자용 loopback 실행

아래 명령은 사전 출시 슬라이스를 시험하는 개발자용이며 최종사용자 설치·사용 절차가 아니다.
Python 3.12 환경에 requirements.txt를 설치한 뒤 저장소 루트에서 실행한다.
`--data-dir`은 **DeepTwin 전용 디렉터리**여야 한다. 이 디렉터리에 0700 권한을 설정한다.
홈·저장소 루트 같은 범용 폴더를 지정하지 않는다.

```sh
python -m app.server --data-dir /absolute/path/to/deeptwin-dev-instance-data --port 4193
```

127.0.0.1에만 바인딩한다. `--port 0`은 격리된 테스트용 임시 포트다.
stdout의 `DEEPTWIN_URL=...` 이후 해당 주소가 응답하면 브라우저로 연다.

## 개발 인스턴스 보관과 경계

- `intake.sqlite3`이 원본/수정본/이벤트/설계 요청의 기준 저장소다. DB는 0600 권한.
  DB 암호화, 배포 프로필의 자격증명 저장소·보안 검증은 아직 없다.
- 브라우저 localStorage에는 선택한 업무 ID만 둔다. 저장 실패한 입력은 열린 화면에 남지만
  화면을 강제로 닫으면 복원되지 않는다. 미저장 상태에서 나갈 때 경고한다.
- 로그에는 이벤트 종류·시각·ID·수정본·해시·크기·읽기 상태를 남긴다. 일반 이벤트에
  입력 본문·파일명·인증정보를 중복 기록하지 않는다. 본문과 원본 자체는 업무 저장소에 있다.
- 저장소 세션 시작부터 기록한다. 배포·최초 웹 설정 이벤트, 앞으로 추가될 도구/설계/평가 이벤트와
  전체 로그 추출은 아직 없다. 외부 추적 서비스/텔레메트리는 켜지 않는다.
- 동일 출처 검사, 메모리 CSRF 토큰, 요청 크기 제한, 허용된 정적 파일만 제공하는 라우팅,
  원본 attachment 다운로드와 CSP를 적용한다. 업로드 자료의 지시는 실행하지 않는다.
- 이 loopback 개발 슬라이스는 같은 개발 호스트의 다른 프로세스나 동일 OS 계정
  사용자로부터 격리하는 보안 경계가 아니다. 웹 릴리스의 격리 보증으로 해석하지 않는다.
- 저장소를 자동 초기화·삭제하지 않는다. 손상·저장 실패를 완료로 표시하지 않는다.

## 검증

```sh
python -m pytest app/tests -q
```

브라우저 검사에는 설치된 Playwright와 Chrome, 위 Python 환경을 지정한다.
테스트 서버는 매번 별도 임시 보관함을 사용하며 실제 사용 중인 보관함을 건드리지 않는다.

```sh
CONTROL_PYTHON=/absolute/path/to/python CONTROL_PLAYWRIGHT_MODULE=/absolute/path/to/playwright/index.mjs node --test app/tests/browser-first-use.test.mjs
```

Codex 연결 회귀는 `app/tests/browser-codex-connection.test.mjs`도 같은 방식으로 실행한다.
이 검사는 실제 loopback 개발 서버·상태 관리자·RPC를 사용하되 Codex 하위 프로세스만 통제된
테스트 대역으로 바꾼다. 자동 검사가 실제 계정의 로그인이나 모델 호출을 수행하지 않는다.
업무 이해 화면은 `app/tests/browser-understanding.test.mjs`로 검사한다. 이때에도 실제
저장/worker/API를 사용하되 모델 경계만 통제한다. 브라우저 시험의 합성 응답을 모델 품질
또는 철학 렌즈의 효과로 보고하지 않는다.

모델 선택은 `app/tests/browser-model-selection.test.mjs`, 음성은
`app/tests/browser-speech-input.test.mjs`로 검사한다. 음성 브라우저 시험은 생성한 WAV의
가짜 오디오 기기와 통제된 전사 엔진을 사용하며 실제 사용자 마이크를 열지 않는다.
마지막으로 기록한 전체 회귀는 Python 316개와 브라우저/오디오 worklet 62개, 합계 378개 통과다.
실패·건너뜀 0, 기존 Starlette/AnyIO deprecation 경고 1건이 있다. 구독 모델의 실제 합성
추론 2건은 이 통제 회귀 수치와 구분한다. 실제 엔진 합성 음성 확인과 한국어 오인식 한계는
위 구현 기록에 따로 남겼다.

테스트 종료 시 삭제하는 것은 테스트가 직접 만든 임시 디렉터리뿐이다.

호스트/브라우저 검증은 후속 작업이다.
