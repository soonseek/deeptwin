# DeepTwin 초기 UI 정보 구조·화면 흐름 설계

작성일: 2026-09-06

상태: 검토 제안, 화면/엔진 미구현

후속 보완(TOOLS-UX-001): 개별 에이전트의 실제 외부 도구·PDF 등 산출물 지원과 독립 제품 책임을 반영했다. 도구 준비·연결, 관제 정보 우선순위, 실패·사람 개입·복구의 세 경험 원칙은 사용자가 각각 확인했다. §8은 그 원칙을 기존 흐름에 통합한 문서로 최종 문서 검토 대기이며, A/B 골격·기본 모드·세부 조작·구현 기술은 여전히 미확정이다. 기존 §1–7의 문서 검토 결과를 새 기능의 동작 검증으로 소급하지 않는다.

제품 의도 기준표와 수용·거부 사례는 원 작업 폴더의 로컬 근거이며 독립 배포물에 포함되지 않는다.

이 문서는 채택된 제품 기준선에 따라 초기 UI의 정보 구조와 화면 흐름을 제안한다. 구체적인 식별 표시·배치·조작은 검토 대상이며, 이 문서에 대한 UI 설계 승인은 DeepTwin 엔진의 흡수·전이·회귀 효과를 입증하지 않는다. 실제 효과는 별도의 구현과 실제 실행·검증으로 확인해야 한다.

## 1. 공통 맥락과 선택 대상

작업공간·대화·그래프는 같은 업무 환경과 그 안의 업무·산출물·대안·탐구·실험·평가·승인 이력을 다루는 세 화면 모드다. 사용자가 어느 환경의 어떤 결과를 보고 있는지 식별하고, 보기를 바꿔도 그 대상을 이어 다룰 수 있도록 다음 참조를 공통 맥락으로 제안한다.

아래 항목은 사용자가 구별해야 할 대상과 연결 관계다. 데이터베이스 스키마, 내부 ID 형식, URL 계약이나 모든 항목을 항상 한 화면에 표시한다는 배치 규칙을 확정하지 않는다. 표시 이름과 함께 같은 이름의 다른 업무·실행·버전을 구별할 수 있어야 하며, 정확한 표기 방식은 후속 설계한다.

| 선택 대상 | 화면에서 구별할 참조와 상태 |
| --- | --- |
| 업무 환경 | 환경을 식별할 이름·참조, 현재 운영 버전, 검토 중인 설계 또는 변경 후보 버전. 후보를 보고 있다는 사실과 실제 운영에 적용된 버전을 구별한다. 운영을 시작하기 전에는 운영 버전이 아직 없을 수 있다. |
| 업무 한 건 | 해당 환경의 업무 참조, 실제 입력과 입력 버전, 실행 참조와 진행 상태, 그 실행에 사용된 환경 버전. 같은 입력의 재실행도 어느 실행인지 구별한다. 환경을 설계하거나 둘러보는 동안에는 업무가 아직 없거나 선택되지 않은 상태를 허용한다. |
| 역할·산출물 | 선택한 역할과 실행, 그 역할이 실제 사용한 입력 산출물·버전 및 만든 출력 산출물·버전. 산출물 전체와 현재 선택한 단락·문구·필드 등의 영역을 구별하며, 선택 영역에서 전체 문맥과 앞뒤 역할의 산출물로 연결한다. 역할별 완결 산출물은 전체 업무에서는 중간 결과일 수 있고, 다음 역할은 이를 입력으로 사용해 자신의 산출물을 만든다. |
| 역할의 도구 작업 | 선택한 역할·실행에 속한 도구와 허용 범위, 실제 호출·입출력·시점·오류·재시도·외부 행동의 참조. 설계상 사용할 도구, 연결/권한의 준비 상태, 실제 실행 결과를 구별한다. 현재 화면·과거 기록과 성공·실패·결과 미확인을 혼동하지 않으며 해당 산출물·입력 버전으로 연결한다(§8). |
| 사용자 대안 | 실제 대안의 존재 여부, 작성자·버전·원본과의 순서, 연결된 원본 산출물 버전과 업무·역할·입력 상태, 전체/부분 대안 범위, 사용자가 실제 검토한 범위. 원본을 본 뒤 만든 대안인지 독립 수행인지 구별하고 확인되지 않은 조건은 미확정으로 남긴다. 사용자가 제공한 자기 버전과 시스템의 해석·선택적 이유 설명을 분리한다. |
| 진단·탐구 | 어떤 원본·실제 대안에서 관찰한 차이인지, 그 차이에 대한 경쟁 가설, 이를 구별하려는 탐구와 새 수행·응답 증거의 참조. 관찰 사실, 가설, 실제 확보한 새 증거, 시험할 작동 변경 후보를 구별하며 원인 미확정이나 일반화할 지식 없음도 유지한다. |
| 개선 실험 | 실험 참조와 반복 회차, 비교하는 기준 환경·후보 버전, 대상 업무·입력, 변경 내용과 예상 영향, 실제 재실행 결과·평가 근거. 운영과 격리된 비교인지 및 외부 부작용 통제 상태를 식별한다. 이전 업무 큐의 반복 평가와 최종 확인 자료를 구별하고 회차별 개선·악화·실패·미확인을 연결한다. |
| 승인·운영 | 승인 대상과 정확한 버전, 효력과 적용 범위, 검증 근거, 실제 평가한 후보·승인한 후보·운영에 적용된 버전의 연결. 설계 승인, 이번 업무의 외부 행동 허가, 지속 운영 승인을 구별한다. 보류·거절·철회 및 되돌릴 운영 버전을 관련 대상과 연결하고, 승인 기록과 실제 적용·롤백 결과를 구별한다. |
| 보기 모드 | 현재 작업공간·대화·그래프 중 어떤 모드인지. 모드별 강조점이 달라도 위 대상과 권한·이력은 이어진다. 기본 진입 모드, 기능 동등성, 전환 조작과 그래프 직접 편집 범위는 아직 정하지 않는다. |

산출물의 전달 관계에서는 설계상 예정된 연결, 실제 전달 기록, 관찰된 산출물 계보, 개입으로 확인한 영향을 구별한다. 다음 역할에 전달됐다는 사실만으로 내용을 적절히 활용했거나 인과가 입증됐다고 표시하지 않는다. 일부 문구를 선택해도 역할의 전체 입력·출력 맥락을 짧은 코멘트로 축소하지 않으며, 모든 업무를 직렬 구조로 고정하지 않는다.

대안이 실제로 없는 상태, 아직 선택하지 않은 상태, 존재나 조건을 확인하지 못한 상태를 혼동하지 않는다. 실제 선행 산출물과 이후 사용자 대안의 출처·순서를 보존하고, 업무 설명·코칭 지시·침묵·시스템이 추론한 의도를 사용자 대안으로 채우지 않는다. 대안·탐구·실험이 없으면 해당 부재를 드러내며 가상의 기록이나 완료 상태를 만들지 않는다.

부분 대안을 남긴 범위, 시험할 작동 변경의 대상, 영향·검증 범위는 각각 연결해 보여 준다. 작은 대안에서 다른 단락·산출물·역할·관련 업무에 영향을 주는 후보가 나올 수 있다. 미검토 영역을 승인 완료나 변경 금지로 해석하지 않으며, 부분 증거만으로 전역 개선을 확정하지 않는다.

### 모드 전환에서 이어지는 맥락

작업공간에서 산출물의 일부를 선택한 뒤 그래프로 이동하고 대화로 이어 가는 경우, 같은 환경·업무·실행·역할·산출물 버전과 선택 영역, 연결된 사용자 대안 및 그 범위, 선택한 실험 회차를 유지한다. 대안이나 실험을 선택하지 않았다면 그 상태도 유지한다. 그래프는 해당 산출물의 앞뒤 전달 관계를, 대화는 같은 산출물·범위를 참조하도록 제안한다. 각 모드에서 모든 정보를 같은 배치로 반복할 필요는 없다.

대화에 실제 자기 버전을 남기는 경우에도 해당 업무 상태·역할·원본 산출물 버전과 전체/부분 범위를 연결한다. 이유·원인 해설을 필수 입력으로 요구하지 않으며, 대화로 제공했다는 이유로 대안을 일반 코멘트로 축소하지 않는다.

다른 업무로 전환할 때에는 새로 선택한 업무에 속한 실행·산출물·대안·실험 맥락을 확인한다. 이전 업무의 선택 산출물을 새 업무의 결과처럼 붙이지 않는다. 관련 대상을 아직 선택하지 않았거나 새 업무에 해당 기록이 없으면 그 상태를 드러낸다. 비교를 위해 다른 업무의 기록을 참조하더라도 원래 소속과 버전을 유지한다.

작성 중인 대안과 대화 내용은 모드·업무 전환 중에도 유실되지 않도록 한다. 이전 업무에 속한 작성 내용의 연결 대상을 유지하면서, 저장 시점·임시 저장 방식·전환 중 확인·동시 수정 충돌 처리는 후속 설계 결정으로 남긴다. 이 보존 원칙을 제출 강제, 작성 완료 선언 또는 승인 절차로 확정하지 않는다.

모드 전환 자체는 새 실행·탐구·학습·실험·승인·운영 버전업을 일으키지 않는다. 작성 내용의 보존이나 선택 상태의 변경도 실행·운영 승인을 대신하지 않는다. 실제 행위가 일어날 때에는 해당 대상과 모드가 공통 권한·검증·이력 경계에 연결돼야 한다.

사용자에게 공통 맥락을 보여 준다는 것은 모든 에이전트에게 진단 자료를 공개한다는 뜻이 아니다. 원 수행·실험 실행·진단·평가는 각 경로의 접근 경계를 유지하며, UI에서 연결된 대안이나 사후 해석이 실행 입력에 자동으로 들어가지 않도록 설계한다.

## 2. 공통 화면 골격 대안

두 안 모두 작업공간·대화·그래프를 제공한다. 비교 대상은 어느 모드를 채택할지가 아니라, 세 모드에서 환경·업무 탐색과 현재 대상·버전을 어떻게 배치하고 이어 갈지다. 아래 골격은 정보 영역과 접근 위치를 제안하며 픽셀, 색, 화면 크기별 배치, 프레임워크를 확정하지 않는다.

| 비교 기준 | A — 탐색을 유지하고 중앙 전환 | B — 모드별 작업면적 확대 |
| --- | --- | --- |
| 공통 맥락 배치 | 환경·업무 탐색을 한쪽에 유지하고, 현재 대상·버전과 모드 전환을 중앙 작업 영역 위에 둔다. | 현재 대상·버전·복귀 경로와 모드 전환을 고정하고, 환경·업무 탐색은 공통 진입점에서 연다. |
| 주작업 내용 | 중앙에서 원 자료·산출물, 대화 또는 그래프를 바꿔 본다. 근거·상태 상세는 필요할 때 연다. | 선택 모드의 주작업 내용을 넓게 펼친다. 탐색과 근거·상태 상세는 공통 진입점에서 필요할 때 연다. |
| 예상 장점 | 탐색 목록과 현재 선택을 함께 볼 수 있어 업무 사이를 오갈 때 소속과 위치를 확인하기 쉽다. | 큰 산출물의 본문·비교와 넓은 역할 그래프에 더 많은 작업면적을 배정할 수 있다. |
| 예상 위험 | 탐색과 상세를 모두 펼치면 과밀해질 수 있다. 상세는 상시 패널로 쌓지 않고 선택해 연다. | 탐색이 닫혀 있을 때 업무 간 관계를 파악하기 어렵고, 전환 중 맥락이 약해질 수 있다. 대상·버전·복귀 경로로 위치를 확인하게 한다. |
| 초기 설계 추천 | 탐색 연속성을 우선하는 안으로 추천한다. | 큰 산출물·그래프의 공간 요구를 검토할 비교안으로 유지한다. |

장단점과 추천은 설계 추론이며 사용자 선택이나 실측 효과가 아니다. A를 채택한 것으로 기록하지 않으며, 기본 진입 모드도 이 비교로 정하지 않는다.

### A의 텍스트 와이어프레임

```text
[환경·업무 탐색 영역]  [현재 대상·버전 식별 영역]
                      [작업공간 / 대화 / 그래프 전환 영역]
                      [선택 모드의 주작업 영역]
                      [필요 근거·상태 상세 진입 영역]

작업공간 주작업: [원 자료·산출물 목록 영역] [원 산출물 본문 영역]
                 [실제 대안·비교 영역 — 해당 대상 선택 시]
대화 주작업:     [참조 대상·선택 범위 영역] [대화 내역·작성 영역]
그래프 주작업:   [역할·입출력·진행·전달·실패 탐색 영역]
선택해 연 상세:  [대상 상세 영역] [관련 근거·상태·이력 영역]
```

환경·업무 탐색과 현재 대상·버전의 위치를 유지하면서 중앙 주작업을 전환한다. 원 자료 목록, 대안·비교, 상세 영역을 모두 항상 펼치는 뜻은 아니다. 필요한 내용을 선택해 열고 닫되 현재 선택과 작성 상태는 이어진다.

산출물을 선택하면 공통 식별 영역에서 환경·업무·실행·역할·산출물 버전을 확인하고, 본문 또는 참조 영역에서 전체/부분 선택 범위를 확인한다. 상세에서 같은 이름의 다른 실행·버전과 구별할 참조 및 연결된 대안·실험으로 이어진다.

### B의 텍스트 와이어프레임

```text
[환경·업무 탐색 진입 영역] [현재 대상·버전 식별 영역] [이전 보기 복귀 영역]
[작업공간 / 대화 / 그래프 전환 영역] [필요 근거·상태 상세 진입 영역]
[선택 모드의 확장 주작업 영역]

작업공간 주작업: [원 자료·산출물 선택 영역] [원 산출물 본문 영역]
                 [실제 대안·비교 영역 — 해당 대상 선택 시]
대화 주작업:     [참조 대상·선택 범위 영역] [대화 내역·작성 영역]
그래프 주작업:   [역할·입출력·진행·전달·실패 탐색 영역]
선택해 연 탐색:  [환경·업무 탐색 영역]
선택해 연 상세:  [대상 상세 영역] [관련 근거·상태·이력 영역]
```

모드별 주작업 영역을 넓게 쓰면서 공통 대상·버전과 복귀 경로를 유지한다. 탐색이나 상세를 닫아도 선택 대상을 잃지 않고 이전 보기로 돌아갈 수 있게 한다. 복귀는 보기와 선택의 회복이며 실행 취소나 운영 버전 롤백을 뜻하지 않는다.

산출물을 선택하면 고정 식별 영역에서 A와 같은 환경·업무·실행·역할·산출물 버전을 확인한다. 넓은 작업 영역에서도 전체/부분 선택 범위를 식별하고, 대화 참조나 그래프에서 동일 버전의 산출물 상세로 연결한다. 업무·산출물이 미선택인 상태는 선택된 결과처럼 채우지 않는다.

### 두 안에 공통으로 남는 전환·작성 경계

작성 중인 대안·대화와 미저장 내용은 §1의 보존 원칙에 따라 원래 대상·버전·범위와 연결한다. 다른 모드나 업무로 옮겨도 유실하거나 새 업무의 내용으로 바꾸지 않는다. 저장 여부·저장 중·저장 실패 등의 상태를 표시할 필요가 있다면 작성 영역과 공통 상태 진입점에서 확인할 수 있게 하되, 실제 상태가 확인된 범위만 표시한다.

이 상태 접근 제안은 자동 저장 주기, 저장 매체, 전환 확인창, 충돌 해결이나 실패 복구 정책의 승인이 아니다. 구체 저장·복구 방식은 후속 설계한다. 전환을 위해 직접 그래프를 편집하거나 대안을 명시적으로 제출해야 한다는 의무를 만들지 않는다.

## 3. 세 모드의 책임과 연결

세 모드는 같은 대상에 접근하되 다음 작업을 중심으로 구성한다. 모든 기능을 세 번 복제할 필요는 없으며, 어느 모드에서도 동일 대상·버전의 상세와 관련 근거로 연결한다.

| 모드 | 중심 책임 | 다른 보기·상세로 이어지는 연결 |
| --- | --- | --- |
| 작업공간 | 원 자료와 역할별 완결 산출물을 읽고, 실제 자기 대안을 전체/부분으로 남기며 원본·대안·실험 결과를 비교한다. | 선택한 산출물·범위를 대화의 참조로 이어 가고, 그래프에서 해당 역할의 실제 입력·출력과 전달 관계를 연다. |
| 대화 | 같은 환경·업무·산출물을 참조해 요청·설계 조정·질문·탐구를 이어 간다. 대화에 남긴 실제 자기 버전도 원본과 연결한다. | 참조에서 원 산출물 전체와 선택 범위·실제 대안을 열고, 관련 역할·실행·탐구의 상세로 연결한다. 일반 요청·이유 설명을 자기 대안으로 추정하지 않는다. |
| 그래프 | 설계 구조와 실제 역할·입출력·진행·전달·실패를 탐색한다. | 역할·산출물·전달 관계에서 해당 버전의 원본, 실제 입력·출력, 실행 기록과 근거를 연다. 노드 탐색을 직접 편집 의무로 확대하지 않는다. |

작업공간에서 원 산출물 일부를 선택해 그래프로 가면 해당 역할·산출물·전달 관계가 탐색의 출발점이 된다. 거기서 대화로 옮기면 같은 실행·버전·범위를 참조하고, 다시 산출물 상세를 열면 원본 전체와 선택 영역을 함께 확인한다. 아직 없는 대안·탐구·실험은 연결된 기록처럼 생성하지 않는다.

그래프에서 표현하는 관계는 다음처럼 근거의 종류를 구별한다. 구별 표기와 상세 접근은 필요하지만 선의 모양·색·편집 조작은 미정이다.

| 관계 종류 | 의미와 확인할 근거 |
| --- | --- |
| 설계상 예정된 연결 | 역할 사이에 어떤 입출력을 전달하도록 설계했는지. 실제 실행·전달 완료를 뜻하지 않는다. |
| 실제 전달 기록 | 어느 실행에서 어떤 산출물 버전이 어느 역할로 전달됐는지. 내용의 적절한 활용까지 증명하지 않는다. |
| 관찰된 산출물 계보 | 실제 입력·출력과 출처 기록으로 연결된 산출물 관계. 관찰된 연결을 원인 확정으로 확대하지 않는다. |
| 개입으로 지지된 영향 | 특정 변경을 가한 실행·비교 근거가 어느 영향과 범위를 지지하는지. 확인한 조건·한계와 미확인 범위를 함께 연결한다. |

그래프의 선 자체는 인과 증명이 아니다. 일부 전달·영향만 확인됐으면 해당 근거와 범위를 식별하고, 미확인을 성공이나 실패로 단정하지 않는다. 세 모드의 상태 표시와 상세 접근은 공통 권한·검증·이력을 따르며, 보기 전환이나 내용 보존으로 새 실행·학습·승인 효력을 만들지 않는다.

## 4. 전체 여정과 반복 흐름

아래 이동도는 [통합 기준선 §3–6](2026-09-06-deeptwin-integrated-product-design.md#3-화면과-실제-작동이-이어지는-전체-흐름)을 화면의 대상·근거·이동 관계로 연결한 제안이다. 고정 메뉴 수나 모든 클릭의 순서를 정하지 않는다. §1의 공통 맥락, §2의 골격 대안, §3의 모드 책임을 사용하며 구체 버튼·실행 계기·승인 조작은 후속 설계한다.

```text
업무 설명·자료 ↔ 업무 이해·출처 ↔ 실제 구조 후보 비교·수정
                                      ↓
                            승인된 설계·실제 구성 상태
                                      ↓
                    실제 업무 실행 ↔ 역할 입력·산출물·전달 관계
                                      ↕
                          실제 자기 대안·탐구·개선 실험
```

### 업무를 맡기고 실제 산출물에 도달하는 흐름

| 구간 | 화면에서 다룰 내용과 이동 | 실제 작동과 확인 경계 |
| --- | --- | --- |
| 업무 설명·자료 | 대화의 요청과 작업공간의 원 자료에서 이해한 업무·출처 상세로 이동한다. | 목적·완료 조건·권한·위험·미해결 사항을 자료와 연결한다. 읽지 못한 자료와 미확정 조건을 드러내고 필요한 조건을 보완한다. |
| 업무 이해·출처 | 해석한 조건에서 근거 자료로 돌아가거나 구조 후보 비교로 이어진다. | 후보들은 같은 사용자 목적·필수 제약을 공유한다. 자료 안의 지시가 실행 권한으로 바뀌지 않도록 §1의 접근 경계를 따른다. |
| 실제 구조 후보 비교·수정 | 작업공간에서 후보별 차이·근거·검토 결과를 비교하고, 그래프에서 역할·입출력·조정 구조를 보며 대화로 선택·병합·수정을 이어 간다. | 프레임워크가 실제 역할·기억·권한·도구·평가 구조를 구성할 후보를 만든다. 이름·문구·에이전트 수만 달리한 안을 구조 다양성으로 세지 않는다. |
| 승인된 설계·구성 상태 | 선택·수정한 정확한 설계 버전, 승인 효력, 필요한 연결과 실제 구성 상태를 관련 상세에서 확인한다. | 프레임워크가 승인 설계를 실행 구성으로 변환한다. 사용자 코드·CLI·YAML·어댑터 제작을 요구하지 않으며, 설계 승인만으로 구성·실행 성공을 표시하지 않는다. |
| 실제 업무 실행·산출물 | 역할별 진행·대기·실패에서 해당 실행의 실제 입력·완결 산출물을 열고 앞뒤 전달 관계로 이동한다. | 승인된 구성·권한·도구·게이트로 실행한 기록을 연결한다. 전체 업무의 중간 결과여도 역할의 전체 산출물을 읽고 자기 대안을 남길 수 있다. |

도구 구성은 이 여정 밖에서 사용자가 따로 조립하는 선행 작업이 아니다. 설계 비교의 역할별 도구·자료·산출물 계획과 준비 상태는 §8.2, 실제 도구 작업·파일·후속 전달은 §8.3, 실패·사람 개입과 복구는 §8.4로 이어진다. 어떤 모드에서 들어가도 같은 업무·실행·역할·버전과 권한을 유지한다.

여기서 비교하는 업무 환경 설계 기본 3안은 §2의 UI 골격 두 안과 별개다. 적합한 실제 구조가 기본 3안이며 최소 두 구조 축에서 달라야 한다. 결정적 워크플로나 단일 에이전트가 적합한 경우도 근거와 함께 비교하되 멀티에이전트 구성·관제 역량은 유지한다. 적합한 후보가 부족하면 수와 이유를 표시하고 안을 꾸며 채우지 않는다.

별도 크리틱은 후보를 개별·병렬·블라인드로 평가하며 생성자의 렌즈 정체성·자기평가와 타 크리틱 결론을 가린다. 비교 상세에는 실제 업무 근거·출처 검사·반례·시험 결과와 필수 실패·근거 부족을 연결한다. 필수 실패나 근거 부족은 높은 평균 점수로 상쇄할 수 없고, 크리틱 구성만으로 오류 독립성이 입증됐다고 표시하지 않는다.

### 실제 자기 대안에서 다시 수행을 보는 반복

```text
역할 입력·원 산출물 전체 ↔ 실제 전체/부분 자기 대안 ↔ 관찰 차이·경쟁 가설
        ↕                                                   ↕
같은/다른 산출물의 새 대안 ↔ 작동 변경 후보·실험 결과 ↔ 필요한 질문·새 실제 증거
```

| 연결 구간 | 이어서 읽거나 다룰 대상 | 남겨야 할 구별 |
| --- | --- | --- |
| 원 수행 ↔ 자기 대안 | 역할의 실제 입력·원 출력 전체, 선택 영역, 사용자가 실제 작성한 전체/부분 버전. | 원본·대안의 출처·순서·검토 범위는 §1대로 보존한다. 실제 대안이 없으면 비교 증거 없음으로 남기며 대안을 생성해 채우지 않는다. |
| 자기 대안 ↔ 관찰 차이 | 표현·내용·조건·근거·우선순위·정보 활용의 차이와 관련 문맥. | 사용자의 이유·원인 설명은 선택 사항이다. 업무 요청·코칭·침묵이나 시스템 해석은 실제 자기 대안이 아니다. |
| 차이 ↔ 경쟁 가설 | 정보 추출·검색·활용·전달 실패라는 시스템 설명과 조건부 사용자 판단 가설을 각각 열어 본다. | 일회성 예외, 사용자 대안 오류, 원인 미확정, 일반화할 지식 없음도 유지한다. 설명에 동의한 것을 새 수행 증거로 대체하지 않는다. |
| 가설 ↔ 질문·새 증거 | 가설을 구별할 질문·실제 업무 사례·새 수행 또는 응답과 그 출처. | 미발동·기권·근거 부족·질문 보류·거절을 기록한다. 필요한 증거가 없는 해당 탐구는 보류할 수 있지만 무관한 업무 전체를 중단하지 않는다. |
| 증거 ↔ 변경 후보·결과 | 무엇을 바꿀지, 예상하는 국소·후속 영향, 실제 재실행과 비교 근거. | 원 대안 문구를 실행 입력에 붙여 넣어 결과가 비슷해진 것을 학습·흡수 성공으로 판정하지 않는다. 사후 대안·진단과 실행 입력의 경계는 §1대로 유지한다. |
| 결과 ↔ 다음 대안 | 달라진 수행의 같은 부분·다른 부분·다른 역할 산출물을 읽고 실제 자기 버전을 다시 남긴다. | 전체 대안 완성이나 모든 질문 종료를 매 회차의 선행 조건으로 두지 않는다. 새 대안은 해당 회차의 실제 산출물·입력·버전에 연결한다. |

대안·비교 구간에서 원 산출물의 앞뒤 역할 입력·출력과 관련 이전 업무 큐로 이동하고 돌아올 수 있게 한다. 다른 업무를 비교해도 원래 소속과 회차를 유지하며, 아직 실행하지 않은 후보 결과는 실제 산출물처럼 채우지 않는다.

### 실험·지식 변경·운영으로 이어지는 경계

| 구간 | 연결할 화면 내용 | 보존할 검증·권한 경계 |
| --- | --- | --- |
| 실험 범위 | 실제 대안·검토 범위, 시험할 변경 대상, 예상 영향·검증 대상. | 부분 대안의 크기는 변경·영향·검증의 상한이 아니다. 다른 단락·역할·관련 업무로 이어지는 영향을 시험하며 미검토를 승인 또는 변경 금지로 취급하지 않는다. |
| 반복 비교 | 기준 환경·후보 버전·입력·회차별 산출물과 관련 이전 업무 큐. | 개선·악화·실패·미확인을 모두 보존한다. 튜닝에 쓴 큐는 최종 미관측 자료로 재명명하지 않는다. |

| 후보 고정·최종 확인 | 고정한 후보 버전과 별도 미관측/전향 자료, 경계·회귀·출처·안전 검사 근거. | 반복 튜닝 결과와 별도 최종 증거를 구별한다. 후보를 다시 바꾸면 변경된 버전의 검증 상태를 따로 확인한다. |
| 최종 승인·적용 | 선택한 변경 묶음·실제 검증 범위·정확한 후보 버전을 사람의 최종 운영 승인 대상으로 연결하고, 남은 한계·실제 적용 결과·이전 운영 버전·롤백 이력을 확인한다. | 평가한 후보·승인한 후보·실제 운영 버전이 일치해야 한다. 승인 기록만으로 적용 성공을 표시하지 않으며 지속 운영 전환은 최종 승인을 거친다. |

```text
관련 이전 업무 큐의 반복 실험 ↔ 후보 수정
                 ↓ 후보 고정
별도 최종 증거 → 사람의 최종 운영 승인 → 정확한 버전 적용 ↔ 재검증·철회·롤백
```

작은 작동 변경도 환경 버전에 담아 승인할 수 있으며 매번 환경 전체를 재설계·재승인하는 흐름으로 만들지 않는다. 선택한 변경과 관련 영향의 필수 검증은 유지하되, 별개의 모든 개선 과제를 해결해야 그 변경을 승인할 수 있는 것은 아니다([AC-025·027](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md)).

| 작동 변경의 종류 | 변경 상세에서 구별할 내용 |
| --- | --- |
| 기존 기능 복원·보호 보강 | 정보 활용·전달 등 기존 수행의 복구 또는 보호 장치 보강인지. 모든 수정이 새 지식 추가는 아니다. |
| 새 지식·절차 추가 | 어떤 실제 증거에서 어떤 조건·행동·예외를 추가할 후보가 생겼는지. 저장만으로 검증·운영 적용을 뜻하지 않는다. |
| 기존 지식 재검토 | 조건 분화·범위 수정·대체·비활성 중 무엇인지, 기존 버전과 충돌·영향·검증 근거. 최신 대안으로 과거 지식을 일괄 덮어쓰지 않는다. |

실험·실행 상세에서 현재 운영, 운영과 격리한 후보 실험, 실제 출력에 영향 없는 관찰 전용을 구별한다. 제한된 적용도 적용 권한·범위와 연결하며 지속 운영 승격과 구별한다. 합의한 데이터·도구·변경 종류·시간·사용량·반복 한도 안에서는 자동 반복하고, 새 증거·추가 권한·한도·안전 문제는 관련 범위의 사람 개입이나 보류로 연결한다. 설계 승인·이번 외부 행동 허가·지속 운영 승인은 §1의 서로 다른 효력을 유지한다.

### 세 탐구 경로와 일반 화면·감사의 연결

| 내부 경로 | 진입과 필요한 근거 | 일반 화면의 위치와 업무 표현 |

일반 UI에는 구체적인 업무 용어를 쓰고 철학·렌즈·철학자 이름을 노출하지 않는다. 이름 비노출은 관찰 차이·질문 목적·사용한 실제 근거·진행·부족 상태를 숨긴다는 뜻이 아니다. 이 문서의 내부 용어는 화면 문구 확정안이 아니다.

권한 있는 감사 경로에서만 렌즈 출처·정의·버전·단독/하이브리드 조합, 탈락·실패를 포함한 후보와 이유, 새 수행·응답을 보기 전에 봉인한 정의·질문·예측, 실제 결과를 연결해 조회한다. 일반 화면의 관련 비교·탐구 상세에서 이 감사 기록으로 이어지되 §1의 접근 경계를 유지한다. 미발동·미확정·기권·근거 부족도 보존한다.

에피소드 철학 해석 `H_phi/S_phi`는 운영 규칙이나 개입·변경 후보의 직접 입력이 아니다. 판별 질문 이후의 실제 새 행동·응답 증거로 사용자 판단 가설 `H_exp`를 갱신하고, 그 근거에서 조건·행동·예외를 가진 작동 변경을 시험한다. 사용자별 철학·성격·민감 특성 프로필을 만들지 않는다.

렌즈·크리틱의 효용과 판단 오류 독립성은 미검증 요구로 유지한다. 이름 비노출·동의·병렬 호출·다수결·사람 승인이 입증을 대신하지 않는다. 실제 구현 후 비용·정보 접근·평가 자료를 맞춘 기준선 비교와 수용 시험이 필요하며, 감사 출처는 효과 증거와 구별한다.

연결 상세는 선택한 제공자·실행기/모델 버전·구독/API 경로와 실제 실행 경로를 연결한다. 인증·한도 실패에도 현재 업무·작성 내용·실행 기록을 보존하고 API로 자동 과금 전환하지 않는다. 공식 인증·실행 계약은 별도 검증 대상이며 이 설계는 실제 인증 성공이나 배포물 지원 완료를 주장하지 않는다.

```text
어느 업무 상태 ↔ 관련 기록 선택 → 공개 범위·가림·결손·재현 한계 확인 → 증거 묶음 추출
                                                                    ↘ 선택한 경우 전달
기록 선택·공유 검토 중 취소/닫기 → 원 업무·대상·버전·작성 상태로 복귀
```

공유 검토를 취소하거나 닫으면 새 추출·전송 없이 원래 업무·선택 대상·버전·작성 상태로 돌아가며 원 기록이나 작성 내용을 삭제하지 않는다. 이미 추출·전달을 마친 뒤 보기를 닫는 것은 완료된 추출·전송을 소급 취소하거나 파일·기록을 삭제하는 동작이 아니다. 이 복귀 경로의 구체 버튼명·조작은 후속 설계한다.

추출은 전송이 아니며 내보내거나 전달하지 않아도 업무 수행·환경 개선·운영 승격을 완료할 수 있다. 해시만으로 빠진 원문을 복구하거나 재현을 보장하지 않는다. 기록은 프레임워크 내부 사건에 한정하고 인증 토큰·키·자격증명·숨은 추론·다른 앱 감시·키로깅을 수집하지 않는다. 제공자 모델 호출에 필요한 자료 전송과 제작자에게 선택 전달하는 진단 증거 묶음도 서로 구별한다.

## 5. 상태와 승인 효력

아래는 상태별 정보·선택·근거의 표시 제안이다. 객체마다 다른 상태군을 하나의 공통 상태 기계나 순차 진행률로 합치지 않는다. 예를 들어 대안 일부가 보존되어도 탐구는 보류 중일 수 있고, 설계가 승인되어도 제공자는 미연결일 수 있다. 현재 대상·버전과 연결은 §1, 이동 위치는 §3–4를 따른다.

| 상태군·상황 | 사용자가 알아야 할 정보 | 가능한 다음 선택 | 연결할 근거 | 허용하지 않을 오해 |
| --- | --- | --- | --- | --- |
| 자료·업무 이해 — 자료 없음·부분 읽기 불가 | 받은 자료와 읽은/못 읽은 범위, 해석 출처, 중요한 미확정 조건. | 자료 보완·해석 수정·필요 조건 확인; 해당 조건에 의존하지 않는 작업 계속. | 원 자료·읽기 결과·업무 조건과 출처 연결. | 자료 없음과 읽기 실패를 같게 표시하거나 못 읽은 부분까지 반영했다고 하지 않음. |

## 6. 상세 선택과 제안 근거

다음 여섯 선택은 [통합 기준선 §9](2026-09-06-deeptwin-integrated-product-design.md#9-상세-설계-전에-남은-결정)의 UI 미결 사항을 비교 가능한 안으로 구체화한다. 확인된 제품 원칙과 이번 추천을 구별하며 아래 상세 조작을 일괄 채택·잠정 확정하지 않는다.

### 6.1 공통 골격

기존 근거: §1의 맥락 연속성과 §2의 A/B 비교, [AC-004·018](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md).

구체 추천: A처럼 환경·업무 탐색과 대상·버전을 유지하고 중앙에서 세 모드를 바꾼다. 근거·상태 상세는 선택해 연다.

대안·차이: B는 탐색을 접고 산출물·그래프 작업면적을 늘린다. A는 업무 사이 이동을, B는 큰 본문·구조 읽기를 우선하므로 실제 화면 폭과 주요 작업으로 비교한다.

확인 상태: 세 모드와 공통 맥락은 확인됐다. A 추천은 유지하되 골격 채택·상세 배치는 사용자 미합의다.

### 6.2 기본 진입 모드

기존 근거: §3의 모드 책임과 업무 설명에서 시작하는 §4, [INT-024](/Users/soonseekyang/Documents/Deeptwin/docs/product-intent.md)의 기본 모드 미결.

구체 추천: 새 환경의 첫 진입은 대화에서 업무 설명·자료로 시작하고, 재방문은 마지막 사용 모드와 선택 대상을 복원한다. 세 모드 전환은 같은 위치에서 제공하고 작업 진행만으로 모드를 자동 변경하지 않는다.

대안·차이: 항상 작업공간의 자료·업무 개요로 진입하는 안은 재방문 시 전체 현황을 먼저 파악하기 좋다. 추천안은 작성·탐색하던 맥락을 이어 가기 좋지만, 현황을 보려면 작업공간으로 이동해야 한다.

확인 상태: 첫 진입 대화·마지막 모드 복원 모두 사용자와 미합의인 설계 제안이다. 세 모드 제공을 대화 중심 제품의 채택으로 바꾸지 않는다.

### 6.3 기능별 상세 이동

기존 근거: §1의 대상·버전 연결, §3의 모드별 책임, [AC-004·017·028](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md).

구체 추천: 산출물 읽기·대안 비교는 작업공간, 요청·탐구 응답은 대화, 역할·전달 관계 탐색은 그래프를 주 진입으로 둔다. 어느 모드에서도 선택 대상의 근거·평가·승인 상세를 열고 원래 보기로 돌아오게 한다.

대안·차이: 모든 상세 조작을 각 모드 안에 복제하면 이동은 줄지만 배치와 상태가 복잡해진다. 추천안은 대상·작성 맥락을 유지한 이동을 우선하며 그래프 직접 편집을 필수로 요구하지 않는다.

확인 상태: 각 모드의 중심 책임은 기준선에 있다. 상세를 패널/별도 화면 중 어디에 열지, 모드별 조작 동등성과 직접 편집 범위는 미합의다.

### 6.4 대안 저장·탐구·재실행 계기

기존 근거: §1·4의 실제 대안·부분 반복·권한 경계, [INT-031·033](/Users/soonseekyang/Documents/Deeptwin/docs/product-intent.md), [AC-026·029·031·033](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md).

구체 추천: 입력 중인 내용은 대상·버전·범위와 함께 자동 임시 보존하고 저장 상태를 표시한다. 원본에 연결된 대안 작성 영역에서 남긴 자기 문구·단락·전체 본문 또는 대화로 제시한 실제 교체 내용을 대안으로 식별하되, 입력 중인 조각을 곧바로 비교 증거로 올리지 않는다. 비교에 사용할 부분 버전의 식별은 재현을 위한 것으로 판단 완결 선언이 아니다. 문맥상 자기 대안인지·어느 부분인지 모호하면 그 부분만 확인하고 나머지 작성 내용은 보존한다.

업무 설명·일반 대화·수정 지시·미완성 편집은 각각의 맥락으로 보존한다. 자기 버전의 성립, 임시 보존, 탐구·재실행 권한은 별개다. 명확히 제공된 부분 대안이 있고 합의된 허용 범위 안이면 필요한 탐구·후보 시험을 이어 가는 안을 추천한다. 추가 권한·새 사용자 증거·한도 문제가 있으면 관련 작업만 요청/보류하고, 사용자가 시험을 요청할 때에는 현재 후보·시험 범위·조건을 연결한다.

대안·차이: 실제 대안 보존 후 사용자가 원할 때 탐구·시험을 시작하는 안은 시점 통제가 더 직접적이지만 반복 개입이 늘 수 있다. 어느 안도 이유 입력·전체 대안 완성·명시 제출 선언·모든 렌즈 질문 종료를 일률적 시험 조건으로 삼지 않는다. 무응답·모드 전환·자동 저장 자체는 실행 허가가 아니다.

확인 상태: 부분 대안에서 반복하고 이유 설명을 요구하지 않는 원칙은 확인됐다. 자동 보존의 구체 시점, 자기 대안 식별·모호성 확인 조작, 탐구/시험 계기와 자동화 허용 범위의 상세는 사용자 미합의다.

### 6.5 전환 중 편집·충돌 처리

기존 근거: §1–2의 작성 내용 보존, [AC-006·018](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md).

구체 추천: 모드·업무 전환 때 원래 대상에 연결한 초안을 유지하고 저장 중/실패를 알린다. 같은 사용자의 여러 보기나 오래된 초안과 현재 기반 버전 사이에 수정 충돌이 생기면 양쪽 내용·버전을 보존한 뒤 충돌 범위만 비교·병합하도록 제안한다. 저장 실패나 충돌이 있는 내용을 확정 버전으로 실험에 넘기지 않는다. 새로 열거나 새로고침한 뒤에도 보존된 업무·버전·진행 맥락을 UI에서 다시 열고 복구하며 사용자 CLI/API 조작으로 넘기지 않는다.

대안·차이: 편집 대상을 잠그는 안은 충돌을 줄이지만 같은 사용자가 다른 보기에서 이어 편집하는 것도 제한할 수 있다. 추천안은 양쪽 내용을 보존한 상태에서 해결할 수 있지만 충돌 확인이 필요하다. 전환마다 저장·폐기 선택을 강제하는 대신 복구 가능한 보존을 우선한다.

확인 상태: 전환 중 내용과 맥락 보존은 확인됐다. 자동 병합 가능 범위·복구 방식·저장 위치·실패 처리 세부 정책은 미합의이며, 최신 내용으로 조용히 덮어쓰는 권한은 부여하지 않는다. 이 제안으로 실시간 다중 사용자 동시 편집 지원을 확정하지 않는다.

### 6.6 승인 대상 표시

기존 근거: §4–5의 세 승인 효력·버전 일치, [통합 기준선 §4.1·6](2026-09-06-deeptwin-integrated-product-design.md#41-대안의-범위와-변화의-범위는-다르다), [AC-011·023·025·027](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md).

구체 추천: 결정 위치에 효력, 선택한 변경 묶음 또는 행동, 정확한 대상 버전, 적용·실제 검증 범위와 남은 한계를 요약하고 상세 근거로 연결한다. 지속 운영 승인에는 평가한 후보·승인 대상·현재 운영·되돌릴 버전을 함께 대조하며 실제 적용 상태는 별도로 표시한다.

대안·차이: 승인 전용 검토 화면에 모으는 안은 여러 건을 일괄 검토하기 좋지만 현재 산출물·시험과의 이동이 늘어난다. 추천안은 현재 대상 옆에서 판단할 근거를 열되, 전체 환경 재설계 승인을 매번 강요하지 않는다.

확인 상태: 서로 다른 승인 효력·사람의 최종 운영 승격·필수 검사 우선은 확인됐다. 요약 배치·변경 묶음 조작·승인/보류/기각 방식은 미합의다. 평가 기준·승인 설정을 바꾸는 후보도 원 기준과의 비교 및 변경 권한을 드러내며 자기 합격 기준·승인 권한의 자율 변경을 허용하지 않는다.

## 7. 검토할 화면 구조와 남은 결정

검토 제안은 **A — 탐색을 유지하고 중앙 전환**이다. 환경·업무 목록과 현재 대상·버전을 함께 두면 산출물, 역할 관계, 대안과 실험을 오갈 때 소속을 확인하기 쉽다는 설계 추론이다. **B — 모드별 작업면적 확대**는 큰 본문과 그래프에 공간을 더 주는 비교안이다. A의 채택이나 실제 사용성 우위는 아직 확인하지 않았다.

두 골격과 아래 흐름을 한 묶음으로 검토한다. 모든 페이지 순서·버튼·상세 배치를 고정하지 않으며, UI 골격 A/B는 업무 환경 구조의 기본 3안과 별개다. 새 업무·자기 대안·자기 철학 설명을 사용자에게 요구하는 검토 절차도 아니다.

A — 업무 사이 이동과 현재 선택을 함께 확인한다.

```text
[환경·업무 탐색]  [현재 대상·버전·선택 범위]
                  [작업공간 / 대화 / 그래프]
                  [선택 모드의 본문·비교·대화·역할 관계]
                  [근거·상태·이력 상세 열기]
```

B — 공통 식별과 복귀 경로를 남기고 주작업 영역을 넓힌다.

```text
[탐색 열기] [현재 대상·버전·선택 범위] [이전 보기]
[작업공간 / 대화 / 그래프] [근거·상태·이력 상세 열기]
[                 선택 모드의 넓은 작업 영역              ]
```

어느 안에서도 작업공간의 선택 산출물·문구 → 그래프의 해당 역할·전달 관계 → 대화의 같은 대상 참조 → 원본 전체로 돌아간다. 환경·업무·실행·역할·원본 버전·선택 범위와 연결된 실제 대안·실험 회차, 작성 내용을 이어 간다. 미선택·부재도 유지하며 보기 전환이나 초안 보존은 실행·학습·승인이 아니다(§1–3).

```text
업무 설명·자료 ↔ 업무 이해·출처 ↔ 실제 구조 후보 비교·수정
  → 승인된 설계·실제 구성 상태 → 실제 업무 실행 ↔ 역할 입력·원 산출물 전체

원 산출물 ↔ 실제 전체/부분 자기 대안 ↔ 차이·가설·질문·새 증거 ↔ 운영과 격리한 후보 실험
후보 실험 ↔ 이전 업무 큐 반복·후보 수정 ↔ 결과 ↔ 같은/다른 산출물의 새 대안

이전 업무 큐 반복·후보 수정 → 후보 고정 → 별도 최종 근거
  → 사람이 선택한 변경·실제 검증 범위·정확한 후보의 최종 운영 승인
  → 실제 적용·운영 버전 ↔ 재검증·철회·되돌릴 버전과 롤백 결과
```

반복 큐에는 개선·악화·실패·미확인 회차를 모두 남기고, 후보 고정 뒤 별도 미관측/전향 자료의 최종 근거로 연결한다. 부분 대안 밖 역할·관련 업무의 영향도 검증하며, 이유 설명·전체 대안 완성·모든 질문 종료를 일률적 시험 조건으로 삼지 않는다. 작은 변경은 선택한 변경 묶음과 관련 영향의 검증·승인으로 다루며 환경 전체 재설계 승인을 매번 요구하지 않는다(§4).

실패·보류는 해당 대상·회차의 상태에서 근거·상태 상세로 연다. 후보의 필수 실패·부족은 검사 출처로, 탐구 보류는 필요한 새 증거·질문으로, 실행 실패는 실제 입출력·오류·권한 기록으로 연결한다. 승인 위치에는 남은 한계와 평가 후보·승인 대상·현재 운영·되돌릴 버전을 대조한다. 검사 결과·사람의 결정·실제 적용 결과는 각 상태로 유지하고 설계 승인·이번 외부 행동 허가·지속 운영 승인의 효력을 구별한다(§5).

§6의 남은 선택은 이 골격과 이동을 구체화할 쟁점이다. 확인된 제품 원칙은 유지하며 아래 추천 조작은 사용자 미합의로 남긴다.

| 연결된 선택 | 이번 추천 | 확인된 원칙과 남은 결정 |
| --- | --- | --- |
| §6.1 공통 골격 | A의 탐색 유지·중앙 전환 | 세 모드·공통 맥락은 확인됨; A/B 채택·배치는 미합의. |
| §6.2 기본 진입 | 새 환경은 대화, 재방문은 마지막 모드·대상 | 세 모드는 제공; 진입·복원 조작은 미합의. |
| §6.3 상세 이동 | 모드별 중심 작업에서 공통 근거 상세로 연결 | 중심 책임은 확인됨; 상세 위치·조작 동등성·그래프 편집 범위는 미합의. |
| §6.4 대안·탐구·재실행 | 초안 임시 보존, 명확한 부분 대안에서 허용 범위의 반복 | 부분 대안·이유 선택은 확인됨; 식별·보존 시점·실험 계기·자동화 상세는 미합의. |
| §6.5 편집·충돌 | 원 대상의 초안과 충돌 양쪽 버전 보존 후 해결 | 전환 중 맥락 보존은 확인됨; 저장·복구·병합 정책은 미합의이며 다중 사용자 동시 편집 확정이 아님. |
| §6.6 승인 표시 | 현재 결정 위치에 정확한 대상·검증·효력과 근거 연결 | 사람의 최종 운영 승인·필수 검사 우선은 확인됨; 배치·변경 묶음·결정 조작은 미합의. |

철학·렌즈의 초기 구조 탐색, 후보 반례·질문, 대안 이후 차이 탐구 세 경로는 §4대로 유지한다. 일반 화면에는 업무 말로 차이·질문·근거·상태를 보여 주고, 관련 상세에서 권한 있는 감사의 출처·조합·봉인 기록·탈락 이력으로 연결한다. 이름 비노출을 탐구와 근거 전체를 숨기는 것으로 바꾸지 않는다.

어느 업무에서도 Claude·Codex 각각 보유 구독 하나로 핵심 여정을 지원해야 한다는 요구와 명시 선택 API 경로를 유지한다. 연결·한도·인증 상세에서 보존된 업무로 복귀하며 자동 API 과금 전환은 없다. 실제 공식 연결·실행·배포 지원은 각각 미검증이다.

초기 사용부터 탈락·실패·보류·승인까지 전 과정 로그는 §4의 기록 범위 안에서 연결한다. 기록 선택 → 공개 범위·가림·결손·재현 한계 → 추출 → 선택 전달은 업무 단계와 독립적이며 공유 없이도 업무를 완료할 수 있다. 공유 검토 취소/닫기는 새 추출·전송 없이 원 업무·대상·버전·작성 상태로 돌아간다.

이 묶음은 §1–6을 요약한 검토 제안이며 화면/엔진은 미구현이다. 후속 사용자 확인으로 구체화한 독립 제품의 도구 준비·실제 수행·복구 경험은 §8에 연결한다. [UI 검토 사례](../../ui/initial-ui-review-cases.md)는 기존 UI-01–12에 보완 UI-13–15를 더한 문서상 연결 검토이며 사용자 문서 승인, 제품 동작·학습·흡수·전이·회귀 효과의 입증과 구별한다.

| 설계 때 필요한 기능·준비 상태를 먼저 제시하고, 실제 사용 전 부족한 연결을 안내한다. 모든 계정 연결을 설계 검토의 선행 의무로 두지 않는다. | §4 설계·구성 흐름 → §8.2 |
| 업무 진행·역할별 실제 산출물을 기본으로 보고 선택한 역할의 실제 도구 작업·상세 근거를 필요시 확인한다. | §1 공통 대상, §3 세 모드 → §8.3 |
| 허용된 안전한 복구는 프레임워크가 맡고 사람이 필요한 문제는 영향받는 작업과 연결한다. 결과가 불명확한 외부 행동은 확인 전 반복하지 않는다. | §5 상태·권한 → §8.4 |

논문 4.2–4.4절(16–18쪽)은 도구·자료·산출물을 업무 모델에서 추출하고 권한·실패·부작용을 설계 및 사건 기록에 연결한다. 6.1절(37–38쪽)은 실행 엔진이 그래프·역할·도구 호출을 수행하며 특정 프레임워크에 종속되지 않는 인터페이스를 제안한다. 위 제품 경험은 그 근거와 사용자 직접 요구를 구체화한 것이지 논문이 특정 UI·패키지·구독 연결 구현을 확정한 것은 아니다.

DeepTwin이 업무 설계·역할 조정·도구·파일·기억·기록·개선 상태와 사용자 경험을 책임진다. 사용자가 Claude/Codex 앱에서 따로 에이전트를 구성하거나 CLI·MCP 설정·어댑터를 작성해야 업무가 이어지는 제품으로 만들지 않는다. 외부 도구와 제공자의 공식 로그인 화면은 허용된 인증 과정으로 구별하며 DeepTwin의 업무 맥락으로 돌아온다.

제공자 연결은 제품 내부의 교체 가능한 경계로 둔다. 내부 공식 실행 구성요소의 사용을 금지하는 요구는 아니며, 그 안에 수행 루프가 있다면 실제 제어·상태·권한·기록을 DeepTwin이 연결할 수 있는지 검증해야 한다. UI만 감싸거나 구성요소의 이름을 ‘모델 연결부’로 바꾸는 것으로 독립 운영 책임이 충족됐다고 하지 않는다. 제공자 전환 뒤에도 기존 환경·파일·이력은 남기되 기존 평가의 호환성·재검증 필요는 구별한다.

Claude와 Codex는 각각 본인 구독 하나로 핵심 LLM 여정을 지원해야 하고 API는 명시적으로 선택하는 추가 경로다(§4–5). 구독 토큰을 추출해 임의의 범용 API로 중개하지 않으며 실제 공식 통합은 미검증이다. 외부 업무 도구의 별도 인증·비용을 모델 구독과 구별한다. 현재 제작 환경에 설치된 스킬·도구·로그인은 배포된 DeepTwin의 기능이나 사용자 권한으로 자동 상속되지 않는다.

### 8.2 설계에서 도구 준비와 연결로

역할별로 필요한 기능, 접근할 자료 범위, 만들 산출물 형식, 권한·비용 조건과 현재 준비 상태를 설계 비교에 함께 제시한다. 사용자는 업무 언어로 역할·자료·도구·완료 조건을 수정하고 필요한 권한·연결을 확인할 수 있다. 기술 설정과 실행 구성으로 변환하는 책임은 프레임워크에 있다.

| 확인할 구별 | 사용자 경험과 실행 경계 |
| --- | --- |
| 준비됨 | 해당 역할·자료 범위에서 연결·권한·검증이 확인된 기능이다. 설계에 이름이 있거나 로그인했다는 사실만으로 이 상태를 부여하지 않는다. 확인한 조건·시점을 연결한다. |
| 미연결·인증 필요 | 필요한 서비스와 이유, 연결 전 제한되는 역할·의존 작업을 보여 주고 실제 사용 전에 공식 인증을 안내한다. 설계 자체에 그 자료가 필요하면 읽지 못한 범위·가정도 드러낸다. |
| 권한 부족 | 기존 권한과 추가로 필요한 접근/행동·범위를 구별한다. 연결 성공을 권한 확대나 외부 행동 허가로 간주하지 않는다. |
| 미지원·검증 전 | 없는 기능과 구현은 있으나 필요한 경로에서 검증되지 않은 기능을 구별한다. 가능한 업무 범위·제약을 밝히고 이름만 있는 도구를 사용 가능한 것처럼 표시하지 않는다. |

설계 검토를 위해 모든 계정·도구를 먼저 연결하도록 요구하지 않는다. 실제 수행 전에 부족한 연결·권한·비용 선택을 안내하고, 준비되지 않은 역할과 그 결과에 의존하는 작업이 기다리는 이유를 연결한다. 설계에 필수인 자료/권한의 부재까지 무시해도 된다는 뜻은 아니다. 도구 목록에서 직접 조립하는 고급 경험은 별도 선택지이며 기본 이용 의무나 채택된 추가 기능이 아니다.

승인된 설계에 도구가 있다는 사실만으로 신규 도구 제작·설치·업데이트·계정 연결·유료 사용 권한을 얻지 않는다. 이미 허용되고 준비된 기능의 사용과 새로운 권한/외부 변경은 구별하며 모든 도구 호출에 사람 승인을 반복하지 않는다. 최초 지원 목록과 패키징·자동화 상세는 §8.6의 검증 대상으로 남긴다.

### 8.3 실제 도구 작업과 산출물

정보의 기본은 업무 진행과 역할별 실제 산출물이다. 전체 업무 완료 전에도 각 역할이 완료한 산출물의 정확한 버전을 다룰 수 있어야 한다. 현재 작성 중인 파일·부분 출력, 역할이 완료한 산출물, 사람이 검토하거나 실험에 사용한 버전은 구별하고 뒤의 작성으로 이전 기준을 덮어쓰지 않는다.

| 출발 대상 | 이어서 확인할 대상 |
| --- | --- |
| 업무 진행·역할 상태 | 실제 수행 중인 작업, 대기/실패 이유, 이미 완료한 범위와 역할별 입력·산출물. |
| 선택한 역할의 도구 작업 | 실제 입력·도구 결과·시점·출처·오류·재시도와 지원되는 도구의 화면/기록. 현재 화면·당시 저장된 화면·기록 재생·미확인을 구별한다. |
| PDF 등 실제 파일 | 열람·다운로드할 실물, 만든 역할·사용한 자료/앞선 산출물·입력 버전·출력 버전과 검토 근거. 생성 완료 메시지가 실물이나 품질 검사를 대신하지 않는다. |
| 다음 역할의 수행 | 실제 전달된 파일/산출물 버전과 그 역할의 입력·결과. 전달 성공, 적절한 활용의 근거와 개입으로 지지된 영향을 구별한다. |

작업공간은 실제 자료·파일·대안 비교를, 대화는 같은 대상에 대한 요청·확인을, 그래프는 관련 역할·도구·산출물·전달 관계를 이어 다룬다. 상세를 열고 돌아올 때 업무·실행·역할·버전·선택 범위를 유지한다. 특정 기본 모드, 동일한 패널 배치, 세 모드의 완전한 기능 복제나 모든 브라우저의 상시 실시간 표시를 이 원칙으로 확정하지 않는다.

사용자는 모든 역할의 원시 로그나 브라우저 창을 항상 펼쳐 두지 않고도 업무와 결과를 파악하고 필요한 상세에 접근할 수 있어야 한다. 관찰 가능한 도구 작업을 숨은 모델 추론 과정으로 표시하지 않는다. 사용자의 일반 브라우저 세션이나 다른 앱을 임의로 감시·공유하지 않으며 필요한 세션·자료 접근은 역할·권한 경계에 연결한다.

파일 열람·관찰·로그인·모드 전환은 그 자체로 사용자 대안이나 실행/운영 승인이 아니다. 자기 대안은 같은 역할·업무 상태의 실제 전체/부분 산출물이라는 §1·4의 원칙을 유지한다. 일부를 다뤄도 원본 전체 문맥으로 돌아가고, 작성한 범위 밖의 영향을 탐구·검증할 수 있어야 한다. 파일별 대안 작성·편집 방식은 별도로 설계한다.

새로고침·재접속·재인증 성공은 새 권한이나 새 실행을 자동 승인한 것이 아니다. 그렇다고 이미 허용된 범위의 재개를 금지하지도 않는다. 실제 재개 조건을 확인하며 인증 뒤 즉시 자동 재개 여부, 버튼·알림·재시도 간격/횟수는 후속 상세 정책이다. 프레임워크 밖에서 사용자가 환경을 재구성해야 복구되는 방식으로 넘기지 않는다.

이번 실행의 허용된 재시도·복구는 새로운 학습 지식이나 운영 환경 버전의 승격이 아니다. 도구·절차·권한 등 현행 구성을 바꾸는 후보가 필요하면 해당 변경의 검토·검증 경로에 연결한다. 미지원 기능을 자동 개발/설치하거나 구독 오류를 유료 API 자동 전환으로 처리하지 않는다.

### 8.5 DeepTwin 탐구·재실험·기록과의 연결

첫 사용부터 역할·도구·실행 경로·입출력·시점·오류·재시도·사람 개입·외부 행동 결과와 산출물 버전을 §4의 사건·계보에 연결한다. 비밀정보·자격증명·숨은 추론은 제외하고 가림·결손·접근 제한과 진단/재현 한계를 구별한다. 기록이 없거나 저장에 실패했는데 보존·완전 재현을 주장하지 않는다. 로그 추출·제작자 전달은 별도 선택 행위이며 도구 사용 동의가 자동 전송 동의가 되지 않는다.

원 수행과 실제 자기 대안의 차이를 탐구할 때 도구 선택·정보 출처·조회 결과·전달 누락·오류도 시스템 설명 가설의 근거가 될 수 있다. 모든 차이를 말투/프롬프트 문제로 단정하거나 모든 도구 오류에 철학 렌즈를 강제하지 않는다. 필요한 판단 차이의 경쟁 가설·렌즈 질문·실제 새 증거·조건부 변경과 기존 출처/접근 방화벽을 유지한다. 원본·대안·해석 기록을 서로 대체하지 않는다.

이전 업무 큐의 개선 실험에서는 보존된 도구 결과 재사용과 새 조회, 격리된 행동과 실제 외부 쓰기를 구별한다. 시점이 바뀐 자료를 동일 조건의 재현이라고 표시하지 않는다. 기존 외부 행동의 중복을 통제하고 근거가 부족하면 비교 가능 범위·실패·미확인을 남긴다. 부분 대안 밖의 영향도 검증하되 운영 승격은 정확히 검증한 변경 후보에 대한 사람의 최종 승인으로만 이어진다. 일반 오류 복구와 이 개선 순환의 상태·버전은 구별한다.

### 8.6 남은 상세 설계와 확인 범위

이 절의 책임·경험 원칙은 확인됐지만 구체적인 연결/실행 기술과 동작은 미검증이다. 아래는 후속 작업의 설계·시험 대상이며 확인된 역량을 선택 기능으로 축소하는 목록이 아니다.

- 최초 지원 도구·파일·OS와 패키징·설치/업데이트/회수, 지원하지 않는 기능의 처리. 모든 사이트·앱·파일 형식을 즉시 지원한다고 약속하지 않는다.
- 각 구독 경로에서 역할별 도구·권한·실제 파일·상태·중단/재개·기록을 연결하는 공식 통합과 비용 경로. 제공자 내장 수행 루프를 포함한 실제 제어 경계를 검사한다.
- 브라우저 세션의 격리/필요한 공유, 실제 화면·스냅샷·기록 접근과 접근권한, 파일 미리보기·다운로드·대안 편집·버전 처리.
- 도구별 안전한 재시도 조건·한도·자동 재개·부작용 확인·재실험 격리와 저장 실패 처리. 공통 원칙만으로 모든 도구의 복구 가능성을 단정하지 않는다.
- 문서에 적힌 연결을 실제 UI에서 따라가고, 역할의 브라우저 작업·PDF 실물과 후속 역할의 활용, 연결 부족·결과 미확인·복구 실패를 실제로 검증하는 수용 시험. 모의 로그·생성 메시지·문서 검토를 실행 증거로 대체하지 않는다.

[UI-13–15](../../ui/initial-ui-review-cases.md)는 이 보완을 문서에서 추적하는 사례다. 기존 UI-01–12와 함께 부분 대안·렌즈·이전 큐·사람 승격·세 모드·선택적 공유의 연결을 대조한다. 통합 문서에 대한 사용자 검토 뒤 승인된 범위의 다음 계획을 작성하며 이 기록으로 새 UI/엔진 구현을 시작하지 않는다.
