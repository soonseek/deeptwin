# DeepTwin Critic Evaluation B Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A의 원시 호출부 앞뒤에 출처가 고정된 입력, 책임별 판정 계약, 호출 전 기록과 오프라인 실행 검사를 연결한다.

**Architecture:** 모델 입력을 만드는 순수 계약 계층과 모델에게 보이지 않는 감사·실행 계층을 분리한다. 형식·참조 검사는 기계적으로 수행하되 의미 판단의 정확성은 별도 평가 책임으로 남긴다. 모델이 내놓은 판정, 검사기가 확인한 사실, 시험 자체의 유효성을 서로 다른 결과로 보존한다.

## 2. 렌즈가 실제로 들어가는 위치

네 책임 모두 동일하게 고정한 원자료·평가 기준·후보의 **기능**을 받는다. 기능에는 각 역할의 모델, 도구, 권한, 전체 산출물 형식·버전·접근, 전달과 제어 경로가 포함된다. 그래프 이름이나 설명문만 남기는 투영은 금지한다.

| 책임 | 추가로 받는 내용 | 받지 않는 내용 |
| --- | --- | --- |
| 검토 | 없음 | 생성자 렌즈·자기점수·다른 검토 총평 |
| 반례 탐구 | L-P050-01/L-P033-02의 출처 제한·적용/제외/기권 조건·질문·반대 예측·반박 조건 | 생성자의 렌즈 정체성, 숨은 정답 |
| 반례 타당성 | 정확한 반례 ID/버전·명제·성립 조건·출처 | 제안자의 렌즈 권위·자기평가 |
| 후보 대응 | **동일 반례**, 타당성 상태와 근거, 정확한 후보 버전 | 다른 후보의 성적·다른 크리틱의 전체 결론 |

첫 두 규칙은 이름표가 아니라 서로 다른 탐구를 수행한다. L-P050-01은 같은 ‘제작자’ 필드가 추정 공방과 확정 작가를 같은 의미로 뭉개는지 묻는다. L-P033-02는 전체 자료가 전달됐더라도 수신자가 이미 알려진 근거 대응을 다시 찾아야 하는지를 묻는다. 이미 적절한 의미·대응 정보가 있으면 변경하지 않는 결론도 유효하다. 특정 CSV나 노드 추가를 정답으로 강요하지 않는다.

규칙별 사용/제외/기권, 질문, 제시한 반례와 근거 연결을 남긴다. 기록 존재는 실제 규칙 기여나 오류 독립성의 증거가 아니다. source 문구·후보 기능에서 숨긴 정체성을 추론할 가능성까지 없앴다고 주장하지 않는다.

## 3. 판정의 세 층

1. **응답 계약 검사:** JSON·크기·닫힌 필드·ID/버전·출처 위치·상태 조합을 검사한다. 인용 위치가 존재한다고 그 인용이 주장을 지지한다고 판정하지 않는다.
2. **내용의 타당성 검사:** Q01의 독립 원자료와 고정 기준으로 실제 명제를 검사한다. 알려진 결함을 통과했는지, 정상 대안을 오거절했는지, 근거 부족을 정직하게 남겼는지는 여기서 판정한다. 현재 완료 출력은 항상 `semantic: not_checked`, `score: null`이며 의미 판정 통과가 아니다.
3. **시험 유효성 검사:** 접근 누출, 기록 실패, 잘못된 초기화, 제공자·판정기 장애는 시험 무효이며 에이전트 점수가 없다. B2에서는 transport/factory 오류·다른 model 보고를 `invalid`와 일반화한 원인으로 남기며 예외 본문은 저장하지 않는다. journal 장애는 기록 불가 오류로 전파하고 가짜 terminal을 만들지 않는다. 정상 대역에서 잘못된 JSON·참조·상태를 낸 경우는 `completed` + `output_contract: model_output_invalid`로 보존하며 인프라 장애로 지우지 않는다.

타당성이 미결인 반례로 후보의 확정 실패를 만들지 않는다. 반례를 전부 기각하거나 전부 타당하다고 해도 통과하지 않도록 정상·다른 유효안·결함·기각·미결 사례를 함께 둔다. 특히 중앙 50% 크롭이라는 규칙만으로 M01의 실제 단서가 잘렸다고 단정할 수 없다. 이는 사진과 단서 위치가 없는 Q01 자료의 한계다.

Q01은 **PDF/HTML 등을 생산할 설계 계약**을 검사한다. 실제 PDF·이미지·DOCX가 생성돼 렌더링까지 검증됐다고 기록하지 않는다. 이후 제품 수행 시험은 실제 원형 파일과 외부 도구 효과를 별도로 확인해야 한다.

## 4. 기록·실행의 불변 조건

- `freeze_call`과 호출 직전 `ModelSelection.for_request`/`ModelCatalog.validate_choice`로 현재 SQL 선택 버전·account binding을 재검증한다. 실제 provider refresh나 실계정 preflight는 하지 않는다. 기존 전송부 `_valid_selection`은 형태 검사에 불과하며 합성 카탈로그는 실계정 유효성 증거가 아니다.
- 불변 `FrozenCall` 10필드에 정확한 입력·canonical 스키마/manifest·모델 선택·지시 내용과 해시·코드 해시 snapshot·유한 예산을 고정한다. 별도 private SQLite journal의 reserve transaction이 commit되지 않으면 호출하지 않는다. 중복/한도·첫 종료 commit과 상태/events의 단일 읽기 snapshot을 검사한다. requested model/effort, 대역이 보고한 model, 확인 불가 `actual_effort: null`을 구별한다. runtime profile은 `declared_not_preflight_confirmed`다.
- caller가 통제한 `OfflineTransport`만 인스턴스별 직렬 실행하며 실제 backend 기본값은 없다. 각 `runtime_root / run / purpose / request`에 별도 0700 요청 경로를 만들고 journal을 다른 tree에 둔다. Task·정답·verifier도 실제 harness에서는 모델 경로 밖에 둬야 한다. 현재 타입·경로 검사는 우발적 사용 방지이며 적대적 Python/OS 격리나 실제 접근 감사 완료가 아니다.
- request ID 재사용·자동 재시도·재생은 금지한다. 활성 요청 취소는 먼저 commit한 뒤 신호를 보내고 quarantine한다. 취소 commit 실패는 원래 실행에도 audit fault를 전하며 공유 journal의 다른 ID에서 난 오류도 모든 활성 결과 적용을 막는다. 준비 검증 뒤 최종 gate는 동시 quarantine을 다시 확인한다. 모든 timeout 경로는 dispatch 전 만료와 worker 완료 후 poll까지 quarantine하며 늦은 응답은 종료 상태를 뒤집지 못한다. reserve/journal/시작/조회 실패는 가짜 terminal 없이 오류·로컬 차단·활성 등록 정리로 남긴다.
- 생성자는 자동 복구하지 않는다. 호출자가 이전 worker 부재를 확인한 후 `Ledger.recover()`를 명시적으로 호출해야 미완료를 `interrupted`로 남긴다. 늦은 worker는 bounded event만 남기고 원시 본문은 생략한다. 관측 쓰기 실패 시 event가 없을 수 있으며 완전한 감사나 원격 종료를 보장하지 않는다.
- 구독의 실제 토큰/금액이 제공되지 않으면 관측 불가다. 호출·시간·동시성 한도를 금액 상한으로 설명하지 않는다. 모델 대체·API 전환·예산 증액은 자동으로 하지 않는다.
- 원시 **최종 응답**과 공개 근거만 제한적으로 보존한다. 내부 사고과정·인증 정보·무관한 사용자 활동은 수집하지 않는다. 내보내기/제작자 전달은 선택 기능이며 자동 전송은 없다.

현재 완료 출력의 원문은 UTF-8 64,000 bytes까지 보존하고 SHA-256·byte 수를 남긴다. 초과 원문은 사유와 해시·byte 수만, 잘못된 Unicode는 사유와 해시/byte 수 `null`을 남기며 모두 출력 계약 오류로 기록한다. 취소·시간 초과·audit 오류에는 점수가 없다. 특히 `Ledger.begin`의 dispatch 전 만료는 `timed_out` + `{"transfer":"not_started"}`이므로 모든 실패 레코드에 literal `score: null`이 있다고 하지는 않는다.

## 5. 실제 시험 전에 반드시 닫아야 할 준비 조건

### 5.1 호출 중단은 현재 구현만으로 보장하지 않는다

코드 조사에서 A의 timeout은 `turn/start` 뒤부터 적용되며, 그 전에 버전 확인·계정·설정·skills preflight가 있다. `cancel_event`도 모든 preflight 호출 앞에 검사되는 것은 아니다. `CodexRPC.close()`에는 소유 프로세스 종료가 있지만 공용 모델이 외부 실행기에 그 수명주기를 제공하지 않는다.

따라서 B의 오프라인 실행기는 **로컬 적용 차단과 신규 호출 금지**를 검증한다. 늦게 돌아온 worker나 원격 사용량 종료까지 보장했다고 기록하지 않는다. 실제 호출을 연결하려면 전 구간 deadline/cancel 검사, 소유 RPC의 종료·확인, 시작/취소 경쟁을 다룬 좁은 어댑터 변경을 추가 검토하고 시험해야 한다. 이 준비가 끝나기 전 실제 모델 backend 활성화는 금지한다. A의 환경 제한·원계정 인증 위치·정확한 CLI 버전을 완화하는 해결은 허용하지 않는다.

### 5.2 Harbor는 설치·연결 상태가 아니다

이번 읽기 전용 조사에서 PATH와 프로젝트 가상환경에 `harbor` 실행 파일이 없었고 해당 가상환경의 `harbor` 배포 패키지도 확인되지 않았다. Docker 실행 파일은 있으나 daemon·이미지·실제 환경은 검사하지 않았다. 버전과 지원 adapter를 가정한 `task.toml`이나 가짜 Harbor 실행 명령을 만들지 않는다.

실제 평가 패키지의 준비 순서는 다음과 같다. 이는 아직 수행하지 않은 **별도 준비 게이트**이며 B 코드 단위 검사로 대체할 수 없다.

- [ ] 설치/채택 범위를 확인한 후 지원 버전을 고정하고 그 CLI의 help·공식 schema를 읽는다.
- [ ] Q01의 `task.toml`, 정확한 `instruction.md`, 명시적 allowlist의 `environment/`, `tests/test.sh`와 독립 증거 검사기를 구성한다. Task.md·정답·tests·solution·인증 정보를 agent image에 복사하지 않는다.
- [ ] Codex 구독의 host 인증을 유지하는 지원 harness 연결을 확인한다. HOME/CODEX_HOME 복사·통째 mount·API 자동 대체로 Docker 경계를 우회하지 않는다. 지원되지 않으면 지원 불가를 먼저 보고한다.
- [ ] 실제 Harbor 경로로 설정 parse, build/readiness, agent-visible 파일·네트워크·금지 접근, verifier 주입·권한·출력·reset을 감사한다.
- [ ] 정상·다른 유효안·오답·지름길·부수 변경·증거 유실 사례를 실제 verifier 명령으로 실행한다. 정상 완료의 reward와 무효 시험의 no-score를 구별한다.

### 5.3 의미 검사기와 C 승인

여러 호출을 잇는 실제 harness는 단순 ID 일치 외에 제안 반례의 원본 내용 해시, 타당성 응답의 입력/결과 해시, 대상 후보 버전을 함께 연결해야 한다. 검토된 prior record에서 선택한 동일 명제·조건·출처만 다음 호출에 전달한다. authored 반례는 모델 제안으로 가장하지 않고 고정 합성 자료의 출처와 해시를 따로 기록한다. 현재 B의 개별 호출 기록과 파서만으로 이 교차 호출 계보 검증까지 구현됐다고 하지 않는다. 동일 ID의 명제 교체·다른 후보의 판정 재사용·부모 기록 유실을 실제 harness 준비 검사에 포함한다.

의미 평가 입력은 정확한 원자료·기준·해당 응답으로 고정하고, 모델 출력 안의 자체 점수·“확인했다”는 선언은 정답으로 쓰지 않는다. 원자료 대조로 결정 가능한 항목을 먼저 검사하고, 남은 판단만 범위가 제한된 별도 판정자에게 맡긴다. 사람 검토와 모델 판정 중 어느 경로를 사용할지, 판정자 설정·불일치 처리·검사 버전을 C 전에 확정한다. 개발 fixture에 대한 합의는 새 사례의 효과나 동일 모델의 오류 독립성 보장이 아니다.

위 준비를 마친 뒤에만 실제 제공자·역할별 모델/추론·반복 수·판정 경로·시간·동시성·사용량/비용 한도를 사용자에게 묶어서 확인한다. 모델 이름이나 숫자를 임의로 승인값으로 채우지 않는다.

## 6. 완료 보고와 제품 정체성

B 완료 보고는 `입력 투영 / 파서 / 사전 기록 / 실행 상태 / 회귀`의 증거와 `의미 평가·실제 harness·실모델 시험`의 미완료를 함께 표시한다. 최종 보고나 capability 표시를 단위 테스트 개수로 승격하지 않는다.

최종 제품은 여전히 **멀티에이전트 관제 그래프 기반 LLMOps + 철학 렌즈 기반 DeepTwin**이다. Claude/Codex 구독 선택과 선택적 API, 에이전트별 모델 관리, 프레임워크 소유 도구·원형 산출물, 부분 대안에서 시작하는 후속 영향, 이전 업무 큐 재실행과 사람의 환경 버전 승인은 유지한다. B의 좁은 크리틱 시험을 제품 전체 기능이나 사용자 피드백 흡수 루프로 바꿔 부르지 않는다.

## 7. 계획 작성 시점의 검토 기록

root는 A의 B 인수 계약, DG-V01, Q01, 렌즈 정의·조합 계약과 실제 호출·선택 코드를 대조했다. 입력/파서/규칙 보존본은 B1, 선택/기록/로컬 실행 상태는 B2, 회귀·결과 보고는 B3로 연결했다. 실제 의미 verifier·교차 호출 계보·provider 수명주기·Harbor는 구현 계획 완성으로 오인하지 않도록 B4에 남겼다.

별도 읽기 전용 실행 경계 조사에서 timeout 시작 위치·형태만 확인하는 선택 검사·runtime 경로 재사용을 확인했다. `critic_b_contract_plan`이 B1 계획을 작성하고 B2의 인터페이스를 교차 검토했다. root는 모든 계획 코드를 읽고 기능 후보의 경로/권한 모순, 검토자의 무권한 수정, 자료 부족 변형의 간접 답 노출, 호출 전 준비 결과 재검증, 잘못된 Unicode 결과 분류를 수정했다. 이는 문서/구현 계획 검토이지 모델 크리틱의 자격 시험이 아니다.

문서 검사 결과: Python/JSON 코드 블록 10개의 구문 검사 통과, 연결 문서의 로컬 링크 32개 확인, 미완성 코드 표식 없음, `git diff --check` 통과. 기존 안전·업무 이해·API·UI 핵심 파일 7개의 내용 해시는 A 기준과 동일했다. 이 턴에 app 코드 작성·테스트 실행·모델 호출·패키지 설치·사용자 DB 변경·커밋·푸시는 하지 않았다.
