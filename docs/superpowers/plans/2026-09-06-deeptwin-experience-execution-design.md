# DeepTwin Experience and Execution Detailed Design Implementation Plan

> **역사적 계획 경계:** 이 계획은 초기 UI/실행 설계 이력이다. 현재 제품·배포·인증 권위는
> 헌법 3.0.1과 `specs/001-autonomous-release/`에 있으며, DeepTwin의 공식 제품 표면은 자체
> 호스팅 인스턴스의 브라우저 UI다. 네이티브 앱/런처 또는 최종사용자 CLI를 이 계획에서
> 추론하지 않는다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인된 통합 UI 원칙을 실제 화면 제작에 필요한 구체 조작과 독립 실행·도구·기록의 검증 계약으로 구체화하고, 화면 검토를 먼저 시작할 수 있는 후속 작업을 만든다.

**Architecture:** 화면 상세와 실행 계약을 독립적으로 검토할 두 작업 흐름으로 나눈다. 화면은 기존 UI 정본을 구체화하고, 실행 계약은 같은 역할·산출물·권한·버전·사건을 참조한다. 화면 시제품, 실제 제공자/도구 연결, DeepTwin 성장 효과의 세 증거를 분리하며 어느 하나로 나머지를 통과시키지 않는다.

**Tech Stack:** 이번 산출물은 Markdown 설계·검증 계약이다. UI 프레임워크, 배포 형식, 제공자 연결 구성요소, 오케스트레이터, 저장소와 버전은 아직 선택하지 않는다. 실제 코드 단계에서는 승인된 선택과 최신 공식 문서에 맞는 코드·실행 명령·테스트가 포함된 별도 기능 계획을 작성한다.

## 범위·사용자 확인·현재 상태

계획 ID: EXPERIENCE-EXECUTION-DESIGN-001 · 작성일: 2026-09-06 · 상태: Task 1과 Task 2의 시제품 제작·에이전트 동작 검사는 완료했으나 후속 사용자 스크린샷 검토에서 제품 정체성 불일치가 확인됐다. 그래프 기반 환경 비교, 실행 단계·이력별 다형식 산출물 관제가 UI와 코드 계획에서 축소됐으므로 기존안을 기반으로 다음 구현을 진행하지 않는다. 관제 환경 기반 LLMOps와 철학 렌즈 기반 DeepTwin의 연결을 먼저 재검토한다. 새 세부 설계와 실제 엔진·Task 3–6은 미실행.

사용자는 `f55566a`의 통합 UI 문서를 기준으로 다음 상세 설계 계획으로 넘어가는 질문에 “응”이라고 답했다. 이는 통합 원칙을 다음 설계의 기준으로 삼는 확인이다. 이후 별도 질문에서 첫 시제품의 A 기본 골격만 선택했다. 기본 모드, 대안 입력/자동화 조작, 구독 연결 기술·실행 권한을 일괄 선택한 것은 아니다.

이 계획은 **상세 설계 산출물을 만드는 작업 계획**이다. 완성 앱이나 전체 플랫폼의 코드 구현 계획으로 부르지 않는다. UI 시제품·실행 기반·성장 엔진은 독립 범위로 분해해 각각 검토된 설계와 실행 계획을 갖는다. 현재 단계에서 모든 하위 시스템의 구현 코드를 한 문서에 추정해 넣지 않는다. Spec Kit의 기능별 구현 목록과 경쟁하는 두 번째 목록도 만들지 않는다.

개발 내부 명령은 에이전트가 실행한다. 사용자는 DeepTwin 화면과 결과를 검토하며 CLI·MCP·개발 스킬을 직접 조립하지 않는다. 사용자에게 다시 업무 설명·평가 정답·자기 대안을 제출하게 하는 절차가 아니다. 이전 유튜브 업무 설명과 MANUAL-001은 피드백·효과 증거로 재사용하지 않는다.

이번 계획 작성은 코드·시제품 생성·모델 호출·구독 인증·설치·과금·게시·푸시를 수행하거나 허가하지 않는다. 아래 실행에도 외부 호출이 필요한 기술 검증은 별도 명시된 권한과 데이터/비용 범위가 먼저 필요하다. 문서 확인을 매 내부 단계의 추가 승인 버튼으로 구현하지 않는다.

## 진행 순서와 첫 화면

| 흐름 | 다음 산출물 | 시작 조건·다음 연결 |
| --- | --- | --- |
| 화면: Task 1 → Task 2 | 첫 진입부터 설계 비교·운영·대안·실험·승격까지의 구체 화면 검토안과 시제품 제작 인계 | 기존 UI 기준선으로 시작. 사용자에게 미합의 조작을 한 묶음으로 비교 제시하고, 관련 선택 확인 뒤 시제품 제작 범위를 계획 |
| 실행: Task 3 → Task 4 → Task 5 | 제공자/도구/저장·복구/로그·성장 경계의 계약과 실제 시험 요구 | Task 1과 병행 가능. 한 파일의 Task 3–5 작성은 순서대로 실행. 기술 확인 전 API 전용 구조를 확정하지 않음 |
| 통합: Task 6 | 사용자 의도 → 화면/계약 → 시험 → 후속 기능 작업의 연결 | 각 흐름의 결과를 대조. Task 6 전체 완료를 첫 시제품 검토의 선행 조건으로 만들지 않음 |

**최초의 실제 화면은 Task 2에서 범위를 확인한 직후의 UI 시제품 제작에서 본다.** 모든 실행 계약이나 엔진 완성을 기다리지 않는다. 이 문서 작성 자체는 화면 제작이 아니다. 화면은 처음부터 설계 카드만이 아니라 역할 산출물·부분 대안·실험·승격으로 이어지는 경로를 포함한다. 처음에는 명시된 표시용 상태로 이동을 확인하고, 실제 처리와 품질은 해당 엔진을 연결한 뒤 별도로 검증한다.

시각적 동반 도구는 이전 제안에 아직 동의가 없었다. 실제 시각 자료를 만들기 전 해당 방식과 범위를 확인하고 필요한 스킬을 사용한다. 엔진 미완성을 이유로 사용자의 화면 검토를 계속 문서로 대체하지 않으며, 화면 동의로 구독·도구·학습 효과를 승인받았다고 하지 않는다.
