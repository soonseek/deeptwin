# DeepTwin UI Structure Design Implementation Plan

> **역사적 계획 경계:** 이 계획은 초기 화면 설계 작업의 실행 기록이며 현재 제품 형식이나
> 배포 계약이 아니다. 헌법 3.0.1과 `specs/001-autonomous-release/`의 자체 호스팅 웹
> 프레임워크·공식 브라우저 UI 경계가 충돌하는 과거 가정을 대체한다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 승인된 제품 기준선을 바탕으로 초기 UI의 정보 구조, 세 모드의 연결, 업무·산출물·대안·실험·승인 이동 흐름을 검토 가능한 상세 설계로 만든다.

**Architecture:** 같은 업무 환경과 선택 대상을 공유하는 세 모드의 정보·이동 계약을 먼저 정하고, 전체 여정과 실패·보류 상태를 그 계약에 연결한다. 화면 설계 본문과 수용 기준별 검토 사례를 분리하되 하나의 설계 정본을 유지한다. 실제 제품 엔진과 표현용 화면 구조를 구분한다.

**Tech Stack:** Markdown 설계 문서와 텍스트 와이어프레임, 기존 로컬 파일 뷰어, 읽기 전용 문서 검사. UI 프레임워크·런타임·제공자 SDK·새 패키지를 이 계획으로 선택하거나 설치하지 않는다.

### 이번 실행의 작업 위치

사용자는 단계별 새 작성자와 명세/품질 검토 방식에 “네 추천대로”, 별도 작업 폴더 생성에 “응”이라고 답했다. 작성 위치는 `<repo>`, 브랜치는 `codex/ui-structure`, 시작 커밋은 `03e6bfa`다. 아래 새 설계 문서 두 개와 이 계획의 경로는 이 작업 폴더 아래의 같은 상대 경로로 적용한다. 원 작업 폴더의 기존 자료는 읽기 전용 근거로 참조하며, `docs/brainstorming-progress.md`만 현재 위치를 알리는 진행 기록으로 갱신한다.

원 작업 폴더의 미추적 `.gitignore` 및 자료를 함께 커밋하지 않기 위해 작업 폴더 제외 규칙은 로컬 `.git/info/exclude`에만 추가하고 제외 적용을 확인했다. 시작 작업 폴더에는 기준선·계획 문서만 있고 실행할 앱/테스트가 없다. 깨끗한 Git 상태와 공백 검사로 문서 기준 상태를 확인했으며 패키지 설치나 제품 시험 통과를 주장하지 않는다. 변경은 설계 문서 두 개만 명시해 단계별 로컬 커밋하고, 진행 기록과 계획의 작업 체크는 별도로 보존한다. 푸시하지 않는다.

사용자는 상위 제품 구조를 채택한 뒤 정리된 기준선 문서 검토에 “그래”라고 답했고, 초기 UI의 정보 구조와 화면 흐름을 구체화할 계획 작성으로 이행했다. 이 계획은 **UI 상세 설계 산출물**을 만드는 한정된 작업이다. 실행 가능한 앱을 만드는 코드 구현 계획이나 전체 플랫폼 완료 계획으로 보고하지 않는다. 코드 작업을 넣기 위해 가짜 테스트·하네스·예시 에이전트를 만들지 않는다. 실제 UI 구현에는 여기서 검토한 구체 화면 설계에 맞는 코드·테스트 계획이 필요하다.

제외: 제품 코드·웹 서버·새 목업 앱 제작, 이미지 생성, 모델 호출·인증/계정 조작, 새 콘텐츠 기획안과 사용자 대안 생성, MANUAL-001 재시도, 성능 점수·렌즈 효용 실험, 외부 공유·푸시. 기존에 배제된 유튜브 업무 설명은 설계의 개인화·평가 정답으로 재사용하지 않는다. 이전에 제공받은 목업은 관계 참고 자료이지 배치·문구 전체가 승인된 명세가 아니다.

사용자가 이번 작업의 결과로 보는 것은 **공통 화면 골격 두 안, 세 모드에서 같은 대상이 이어지는 구조, 전체 여정의 이동도, 주요 상태의 표시 위치**다. 새로운 콘텐츠 산출물을 평가하거나 자신의 대안을 작성할 필요는 없다. 실제 클릭 가능한 UI는 이 설계 검토와 해당 제작 계획 뒤에 만든다.
