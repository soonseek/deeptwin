## 병행과 검토 방식

Task 1은 루트가 준비한다. Task 2의 원전 행들은 서로 독립된 읽기·분석 단위이므로 사용 가능한 작업 슬롯 안에서 나눌 수 있다. 공유 파일에는 루트만 병합하고, 각 담당자는 근거와 해석 쟁점을 반환한다. Task 3은 근거가 확인된 항목부터 시작할 수 있다. 한 원전의 접근 실패가 무관한 원전 검토까지 중단시키지는 않는다.

Task 4는 구체 정의 후보를 사용해 작성하며 Task 5는 원전 해석과 계약을 별도 관점에서 검토한다. Task 6에서 전체 묶음을 사용자에게 한 번에 제시한다. 내부 필드마다 승인 질문을 만들지 않는다. 저작/장절 하나의 찾기·읽기·해석 대조·기록을 각각 작은 실행 단위로 나누고, 작업 시간이 길어지면 근거를 유지한 채 다음 단위로 넘긴다.

## 로컬 변경과 실행 인계

현재 계획 작성으로 운영 코드·사용자 DB·모델 호출은 변경하지 않았다. 실제 실행에서도 변경 대상은 위 문서 경로로 한정한다. 기존 변경을 한꺼번에 스테이징하거나 `git add .`를 사용하지 않는다. 로컬 버전 기록을 수행할 권한이 확인된 경우에만 해당 문서의 diff를 검토해 범위가 분명한 묶음으로 기록하며, 푸시는 별도 요청 없이 하지 않는다.

실행 방식은 새 작업별 에이전트와 단계별 검토를 사용하는 **Subagent-Driven**을 추천한다. 같은 대화에서 묶음별로 수행하는 **Inline Execution**도 가능하다. 어느 방식을 선택해도 위 출처·정의·독립 검토·사용자 검토 순서와 경계는 같으며, 사용자에게 새 Codex 작업을 만들거나 CLI를 쓰도록 요구하지 않는다.
