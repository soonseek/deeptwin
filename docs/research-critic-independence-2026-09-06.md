# 동일 모델 크리틱의 독립성: 근거와 설계 경계

조사일: 2026-09-06. 상태: 외부 근거 검토 및 설계 제안이며, DeepTwin 구현·성능 검증 결과나 사용자 승인 완료 사양이 아니다. 대상은 오픈소스를 설치할 최종 사용자다. Claude 또는 Codex 구독 하나만으로도 핵심 실행 경로가 성립해야 한다는 요구를 유지한다. 계정 변경·모델 호출·유료 API 사용은 수행하지 않았다.

## 결론

동일 모델이라는 이유만으로 크리틱을 무효로 취급할 근거는 없다. 검증 질문의 입력 문맥을 분리한 동일 모델 검증이 실제 환각을 줄인 연구가 있다. 그러나 이 결과는 모든 업무에서 생성자와 평가자의 판단 오류가 통계적으로 독립이라는 보증은 아니다. 두 공급자를 사용하거나 철학 렌즈·역할명·프롬프트·난수를 바꾸는 것 역시 그 보증을 자동으로 만들지 않는다.

요구를 낮추는 대신 보증 대상을 분리해야 한다. 프레임워크는 정보 접근·판정 절차·승격 권한의 격리를 기술적으로 강제하고, 업무별로 크리틱의 오류 검출 성능을 별도로 검증하며, 충분한 검증 근거가 없으면 자동 통과하지 않도록 설계할 수 있다. 범용 자연어 판단에 대한 보편적 오류 독립성은 현재 확인한 근거로 보증할 수 없다.

## 직접 확인한 1차 근거

1. **Chain-of-Verification, ACL Findings 2024.** 같은 LLM이 초안·검증 질문·검증 답변·수정을 수행한다. Factored 방식은 질문별 호출에서 원래 답변과 다른 검증 답변을 제외하며, 초안의 환각을 그대로 반복하는 영향을 줄인다. 연구의 여러 사실 질의·장문 생성 과제에서 개선을 보였다. 이는 동일 모델 검증의 유용성을 지지하지만, 모든 오류의 독립성이나 제거를 증명하지 않는다. 검증 질문을 생성하는 단계는 초안을 보므로 완전히 초안과 무관한 평가 설계도 아니다. [논문 §3.3 및 실험](https://aclanthology.org/2024.findings-acl.212.pdf)

2. **Large Language Models Cannot Self-Correct Reasoning Yet, ICLR 2024.** 당시 모델과 추론 벤치마크에서 외부 피드백 없는 내재적 자기수정의 실패·성능 악화를 관찰했고, 동일 호출량의 대조군과 비교할 필요를 제기했다. 제목을 현재의 모든 모델·모든 작업에 대한 불가능성 정리로 읽으면 안 된다. 이 연구가 뒷받침하는 주장은 단순 재질문·토론만으로 개선을 전제하면 안 된다는 것이다. [논문 §1–3](https://proceedings.iclr.cc/paper_files/paper/2024/file/8b4add8b0aa8749d80a34ca5d941c355-Paper-Conference.pdf)

3. **CRITIC, ICLR 2024.** 검색·코드 실행 등의 도구 피드백을 활용해 같은 모델의 출력을 검증·수정하는 방법이 자유형 질의응답·수학 프로그램·독성 감소 과제에서 개선을 보였다. 다른 과제·모델로의 일반화는 미확정이며 외부 도구 자체에도 편향이 있을 수 있다고 명시한다. 따라서 다른 LLM 공급자를 의무화하지 않고도 모델의 내재 지식과 다른 검증 경로를 만들 수 있다. 도구 피드백을 곧 무오류 정답으로 취급해서는 안 된다. [논문 및 부록 A–B](https://arxiv.org/html/2305.11738v4)

4. **Lean 공식 검증 문서.** 정형화된 명제는 생성 도구와 분리된 커널·외부 검사기로 증명을 검사할 수 있다. 다만 명제 자체가 사용자의 뜻을 제대로 나타내는지, 공리·검사기·샌드박스가 타당한지에 대한 가정은 남는다. 이는 일반적인 “좋은 업무 설계인가”와 기계적으로 정의된 제약의 보증 수준을 구분해야 함을 보여준다. Lean 도입을 확정하는 제안은 아니다. [Validating a Lean Proof](https://lean-lang.org/doc/reference/latest/ValidatingProofs/)

## '독립성'에서 구분할 것

다음은 위 연구를 제품에 적용하기 위한 통계·설계 해석이다.

- **정보·절차적 독립성:** 생성자의 대화 기록, 설득 문구, 자기평가, 후보 순위, 다른 크리틱의 판정을 독립 평가 전 읽을 수 없도록 한다. 이는 접근 제어·입력 계약·감사 로그로 시험할 수 있다. 프롬프트에 “독립적으로 판단하라”라고 적는 것만으로 충족되지 않는다.
- **샘플링 독립성:** 고정 입력에서 독립 난수를 사용한 별도 호출이라는 수학적 조건은 모델 가중치가 같아도 가능하다. 이것과 다양한 업무에서 정답성 오류가 함께 발생하지 않는다는 주장은 다르다. 공급자의 실제 난수·숨은 상태 동작을 프레임워크가 확인할 수 없는 경우도 있다.
- **판단 오류의 통계적 독립성:** 무엇을 오류로 정의하고 어떤 업무 분포·조건에서 측정하는지 먼저 고정해야 한다. 쉬운/어려운 업무를 섞거나, 평가자가 생성 결과를 입력받는 구조에서 호출이 분리됐다는 사실만으로 오류 독립성을 추론할 수 없다.
- **검증 후 허용 가능한 잔여 위험:** 실제 제품의 핵심 지표는 잘못된 후보의 통과율, 결함 유형별 검출률, 정상 후보 오거절률, 보류율, 판정 안정성이다. 일치율이 높다는 사실만으로 신뢰도를 선언하지 않는다. 유한한 테스트에서 유의한 상관을 발견하지 못했다고 모든 미래 과제에서 독립이라고 증명한 것은 아니다.

## DeepTwin에 제안하는 검증 프로토콜

아래는 기존 논문을 그대로 인용한 명세가 아니라, 위 근거와 사용자 요구를 연결한 신규 설계 제안이다.

1. **후보를 보기 전에 평가 기준 봉인.** 승인된 업무 목표·원자료·정책으로 평가 기준과 위험·실패 조건을 먼저 만든다. 생성자가 기준을 임의로 바꾸지 못하게 버전과 해시를 고정한다. 초안에 드러나지 않은 요구 누락도 검사한다.
2. **블라인드 재구성 후 후보 대조.** 크리틱은 처음에 초안을 보지 않고 원자료에서 핵심 제약·필수 증거·가능한 반례를 재구성한다. 이를 봉인한 뒤 익명화된 후보를 받아 비교한다. 후보 의존 검증 질문은 별도 표시하고 유도된 답을 질문 속에 넣지 않는다. 원자료·정책 접근은 유지하되 생성자의 요약만 검증의 원천으로 삼지 않는다.
3. **상이한 검증 경로.** 계산·스키마·권한·의존성 같은 항목은 가능한 경우 결정적 검사로, 사실 주장은 원문 대조·별도 검색으로, 실행 가능성은 안전한 재현·시뮬레이션으로 확인한다. LLM 해석이 필요한 결론에는 증거와 미확인 항목을 남긴다. 외부 도구는 사용자가 승인한 권한과 비용 범위 안에서만 쓴다.
4. **봉인된 병렬 판정, 이후 반증 교환.** 각 크리틱의 첫 판정·근거를 다른 크리틱과 공유하지 않은 채 저장한 뒤 불일치를 조정한다. 결론은 단순 다수결·최고 점수보다 증거와 하드 제약을 따른다. 렌즈 다양성은 질문·반례 생성에 활용할 수 있으나 독립성 인증이나 진실 판정 권한이 아니다.
5. **크리틱 자체를 시험.** 사람이 검토한 정답·오답, 실제 과거 실패, 경계 사례와 숨겨진 결함 주입 사례를 봉인 세트로 둔다. 생성자와 크리틱이 테스트 정답을 보지 못하게 한다. 제약 누락·틀린 계산·가짜 출처·위장된 승인·설득적인 오답·이름/순서 변경 등을 포함하고, 정상 후보도 함께 넣어 무조건 반대하는 평가자를 막는다. 이 세트의 결함 분포가 실제 업무를 대표하는지도 검토한다.
6. **업무별 측정·보류·승격.** 단순 자기평가/문맥 분리/증거 검증 방식의 비교에서 호출량·데이터·모델 조건을 기록한다. 오답 통과율 등 지표와 불확실성을 업무군·결함 유형별로 보고한다. 기준 미달, 증거 부족, 분포 변화에서는 자동 통과를 금지하고 추가 증거·새 검증 경로·사람 검토로 전환한다. 모델·평가 기준·도구 변경 시 재검증한다. 최종 업무 환경 버전 승격은 기존 사용자 승인 절차를 유지한다.

검증 기준의 숫자, 최소 사례 수, 불확실성 산정법, 업무별 자동 통과 허용 범위는 별도 승인 대상이다. 원자료·입력 마스킹 목록·봉인 시각·판정/증거·비교 결과·실제 누락 오류·모델/런타임 버전은 감사 가능하게 남기되, 비밀 인증정보나 접근할 수 없는 내부 추론 기록을 요구하지 않는다.

## 권장 제품 계약 문구

> 최종 사용자가 Claude 또는 Codex의 단일 구독·동일 모델만 사용해도, DeepTwin은 생성자와 분리된 증거 기반 크리틱 프로토콜을 제공해야 한다. 정보·절차·승격 권한의 격리를 강제하고, 업무별 봉인 검증으로 크리틱의 오류 검출 성능을 확인하며, 근거 또는 성능 기준을 충족하지 못한 판단을 자동 승인하지 않는다. 모델 다양성은 선택적 보강책이지 필수 전제나 독립성 보증이 아니다. 모든 미래 자연어 업무의 판단 오류가 통계적으로 독립이라는 미검증 주장은 하지 않는다.
