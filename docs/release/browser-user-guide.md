# DeepTwin 브라우저 사용 안내 (개발 미리보기)

작성일: 2026-09-23 · 대상: 인스턴스 소유자(일반 사용자) · 상태: **초안, 릴리스 적격 아님**

DeepTwin의 공식 제품 화면은 **브라우저 UI 하나**다. 네이티브 앱, 데스크톱 래퍼, 사용자용
명령줄(CLI) 사용법은 없으며 이 안내도 그런 경로를 설명하지 않는다. 인스턴스를 설치·배포하는
일은 배포 운영자의 몫이며 [운영자 배포·백업 안내](operator-deployment-backup-guide.md)에서
따로 다룬다.

이 문서는 2026-09-23 현재 저장소의 `app/static/` 화면과
`specs/001-autonomous-release/evidence/`의 근거가 보여 주는 기능만 적는다. 각 화면 상단의
"개발 미리보기" 표시가 말하듯 여러 기능이 아직 구현 중이다. 아래 "아직 없는 기능"을 먼저
확인하기를 권한다.

## 1. 화면 구성 한눈에 보기

| 화면 | 파일 | 하는 일 |
| --- | --- | --- |
| 시작 | `start.html` (인스턴스 주소의 `/`) | 최초 소유자 설정 또는 소유자 로그인 |
| 업무 | `work.html` | 맡길 일 설명 저장, 원본 자료 올리기, 업무별 기록 내보내기 |
| 기록 | `records.html` | 사건 기록 보기, 내보내기 위치 안내, 백업·보존 상태 확인 |
| 실행 관제 | `observe.html` | 이미 기록된 실행 보기, 산출물 보기, 내 버전 만들기, 차이 관측 |

모든 화면은 같은 인스턴스 주소(같은 출처)에서만 동작한다. 다른 주소에서 열면
"이 화면은 이 배포의 주소에서만 사용할 수 있습니다"라는 안내가 나온다.

## 2. 시작 화면: 최초 소유자 설정과 로그인

인스턴스 주소를 열면 시작 화면이 서버의 공개 상태(`/health`)를 확인하고 두 형태 중 하나를
보여 준다.

**최초 소유자 설정** (아직 소유자가 없을 때)

1. 배포 운영자가 배포 준비 과정에서 받은 **일회용 capability**(43자 base64url 값)를 직접
   입력한다. 이 값은 주소(URL)에 넣지 않고, 기록에도 남지 않는다.
2. 소유자 이름(앞뒤 공백 없이)과 **15자 이상**의 비밀번호를 정한다.
3. "최초 소유자 설정"을 누르면 세션이 만들어지고 업무 화면으로 이동한다.

capability가 만료되었거나 시도 횟수를 다 쓴 경우, 또는 설정이 중간에 끊긴 경우 화면이 그
사실을 알려 준다. 이런 상태는 브라우저에서 복구할 수 없으며, 배포 운영자가 새 capability로
인스턴스를 다시 준비하거나 복구 절차를 진행해야 한다.

**소유자 로그인** (소유자가 이미 있을 때)

소유자 이름과 비밀번호를 입력한다. 시도가 너무 많으면 잠시 후 다시 시도하라는 안내가 나온다.
성공하면 업무 화면으로 이동한다.

capability와 비밀번호는 이 인스턴스에만 전송되며 제작자나 다른 곳으로 보내지 않는다.

## 3. 업무 화면 (`work.html`)

### 3.1 맡길 일 설명하기

"어떤 일을 맡기고 싶으세요?" 입력란에 맡길 일을 문장으로 적고 **이 인스턴스에 저장**을
누른다.

- 설명은 최대 20,000자(UTF-8 65,536바이트)까지 저장된다.
- 저장할 때마다 **수정본**이 하나씩 늘어나며 이전 수정본은 덮어쓰지 않는다.
- 아직 저장하지 않은 입력은 **이 브라우저에만** 임시 보관된다. 다른 기기나 인스턴스에는 없다.
- 다른 탭이나 기기에서 같은 업무가 먼저 수정되면 충돌을 알려 준다. 이때 "저장본 다시 열기"로
  최신 내용을 받거나, 현재 입력을 최신 수정본 위에 저장하도록 선택할 수 있다. 조용히 덮어쓰는
  일은 없다.

### 3.2 원본 자료 올리기

"자료 추가"로 파일을 고른다. 설명 없이 자료만 저장할 수도 있다.

- 한도: 파일당 10 MiB, 업무당 20개, 합계 50 MiB.
- 파일 이름에 경로 문자나 제어 문자가 있으면 받지 않는다.
- 전송 중에는 "전송 중지"로 멈출 수 있다. 다만 전송 중지가 곧 저장 취소를 뜻하지는 않으므로,
  화면이 알려 주는 저장 상태를 확인한다.
- 저장된 원본은 목록에 "원본 보관됨"으로 표시되고 다시 내려받을 수 있다.
- **원본 저장은 내용 읽기가 아니다.** 현재 자료의 내용을 읽거나 형식을 검증하거나 이해하는
  기능은 없다.

### 3.3 업무별 기록 내보내기 (선택 사항)

업무 화면 아래쪽 "기록 내보내기"에서 저장된 업무 하나의 기록을 파일 묶음으로 만들 수 있다.
내보내지 않아도 작업은 끝까지 진행된다.

1. **범주 고르기**: 작업 설명 원문, 개정 기록, 첨부 자료 목록 등 정해진 범주 중에서 고른다.
   원문을 그대로 넣을지는 별도 체크박스이며 **기본값은 꺼짐**(메타데이터만)이다.
2. **포함될 내용 미리보기**: 실제로 묶일 항목과 각 항목의 포함 방식·크기, 빠지는 범주와 그
   이유가 표시된다. 예를 들어 이 서버가 아직 모으지 않는 범주(모델 최종 응답, 도구 관측,
   내 버전, 평가 근거)는 "이 서버가 아직 모으지 않음"으로 표시된다. 미리보기의 SHA-256도
   함께 보인다.
3. **명시 동의**: "위 미리보기 그대로 내보내는 것에 동의합니다" 상자를 직접 체크해야 한다.
   동의는 방금 본 미리보기에 묶인다. 미리보기 이후 업무가 바뀌면 거절되고 다시 미리보기를
   요구한다.
4. **내려받기**: 묶음이 만들어지면 크기, 항목 수, SHA-256과 함께 같은 출처의 다운로드 링크가
   나온다. 묶음은 어디에도 자동으로 전송되지 않는다.

## 4. 기록 화면 (`records.html`)

업무 화면과 실행 관제 화면에서 링크로 들어온다. 다섯 영역으로 나뉜다.

- **기록**: 이 인스턴스의 공개 사건 목록이다. 각 줄에는 시각, 사건 종류, 결과, 오류 코드,
  관련 기록 수만 보이고 개인 근거 내용은 보이지 않는다. "다음 기록 보기"로 이어서 읽는다.
  보존 기간 등으로 빠진 구간은 빠진 구간이라고 알려 주며 사건을 지어내 채우지 않는다.
- **내보내기**: 내보내기는 업무마다 업무 화면에서 한다는 안내와 링크만 있다.
- **백업**: 이 서버에는 **백업 워커가 아직 연결되어 있지 않다**는 사실을 알려 준다. 그래서
  이 화면에서는 백업을 만들거나 복원할 수 없고, 백업이 있다고 표시하지도 않는다. 같은 배포의
  키로 만든 백업은 그 키 볼륨을 잃으면 복구할 수 없고, 다른 곳에서 복원하려면 따로 보관한
  복구 키가 필요하다는 설명이 함께 나온다.
- **보존과 삭제**: 자동 삭제는 없으며 기록과 원본은 명시적으로 지우기 전까지 보존된다. 삭제는
  미리보기와 승인이 필요한 기능이지만 **삭제 화면은 아직 없다**.
- **계정과 세션**: 지금 비밀번호를 한 번 더 입력하고 새 비밀번호(15자 이상, 확인 입력 포함)를
  정해 **비밀번호를 바꿀** 수 있다. 바꾸면 이전 비밀번호로 열린 모든 세션(다른 브라우저 포함)이
  끝나고, 지금 브라우저는 새 세션으로 이어진다. 입력한 비밀번호는 시도 직후 칸에서 지워지고
  어디에도 저장되지 않는다. **다른 세션 모두 끝내기**는 지금 브라우저만 남기고 나머지 세션을
  끝내며 몇 개를 끝냈는지 알려 준다.

## 5. 실행 관제 화면 (`observe.html`)

이 화면은 **이미 기록된 실행**을 살펴보는 곳이다. 실행을 새로 시작하는 화면은 아직 없다.

### 5.1 실행 목록과 실행 상태

- "관제할 실행 선택"에서 기록된 실행을 고른다. 자동으로 선택되는 실행은 없다.
  "실행 목록 다시 읽기"로 목록을 새로 받는다.
- 실행을 고르면 서버가 기록한 사실에서 나온 상태가 표시된다. 노드별 수행과 지난 시도가
  별도 행으로 남으며, 최신 산출물을 과거 시도에 붙이지 않는다.
- 실행 상태에 따라 "이어서 진행", "새 dispatch 중단", "복구 시도" 버튼이 나타날 수 있다.
  명령이 현재 상태와 맞지 않으면 거절하고 다시 읽은 최신 상태를 보여 준다.

### 5.2 산출물 보기

선택한 실행의 산출물 목록에서 "미리보기" 또는 "원본 내려받기"를 고른다.

- 텍스트·JSON은 텍스트로, 이미지는 이미지로 미리 본다. 미리보기가 잘리면 잘렸다고 알려 준다.
- PDF·DOCX 같은 형식은 격리된 문서 변환 워커가 연결되어야 미리볼 수 있다. 현재는 이를
  안내하고 원본 내려받기만 제공한다.

### 5.3 내 버전 편집

텍스트·Markdown·JSON 또는 CSV 산출물에서 **내 버전 편집**을 누르면 원본의 복사본을 그 자리에서
고칠 수 있다. 원본은 그대로 남는다. 이유나 지시를 적지 않아도 된다.

- 텍스트는 입력란에서, 표(CSV)는 칸 단위로 고치며 "행 추가"로 행을 늘린다.
- 입력을 멈추고 약 0.8초가 지나면 **자동 저장**되어 새 수정본이 된다.
- 세 가지 보기를 오갈 수 있다.
  - **원본**: 기록된 원본을 읽기 전용으로 보여 준다.
  - **내 버전**: 지금 편집 중인 내용이다.
  - **차이**: 저장된 수정본과 원본 사이에서 관측된 형식상 차이(바뀐 줄·칸 위치)를 보여 준다.
- 다른 탭이 먼저 저장했다면 충돌로 알려 주고 지금 화면의 내용은 그대로 둔다. "최신 수정본
  불러오기" 또는 "지금 내용을 새 초안으로 저장" 중에서 고른다.
- 한 화면에서 편집할 수 있는 크기는 약 256 KiB까지다.
- **분석용으로 고정**을 누르면 저장 후 그 수정본을 고정한다. 기본적으로 바꾼 줄·칸만 내 근거로
  기록되고 나머지는 "검토하지 않은 영역"으로 남는다. "전체를 검토했습니다" 상자(기본 꺼짐)를
  체크했을 때만 전체를 내 버전으로 기록한다. 원본과 같은 내용은 고정할 수 없다.

### 5.4 대안 파일 올리기

산출물 옆의 **대안 파일 올리기**로 원본을 고친 내 파일(최대 4 MiB)을 올릴 수 있다.

- 원본 형식에 맞는 방식으로 고친 부분을 지정한다.
  - PDF: 쪽 번호와 쪽 안의 영역(x·y·너비·높이, %)
  - 이미지: 영역(%)
  - JSON: JSON 위치(예: `/items/0/title`)
  - 오디오·비디오: 시작·끝 시각(초)
- 부분 선택을 지원하지 않는 형식은 원본 전체를 검토했을 때만 올릴 수 있다. 텍스트·표는 전체로만
  올리며, 줄·칸 단위 기록은 "내 버전 편집"을 쓴다.
- 지정한 영역은 원본 위의 위치로만 기록된다. DeepTwin은 원본과 내 파일 사이의 의미 정렬을
  계산하지 않으므로 정렬은 항상 **"미정"(`unresolved`)** 으로 남는다.

### 5.5 차이와 설명

내 버전을 고정하거나 대안 파일을 올리면 **차이와 설명** 영역이 자동으로 열린다.

- 원본과 내 버전 사이의 **관측된 차이**와, 근거 범위(바꾼 곳 수 또는 전체) 옆의 검토하지 않은
  영역을 보여 준다.
- 경쟁하는 설명(시스템 결손, 새로운 조건부 판단, 일회성 예외, 대안 쪽 오류, 일반화할 지식 없음)은
  모두 **"검토되지 않음"** 으로 표시된다. 설명을 만들어 낼 생성기가 아직 연결되어 있지 않기
  때문이다.
- 질문을 하지 않는 이유와, 변경 후보가 없는 이유가 적힌다. 이 영역에는 **입력칸이 없으며
  아무것도 묻지 않는다.** 답하지 않아도 작업은 계속된다.
- 영향 범위는 "따로 조사"로 남는다.

## 6. 아직 없는 기능

아래 기능은 현재 브라우저 화면에 없거나 동작하지 않는다. 있는 것처럼 기대하지 않기를 바란다.

- 업무 화면에서 **실행을 시작**하는 기능 (실행 관제 화면은 이미 기록된 실행만 보여 준다)
- **마이크 음성 입력**
- 올린 자료의 **내용 읽기**와 모델 기반 **업무 이해·환경 설계 생성**
- 모델이나 도구 제공자 **연결 화면**
- 경쟁하는 설명의 실제 생성, 질문(탐구), 변경 후보
- 이 화면에서 **백업 만들기·복원**, 보존 항목 **삭제**
- PDF·DOCX 미리보기 (문서 변환 워커 미연결)
