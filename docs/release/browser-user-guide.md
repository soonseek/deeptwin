# DeepTwin 브라우저 사용 안내 (개발 미리보기)

작성일: 2026-09-23 · 갱신: 2026-09-25 · 대상: 인스턴스 소유자(일반 사용자) · 상태: **초안, 릴리스
적격 아님**

DeepTwin의 공식 제품 화면은 **브라우저 UI 하나**다. 네이티브 앱, 데스크톱 래퍼, 사용자용
명령줄(CLI) 사용법은 없으며 이 안내도 그런 경로를 설명하지 않는다. 인스턴스를 설치·배포·복구·
업데이트하는 일은 배포 운영자의 몫이며 [운영자 배포·백업 안내](operator-deployment-backup-guide.md)에서
따로 다룬다.

이 문서는 2026-09-25 현재 저장소의 `app/static/` 화면(지원 서버가 내주는 닫힌 목록
`app/api/assets.py`)과 `specs/001-autonomous-release/evidence/`의 근거가 보여 주는 기능만 적는다.
많은 기능이 아직 구현 중이다. 2026-09-26부터 화면에는 "개발 미리보기" 표시가 없고, 아직 안 되는 일은
해당 칸에 한 문장으로 적는다(예: "마이크 입력은 아직 지원하지 않습니다"). 아래 "7. 아직 없는
기능"을 먼저 확인하기를 권한다. 여기 적힌 브라우저 동작의 근거는 모두 스크립트로 움직인 시험
행위자의 합성 근거이며, 실사용자 검증 기록은 아직 없다.

## 1. 화면 구성 한눈에 보기

| 화면 | 파일 | 하는 일 |
| --- | --- | --- |
| 시작 | `start.html` (인스턴스 주소의 `/`) | 최초 소유자 설정, 소유자 로그인, 소유자 복구 뒤 다시 설정 |
| 업무 | `work.html` | 맡길 일 설명 저장, 원본 자료 올리기·읽기, 작업 모델, 대화, 설계 후보 비교, 업무별 내보내기, 원본 삭제 |
| 실행 | `observe.html` | 이미 기록된 실행 보기, 승인할 일 결정, 작업 그래프, 산출물 보기, 과정 피드백(표시·메모), 내 버전·대안 파일, 차이 살펴보기 |
| 버전·실험 | `versions.html` | 운영 버전·후보·성장 실험·비교 라운드·도구 효과 경계 |
| 기록 | `records.html` | 사건 기록, 모든 실행의 산출물 색인, 내보내기 안내 |
| 설정 | `settings.html` | 계정과 세션, 모델 연결(Claude 연결, API 자격증명과 전송 검증), 실행 한도, 백업·보존, 업데이트·복구, 확장, 브라우저 접근 허가 |

시작 화면을 뺀 모든 화면의 왼쪽에 같은 메뉴(업무 · 실행 · 버전·실험 · 기록 · 설정)가 있고, 지금 화면이
표시된다. 너비 1024px 미만에서는 메뉴가 위쪽 **메뉴** 단추 뒤로 접힌다(Esc로 닫으면 단추로 돌아간다).
메뉴 위 맥락 줄에는 화면이 실제로 아는 것만 나온다(예: 고른 실행, 저장한 업무). 시작 화면 머리글에는
**설정** 링크가 있다. 모든 화면은 같은 인스턴스 주소(같은 출처)에서만 동작하며,
다른 주소에서 열면 "이 화면은 이 배포의 주소에서만 사용할 수 있습니다"(또는 "…열 수 있습니다")라는
안내가 나온다. 로그인하지 않은 채 다른 화면을 열면 시작 화면에서 로그인하라는 안내가 나온다.

## 2. 시작 화면 (`start.html`)

인스턴스 주소를 열면 시작 화면이 서버의 공개 상태(`/health`)를 확인하고 다음 중 하나를 보여 준다.

**최초 소유자 설정** (아직 소유자가 없을 때)

1. 배포 운영자가 배포 준비 과정에서 받은 **일회용 capability**(43자 base64url 값)를 직접
   입력한다. 이 값은 주소(URL)에 넣지 않고 기록에도 남지 않는다.
2. 소유자 이름(앞뒤 공백 없이, UTF-8 128바이트 이하)과 **15자 이상**의 비밀번호를 정한다.
3. "최초 소유자 설정"을 누르면 세션이 만들어지고 업무 화면으로 이동한다.

capability가 만료되었거나 시도 횟수를 다 쓴 경우, 또는 설정이 중간에 끊긴 경우 화면이 그 사실을
알려 준다. 이런 상태는 브라우저에서 고칠 수 없으며, 배포 운영자가 새 capability로 인스턴스를 다시
준비하거나 복구 절차를 진행해야 한다.

**소유자 로그인** (소유자가 이미 있을 때)

소유자 이름과 비밀번호를 입력한다. 시도가 너무 많으면 잠시 후 다시 시도하라는 안내가 나온다.
성공하면 업무 화면으로 이동한다.

**소유자 복구 뒤 다시 설정**

배포 운영자가 소유자 복구를 마친 인스턴스에서는 시작 화면이 "소유자 다시 설정" 형태로 바뀐다.
화면은 복구로 끝난 것을 알려 준다: 복구 전의 세션·비밀번호·capability와 서비스 클라이언트는 모두
끝났고, 기다리던 승인은 만료되었으며, 열려 있던 실행 동의는 철회되었다. 운영자가 복구 때 새로 만든
일회용 capability와 새 비밀번호로 다시 설정하면 되고, 이전 기록은 그대로 남는다. 운영자의 복구
정리가 끝나지 않았다면 설정과 로그인이 열리지 않는다는 안내가 나온다.

capability와 비밀번호는 이 인스턴스에만 전송되며 제작자나 다른 곳으로 보내지 않는다.

## 3. 업무 화면 (`work.html`)

### 3.1 맡길 일 설명하기

"어떤 일을 맡기고 싶으세요?" 입력란에 맡길 일을 문장으로 적고 **이 인스턴스에 저장**을 누른다.

- 설명은 최대 20,000자(UTF-8 65,536바이트)까지 저장된다.
- 저장할 때마다 **수정본**이 하나씩 늘어나며 이전 수정본은 덮어쓰지 않는다.
- 아직 저장하지 않은 입력은 **이 브라우저에만** 임시 보관된다. 다른 기기나 인스턴스에는 없다.
- 다른 탭이나 기기에서 같은 업무가 먼저 수정되면 충돌을 알려 준다. "저장본 다시 열기"로 최신
  내용을 받거나, 현재 입력을 최신 수정본 위에 저장하도록 선택할 수 있다. 조용히 덮어쓰는 일은 없다.
- 설명과 원본을 저장하는 것만으로는 외부 모델로 아무것도 보내지 않으며, 제작자에게 자동으로 보내는
  것도 없다. 이 화면에서 외부 모델(Claude)로 보내는 일은 아래 3.4의 "작업 모델 만들기"를 소유자가
  누를 때만 일어난다.

### 3.2 원본 자료 올리기

"자료 추가"로 파일을 고른다. 설명 없이 자료만 저장할 수도 있다.

- 한도: 파일당 10 MiB, 업무당 20개, 합계 50 MiB.
- 파일 이름에 경로 문자나 제어 문자가 있으면 받지 않는다.
- 전송 중에는 "전송 중지"로 멈출 수 있다. 다만 전송 중지가 곧 저장 취소를 뜻하지는 않으므로,
  화면이 알려 주는 저장 상태를 확인한다.
- 저장된 원본은 목록에 "원본 보관됨"으로 표시되고 다시 내려받을 수 있다.
- **원본 저장은 형식 검증이나 내용 이해가 아니다.** 내용은 다음 절의 "자료 읽기"에서 자료마다
  직접 읽을 때만 읽는다.

### 3.3 자료 읽기

"자료 읽기" 영역은 저장된 원본마다 읽기 상태(아직 읽지 않음 / 전부 읽음 / 일부만 읽음 / 읽을 수
없음)를 보여 준다. **내용 읽기**(또는 다시 읽기)를 누를 때만 이 인스턴스가 그 원본의 글자를 읽고
얼마나 읽었는지 기록한다.

- 텍스트·PDF·DOCX만 읽는다. 다른 형식은 "읽을 수 없음"과 그 이유가 표시된다.
- PDF·DOCX는 격리된 문서 워커가 이 인스턴스에 연결되어 있을 때만 읽는다. 연결되어 있지 않으면
  그렇다고 알려 주고 아무것도 기록하지 않는다. 원본은 그대로 보관된다.
- 일부만 읽은 경우 이유가 함께 나온다(길이 한도 약 60,000바이트, 글자 층이 없는 쪽, UTF-8이 아닌
  바이트 등). 읽힌 글자의 앞부분을 화면에서 확인할 수 있다.
- 원본을 지우면(3.8) 그 원본에서 읽은 글자도 함께 지워지고, 읽기 기록(상태·글자 수)만 남는다.

### 3.4 작업 모델

작업 모델은 설계를 시작하기 전에 목표·산출물·완료 조건·권한·위험·미결 사항과 권장 형태(에이전트
하나 / 여러 에이전트 / 정해진 절차 / 사람만 수행)를 확인하는 단계다.

- 만들려면 설명이 저장되어 있고 원본 자료가 **하나 이상** 있어야 하며, 설정 화면 **모델 연결**의 **Claude 연결**이
  준비되어 있어야 한다(키 저장과 모델 목록 읽기, 6.7).
- "작업 모델 만들기"를 누르면 저장된 설명과, 자료 읽기로 **직접 읽은 자료의 읽힌 글자만** 선택한
  Claude 모델로 전송된다. 읽지 않은 자료의 내용은 보내지 않는다. 보통 수십 초가 걸린다.
- 모델의 답이 작업 모델 형식에 맞지 않으면 받아들이지 않고 다시 만들 수 있다고 알려 준다.
- 초안을 확인하고 **이 작업 모델 수락** 또는 **거절**을 누른다. 막힌 미결 사항이 있으면 그 작업
  모델로는 설계를 시작할 수 없다고 알려 준다. 미결 사항에 답하려면 설명을 고쳐 저장한 뒤 다시 만든다.

### 3.5 대화

"대화" 영역에 남긴 말은 이 업무의 현재 수정본과, 참조로 표시한 자료·기록에 묶여 이 인스턴스에
기록된다. 보내지 않은 대화 입력은 이 브라우저에만 임시 보관된다.

- **말만으로는 아무것도 승인되지 않는다.** 대화에서 작업 모델 확정·반려를 제안할 수 있지만(작업
  모델을 참조로 표시해야 한다), 실행되려면 화면에 표시된 **확인 문구**를 정확히 입력해 "승인 응답으로
  보내기"를 누르거나 "승인" 버튼을 눌러야 한다.
- 확인 문구가 만료·교체되었거나, 업무가 바뀌었거나, 이미 결정된 경우, 또는 문구가 정확하지 않은
  경우 승인으로 처리하지 않고 아무것도 바꾸지 않는다. "확인 문구 다시 받기"로 새 문구를 받을 수 있다.

### 3.6 설계 후보 비교

"설계 후보 비교" 영역은 이 인스턴스가 가진 설계 요청의 후보를 보여 준다: 통과한 구조적으로 다른
후보(기본 3안, 채우지 못하면 실제 수), 제시하지 않은 후보와 이유, 후보 두 개를 나란히 놓는 비교와
같은 노드의 차이, 그리고 **선택·수정 지시·합치기**로 새 설계 버전 만들기, **재검토**, **이 설계로 준비**.

현재 한계를 그대로 적는다.

- 지원 서버에는 아직 설계 요청을 만드는 제품 경로가 없다. 그래서 보통은 "이 인스턴스에 비교할 설계
  요청이 없습니다"가 표시된다.
- 선택·수정·합치기로 만든 새 버전은 재검토가 필요하며 원본의 평가·승인을 이어받지 않는다. 수정·
  합치기 지시를 반영한 그래프를 만드는 생성 단계가 아직 없어 그런 버전은 재검토할 수 없다.
- 자격을 갖춘 평가자(critic) 구성이 아직 없으므로 **설계 승인은 제공되지 않는다.** "이 설계로 준비"는
  "지금은 승인할 수 없습니다"와 그 이유를 보여 준다. 화면의 평가는 기록된 결론이며 실시간 평가가 아니다.

### 3.7 업무별 기록 내보내기 (선택 사항)

업무 화면의 "기록 내보내기"에서 저장된 업무 하나의 기록을 파일 묶음으로 만들 수 있다. 내보내지 않아도
작업은 끝까지 진행된다.

1. **범주 고르기**: 작업 설명 원문, 개정 기록, 첨부 자료 목록, 모델 최종 응답, 도구 관측, 내 버전, 평가
   근거 중에서 고른다. 원문을 그대로 넣을지는 별도 체크박스이며 **기본값은 꺼짐**(메타데이터만)이다.
   원문 포함을 고른 경우에만 첨부 원본도 넣을 수 있다.
2. **포함될 내용 미리보기**: 실제로 묶일 항목과 각 항목의 포함 방식·크기, 빠지는 범주와 그 이유가
   표시된다. 모델 최종 응답과 도구 관측은 "이 서버가 아직 모으지 않음"으로 빠지며, 평가 근거는 이
   업무에 관련된 설계 평가·렌즈·비교 기록만 메타데이터로 담기고 실행의 완료 판정 근거는 아직 모으지
   않는다고 표시된다. 미리보기의 SHA-256도 함께 보인다.
3. **비밀 의심 값**: 원문에서 API 키·토큰·개인 키처럼 보이는 값을 찾으면 값은 보이지 않고 위치만
   알려 주며 해당 원문은 제외된다. 직접 확인했다고 표시해야만 그 원문을 그대로 포함할 수 있다. 첨부
   PDF는 격리된 문서 워커가 검사하고, 찾으면 가린 사본만 넣거나 뺀다.
4. **명시 동의**: "위 미리보기 그대로 내보내는 것에 동의합니다" 상자를 직접 체크해야 한다. 동의는 방금
   본 미리보기에 묶인다. 미리보기 이후 업무가 바뀌면 거절되고 다시 미리보기를 요구한다.
5. **내려받기**: 묶음이 만들어지면 크기, 항목 수, SHA-256과 함께 같은 출처의 다운로드 링크가 나온다.
   묶음은 어디에도 자동으로 전송되지 않는다.

### 3.8 원본 삭제 (선택 사항)

**원본 삭제** 칸에는 저장된 원본이 상태(저장됨/삭제됨)와 함께 나열된다. 지울 원본을 고르고 이유(더는
필요하지 않음 / 권리·개인정보 요청)를 정해 **삭제 미리보기**를 누르면 서버가 실제로 계산한 내용을
먼저 보여 준다: 지워질 원본과 크기, 그 원본을 가리키는 기록 수, 같은 내용을 가진 다른 원본(한 벌만
저장되므로 함께 "삭제됨"이 된다), 그 원본에서 읽은 글자(함께 지워진다)와 그 글자로 만든 작업 모델
초안(남는다), 그리고 이 삭제가 닿지 않는 곳(이 삭제 전에 만든 백업, 이미 내보내거나 보낸 사본, 이
인스턴스 밖의 사본).

동의 칸은 따로 있고 기본으로 꺼져 있으며, 미리보기 이후 업무가 바뀌면 삭제는 거절되고 미리보기를
다시 해야 한다. 삭제하면 원본 바이트가 지워지고 그 자리에 최소 삭제 표시(tombstone)만 남는다.
원본을 가리키던 기록은 그대로 남아 읽히며 원본은 "삭제됨"으로 표시된다. 결과는 파일 제거를
확인했는지, 아직 확인 중인지를 원본마다 말한다. 삭제는 되돌릴 수 없다.

## 4. 실행 화면 (`observe.html`)

이 화면은 **이미 기록된 실행**을 살펴보는 곳이다. 새 실행은 업무 화면의 "실행 시작"에서 준비된 환경이
있을 때만 시작한다.

### 4.1 실행 목록과 실행 상태

- "관제할 실행 선택"에서 기록된 실행을 고른다. 자동으로 선택되는 실행은 없다. "실행 목록 다시
  읽기"로 목록을 새로 받는다. 주소의 `#run=<실행 ID>`로도 그 실행이 열린다.
- 실행을 고르면 머리에 업무 이름, 상태, 시작·끝·걸린 시간, 호출 수(모델·도구·시도·재시도), 토큰,
  비용이 보인다. 기록되지 않은 비용은 "미확인", 한도 요율로 잡은 예약은 "추정"으로 표시된다. 사람
  승인이 필요하면 한 줄 배너와 "승인 화면 열기"가 나오고, 그래프의 그 노드가 점선으로 표시된다.
- 실행 상태에 따라 "이어서 진행", "새 작업 보내기 중단", "복구 시도" 버튼이 나타날 수 있다. 명령이 현재
  상태와 맞지 않으면 거절하고 다시 읽은 최신 상태를 보여 준다. 노드별 상태를 글로 적은 목록은 "노드별
  상태를 글로 보기"를 펼치면 보인다.
- **최종 결과**가 먼저 나온다. 그래프의 끝 단계가 만든 산출물마다 미리보기, "내 버전 만들기", "원본
  내려받기", "대안 파일 올리기", "과정에서 보기"가 있다. 결과가 없으면 없다고 적고 실행이 멈춘 지점을
  보여 준다.
- **과정**에서는 그래프와 타임라인이 한 선택을 같이 쓴다. 단계를 고르면 선택 칸에 그 단계의 수행과
  시도가 나온다. 기본은 가장 최근 시도이고, "시도 선택"으로 지난 시도를 고를 수 있다. 지난 시도에는
  그 시도가 남긴 것(입력, 오류, 호출, 기록)만 보이며 뒤 시도의 산출물은 붙지 않는다.
- 선택 칸의 탭은 다음과 같다.
  - **입력**: 앞 단계 산출물의 정확한 버전.
  - **산출물**: 고른 단계의 것만.
  - **전달**: "전달됨"과 "활용 근거"를 구분한다.
  - **도구·모델**: 호출마다 시간, 결과, 토큰, 비용 근거. 숨은 추론은 저장하지 않는다.
  - **기록**: "전체 기록에서 이 실행 보기"는 기록 화면을 이 실행으로 걸러 연다.
- **과정 피드백**(2026-09-26 추가): 최종 결과 아래 "이 결과 전체"와, 선택 칸의 고른 단계·시도("이 단계:
  … · 시도 1")에 **괜찮음**·**확인 필요** 표시와 **메모 쓰기**(선택, 최대 4,000자)가 있다. 이유를 적지
  않아도 되며 표시만, 메모만, 또는 둘 다 남길 수 있다. **저장**을 눌러야 저장되고 "저장됨 · 3분 전"이
  보인다. **지우기**는 새 기록으로 남으며 이전 기록은 지워지지 않는다. 피드백이 있는 단계는 그래프 노드와
  타임라인 줄에 표식(! 확인 필요, ✓ 괜찮음, ✎ 메모만)과 말로 표시되고, 머리에 "내 피드백: 확인 필요 2개
  단계"처럼 요약된다. 피드백은 내 버전(대안)이 아니며 대안으로 세지 않는다.

### 4.2 승인할 일

"선택한 실행의 승인" 영역은 그 실행에서 사람의 결정을 기다리는 일을 보여 준다.

- **게이트 승인**: 그래프의 사람 승인 노드(실행·노드·범위 표시).
- **실행 시도 승인**: 한 실행 시도 하나에 묶인 승인(입력 digest와 시한 표시). 재시도는 새 시도이므로
  이전 시도의 결정이 적용되지 않고 새 결정이 필요하다.
- 각 항목에서 **승인** 또는 **거절**을 누른다. 결정을 기록해도 실행이 저절로 이어지지는 않으며,
  이어서 진행하는 것은 실행 명령(4.1)에서 따로 한다.
- 시한이 지난 요청은 "만료됨", 소유자 복구 이전의 결정은 "대체됨"으로 표시되며 아무것도 허가하지 않는다.
- 시한은 이 기기 시간대의 시각(초 단위)으로 보인다.
- 결정할 일이 없으면 이 영역은 "이 실행의 승인 기록 N건 · 보기" 한 줄로 접힌다. 누르면 기록이 펼쳐진다.

### 4.3 작업 그래프

선택한 실행의 작업 그래프가 노드와 연결로 표시된다. 노드마다 종류(에이전트, 정해진 처리, 분기, 합류,
사람 승인, 제한 반복)와 실행 상태(완료, 실패, 대기, 승인 대기, 미방문)가 보인다. 노드를 고르면 책임,
입력·출력, 실패 처리(예: "실패하면 뒤 단계 멈춤"), 필요한 승인, 권한, 모델 연결, 도구 연결, 들어오는·나가는
연결(산출물·제어·승인·관찰)을 볼 수 있다. 처리기 설정 원문(JSON)은 **기술 정보**를 펼치면 보인다.

### 4.4 산출물 보기

선택한 실행의 산출물 목록에서 "미리보기" 또는 "원본 내려받기"를 고른다. 과정에서 단계를 고르면 목록에는
그 단계(고른 시도)의 산출물만 나오고, "실행 전체 보기"를 누르면 실행 전체의 목록으로 돌아간다. 형식은 "텍스트", "표(CSV)",
"PDF"처럼 우리말로 보이며, 이 값은 산출물을 만든 쪽이 밝힌 형식이다(미리보기는 실제 내용을 보고 방법을
고른다). 밝힌 형식 원문, 산출물 ID와 SHA-256은 줄마다 **기술 정보**에 있다.

- 텍스트·JSON·CSV는 텍스트로, 이미지는 이미지로 미리 본다. 미리보기가 잘리면 잘렸다고 알려 준다.
- **PDF**는 격리된 문서 변환 워커가 그린 쪽 이미지로 보며, "이전 쪽/다음 쪽"으로 이동한다. 이미지에
  없는 것(링크, 양식, 주석 등)은 따로 적힌다. **DOCX**는 본문 문단과 표 셀의 텍스트로 보며, 포함하지
  않은 것(머리글·바닥글, 각주, 이미지 등)이 따로 적힌다.
- 문서 변환 워커가 이 인스턴스에 연결되어 있지 않거나, 응답하지 않거나, 파일을 거부하거나, 크기
  한도를 넘으면 그렇다고 알려 주고 **대신 보여 주는 것 없이** 원본 내려받기만 제공한다.

### 4.5 모든 실행의 산출물 (기록 화면)

실행 화면은 고른 실행의 것만 보인다. 모든 실행의 산출물 색인은 2026-09-26부터 기록 화면의 "모든 산출물"에
있다. 형식 필터(모든 형식, PDF, DOCX, 이미지, 텍스트·CSV, JSON)와 "더 보기", "색인 다시 읽기"가 있고, 읽지
못한 실행이나 색인 한도 밖의 실행이 있으면 그 수를 알려 준다. "실행 화면에서 열기"는 그 실행을 열고 해당
산출물을 미리 본다(`observe.html#run=…&artifact=…`).

### 4.6 내 버전 편집

텍스트·Markdown·JSON 또는 CSV 산출물에서 **내 버전 편집**(최종 결과에서는 **내 버전 만들기**)을 누르면
원본의 복사본을 그 자리에서 고칠 수 있다. 편집기는 그 산출물 바로 아래에 열리고, 제목에 산출물·단계·
수행이나 시도가 적힌다. "닫기"로 닫는다. 원본은 그대로 남는다. 이유나 지시를 적지 않아도 된다.

- 텍스트는 입력란에서, 표(CSV)는 칸 단위로 고치며 "행 추가"로 행을 늘린다.
- 입력을 멈추고 약 0.8초가 지나면 **자동 저장**되어 새 수정본이 된다.
- **원본**(읽기 전용), **내 버전**(편집 중인 내용), **차이**(저장된 수정본과 원본 사이의 형식상 차이)
  세 보기를 오갈 수 있다. 넓은 화면에서는 원본과 내 버전이 나란히 보인다.
- 다른 탭이 먼저 저장했다면 충돌로 알려 주고 지금 화면의 내용은 그대로 둔다. "최신 수정본 불러오기"
  또는 "지금 내용을 새 초안으로 저장" 중에서 고른다.
- 한 화면에서 편집할 수 있는 크기는 약 256 KiB까지다.
- **차이 살펴보기**(예전 이름 "분석용으로 고정")를 누르면 저장 후 그 수정본을 고정한다. 기본적으로 바꾼 줄·칸만 내 근거로
  기록되고 나머지는 "검토하지 않은 영역"으로 남는다. "전체를 검토했습니다" 상자(기본 꺼짐)를 체크했을
  때만 전체를 내 버전으로 기록한다. 원본과 같은 내용은 고정할 수 없다.

### 4.7 대안 파일 올리기

산출물 옆의 **대안 파일 올리기**로 원본을 고친 내 파일(최대 4 MiB)을 올릴 수 있다.

- 원본 형식에 맞는 방식으로 고친 부분을 지정한다: PDF는 쪽 번호와 쪽 안의 영역(x·y·너비·높이, %),
  이미지는 영역(%), JSON은 JSON 위치(예: `/items/0/title`), 오디오·비디오는 시작·끝 시각(초).
- 부분 선택을 지원하지 않는 형식은 원본 전체를 검토했을 때만 올릴 수 있다. 텍스트·표는 전체로만
  올리며, 줄·칸 단위 기록은 "내 버전 편집"을 쓴다.
- 지정한 영역은 원본 위의 위치로만 기록된다. DeepTwin은 원본과 내 파일 사이의 의미 정렬을 계산하지
  않으므로 정렬은 항상 **"미정"(`unresolved`)** 으로 남는다.

### 4.8 차이 살펴보기

내 버전을 고정하거나 대안 파일을 올리면 그 산출물의 편집기 바로 아래에 **차이 살펴보기** 영역이 열린다
(2026-09-26부터. 예전에는 페이지 아래의 "차이와 설명" 카드였다).

- 먼저 원본과 내 버전 사이의 **관측된 차이**, 근거 범위(바꾼 곳 수 또는 전체)와 검토하지 않은 영역,
  그리고 **관련 실행 구간**(그 산출물을 만든 단계, 수행·시도, 받은 입력, 도구·모델 호출)을 보여 준다.
  차이를 기록할 뿐 원인은 해석하지 않는다. "과정에서 이 단계 보기"로 그 단계를 과정에서 고른다.
- 차이를 고르면 **원본 부분**, **내 버전 부분**, 앞뒤 3줄 문맥이 나온다. 위치는 제안된 정렬이다. 올린 파일은
  부분 대응을 계산하지 않으므로 관측 설명만 보인다.
- **경쟁 설명 만들기**: Claude 연결이 준비되어 있으면 모델을 골라 경쟁하는 설명(시스템 결손, 새로운
  조건부 판단, 일회성 예외, 대안 쪽의 오류, 일반화할 지식 없음)을 만들 수 있다. 누르면 관측된 차이와
  (텍스트 형식이면) 원본·내 버전이 선택한 Claude 모델로 전송된다. 만들어진 설명은 성립 조건과 구별할
  예측을 함께 보여 주며 **모두 "제안" 상태**다. 실제 비교·행동 증거 없이 확인되지 않는다.
  만들지 않은 설명은 "검토되지 않음"으로 표시된다.
- 이 화면은 질문에 답하도록 요구하지 않는다. **입력칸이 없으며 아무것도 묻지 않는다.** 질문(탐구)과
  변경 후보는 아직 만들어지지 않는다. 영향 범위는 따로 조사할 일로 남는다.

## 5. 버전·실험 화면 (`versions.html`)

운영 버전과 후보를 보는 화면이다. 서버가 기록한 것만 보이며, 기록을 정확히 다시 읽지 못한 항목은
결정 대상으로 보이지 않는다고 밝힌다.

- **운영 버전**: 지금 운영 중인 환경과 이력, "이전 버전으로 되돌리기"(이유 필수). 되돌려도 이미 보낸
  것·게시한 것은 되돌리지 않는다. 설계 승인으로 준비된 환경이 없으면 "운영 버전이 아직 채택되지
  않았습니다"가 표시된다(3.6: 설계 승인은 아직 제공되지 않는다).
- **후보**: 검증 게이트별 결과와 **거절/보류/승인**, 그리고 "승인한 이 버전 적용". 봉인 검증을 통과하지
  못한 후보는 승인할 수 없다.
- **성장 실험**: 계보별 상태, 멈춘 이유, 최고 기록, 연속 비개선 수, 소비한 예산.
- **비교 라운드**: 라운드마다 유효성, 측정값과 효용(유효한 라운드만), 항목별로 기준과 후보의 노드 결과를
  나란히 보여 준다. 과거 발송·게시는 다시 실행하지 않는다.
- **도구 효과 경계**: 과거에 발송·게시한 업무를 다시 비교할 때 도구마다 쓸 경계(기록 재생 또는 격리
  싱크)를 소유자가 **승인/거절**한다. 어느 경계도 실제 서비스로 보내지 않으며, 승인하지 않은 경계가
  필요한 항목은 비교하지 않는다.

## 6. 기록 화면 (`records.html`)과 설정 화면 (`settings.html`)

기록 화면에는 6.1 기록, 6.2 내보내기 안내, 그리고 모든 실행의 산출물 색인(4.5)이 있다. 6.3–6.11은 설정 화면에 있다(2026-09-26에 기록
화면에서 옮김). 설정 화면은 왼쪽 목록(좁은 화면에서는 위쪽 단추)에서 한 항목을 골라 한 번에 하나씩
보여 준다: 계정과 세션, 모델 연결(Claude 연결·API 자격증명), 실행 한도, 백업·보존, 업데이트·복구, 확장,
브라우저 권한. 예전 주소의 항목 이름(예: `settings.html#records-credentials`)으로 열면 그 항목이 든 칸이
열린다. 어느 항목도 필수 단계가 아니고 순서도 없다. 내보내기와 백업은 선택 사항이다.

### 6.1 기록

이 인스턴스의 공개 사건 목록이다. 각 줄에는 무슨 일이 있었는지 한 문장(예: "업무 설명을 고쳤습니다
(수정본 4)", 성공하지 않은 사건은 "업무 만들기"처럼 주제만), 결과(글자와 기호), "3분 전"과 초 단위의 이
기기 시각, 관련 기록 수, 오류가 있으면 그 뜻이 보인다. 원래 사건 이름·순번·UTC 시각·오류 코드는 줄마다
**기술 정보**를 펼치면 보인다. 개인 근거 내용은 보이지 않는다. "다음 기록 보기"로 이어서 읽으며, 더 읽을
기록이 없으면 이 단추는 보이지 않는다. 실행이 멈춘 사건은 사건 기록의 성공 여부가 아니라 실행 결과("완료",
"실패로 멈춤", "취소·거절로 멈춤" 등)를 결과 칸에 보인다(기록 자체의 상태는 기술 정보에 있다). 보존 기간 등으로
빠진 구간은 빠진 구간이라고 알려 주며 사건을 지어내 채우지 않는다.

### 6.2 내보내기

내보내기는 업무마다 업무 화면(3.7)에서 한다는 안내와 링크만 있다.

### 6.3 백업과 복원

- 백업은 **격리된 백업 워커**가 이 인스턴스에 연결되어 있을 때만 만들 수 있다. 화면은 지금 상태를
  그대로 말한다: 워커 연결됨 / 워커 없음(백업을 만들 수 없음) / backup-key 볼륨 없음 또는 손상 /
  워커에 연결하지 못함. 워커가 없으면 백업을 만들거나 복원하지 않으며, 백업이 있다고 표시하지도 않는다.
- **백업 만들기**: 실제로 포함될 내용(범주별 수·크기, 빠지는 범주와 이유, 미리보기 SHA-256)을 먼저
  보여 주고, 그 미리보기에 동의해야 만든다. 만든 뒤 복원 확인까지 마치며 어디에도 자동으로 보내지
  않는다. 미리보기 이후 기록이 바뀌면 다시 미리보기를 요구한다.
- 이 화면이 만드는 백업은 **이 배포용 키(instance backup key)** 백업이다. 이 호스트의 backup-key
  볼륨을 잃으면 복구할 수 없고, 키를 다시 만들어도 이전 백업은 열리지 않는다.
- **만든 백업**: 목록에서 암호화된 백업(`.age`)과 외부 영수증(`.receipt.json`)을 내려받는다.
- **복원**: 외부 영수증과 암호화된 백업을 모두 골라 **스테이징 영역에 복원**한다(이 화면에서 받는 크기는
  64 MiB까지). 휴대용 복구 백업이라면 따로 보관한 복구 키(`AGE-SECRET-KEY-1…`)를 입력한다. 이 키는
  한 번만 쓰고 저장하지 않는다. 업로드는 "업로드 중단"으로 멈출 수 있다.
- 복원본은 **검토 대기(`restored_review`)** 상태이고 실행은 막혀 있으며, 활성 인스턴스는 바뀌지 않는다.
  화면은 복원하지 않은 범주(인증 수단, 자격증명, 쓰지 않은 권한 등)와 복원 후 필요한 단계(새 소유자
  초기 설정, 제공자 연결과 서비스 클라이언트 다시 만들기, 정확한 환경을 검토하고 명시적으로 다시
  활성화하기)를 보여 준다. 스테이징된 복원본을 활성 인스턴스로 바꾸는 기능은 이 화면에 없다.

### 6.4 보존과 정리

- 자동 삭제는 없다. 기록과 원본은 명시적으로 지우기 전까지 보존되고, 백업도 자동으로 지우지 않는다.
- **범주별로 남기는 것**: 핵심 기록(기한 없이 보존, 지우지 않음), 삭제 표시, 저장한 원본(업무 화면의
  "원본 삭제"에서만 지움), 암호화된 백업, 스테이징된 복원본, 다시 만들 수 있는 캐시(이 서버는 디스크에
  저장하지 않음), 원시 음성(저장하지 않음).
- **소유자가 정리할 수 있는 항목**: 더 최근 백업이 있는 오래된 백업, 실패한 복원의 남은 자리, 검토 대기
  중인 복원본 등. 가장 최근 백업은 항상 남긴다. 항목을 고르고 **정리 미리보기**로 지워질 것, 남는 것,
  닿지 않는 것(이미 내려받은 사본, 이 인스턴스 밖의 사본), 어떤 경우에도 지우지 않는 것을 확인한 뒤,
  동의해야 정리한다. 지운 자리에는 삭제 표시가 남는다. 되돌릴 수 없다.
- **지난 정리** 목록이 남는다.

### 6.5 업데이트와 복구

이 영역은 **읽기만 한다.** 현재 릴리스, 진행 중인 업데이트 요청(대상, 매니페스트·이미지 잠금 digest,
만료), 이전에 필요한 검증된 백업과 그 백업이 지금 자료 전체를 담고 있는지, 최근 거절 이유, 그리고
**운영자가 할 일**을 보여 준다. 업데이트와 복구는 서비스를 멈춘 상태에서 배포 운영자만 하며, 이 화면에는
버튼·입력칸·파일 선택이 없고 브라우저에서 올린 파일은 업데이트나 복구의 근거가 되지 않는다.

### 6.6 계정과 세션

지금 비밀번호를 한 번 더 입력하고 새 비밀번호(15자 이상, 확인 입력 포함)를 정해 **비밀번호를 바꿀** 수
있다. 바꾸면 다른 곳의 세션은 모두 끝나고, 지금 브라우저는 새 세션으로 이어진다. 입력한 비밀번호는
시도 직후 칸에서 지워지고 어디에도 저장되지 않는다. **다른 세션 모두 끝내기**는 지금 브라우저만 남기고
나머지 세션을 끝내며 몇 개를 끝냈는지 알려 준다.

### 6.7 Claude 연결

- Claude API 키를 저장·교체·지우고, **모델 목록 읽기**로 모델 목록을 받아 실행에 쓸 모델을 고른다.
- 이 키는 **이 서버의 메모리에만** 보관된다. 서버를 다시 시작하면 다시 입력해야 한다. 키를 저장하거나
  모델 목록을 읽는 것만으로는 과금되는 모델 호출이 일어나지 않는다.
- 작업 모델(3.4), 경쟁 설명(4.8)과 현재의 실행은 이 키를 쓴다. 아래 API 자격증명의 키와는 별개다.

### 6.8 API 자격증명

- 제공자 API 키를 이 배포의 **자격증명 게이트웨이**에 암호화해 보관한다. 게이트웨이가 이 배포에
  연결되어 있지 않으면 그렇다고 알려 준다. 화면에는 키 값이 다시 나오지 않는다.
- 저장된 자격증명과 제공자 연결(바인딩 수정본, 모델 목록 유무, 모델 선택)을 보고, 키를 **저장·교체·
  삭제**한다. 키를 교체하거나 삭제하면 이전 바인딩의 모델 목록과 모델 선택은 무효가 된다. 새 목록은
  "모델 목록 새로 고침"을 누를 때만 생긴다.
- 여기서 삭제해도 **제공자 쪽의 키는 폐기되지 않는다.** 더 쓰지 않으려면 제공자 콘솔에서 직접 폐기한다.
- **끝나지 않은 요청**: 결과를 확인하지 못한 저장 요청은 그대로 표시되며, 차단 가능 시각이 지나면
  **이 요청 차단**으로 끝낼 수 있다. 늦게 저장된 기록은 연결하지 않고 정리한다.
- **전송 매니페스트 검증**: 게이트웨이는 제공자 전송 매니페스트의 검증을 채택하기 전까지 저장된 키로
  어떤 요청도 보내지 않는다. 화면은 요구 조건(검증된 제공자 설치에서 4/4로 통과한 적합성 검사, 오프라인
  전송 적합성 검사)과 충족 여부를 보여 주며, 조건이 맞으면 검증을 실행한다. 검증하는 동안 실제
  제공자에게는 아무것도 보내지 않는다.
- 지금의 실행은 이 게이트웨이 키가 아니라 6.7의 Claude 연결 키를 쓴다.

### 6.9 실행 한도

소유자가 동의한 실행에서 런타임이 그대로 지키는 유한한 상한(모델 호출, 도구 호출, 노드 방문, 반복
라운드, 출력 바이트, 동시 실행, 실행 시간, 후보 수)을 저장한다. 구독 연결 한도는 사용량으로만 정하고,
API 키 연결 한도에는 통화와 비용 상한이 반드시 필요하다. 저장만으로는 모델을 부르거나 실행을 시작하지
않는다.

### 6.10 브라우저 접근 허가 (설정 화면)

에이전트의 브라우저 도구가 요청을 보낼 수 있는 곳과 그 요청에 실릴 수 있는 값을 정한다. 허가가 없으면
브라우저 도구는 아무 곳에도 요청하지 않는다.

- 새 허가: 이름, 허가할 도구(열기, 본문 읽기, 화면 캡처), 열 수 있는 정확한 https 주소(쿼리·포트·계정
  없이), 값이 실릴 수 있는 쿼리 매개변수와 그 값(한 줄에 하나, 비우면 순수 탐색), 추가로 받을 수 있는
  호스트, 유효 기간(1~90일).
- 허가한 값은 SHA-256 요약으로만 저장되어 다시 보이지 않는다.
- 목록에서 유효·철회됨·만료됨 상태를 보고 **이 허가 철회**로 철회한다. 철회한 뒤의 브라우저 호출은 그
  허가로 실행되지 않는다.
- 허가를 만들 수는 있지만, 현재 제품 실행 경로는 아직 브라우저 도구를 쓰지 않는다(7).

### 6.11 설정 > 확장

확장은 선택 사항이며 확장 없이도 기본 기능으로 업무를 계속할 수 있다. 이 화면은 이 서버의 확장 경로가
실제로 보내는 내용만 보여 주고, 보내지 않는 항목은 **"제공되지 않음"**으로 표시한다.

- **확장 후보**: 실행형 확장 후보의 검토용 메타데이터(manifest, service descriptor, 라이선스·출처·
  SBOM·정책 문서)를 등록하고 읽는다. 등록해도 설치·검증·실행되지 않으며, 코드나 이미지를 올리지 않고
  출처 주소도 가져오지 않는다. 출처·라이선스·이미지는 확인되지 않은 신고 내용으로 표시된다.
- **설치와 검증**: 운영자가 배치한 제공자 설치 목록, 설치를 검증된 설치로 기록하기(릴리스 증거 묶음
  파일), 검증된 설치의 제공자 적합성 검사(고정된 4개 벡터) 실행과 결과.
- **바인딩**: 서버가 계산한 slot key로 검증된 제공자 설치를 바인딩하고, 비활성화·롤백·롤백 보존 해제를
  한다. 바인딩은 봉인된 전송 매니페스트 검증 기록이 있는 **제공자 포트만** 가능하다. 모든 조작은 화면이
  마지막으로 읽은 상태를 그대로 보내며, 그사이 서버 상태가 바뀌었으면 아무것도 바꾸지 않는다.
- 실행형 확장의 배치(staging)는 인스턴스 운영자의 권한이며 이 화면의 단계가 아니다.

## 7. 아직 없는 기능

아래 기능은 현재 브라우저 화면에 없거나 동작하지 않는다. 있는 것처럼 기대하지 않기를 바란다.

- 브라우저에서 **실행을 시작**하는 기능과 실행 동의를 기록하는 화면 (실행 관제 화면은 이미 기록된
  실행만 보여 준다)
- **마이크 음성 입력** (T024)
- **Codex 구독 연결**(관리형 실행기, T088) — 화면에 없다
- 에이전트 실행에서 **브라우저 도구**를 쓰는 제품 경로 (허가 화면은 있지만 제품 실행기가 아직 브라우저
  도구를 등록하지 않는다, T043)
- 제품 경로에서 **설계 요청 만들기**와 **설계 승인** (자격을 갖춘 평가자 구성이 없다, T036/T077)
- 경쟁 설명의 확인, 질문(탐구), 변경 후보
- 스테이징된 복원본을 활성 인스턴스로 바꾸기, 이 화면에서 휴대용 복구 키로 **백업 만들기**
- 원본 외 기록의 삭제 화면
- 내보내기의 모델 최종 응답·도구 관측 범주와 실행의 완료 판정 근거
- 코드 없는 렌즈·평가자 정의 가져오기, 제공자 포트 외의 확장 바인딩
- 서비스 클라이언트(자동화용 자격증명) 화면

PDF·DOCX 읽기와 미리보기, 백업·복원, 자격증명 게이트웨이, 브라우저 도구는 모두 해당 격리 워커가
배포에 연결되어 있어야 동작한다. 최종 배포 이미지(T081)가 아직 없으므로, 어떤 배포에서 이 워커들이
연결되어 있는지는 그 배포의 운영자가 확인해야 한다.

위 목록은 2026-09-25 기준이다. 브라우저 동작 근거는 스크립트로 움직인 시험 행위자의 합성 근거다
(예: `evidence/us4.md`, `evidence/us3.md`, `evidence/extensions-ui-2026-09-25.md`,
`evidence/browser-grants-t043-2026-09-25.md`, `evidence/update-recovery-t072-2026-09-25.md`).
