# DG-L01 검토 결과와 사용자 확인 묶음

2026-09-07 · 문서 검토본. **운영 미활성 · 학술 미검토 · 실제 효과 미검증 · DG-V01 기준 자료 사용 승인.**

## 1. 이번에 준비한 것과 권고

논문 예시의 원전 13항목을 조사해 실제 읽은 범위에서 17개의 원자적 정의 후보와 3개의 조합 사례를 작성했다. 17개가 최초 지원 목록이나 기본 호출 개수라는 뜻은 아니다. 원전 전체·현대 번역 전체를 읽었다거나 철학 전체를 포괄했다는 주장도 아니다.

권고는 **아래 후보를 DG-V01의 검증 설계 입력으로 넘기되, 운영 기본값으로 채택하지 않는 것**이다. 같은 기본 요구를 충족하는 기존 절차·렌즈 없음·단독·조합을 비교해 실제 추가 질문과 판단 차이, 실패·비용을 확인한 뒤 용도별 사용 범위를 결정한다. 철학자 이름만 다른 후보나 당연한 기본 기능의 복구를 개선으로 세지 않는다.

| [정의 후보](definition-candidates.md) | 17개 카드의 주장·질문·반대 예측·기권·역할/산출물/전달에 대한 공학적 제안 |

일반 사용자 화면은 철학 분류표가 아니라 멀티에이전트 그래프와 업무상의 차이를 보여 준다는 기존 정체성을 유지한다. 이 문서는 내부 엔진을 준비하는 개발 자료이며 UI 메뉴·새 승인 버튼을 추가한 것이 아니다. 앱 코드·사용자 DB·모델 연결·실제 그래프 생성은 이번 작업에서 바꾸지 않았다.

## 3. 조합이 실제로 무엇을 바꿀 수 있는가

모두 [조합 계약 §4](composition-contract.md)의 새 합성 박물관 업무다. 실제 사용자 업무·산출물·실험 결과가 아니다. 모든 비교는 PDF·HTML·원형 파일 전체 인계·기본 정확성·권한을 동일하게 유지한다.

| 문서 조합 | 질문의 분담 | 가능한 설계 차이·남은 판단 |
| --- | --- | --- |
| HC-S0-A · L-P050-01 + L-P033-02 | A는 명칭에 묻힌 귀속 상태, B는 C의 캡션-근거 역추적 부담을 점검 | A→B의 의미 상태와 B→C의 항목 대응을 연결. 기존 표가 이미 해결했다면 조합 불필요. |
| HC-S0-B · L-P029-01 + L-P031-01 | 같은 PDF 패널에서 관람 거리의 읽기 부담과 용어면 왕복 부담을 각각 질문 | 더 큰 글자·간격 또는 추가 설명 중복의 두 유효 후보를 보존. 경험적 긴장이며 철학자들이 필연적으로 대립한다는 뜻은 아님. 가독성 기준 미달안은 충돌안이 아니라 탈락. |
| HC-S0-C · L-P032-01 + L-P052-01 | 기존 예상-관찰 대조와 문제 재구성이 이미 같은 질문을 수행 | 새 질문·판단이 없다면 조합 제외를 제안. 이름이 늘었다고 구조 다양성·효과를 인정하지 않음. |

규범 충돌도 평균·다수결로 없애지 않는 일반 규칙을 별도로 둔다. 실제 충돌 우선순위, 점수·가중치·예산을 이 세 예시로 확정하지 않는다. 세 예시는 제품의 기본 설계 3안이나 고정 토폴로지가 아니다.

## 4. 누가 무엇을 확인했는가

정의 작성자는 `l01_definitions`, 조합 작성자는 `l01_composition`이다. 최초 원전 조사 담당자는 출처 지도에 기록되어 있다. 아래 검토는 그 작성자의 자기평가·추천 점수를 결론의 근거로 사용하지 않았다. root의 내용 대조도 정의 작성 에이전트와 구별하지만 개발 조정자의 검토이므로 완전한 맹검이나 전문가 심사가 아니다.

## 6. 검토 사례와 후속 인계

LC-01–12는 실제 문서 조항과 대조했다. [사례별 결과](review-cases.md)의 ‘문서 부합’은 선언된 계약의 존재·연결을 확인한 결과다. 모든 엔진 결과는 **미실시 — 엔진 미연결**이며 합성 대화 실험이나 사용자 대안 수집을 하지 않았다.

파일 검사에서 Markdown 5개, 출처 ID 13개, 중복 없는 정의 ID와 상태 행 각17개, 사례12개·엔진 미실시12개를 확인했다. 로컬 문서 링크 누락·미완성 표식·끝 공백은 발견되지 않았고 `git diff --check`에도 오류 출력이 없었다. 이는 파일 구조·참조·표기의 검사이며 원전 진위·의미 판단·효과의 자동 검사가 아니다.

DG-V01에 넘길 입력은 정확한 후보 ID·내용 버전, 적용/기권 조건, 질문·반대 예측·교란, HC-S0-A/B/C의 미해결 비교와 중복 가능성이다. 검증 설계에서는 다음을 정해야 한다.

- 같은 업무·필수 기능·비용 조건에서 기존 절차/렌즈 없음/일반적 다각도 점검/단독/조합의 추가 판별력을 비교한다. 원전 역할극을 정답으로 두지 않는다.
- 반례 자체의 타당성과 후보 대응, 정상안의 오거절, 동일 모델의 공동 실패, 크리틱 구성 자격과 자동 통과 차단 범위를 별도로 판정한다.
- 실제 효과·비용·구조 다양성·허용 오류·호출/시간/반복 한도와 진전 없음의 기준을 코드 상수 전에 검토한다. 수치를 이번 묶음이 대신 정하지 않는다.
- 사용자 대안에서 출발하는 실제 성장에서는 부분 증거와 후속 영향을 구별하고, H_phi/S_phi를 운영 지식으로 직결하지 않는다. 새 E_phi로 H_exp를 갱신하고 이전 업무 큐 재평가·미관측/경계/회귀 검사·정확한 환경 버전의 사람 승격을 거친다.

DG-C01에는 경로별 입력 자격, 정의/조합/업무 요구/모델 설정/후보/검토의 버전 연결, 원형 다중형식 산출물과 프레임워크 도구·권한, 비평가 자료 접근 경계, 전체 선택·탈락·변경 로그와 선택적 내보내기 계약을 넘긴다. 이전 그래프 보존·명시적 새 생성·중단/재접속/늦은 응답·실제 그래프 비교의 수용 시험은 후속 명세·구현이다.

DG-L01의 제한된 문서 작업과 결과 묶음 검토는 완료했다. 미실독 원전·학술·효과·운영 채택의 공백은 그대로 남는다. 후속 DG-V01은 설계로 이행하며 실제 시험·엔진 구현·자동 호출을 승인하거나 활성화한 것은 아니다.
