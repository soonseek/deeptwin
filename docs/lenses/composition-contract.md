# 미세렌즈 선택·조합·검토 계약 제안

DG-L01 Task 4 · 2026-09-07 · 카드 draft-1 · 묶음 검토 revision 2(2026-09-08) · 문서 제안. 구현, 모델 호출, 라이브러리 사용 승인 또는 업무 환경 승격 기록이 아니다.

근거는 [정의 후보 17개](definition-candidates.md)의 실제 `draft-1` 카드와 C1·C2·S0·R0, [원전 실독 기록](source-map.md), [그래프 생성 계약](../superpowers/specs/2026-09-07-deeptwin-graph-generation-design.md)이다. 17개는 이번 문서의 검토 대상이며 최초 지원 수·영구 목록이 아니다. 원전 주장, 프로젝트의 공학 번역, 합성 사례, 실제 검증 결과를 분리한다. 이 문서 작성자가 원전을 모두 직접 재독했거나 학술 검토를 완료했다고 주장하지 않는다.

## 1. 입력 경로와 허용된 판단

| 경로 | 반드시 갖춰야 할 입력 | 허용된 출력과 경계 |
| --- | --- | --- |
| 초기 환경 설계 | 사용자가 확인한 업무 목적·산출물·완료 조건·관찰 가능한 상황·필수 제약·권한과 허가된 원자료 | 업무 조건에 맞는 질문과 설계 판단, 구조 후보. 최초 설명·업로드·이해 수정은 대안 산출물, 판단 차이, H_exp, H_phi 또는 개인 철학이 아니다. |
| 비평가의 반례 탐색 | 검토할 실제 후보 버전, 접근이 허용된 원본, 후보 생성 전에 고정한 공통 평가 기준 | 후보의 전제·책임·예외를 구별할 반례 제안과 근거. 제안은 실제 발생 사실이나 검증된 실패가 아니다. 반례 타당성과 후보 대응은 별도 판정한다. |
| 대안 이후 SPLI | 실제 전체 또는 부분 대안 산출물, 실제로 관찰된 판단 차이, 확인된 전문가 판단 가설 H_exp와 각각의 근거 | 차이를 구별할 질문·반대 예측을 만들고 새로운 E_phi를 얻어 H_exp를 검증·갱신. 에피소드 해석 H_phi/S_phi를 지식·개입 입력으로 직결하지 않는다. |

세 경로는 같은 정의를 참조할 수 있지만 입력 자격과 결과 효력이 다르다. 입력이 부족하면 필요한 증거와 기권 이유를 남긴다. 초기 후보끼리 다르다는 사실이나 내부 비평 결과로 SPLI 전제를 채우지 않는다. 부분 대안은 증거 범위를 표시하며, 그 차이가 다른 역할·인계·기억·환경 전체에 미칠 후속 영향을 조사할 가능성까지 제한하지 않는다.

현재 제공된 실제 사용자 대안·판단 차이·확인된 H_exp는 없다. 아래 S0 예시는 새로 만든 합성 업무이며 사용자 YouTube 설명이나 MANUAL-001을 전환한 피드백·평가 자료가 아니다. 이 문서에서는 어느 경로도 실행하지 않는다.

## 2. 업무별 선택 결과의 최소 내용

선택은 철학자 이름과 업무 키워드의 대응이 아니라 관찰 조건과 판별 질문의 대응이다. 사용 범위가 채택된 정의라도 모든 업무에 적합한 것은 아니며, 적합한 정의가 없으면 분류를 강제하지 않는다.

| 기록 항목 | 남겨야 할 내용 |
| --- | --- |
| 입력 범위 | 경로, 업무 요구 revision, 원자료·권한, 공통 평가 기준의 버전; 확인된 사실과 미확정 조건 |
| 정의 식별 | 구성 정의 ID·버전, 원전 위치와 실제 실독 범위, 허용 용도·검토 상태; 당시 내용의 보존본 참조 |
| 적용 근거 | 카드의 적용 조건을 지지하는 업무 자료·위치와 관찰; 법·정책·기존 절차 등 다른 설명 |
| 담당 설계 판단 | 어떤 업무 질문을 맡았는지, 예상·반대 예측, 연결되는 역할 내부 판단·입출력·인계·기억·권한·평가 요소 |
| 선택 상태 | 적용 제안 / 제외 / 기권 / 적합성 미확정과 이유. 용도 미채택과 업무 비적합, 증거 부재, 기존 절차와 중복을 구별 |
| 조합과 후보 연결 | 조합 ID·버전, 각 구성 정의의 기여·중복·충돌, 연결된 후보·수정본·탈락 및 선택 근거 |

위 표는 문서 계약이며 런타임 스키마를 확정하지 않는다. 이름이 같은 `draft-1`의 내용이 바뀌어도 과거 판단을 재구성할 수 있도록 내용 보존본을 구별해야 한다. 검토하지 않은 정의는 제외 판정을 받은 것처럼 쓰지 않고 미검토 범위로 표시한다.

고정 철학자 목록, 필수 조합 수, 정의별 가중치, 후보 생성 수·예산·반복 한도를 여기서 정하지 않는다. 점수·선별·구조적 다양성의 판정과 수용 기준·탐색 한도·진전 없음은 DG-V01 계약 대상이다. 그 미결 값을 임시 상수로 채우거나 무제한 탐색을 허용하지 않는다.

## 3. 조합과 충돌의 처리 규칙

1. 비교마다 같은 업무 목적·자료·필수 산출물·권한·완료 기준을 고정한다. 요구를 바꾸는 선택은 새 조건으로 명시하며 기존 비교의 승리로 세지 않는다.
2. 각 구성 정의를 질문과 담당 설계 판단에 연결한다. 한 정의가 여러 요소에 기여하거나 여러 정의가 같은 판단을 다룰 수 있다. 정의마다 에이전트·상위 감독·승인 노드를 만들지 않는다.
3. 상보성은 서로 다른 누락을 보완한다는 가설이다. 같은 질문·구조 선택을 반복하면 중복으로 기록하고, 같은 근거를 독립 증거 여러 표로 세지 않는다.
4. 충돌 기록에는 구성 ID·버전, 담당 판단, 양립하지 않는 제안·논거, 공통 요구 위반 여부, 추가 증거, 가능한 처리, 미해결 상태를 모두 남긴다. 선별에서 제외한 조합도 보존한다.
5. 필수 제약 위반은 해당 후보의 탈락 사유다. 다른 이점·높은 점수·다수결·사람의 위험 수용으로 검사 성공을 대체하지 않는다. 위반안을 유효한 가치 충돌의 한쪽으로 유지하지 않는다.
6. 사실·효과의 불확실성에서 생긴 긴장과 규범적 양립 불가능성을 구별한다. 실제 규범 충돌도 평균·다수결로 합의됐다고 처리하지 않으며, 원전 저자들이 필연적으로 반대한다고 추정하지 않는다.
7. 가능한 처리는 조건을 표시한 후보 분리, 해당 판단의 기권, 권한 내 새 증거 수집, 업무 결과를 실질적으로 바꾸는 사용자 선택이다. 증거가 결론을 정하면 그 이유를 기록한다. 숨어 있는 정의 우선순위로 결정하지 않는다.
8. 사용자에게 묻는 경우에는 그래프·업무 결과·남은 불확실성과 선택의 범위를 보여 준다. 내부 조합 변경마다 승인을 추가하지 않는다. 해결되지 않으면 미해결인 채 남기며 선정 개수를 채우려고 임의 봉합하지 않는다.

`L-P030-01`을 조합할 때에는 조건·행위·목적의 준칙, 보편 채택의 생각 가능성, 그 법칙의 의욕 가능성을 구별한다. 단순 대칭성·추적성 검사로 바꾸지 않는다. `L-P030-02`와 연결된 공식이라는 관계도 유지하며, 두 카드를 독립 윤리학·효과 증거 두 개로 세지 않는다. 어떤 조합도 카드의 해석 제한·금지 추론을 제거하지 못한다.

## 4. 합성 사례의 공통 S0 계약

사례는 박물관의 허가된 소장품 카탈로그 문서·표·이미지로 정확하고 이해 가능한 전시 안내물을 만드는 S0를 사용한다. 실제 파일·관람자 관찰·모델 실행은 없다. 사례별 조건은 아래에 추가하며 각 사례 안의 기준 후보·단독·조합 비교에서는 전부 동일하게 유지한다.

| 역할·인계 | 모든 비교에서 유지할 전체 산출물과 기능 |
| --- | --- |
| A 자료 해석 → B 안내물 구성 | 근거 표 CSV·해석 문서 DOCX 전체, 카탈로그 PDF·문서·표·원본 이미지의 허가된 접근 정보. 원본을 요약문으로 대체하지 않음. |
| B → C 형식·근거 점검 | A의 전체 묶음 + 안내 PDF·HTML·캡션 CSV·미리보기 PNG·구성 결정 DOCX 전체. 최종 산출물과 원본을 각 실제 형식으로 열 수 있음. |
| C 이후 | 확인 표 CSV·주석 DOCX와 앞선 전체 묶음. 모든 추가 표·표시 이미지·수정본·기각본도 원형과 버전을 보존. |

PDF와 HTML을 모두 만들며 기본 설명·정확성·접근성·확인된 가독성·마감·원본 이용 조건을 유지한다. 전체 인계는 기본 요구다. 인계가 없던 기준 후보를 만들어 조합의 이점으로 보고하지 않는다. 파일 존재와 최종 표현·실제 이용 편의는 별도 질문이다.

역할별 모델 선택 조건은 업무 설정으로 고정한다. 프레임워크가 브라우저·파일 도구를 소유·실행하고 경로·행위 권한을 검사한다. A 모델은 허가된 원본 읽기, B 모델은 승인된 작업 경로의 새 문서·표·이미지·PDF·HTML 쓰기, C 모델은 전체 읽기와 별도 점검 산출물 쓰기를 요청할 수 있다고 가정한다. 도구의 실제 이용 가능성은 별도 확인 대상이다.

모델 간 인계에서도 원형 파일·출처·허용 행위를 유지한다. 어떤 조합도 게시, 원본 덮어쓰기, 새로운 외부 접근, 사람에 대한 제재 권한을 만들지 않는다. 사례의 구조 차이는 이 기존 역할과 기능 계약 안에서 설명한다.

### 사례 A — 의미 구별과 수신자 근거 대응의 상보성

`HC-S0-A / draft-1`은 문서용 조합 예시다. 고정 조건: 카탈로그의 ‘제작자’에 확정 작가와 추정 공방이 함께 있고, B가 만든 모든 캡션의 근거를 C가 대조해야 한다. 전체 원형 파일과 출처 위치는 이미 인계되지만 최종 캡션-근거 행 대응은 아직 없다. 목적·PDF/HTML·정확성·마감·권한은 동일하다.

| 구성 정의·버전 | 담당 질문·판단 | 가능한 구조 기여 |
| --- | --- | --- |
| L-P050-01 · draft-1 | A: 같은 ‘제작자’ 이름이 확정 작가와 추정 공방을 같은 의미로 합치는가? | 원어·의미·귀속 상태 CSV를 만들고 B의 상태별 캡션 표현에 연결. 원본은 수정하지 않음. |
| L-P033-02 · draft-1 | B: 편집 중 이미 아는 근거 대응을 C에게 다시 찾게 하는 부담이 남는가? | 최종 캡션 ID-근거 행 대응 CSV를 기존 편집 기록에서 인계. C의 전체 원본 대조 책임 유지. |

- **기준·단독·조합 대비:** 기준은 파일·출처·철자·누락·출력 형식을 확인한다. 첫 정의만으로 의미 상태를 보존해도 최종 캡션 대응 탐색이 남을 수 있다. 둘째만으로 대응이 명료해져도 같은 이름에 합쳐진 의미 오류가 남을 수 있다. 조합은 의미 상태와 항목 대응을 연결하는 후보이며 에이전트 추가가 아니다.
- **대립 주장:** 현재 설정에서 직접 양립 불가능한 주장은 없다. 두 표를 하나의 표에 합칠 수 있다는 구현 선택은 가능하되 두 질문·근거·기여를 지우지 않는다. 실제 부담 감소는 아직 주장할 수 없다.
- **공통 요구 위반:** 제안상 없음; 실제 형식·정확성·전체 인계 검사는 미실시. 어느 후보든 필수 귀속 정확성을 실패하면 별도 탈락하며 이를 상보성의 실증 결과로 쓰지 않는다.
- **새 증거:** 승인된 용례·귀속 구별, 기존 편집 기록이 제공하는 대응 범위, C의 실제 역추적·오류 자료. 이미 같은 구별·대응이 있다면 두 정의의 추가 가치가 사라질 수 있다.
- **가능한 처리·미해결:** 전체 결합, 의미 구별만 추가, 대응만 추가 또는 모두 제외를 근거별로 비교한다. 상태는 상보 가설 / 추가 효과 미검증 / 실제 채택 미결이다.

### 사례 B — 같은 지면 판단에서 생기는 조건부 설계 긴장

`HC-S0-B / draft-1`. 고정 조건: PDF를 인쇄해 보는 관람자와 HTML 이용자가 있고, 확인된 관람 거리와 고정된 지면 크기가 있다. 필수 핵심 설명은 두 형식 모두 자체 완결적으로 제공하고 정해진 가독성·접근성 기준을 충족해야 한다. 추가 용어 설명은 같은 PDF의 인접 용어면에도 수록되며, 본문 옆에 중복 배치할지는 선택 가능하다. 자료·목적·마감·전체 인계·모델·권한은 동일하다.

| 구성 정의·버전 | 담당 질문·같은 설계 판단 | 서로 다른 조건부 제안 |
| --- | --- | --- |

## 6. 해석 감사와 SPLI 학습 방화벽

초기 설계·비평 경로의 렌즈 기록은 질문·구조·검토 근거의 해석 감사다. 이를 사용자의 판단 학습 또는 운영 성능 향상으로 표시하지 않는다. SPLI에서 H_phi/S_phi를 만들더라도 에피소드별 해석·출처 참조로 격리하며, 개인 정체성·철학 프로필로 저장하거나 지식 저장소·행동 규칙·개입 후보의 직접 입력으로 전달하지 않는다.

1. 실제 대안과 기존 결과의 원형·버전, 판단 차이, 확인된 H_exp를 연결한다. 표현 차이·취향 추측을 전문가 판단의 근거로 확정하지 않는다.
2. 복수의 경쟁 해석, 렌즈 없이 설명되는 가능성과 미지·미확정을 열어 둔다. **아직 보지 않은 새로운 E_phi를 얻기 전에** 질문·반대 예측·판별 조건·대상 범위를 고정하고 그 버전을 보존한다.
3. 질문은 “어떤 항목에서 이 설명이 필요했는가?” 같은 실제 업무 언어로 묻는다. 철학자 선택·도덕 성향·정체성 설문을 하지 않는다. 질문에 맞는 답을 유도하거나 나중에 예측을 고쳐 사전 예측처럼 쓰지 않는다.
4. 질문 이후의 실제 업무 행동·응답을 새 E_phi로 기록하고, 이를 통해 H_exp를 검증·갱신·기각한다. 추가 자료가 없거나 구별하지 못하면 미확정이다. H_phi/S_phi 자체와 원전 권위는 이 증거를 대신하지 않는다.
5. 증거로 갱신한 H_exp의 조건·행동·예외·근거를 바탕으로 별도의 변경 후보와 검증을 설계한다. 원 대안 문구의 복사나 해석 점수의 저장을 지식 흡수·개입 성공으로 세지 않는다.
6. 기준 환경과 후보 환경에서 관련 이전 업무 큐를 실제로 재실행·비교하고 수정·재시험한다. 후보를 고정한 뒤 튜닝에 쓰지 않은 미관측·전향 자료와 경계·회귀 검사를 수행한다. 기존 큐의 반복 성공을 미관측 검증으로 재명명하지 않는다.
7. 권한 있는 사람이 근거·실패·범위와 **정확한 환경 후보 버전**을 확인해 승격한 경우에만 그 버전이 운영에 연결된다. 그래프 확정·라이브러리 배포·내보내기·다른 버전의 성공으로 이를 대신하지 않는다.

감사 내보내기는 권한 있는 사용자가 선택하는 분기이며, 학습·승격을 위해 제작자에게 자료를 보내야 하는 필수 직렬 단계가 아니다. 개인 자료를 요청하거나 외부로 자동 업로드하지 않는다. 이 방화벽의 실제 강제·검증은 후속 구현·평가 과제다.

## 7. 비평가 격리와 판정 책임

프레임워크가 전달 묶음과 읽을 수 있는 저장소를 제한해 생성자의 렌즈 정체성·자기평가 및 다른 비평가 결론을 차단해야 한다. “보지 말라”는 프롬프트만으로 충족하지 않는다. 허가된 원본, 고정 기준, 후보의 역할·실제 모델 설정·입출력·원형 인계·도구·권한 등 기능 정보는 평가에 필요한 만큼 제공한다. 감사 저장소 전체를 비평가에게 자동 공개하지 않는다.

구조·권한 검사는 명세로 판정 가능한 필수 조건을 검사하고, 원자료 대조는 인용의 존재와 의미 지지를 구별한다. 렌즈 기반 반례 제안자는 반례·근거·예상을 제안한다. 별도 판정 책임은 먼저 그 반례의 타당성을 검토하고, 후보 대응 판정은 타당성 상태와 고정 기준에 따라 성공·실패·미결을 남긴다. 제안자가 자기 반례와 후보 실패를 최종 정답으로 확정하지 않는다.

동일 모델을 사용해도 책임·입력·기록 경계와 구성 자격 검사를 유지한다. 필수 결함을 놓친 구성의 해당 항목 자동 통과를 차단하고 관련 변경 뒤 재검사한다. 격리·별도 호출·자격 검사 통과를 모든 업무의 판단 오류 통계적 독립성 증명으로 쓰지 않는다. 공동 실패·오거절·정량 수용 기준과 비용은 DG-V01에서 별도로 다룬다.

## 8. 사용자 화면·기록·후속 검토

일반 화면에는 실제 멀티에이전트 그래프와 역할·입력·출력·전달·도구·권한·예상 업무 차이 및 미확정 이유를 표시한다. 기본 비교 화면에 철학·렌즈·철학자 이름을 노출하지 않는다. 사용자가 원할 때 권한 있는 감사 경로에서 정의·출처·조합·버전·근거·충돌 처리를 확인할 수 있게 한다.

배포 후 프레임워크가 관측 가능한 첫 제어 사건부터 입력 revision, 검토한 정의의 선택·제외·기권, 하이브리드와 단독 대안, 전체 후보·수정본·탈락본, 설계 판단, 검토 근거·미결, 사용자 결정과 정확한 버전을 연결해 기록하는 계약을 유지한다. 선정 결과만 보존하지 않는다. 공개 가능한 판단 근거를 기록한다는 뜻이며 숨은 사고과정, 인증 비밀 또는 자료 원문 전체의 무조건 수집을 요구하지 않는다. 저장·보존·가림·권한·선택적 내보내기의 구체 형식은 후속 계약이다.

작성자 자체 대조 이후 별도 계약·품질 검토를 수행했으며 담당자·범위는 [검토 보고서](review-report.md)에 기록했다. 이 검토는 세 입력 경로, 정의의 제한, 같은 업무·전체 인계, 충돌·필수 탈락, 생애주기, 학습 방화벽과 비평가 격리의 문서 대조다. 사용자 묶음 검토에서 DG-V01 기준 자료 사용에 동의받았다. 실제 산출물 비교·학술 검토·효과 시험·자격 검사·운영 채택·사람 승격은 미실시다. DG-V01의 선별·수용·한도와 DG-C01의 저장·화면·실행 연결 계약은 후속 작업이다.
