# Codex 우선 연결 — 구현과 검증 경계

> **후속 아키텍처로 대체된 범위:** 아래의 개발 호스트 계정 공유 방식은 역사적 실험이다.
> 현재 오픈소스 웹 프레임워크는 서버 소유·격리 관리형 실행기를 통해 Codex 구독을 연결하고,
> 사용자 브라우저 기기의 CLI·인증 저장소를 제품 전제로 삼지 않는다. Claude 승인 경로는
> Claude API-only로 대체됐다.

2026-09-07 사용자의 “응”은 Codex 연결 우선 구현과 Claude 승인 경로 별도 확인에 대한 동의다.
두 구독 지원 요구의 폐기, Claude API 유료 전환, 실제 사용자 자료의 외부 전송 동의가 아니다.

후속 구현에서 인증/메타데이터 RPC에 명시 `model/list` 조회를 추가했다. 업무별 모델·추론 수준
선택과 최신 검증은 [모델·음성 기록](2026-09-07-model-control-and-voice.md)에 이어 기록한다.
아래 계정 연결 시험을 실제 추론 성공의 증거로 해석하지 않는다.

## 현재 연결

입력 중심 화면을 유지하고 작은 `연결` 진입점에서 계정 상태를 확인한다.
로그인 확인·계정 연결은 업무 저장 큐와 분리되어 저장 실패/한글 입력/자료 추가 대기 중에도
작성 내용을 건드리지 않는다. frontend-design에 따라 기존 청록색/시스템 한국어 타입을 유지하며
기술 설정 마법사를 추가하지 않았다.

`app/codex_rpc.py`는 공식 JSONL stdio 프로토콜의 연결·응답 상관관계·알림·수명주기를 담당한다.
`app/codex_connection.py`는 계정/로그인 상태, URL 검증, 구독/API 구분, 메타데이터 로그를 담당한다.
`app/server.py`의 출처/CSRF 보호 안에 명시 계정 동작 API를 두었다.

로그인 경로는 `account/login/start {type:chatgpt}`만 허용한다.
이메일·토큰·원시 서버 오류·로그인 URL·Codex 홈 경로는 사용자 로그나 일반 API 출력에 섞지 않는다.
로그인 URL은 요청이 대기 중일 때만 메모리/API 응답에 있으며 HTTPS 공식 호스트를 확인해
사용자가 링크를 직접 연다. 세션 완료는 로그인 ID 상관관계와 `account/read` 재확인이 필요하다.

**공식 Codex 로그인 저장소와 공유되는 연결**이다. DeepTwin은 직접 자격 증명을 읽거나 저장하지 않는다.
사람이 새 로그인을 완료하면 같은 인증 저장소를 쓰는 Codex 도구에도 영향을 줄 수 있다.
이를 UI에 표시하며, `forced_login_method`처럼 불일치 시 기존 로그인을 해제하는 옵션을
안전장치로 사용하지 않는다. `account/logout`, API 키 로그인, 외부 ChatGPT 토큰 모드는 제공하지 않는다.

## 실제 확인과 자동 검사를 구분

로컬 설치본 `codex-cli 0.144.4`의 공식 스키마를 생성해 계정 호출 형식을 확인했다.
루트가 실제 설치본에 인증 전용 조회를 수행한 결과:

- ChatGPT 계정 종류와 Pro 플랜이 확인됨.
- 사용 한도 창 4개의 값이 반환됨.
- 재로그인/로그아웃/토큰 파일 열람/모델 추론/업무 자료 전송/유료 API 호출 없음.
- 검사 후 해당 검사 프로세스를 종료함. 실제 OAuth 신규 로그인 완료는 사람이 수행하지 않았으므로 검증 완료라고 주장하지 않음.

자동 테스트는 실제 앱·관리자·RPC와 통제된 하위 프로세스를 사용한다.
오류 및 시간 순서를 재현하는 단위 검사에서는 계정 RPC 경계 대역을 사용한다.
실제 OAuth 서버·사용자 계정을 자동 테스트에서 변경하지 않는다.

최종 소스 동결 후 루트 재실행 결과: **Python 110개 + 브라우저 28개 = 138개 통과**, 실패·건너뜀 0개.
Python에는 기존 Starlette/AnyIO 타입 별칭 deprecation warning 1건이 남는다.
루트가 밝은 계정 연결 화면, 어두운 모바일 로그인 대기 화면, API 계정 구분 화면을 직접 시각 검토했다.
해당 PNG는 통제된 계정 대역의 결과이며 실제 사용자 계정 화면이라고 표시하지 않는다.
`git diff --check` 및 Python 구문 검사 통과, 커밋·스테이징·푸시 없음.

현재 실행 중인 사용자 개발 서버 `http://127.0.0.1:4193/`도 새 연결 기능으로 재시작했다.
이 서버의 실제 `/api/providers/codex/check`에서 ChatGPT/Pro와 한도 창 4개를 확인했다.
기존 업무 보관함을 초기화하지 않았으며 모델 호출과 신규 로그인은 시작하지 않았다.

TDD/독립 검토가 잡고 수정한 항목:

- 설치본의 한도 조회는 params null/생략인데 전송 계층이 dict만 허용하던 계약 불일치.
- 한도 조회 중 프로세스가 죽어도 연결됨이 남는 문제.
- 만료 취소의 notFound를 완료와의 경합으로 처리하지 않아 계정 상태가 오래된 문제.
- 연결 확인 중 패널 재진입과 키보드 포커스 유지.
- 응답 크기/알림/동시 요청/송신 큐 제한, 잘못된 응답 ID, 하위 프로세스 종료/시간 초과,
  금지된 도구 요청 거부, API/외부 토큰 로그인 거부.

## 아직 검증하거나 구현하지 않은 것

- 이 계정으로 실제 LLM 추론을 완료했다는 검증.
- 자료 이해, 철학 렌즈/독립 크리틱, 실제 구조별 후보 그래프, 승인된 환경 실행, 프레임워크 소유 도구.
- Claude 구독 통합에 필요한 사전 승인. 이를 API 대체로 처리하지 않음.
- Windows/Linux 및 다른 Codex 버전의 호환성, 최종 설치 패키지, 엔터프라이즈 등록/규정 검토.
- 상속되는 Codex 사용자 설정의 앱 범위 MCP 시작 부작용에 대한 완전한 프로세스 격리.
  인증 전용 RPC 허용목록은 명령/모델 실행을 금지하지만 초기화 자체의 모든 네이티브 부작용 격리를 증명하지 않는다.
- 600초 대기 만료는 상태를 다음 조회할 때 평가한다. UI가 닫혀도 정시 취소되는 타이머가 아니다.
