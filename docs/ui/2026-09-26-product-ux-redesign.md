# 제품 화면 재설계 — 여정 중심 구조 (2026-09-26)

상태: **설계안 (소유자 검토 대기)**. 구현·사용성 수용 증거가 아니다.
기준 계약: `specs/001-autonomous-release/contracts/experience.md`(UX-001) §4·§7·§8·§10·§12,
`docs/superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md` §10,
`control-prototype/`(2026-09-06 시제품, 합성 데이터).

## 0. 왜 다시 설계하는가

2026-09-26 실제 서버를 합성 데이터로 띄워 모든 화면을 캡처하고 조작해 본 결과는 이렇다.

- **결과·과정 피드백을 줄 곳을 찾기 어렵다.** "내 버전"은 관제 화면 맨 아래에 있고, 어떤 산출물을
  고치는지 표시되지 않는다. 최종 결과물이 따로 구분되지 않는다. 과정(역할·전달·도구·순서)에 대한
  피드백은 입력할 곳이 없다.
- **트레이싱이 사실상 불가능하다.** 노드마다 `완료, 수행 1회, 산출물 1건`만 보인다. 시도별 입력,
  출력, 전달, 도구·모델 호출, 시간, 비용을 볼 수 없다. 기록 화면은 실행별로 거를 수 없고
  `work.revised · 성공 · 관련 기록 1개` 같은 줄만 반복된다.
- **노드와 산출물이 연결되지 않는다.** 그래프에서 n05를 골라도 산출물 칸에는 n15의 것이 남아 있다.
- **정보 구조가 없다.** 공통 메뉴가 없다. 관제 화면은 실행 목록, 텍스트 노드 목록, 제어, 승인,
  그래프, 노드 버튼, 상세, 산출물, 전체 산출물, 내 버전이 위계 없이 세로로 쌓여 있다.
  기록 화면에는 Claude 키, API 자격증명, 실행 한도 같은 설정이 섞여 있다.
- **내부 용어와 원시 값이 드러난다.** `dispatch`, `block_dependants`, `{"handler_id":…}`,
  `text/plain (선언)`, UUID, 해시, 마이크로초 시각, 이벤트 이름, 영어 서버 사유가 그대로 나온다.

**원인:** 태스크를 백엔드 계약 단위로 진행하면서 화면에는 부품만 붙였다. 여정과 정보 구조 설계는
마지막 태스크(T078)로 미뤄졌다. 브라우저 테스트는 "문구·버튼이 있는가"만 확인했다.
9월 초 시제품(`control-prototype/`)과 UX-001 계약에는 올바른 구조가 이미 있었지만, 별도 시제품이라
제품으로 옮겨지지 않았다.

## 1. 소유자 결정 (2026-09-26)

- **화면 기술:** 빌드 없는 브라우저 기본 ES 모듈을 유지한다(plan.md). 그 위에 디자인 시스템(토큰,
  레이아웃 부품, 표시 규칙)을 먼저 만든다. 조합이 번거로워지면 빌드 없이 쓰는 작은 라이브러리
  (예: Preact+htm, 파일로 들여와 CSP `script-src 'self'` 유지)를 그때 따로 검토한다.
  Next.js와 Vite+React는 채택하지 않는다. 다음 세 가지와 충돌하거나 비용이 크다.
  - 인라인 스크립트와 CSP
  - 인스턴스별 무작위 경로(`/<32hex>/`)와 빌드 시점 경로
  - 배포 구성과 SBOM
- **과정 피드백:** 산출물·전달물 대안(내 버전)에 더해 **선택 표시와 선택 메모**를 허용한다.
  설명은 어떤 단계에서도 필수가 아니다(FR-016).
- **목업 방식:** 별도 목업을 만들지 않는다. 실제 앱 안에서 실제 서버와 합성 데이터로 화면을 만든다.
  확인받은 화면이 곧 제품이다.

## 2. 원칙

1. **한 화면 한 목적.** 그 화면에서 할 일이 첫 화면 높이 안에 보인다. 부가 정보는 접거나 옆 패널로 뺀다.
2. **선택이 따라간다.** 노드를 고르면 그 노드의 수행·시도·입력·산출물·전달·도구 기록이 함께 바뀐다.
   예전 선택을 다른 대상의 기록처럼 보이지 않는다(UX-001 §4).
3. **사람 언어.** 내부 ID·해시·스키마 이름은 "기술 정보" 접힘 안에만 둔다. 시각은 "3분 전"과 절대
   시각(초 단위)으로 표시한다. 상태는 색만이 아니라 글과 아이콘으로 구분한다.
4. **없는 것은 없다고.** 빈 상태는 무엇이 없는지와 다음에 할 일을 한 문장으로 말한다. 미래 단계를
   비활성 설명문으로 나열하지 않는다.
5. **정직한 표시는 유지한다.** 전달됨, 활용 근거, 영향은 다른 주장이다. 추정은 추정으로 표시한다.
   시뮬레이션은 시뮬레이션으로 표시한다. 기존 증거 규칙(헌법 IX)은 바뀌지 않는다.

## 3. 정보 구조 (앱 셸)

```
┌──────────────┬──────────────────────────────────────────────────────────────┐
│ DeepTwin     │ [업무: 화요일 공간 안내] · [환경 v3 운영] · (운영|설계 검토|실험|과거 기록) │
│              ├──────────────────────────────────────────────────────────────┤
│ 업무         │                                                              │
│ 실행         │                     주작업면 (화면별)                           │
│ 버전·실험    │                                                              │
│ 기록         │                                                              │
│ ─────        │                                                              │
│ 설정         │                                                              │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

- 왼쪽 메뉴는 모든 인증 화면에 공통이다. 좁은 화면(< 1024px)에서는 상단 메뉴 버튼으로 접힌다.
- 상단 맥락 줄에는 현재 업무 이름, 환경 버전, 모드 표식(UX-001 §4)을 둔다. 긴 ID는 상세에 둔다.
- 화면과 기존 파일의 대응은 다음과 같다. 파일 이름은 바꾸지 않는다.
  - 업무 → `work.html`
  - 실행 → `observe.html` (목록과 상세)
  - 버전·실험 → `versions.html`
  - 기록 → `records.html`, 로그와 내보내기만 둔다.
  - 설정 → `settings.html`. 계정, Claude 연결, API 자격증명, 실행 한도, 백업·보존, 업데이트,
    확장을 모두 여기로 옮긴다.
- 시작·로그인(`start.html`)만 셸 밖에 둔다. "개발 미리보기" 배너는 모두 없앤다.

## 5. 화면 명세

### 5.1 업무 (`work.html`)

단계형 작업면이다. 이미 도달한 단계만 펼쳐 보인다.

```
┌ 업무: [이름 편집] ───────────────────────────── 저장됨 3분 전 ┐
│ ① 설명·자료        [설명 입력칸……………………]  [자료 추가] [마이크]     │
│    자료 3개: 요약.pdf (전체 읽음) · 표.csv (일부 읽음: 1–200행) · …    │
│ ② 업무 이해        [업무 이해하기]  또는 이해 결과 카드 + 대화           │
│ ③ 환경 제안        [환경 제안받기]  또는 후보 비교(그래프 한 개 크게 +   │
│                    같은 초점 요약) + [이 안 선택]                     │
│ ④ 준비·시작        준비된 환경 요약 + [업무 시작]                      │
└──────────────────────────────────────────────────────────────┘
오른쪽 접힘 패널: 이 업무의 실행 목록, 내보내기, 원본 삭제
```

- 다음 단계를 할 수 없으면 이유를 한 문장으로 보인다. 예: "자격을 갖춘 렌즈가 없어 환경을 제안할 수
  없습니다." 서버 원문은 "기술 정보" 접힘 안에 둔다.
- 내보내기와 원본 삭제는 업무 메뉴(⋯)로 옮긴다. 매 업무의 필수 단계가 아니다(US7-3).

### 5.2 실행 목록 (`observe.html` 기본)

| 업무 | 환경 버전 | 상태 | 시작 | 걸린 시간 | 비용(추정) | 사람 대기 |
|---|---|---|---|---|---|---|

행을 누르면 실행 상세(`observe.html#run=<id>`)로 간다. 상태는 글과 아이콘으로 표시한다.
완료, 진행 중(미완료), 실패, 사람 승인 대기, 취소됨을 구분한다.

### 5.3 실행 상세 — 가장 중요한 화면

```
┌ 화요일 공간 안내 · 실행 #12 · 완료 · 14:02–14:09 (7분) · 약 $0.42 ─ [이어서][중단][복구] ┐
├──────────────────────────────────────────────────────────────────────────┤
│ 최종 결과                                                                  │
│ ┌ 안내문.pdf (3쪽) — "안내문 작성" 역할이 만듦 ────────────── [미리보기][내려받기] ┐ │
│ │  [미리보기 영역]                                                          │ │
│ │  [내 버전 만들기]   이 결과 전체: ( ) 괜찮음  ( ) 확인 필요   [메모(선택)]      │ │
│ └──────────────────────────────────────────────────────────────────────┘ │
├───────────────────────────────┬──────────────────────────────────────────┤
│ 과정                          │ 선택: 근거 확인 (에이전트) · 수행 1 / 시도 2 ▾ │
│ [그래프 | 타임라인] 전환        │ [입력] [산출물] [전달] [도구·모델] [기록]      │
│                               │                                          │
│  근거 확인 ─▶ 초안 ─▶ 검토 ─▶ 안내문 │  입력: 요약.pdf v1 (앞 단계 "자료 수집" 시도 1) │
│   ✓        ✓      ⚠      ✓    │  산출물: 근거표.csv (12행) [열기][내 버전]      │
│                               │  도구·모델: 모델 호출 2회 · 입력 8.1k/출력 1.2k  │
│  타임라인:                     │           토큰 · 41초 · 약 $0.05             │
│  14:02 자료 수집 시도1 완료       │           웹 읽기 1회 (허용된 출처) 3.2초      │
│  14:03 근거 확인 시도1 실패(시간초과)│  기록: 이 시도의 사건 5개 [전체 기록에서 보기]   │
│  14:04 근거 확인 시도2 완료       │                                          │
│  …                            │  이 단계에 대해: ( ) 괜찮음 ( ) 확인 필요 [메모] │
└───────────────────────────────┴──────────────────────────────────────────┘
```

- **최종 결과:** 그래프의 출구 역할이 만든 산출물과, 저장·보고 단계가 받은 산출물이다.
  여러 개면 모두 보인다. 최종 결과가 없으면 "아직 최종 결과가 없습니다"와 멈춘 지점을 표시한다.
- **과정:** 그래프와 타임라인은 같은 선택을 공유한다. 노드를 고르면 오른쪽 상세가 그 노드의
  수행·시도로 바뀐다. 기본값은 가장 최근 시도이고, 과거 시도를 고를 수 있다. 과거 시도에 최신
  산출물을 붙이지 않는다(UX-001 §7).
- **상세 탭:** 입력, 산출물, 전달, 도구·모델, 기록. 모두 같은 수행·시도를 기준으로 한다.
  - 입력: 앞선 산출물의 정확한 버전.
  - 전달: 보낸 버전, 받은 수행·시도, 수신 확인. 전달됨과 활용 근거는 다른 주장으로 구분한다.
  - 도구·모델: 호출마다 제공자·모델, 토큰, 시간, 비용(추정 표시), 오류·재시도, 결과 파일.
    숨은 추론은 저장하지 않으므로 보이지 않는다고 명시한다.
- **내 버전:** 산출물 옆 [내 버전]을 누르면 같은 자리에 원본 | 내 버전 | 차이 분할 작업면이 열린다
  (§5.4). 페이지 맨 아래로 내려가지 않는다.
- **승인 대기:** 사람 승인이 필요한 노드는 그래프에 표시하고 상단에 한 줄 배너를 띄운다.
  [승인 화면 열기]로 간다.
- **통계 줄:** 걸린 시간, 모델·도구 호출 수, 추정 비용. 제공자가 확인하지 않은 비용은 "추정"으로
  표시하고, 모르면 "미확인"으로 표시한다.

### 5.4 내 버전 작업면

```
┌ 내 버전 — 근거표.csv (근거 확인 · 시도 2) ─────────────── 자동 저장됨 ┐
│ [원본 | 내 버전 | 차이]  (넓은 화면에서는 원본과 내 버전을 나란히)          │
│  …편집기(형식별: 텍스트·표·파일 올리기)…                                 │
│ 바꾼 줄·칸만 내 근거로 기록합니다. 나머지는 검토하지 않은 영역입니다.         │
│ [ ] 전체를 검토했습니다            [차이 살펴보기]   [닫기]              │
└──────────────────────────────────────────────────────────────┘
```

- 제목에 어떤 산출물, 역할, 시도인지 항상 보인다.
- "분석용으로 고정"은 UX-D07에 맞춰 **"차이 살펴보기"**로 바꾼다. 동작(정확한 수정본 고정 후 차이
  관찰)은 같다.
- 이유·지시 칸은 없다. 메모는 과정 피드백의 선택 메모와 같은 것이며 대안이 아니다.

### 5.5 차이 살펴보기

UX-001 §8을 따른다. 첫 화면은 관찰 차이와 관련 실행 구간이다. 차이를 고르면 원본·대안 부분,
입력·전달·도구 근거, 경쟁 설명이 함께 나온다. 현재 `inquiry.mjs`의 기능(설명 제안, 질문, 증거,
변경 후보 제안)은 유지하고 이 화면으로 옮긴다.

### 5.6 버전·실험 (`versions.html`)

현재 운영 버전 카드, 후보 목록(게이트·검증 상태), 실험(회차 쌍 비교·정지 이유), 승인·적용·롤백을
각각 탭으로 나눈다. 기존 `versions.mjs`와 `experiments.mjs`의 기능은 유지한다.

### 5.7 기록 (`records.html`)

- 사건 로그에 필터(업무, 실행, 종류, 기간)와 사람 문장 요약을 둔다.
  예: `work.revised` → "업무 설명을 고쳤습니다 (수정본 4)". 원 이벤트 이름은 상세에 둔다.
- 실행 상세의 [전체 기록에서 보기]는 이 화면을 해당 실행·시도로 걸러서 연다.
- 내보내기(범위 선택 → 미리보기 → 파일)는 유지한다. 제작자에게 보낼 피드백 메모 칸을 추가한다.
  자동 전송은 없고 파일 안에만 들어간다(US7).

### 5.8 설정 (`settings.html`)

왼쪽 하위 메뉴: 계정과 세션, 모델 연결(Claude API, API 자격증명), 실행 한도, 백업·보존, 업데이트·복구,
확장, 서비스 클라이언트(Bearer, T025 연결 뒤). 기록 화면에 있던 설정 항목을 모두 여기로 옮긴다.

## 9. 검증 방식

- **여정 테스트:** 사람이 목적을 끝까지 달성하는지 브라우저로 확인한다. 예:
  "실행 상세에서 n05를 고르면 n05의 산출물이 보이고, 내 버전을 만들어 차이를 살펴볼 수 있다."
  "시도 2의 입력과 모델 호출이 보인다." 문구가 있는지만 보는 확인은 보조로만 둔다.
- **스크린샷 검토:** 단계마다 1280px, 390px, 어두운 테마를 캡처해 소유자에게 보내고 확인받는다.
- **기존 보장 유지:** 보안(CSP, textContent, CSRF), 정직한 표시, 시뮬레이션 표기 테스트는 유지한다.
  배치가 바뀌어 달라지는 기대값만 고친다.
- 자동 검사 통과는 사용성 수용이 아니다. 소유자의 화면 확인을 따로 기록한다.

  `prefers-color-scheme: dark`에서 어둡게 바뀐다. 실행 그래프 판은 시제품처럼 두 테마 모두 어둡다.
  기존 규칙은 토큰을 읽도록 고쳤고, 짧은 옛 변수 이름은 개발 미리보기 셸(`index.html`)을 위해 별칭으로 둔다.

  `ui-shell.mjs`, `ui-parts.mjs`, `ui-format.mjs`를 두었다. 설정 화면의 부팅은 `settings-page.mjs`다.
- **앱 셸** (`ui-shell.mjs`): 인증 화면마다 같은 왼쪽 메뉴(업무 · 실행 · 버전·실험 · 기록 | 설정),

  나온다: 실행 화면은 고른 실행(앞 8자, 전체는 title), 업무 화면은 저장한 업무 설명의 첫 줄과 수정본.

  알지 못하므로 표시하지 않는다. 1024px 미만에서는 메뉴가 **메뉴** 단추 뒤로 접힌다. 서랍이 열리면
  본문은 inert가 되고 초점은 현재 화면 링크로 간다. Esc·닫기 단추·배경으로 닫으면 초점이 단추로 돌아온다.

  접힘, 빈 상태, 상태 칩(글과 기호, 색만 쓰지 않음), 버튼 변형(주·보조·위험·조용함), 키-값 목록,
  시각 표시. 모두 `textContent`로만 글을 넣는다. 이번 단계에서 탭 부품은 아직 화면에 쓰지 않았다.
- **표시 규칙** (`ui-format.mjs`): "3분 전"과 이 기기 시간대의 절대 시각(초), 앞 8자 ID, 바이트, 매체
  종류, 내부 용어 사전(노드 종류, 연결 종류, 실패 처리, 실행 명령, 공개 사건 117종의 주제와 문장, 사건
  상태, 오류 코드). 성공하지 않은 사건은 완료형 문장 대신 주제로 적어 끝난 일처럼 읽히지 않게 했다.
  모르는 사건은 "기록된 사건"이고 원 이름은 기술 정보에 남는다. 서버 어휘와 사전이 어긋나면
  `app/tests/test_ui_format_mirror.py`가 실패한다.
- **적용한 곳:**
  - 기록 줄: 사람 문장, 상태 칩, 상대·절대 시각, 관련 기록 수, 오류의 뜻. 원 사건 이름·순번·UTC 시각·
    오류 코드는 줄마다 기술 정보에 있다.
  - 노드 상세: 실패 처리와 연결 종류를 말로 적는다. 처리기 설정 JSON은 기술 정보에 있다.
  - 산출물 줄: `text/plain (선언)` 대신 "텍스트". "형식은 산출물을 만든 쪽이 밝힌 값"이라는 사실은 목록
    위 한 문장으로 남겼다. 원 형식, 산출물 ID, SHA-256은 기술 정보에 있다.
  - 실행 ID는 앞 8자로 보이고 전체는 기술 정보와 선택 목록의 title에 있다.
  - `새 dispatch 중단` → `새 작업 보내기 중단`. 전송 검증 안내의 영어 괄호(qualification,
    transport_unqualified, verified installation, matched 4/4)를 뺐다. "기록 화면에서 키를…" 같은

  - 업무 입력칸 아래: "마이크 입력은 아직 지원하지 않습니다."
  - 실행 화면 머리: "새 실행은 업무 화면의 '실행 시작'에서 준비된 환경이 있을 때만 시작합니다."
  - 설정 > 모델 연결: "Codex 구독 연결(관리형 실행기)은 아직 이 화면에서 지원하지 않습니다."
  - 시작 화면 소개: 설정과 로그인, 로그인 뒤 업무 화면으로 이어진다는 것.
  `index.html`(개발 미리보기 셸이며 지원 서버의 `/`가 아님)은 손대지 않았다.
- **설정·기록 분리:** `settings.html`이 계정과 세션, 모델 연결(Claude 연결, API 자격증명과 전송 검증),
  실행 한도, 백업·보존, 업데이트·복구, 확장, 브라우저 권한을 한 번에 한 칸씩 보인다. 넓은 화면에서는
  왼쪽 목록, 좁은 화면에서는 위쪽 단추로 고른다. 칸은 주소 조각으로 고르며, 예전 항목 이름
  (`#records-credentials` 등)으로 열어도 그 항목이 든 칸이 열린다. 모듈과 요소 id는 그대로이고
  마운트하는 화면만 바뀌었다. `records.html`에는 사건 기록과 내보내기 안내만 남았다. 넓은 화면에서
  내보내기 안내는 기록 옆에 있다. "백업이 없으면 없다고, 자동 삭제는 없다고" 말하는 문장은 그대로
  설정 화면으로 옮겼다.
- **업무 화면(가볍게):** 셸과 페이지 머리를 적용했다. 붙어 보이던 두 링크는 각각 어디로 가는지 적은
  두 개의 이동 단추로 나눴다. 단계 구조는 바꾸지 않았다.
- **검사:** node 단위 테스트(`ui-format`, `ui-parts`, `ui-shell`, `settings-page` 추가), 브라우저 테스트
  `browser-shell.test.mjs`(모든 셸 화면의 메뉴와 `aria-current`, 배너 없음, 두 테마, 1024px 미만 접힘과

  해당 칸을 열도록 바꿨고, 보안·정직 표시 검사는 그대로 두었다.

  매니페스트 SHA-256은 아직 본문에 그대로 보인다.

    어긋나면 `test_ui_format_mirror.py`가 실패한다.

## 13. 단계 4 반영 기록 (2026-09-26)

상태: **구현됨, 소유자 화면 검토 대기.** 자동 검사 통과는 사용성 수용이 아니다(§9). 화면은 단계 3과 같은
fixture(`app/tests/fixtures/trace_server.py`, 테스트 행위자, 제공자 호출 없음)로 찍었다.
근거 문서: `specs/001-autonomous-release/evidence/process-feedback-2026-09-26.md`.

### 13.1 과정 피드백 저장 (§6)

- **레코드:** 새 불변 레코드 종류 `process_feedback`(`process-feedback-v1`, `app/services/run_feedback.py`).
  - 대상은 실행 전체(`{scope: run}`) 또는 노드의 정확한 수행·시도(`{scope: step, node_id, visit_no,
    attempt_no}`)다. 실행기가 직접 처리해 시도 기록이 없는 수행은 `attempt_no: null`로 가리킨다.
  - 표시(`ok`·`needs_attention`)와 메모는 각각 선택이다. 저장하려면 둘 중 하나만 있으면 된다. 이유는
    어디서도 묻지 않는다(FR-016).
  - 메모 한도는 **4,000자**(유니코드 코드 포인트)다. 보이는 글자가 하나는 있어야 하고, 탭과 줄바꿈은
    그대로 두며 다른 제어 문자는 받지 않는다.
  - 대상마다 식별자가 하나이고, 수정본 n은 그 식별자의 레코드 판 n이다. 수정본 1은 실행 매니페스트를,
    n은 n-1을 부모로 가진다. 바꾸면 새 수정본이 앞 것을 대신하고, 지우기도 `cleared` 상태의 새 수정본이다.
    지우거나 덮어쓰지 않으므로 이력이 모두 남는다.
  - 바꿀 때는 기준 수정본(`expected_revision`)을 적는다. 다른 화면이 먼저 바꿨으면 `409`로 거절한다.
- **쓰기 경로:** 다른 소유자 명령과 같다. CSRF를 확인한 같은 출처 POST, 명령마다 명령 ID(같은 명령의 재전송은
  같은 수정본을 돌려주고, 같은 ID에 다른 내용이면 `409`), 레코드와 공개 사건 `feedback.recorded`를 한
  트랜잭션에 쓴다. 사건에는 대상 종류, 표시(없으면 `none`), 메모 유무, 지움 여부, 수정본만 있고 메모 글은 없다.
  사건은 실행을 가리키므로 기록 화면의 `#run=` 거르기에 나온다.
- **경로(`run-feedback-v1`):** `GET|HEAD /api/v1/runs/{run_id}/feedback`(현재와 이력),
  `POST /api/v1/runs/{run_id}/feedback`(표시·메모 저장 또는 지우기). 브라우저 세션 전용이고 Bearer는 `401`이다.
  대상은 그 실행의 트레이싱에 있어야 한다(없으면 `404`). 경로는 146개, 기여는 29개가 되었다.
- **트레이싱:** `run-trace-v1`에 `feedback {run, steps}`가 붙고, 시도(와 시도 없는 수행)마다 현재 피드백이
  붙는다. 지운 대상은 `steps`에 수정본과 함께 남고 제자리에는 `null`이다.
- **내보내기:** 내보내기 계약에 자연스러운 자리가 있었다. `events` 범주가 이미 실행의 소유자 결정(승인)을
  메타데이터로 싣는다. 그래서 피드백이 있으면 `events/run-feedback.json`에 모든 수정본을 메타데이터(대상, 표시,
  상태, 메모 길이)로 싣고 메모 글은 싣지 않는다. `alternatives` 범주에는 절대 들어가지 않는다.
- **대안이 아니다(UX-AC05):** 피드백은 별도 종류라 대안·초안·차이·가설·탐구를 세는 경로가 읽지 않는다.
  기억 컴파일러, 변경 후보 컴파일러, 지식 등록부는 이 종류의 참조를 거절한다. 그래서 탐구에서 쓰더라도
  소유자 관찰일 뿐 정답이나 규칙의 근거가 될 수 없다. 테스트가 이를 확인한다(`test_run_feedback_api.py`).

### 13.2 과정 피드백 화면 (§5.3)

- **"이 결과 전체":** 최종 결과 블록 끝에 괜찮음·확인 필요 토글(`aria-pressed`)과 [메모 쓰기]가 있다. 최종
  결과가 없는 실행에서는 제목이 "이 실행 전체"다.
- **선택한 시도:** 선택 칸의 수행·시도 고르기 아래, 탭 위에 같은 조작이 있다. 제목은 "이 단계: 승인된
  안내문을 저장 도구로 기록한다 · 시도 1"처럼 단계 이름과 시도 번호를 적는다. 실행 전체를 고르면 이 칸은 없다.
- **저장:** 자동 저장하지 않고 [저장]을 눌러야 한다. 저장하면 "저장됨 · 3분 전"(제목에 절대 시각)이 보인다.
  [지우기]는 저장된 피드백이 있을 때만 있고, 지운 뒤 "이전 기록은 남아 있습니다"라고 말한다. 눌린 표시를 다시
  누르면 표시가 빠진다. 안내 문장은 "이유를 적지 않아도 됩니다. 표시만, 메모만, 또는 둘 다 남길 수
  있습니다."다. 다른 곳에서 저장해도 쓰는 중인 다른 칸의 내용은 지워지지 않는다. 오래된 화면에서 저장하면
  최신 내용을 불러오고 까닭을 적는다.
- **표식:** 그래프 노드 상자 오른쪽 위에 작은 표식(! 확인 필요, ✓ 괜찮음, ✎ 메모만)이 있다. 표식의 말은 SVG
  `<title>`에 있고, 노드 목록 단추 끝에 " · 피드백: 괜찮음"처럼 적는다. 색만으로 구분하지 않는다. 타임라인은
  정확한 시도(시도 없는 수행은 수행 줄)에 표식이 붙는다. 한 노드의 표식은 확인 필요 > 괜찮음 > 메모 순이다.
- **머리 요약:** 머리에 "내 피드백"과 칩이 붙는다. 예: [결과 전체: 확인 필요] [확인 필요 2개 단계]
  [괜찮음 1개 단계]. 칩마다 자기 색을 쓰므로 괜찮음 수가 경고색으로 보이지 않는다. 단계 수는 노드 수다.

### 13.3 차이 살펴보기 (§5.5)

- **자리 — 산출물 아래 제자리:** [차이 살펴보기]를 누르면 떼어 놓은 "차이와 설명" 카드 대신 편집기 바로
  아래, 같은 산출물 칸 안에 보기가 열린다. 최종 결과면 최종 결과 카드 안이고, 선택 칸의 산출물이면 선택 칸
  안이다. 선택 칸에서 편집 중이면 과정 영역이 한 열이 되므로 보기도 넓게 쓴다.
  - **고른 까닭:** 소유자는 방금 고친 산출물을 떠나지 않는다. 원본과 내 버전이 바로 위에 남는다. §5.3의
    "페이지 맨 아래로 내려가지 않는다" 원칙과도 같다. 관련 실행 구간은 [과정에서 이 단계 보기]로 과정에
    이어진다.
  - **버린 안:** 실행 상세 안의 전용 보기는 산출물과 편집기를 가린다. 그러면 돌아갈 상태(어느 산출물, 어느
    수정본)를 따로 관리해야 한다. 좁은 화면에서는 어느 쪽이든 세로로 쌓이므로 차이가 없다.
- **첫 화면(UX-001 §8):**
  - 근거 범위 한 줄: "내가 바꾼 N곳이 근거입니다. 바꾸지 않은 부분은 검토하지 않은 영역으로 남고, 영향
    범위는 따로 조사합니다." 부분 범위와 검토하지 않은 영역을 늘 보인다.
  - 관측된 차이 목록.
  - 관련 실행 구간: 그 산출물을 만든 단계, 수행·시도, 받은 입력(앞 단계와 시도, 산출물 역할), 도구·모델
    호출(토큰, 결과). 모두 트레이싱에서 읽으며(`run-trace.mjs` `differenceSegment`) 없는 값은 만들지 않는다.
- **차이를 고르면:** 원본 부분과 내 버전 부분(줄 번호), 앞뒤 3줄 문맥(바뀐 줄은 −/+와 화면 낭독용 글)이
  나온다. 위치는 제안된 정렬이고, 원인은 해석하지 않았다고 적는다. 부분은 편집기가 고정한 바로 그 두
  내용으로 보인다. 고정 중에 계속 쓰던 경우처럼 두 내용이 확실하지 않거나 파일 대안이면 부분을 보이지
  않고 까닭을 적는다.
- **탐구(`inquiry.mjs`, 이 보기 안에 넣음):** 경쟁 설명은 소유자가 명시적으로 요청할 때만 만들고 계속
  `proposed`다. 질문은 모두 선택이다. 근거, 판단, 변경 후보 제안(적용하지 않음), 감사 상세는 그대로다. 보기를
  여는 일은 차이를 읽거나 한 번 관측할 뿐 모델을 부르지 않는다(브라우저 여정 테스트가 요청을 확인한다).

### 13.4 단계 3 화면에서 본 것 정리

- **"모든 산출물":** 실행 화면에서 뺐다. 기록 화면(`records.html#artifacts`)의 "모든 산출물"로 옮겼다. 줄마다
  [실행 화면에서 열기] 링크가 있어 `observe.html#run=…&artifact=…`로 그 실행을 열고 산출물을 미리 본다.
  실행 화면에는 "이 화면은 이 실행의 것만 보입니다"와 기록 화면 링크만 남았다.
- **승인 카드:** 결정할 일이 없으면 "승인 [이 실행의 승인 기록 2건 · 보기]" 한 줄로 접힌다. 결정할 일이 있거나
  방금 결정했으면 펼쳐 둔다. 이 카드의 기록 수는 시도별 승인 요청 수다. 게이트 결정은 과정의 기록 탭에 있다.
- **승인 시한:** UTC가 아니라 이 기기 시간대의 절대 시각(초 단위, `ui-format.mjs`)으로 보인다.
- **기록 화면의 `run.stopped`:** 칩이 사건 기록의 성공 여부가 아니라 실행 결과다. 예: "실패로 멈춤"(오류색),
  "완료", "취소·거절로 멈춤". 사건 기록 자체의 상태는 기술 정보의 "사건 기록 상태"에 있다. 멈춤 이유 8가지 모두
  말이 있고, 서버 어휘와 어긋나면 `test_ui_format_mirror.py`가 실패한다.
- **[다음 기록 보기]:** 짧은 쪽이 오면 쪽이 차거나 서버의 커서가 더 나아가지 않을 때까지 이어 읽는다. 끝이면
  단추를 숨긴다. 거른 읽기는 다른 사건을 지나칠 수 있으므로 짧은 쪽만으로 끝이라고 판단하지 않는다. 한 번에
  최대 40번 읽는다.

### 13.5 미룬 것과 알려진 한계

- **피드백 이력 화면:** 서버는 모든 수정본을 돌려주지만(`GET …/feedback`의 `history`, 내보내기) 화면은 현재
  상태만 보인다.
- **전달 단위 피드백:** 대상은 실행과 수행·시도다. 전달(보낸 것→받은 것) 자체를 따로 가리키는 대상은 없다.
- **탐구에서 피드백 읽기:** 관찰로만 쓸 수 있게 막아 두었을 뿐, 아직 피드백을 읽는 탐구 경로는 없다.
- **차이 보기 다시 열기:** 새로고침하면 보기는 닫힌다. 다시 보려면 편집기에서 [차이 살펴보기]를 다시 누른다.
  그러면 기존 동작대로 같은 수정본의 대안이 하나 더 고정된다.
- **관련 실행 구간:** 산출물을 만든 단계 하나만 보인다. 그 앞 단계들의 사슬과 받은 입력의 내용은 과정 보기에서 본다.
- **머리 요약:** 단계 수는 노드 단위다. 한 노드의 여러 시도에 서로 다른 표시가 있으면 가장 강한 것으로 센다.
- 단계 5–6 항목(실행 목록 표, 기록 필터 확대, 키보드·스크린리더 점검표)은 그대로 남았다.

## 14. 단계 5 반영 기록 (2026-09-26)

상태: **구현됨, 소유자 화면 검토 대기.** 자동 검사 통과는 사용성 수용이 아니다(§9). 업무 화면은 설계 흐름
fixture(`app/tests/helpers/design-arc-fixture.mjs`: 운영 상태의 거절, 그리고 테스트 행위자의 **시뮬레이션 자격**
환경)로, 실행 목록·기록·버전·실행 상세는 단계 3–4와 같은 fixture(테스트 행위자, 제공자 호출 없음)로 찍었다.
화면은 1280×900, 390×844, 어두운 1280의 전체 페이지다. 서버 경로는 늘지 않았다(146개, 기여 29개). 읽기 응답에
필드 몇 개만 더했다(`docs/release/api-compatibility.md` §3d).

### 14.1 업무 단계형 화면 (§5.1)

- **단계:** ① 설명·자료 · ② 업무 이해 · ③ 환경 제안 · ④ 준비·시작(`work-steps.mjs`). 도달한 단계와 다음 단계
  하나만 그린다. 그 뒤 단계는 그리지 않으므로 비활성 문구 벽이 없다. 다음 단계에는 "다음 할 일" 한 줄과
  UX-D06 이름의 단추 하나만 있다(`업무 이해하기` → `환경 제안받기` → `이 설계로 준비` → `업무 시작`).
- **도달 규칙(서버가 가진 것만 센다):** ②는 이 업무의 작업 모델이 있을 때, ③은 이 업무의 설계 요청이 있을 때,
  ④는 준비된 환경이 있을 때 도달한다. 다음 단계는 가장 멀리 도달한 단계의 다음이다.
  - **완료 규칙:** ①은 저장됐고 미저장 편집이 없으며 뒤 단계에 도달했을 때 완료다. ②는 현재 수정본을 이해한
    모델을 수락했을 때 완료다. 앞 수정본의 모델은 현재 수정본의 이해가 아니다. ③은 준비된 환경이 있을 때,
    ④는 이 업무로 시작한 실행이 있을 때 완료다.
  - **예외:** 테스트 행위자가 이해 없이 설계 요청을 만든 경우, ②는 그리지 않고 번호는 1·3·4로 보인다.
    미저장 편집이 생기면 ①이 다시 현재 단계가 된다.
- **접기:** 첫 읽기가 끝난 때 완료된 단계는 한 줄 요약으로 접힌다. 예: "수정본 2 저장됨 · 자료 1개 · 읽지 않음 1",
  "작업 모델 수락함 · 수정본 3 기준 · 목표 2개 · 산출물 1개". [펼치기]/[접기]는 `aria-expanded`/`aria-controls`를
  가진다. 화면에서 방금 끝낸 단계는 접지 않고, 소유자가 누른 접기·펼치기가 이후에는 우선한다.
- **이유 한 문장 + 기술 정보:** 다음 단계를 할 수 없으면 한 문장으로 까닭을 말하고, 서버 원문(거절 코드와
  이유)은 "기술 정보" 접힘 안에 둔다. ④에서 준비된 환경이 없을 때도 "기술 정보 (서버 원문)"에 부재 코드·
  이유·실행 수가 있다.
- **새로고침 뒤 ②:** 작업 모델은 이 업무의 `understanding.completed` 사건에서 찾아 다시 연다. 최근 것부터
  최대 25개 모델을 읽고, 이 업무의 수정본을 가리키는 것만 쓴다. 이해한 수정본을 "설명 수정본 N을(를)
  이해한 결과입니다."로 적는다. 앞 수정본이면 그렇다고 적고 [다시 이해하기]를 준다.
- **③ 범위:** 설계 목록은 이 업무의 요청만 보인다. 목록에 `work_id`가 더해졌다. 저장된 어떤 업무에도 속하지
  않는 요청은 "· 저장된 업무와 연결되지 않음"을 붙여 보인다. 저장된 업무 목록을 읽지 못하면 아무것도 다른
  업무 것이라 하지 않는다.
- **④:** 준비된 환경과 예산 정책을 고르고, "이 실행이 쓰는 것"(환경 버전, 그래프, 작업 수정본, 모델·도구
  연결, 승인된 권한, 평가자 자격, 예산, 동의 범위)을 본다. 동의 칸에 체크한 뒤 [업무 시작]을 누른다.
  시뮬레이션 자격은 "시뮬레이션(테스트 행위자) 자격이며 출시 자격이 아닙니다"로 적힌다(화면 c).
- **옆 패널(1200px 이상, 좁으면 아래):** "이 업무의 실행"은 최근 실행 50개 가운데 이 업무의 것이다. 줄마다
  `observe.html#run=…`로 간다. "⋯ 업무 메뉴"에는 기록 내보내기와 원본 삭제가 접혀 있다(US7-3, 필수 단계
  아님). `work.html#work-records`/`#work-deletion`은 그 접힘을 연다. 저장된 업무가 없으면 패널이 없다.
- **업무 바꾸기:** 저장된 업무가 둘 이상이면(또는 하나인데 새 업무를 쓰는 중이면) 머리에 "다른 업무 열기"
  고르기가 나온다. [새 업무] 단추는 늘 있다. 미저장 입력이나 전송 중인 자료가 있으면 바꾸지 않는다. 그때는
  "저장하지 않은 입력이나 전송 중인 자료가 있어 업무를 바꾸지 않았습니다. 먼저 저장해 주세요."라고 적는다.
  - **목록 출처:** 지원 서버의 공개 스냅샷은 `works-v1` 업무를 싣지 않는다(개발 미리보기의 `works` 표를 읽는다).
    그래서 업무 목록은 각 업무의 `work.created` 사건이 가리키는 `work_revision`에서 읽는다
    (`savedWorkIds`, 최대 20쪽). 이름과 수정본은 각 업무를 다시 읽어 얻는다.
- **정직성 규칙은 그대로다:** 미저장 설명은 이 브라우저에만 남는다. 외부 모델 전송은 명시 요청 때만 한다.
  제작자에게 자동으로 보내는 것은 없다.

### 14.2 실행 목록 (§5.2)

- `observe.html`(`#run=` 없음)은 표를 보인다. 열은 업무 · 환경 버전 · 상태 · 시작 · 걸린 시간 · 비용 ·
  사람 대기다(`run-summaries.mjs`). 행은 스냅샷의 실행 목록을 최근 것부터 20개씩 쓰고, 각 행의 값은 그 실행의
  `run-trace-v1`에서 읽는다(한 번에 4개). 행 어디를 눌러도, 또는 업무 이름 링크(키보드)로 실행 상세로 간다.
  좁은 화면에서는 행이 이름표 붙은 카드가 된다.
- **없는 값:** 환경 버전은 어느 경로도 싣지 않아 "—"다. 표 아래에 까닭을 적는다. 비용은 제공자가 정산한 값이
  없으면 "미확인", 한도 요율로 잡은 값은 "추정"이다. 읽지 못한 행은 그렇다고 적고 다른 행은 계속 읽는다.
- **실행 상세 위:** "← 실행 목록" 링크(`./observe.html`)와 작은 "다른 실행" 고르기가 있다. 뒤로·앞으로 가기로
  해시(`#run=`)가 생기거나 사라지면 새로 읽지 않고 목록과 상세를 오간다.

### 14.3 기록 거르기 (§5.7)

- "사건 기록" 위에 업무 · 실행 · 종류 · 기간 거르기가 있다. 해시(`#run=`, `#work=`, `#kind=`, `#period=`)에 남아
  새로고침과 링크에서도 유지된다. [거르기 지우기]로 푼다.
- **서버가 거르는 것:** 실행(`run_id`) 또는 업무(`work_id`) 중 하나, 그리고 종류다. 종류는 `ui-format.mjs`의
  사건 무리 10개(업무, 설계, 실행, 승인, 내 버전, 변경·버전, 연결, 계정, 기록, 시스템)다. 무리마다 사건 이름을
  반복된 `event_type`으로 보낸다. 모든 사건 이름은 정확히 한 무리에 속한다(테스트).
- **화면이 거르는 것:** 기간은 서버가 거르지 않는다. 그래서 불러온 기록 안에서만 거르고 "불러온 사건 N개 중
  기간에 맞는 M개"라고 적는다. 업무 거르기는 그 업무의 수정본을 가리키는 사건만 보인다고 적는다(실행
  사건은 실행으로 거른다).
- **산출물 색인:** "모든 산출물"은 실행 거르기를 따라 서버가 거른다. 업무 거르기에서는 읽은 산출물 가운데 그
  업무 실행의 것만 보이고 "읽은 산출물 N개 중 이 업무의 것 M개 표시"라고 적는다.
- 세션 요청 어댑터(`session.mjs`)는 같은 이름의 질의 값을 여러 개(1–64개) 보낼 수 있게 되었다.

### 14.4 버전·실험 탭 (§5.6)

- 탭은 운영 버전 · 후보 · 실험 · 승인·적용·롤백이다(`ui-parts` 탭, 개수는 탭 이름에 붙는다. 예: "후보 1").
  후보 탭은 게이트와 검증 상태만 보인다. 승인·거절·보류와 적용, 롤백은 승인·적용·롤백 탭에 모았다.
  실험 탭에는 실험, 회차 쌍 비교, 경계가 있다. 기능은 그대로다.
- **빈 상태:** "아직 운영 버전이 없습니다. 새 환경에서는 정상입니다." 다음 할 일도 한 줄 적는다. 후보와 결정에도
  각각 빈 상태와 다음 할 일이 있다.

### 14.5 단계 4 후속

- **차이 보기 다시 열기:** 최종 결과 카드 아래에 "내 버전 N개 · 차이 살펴본 수정본 M개 [차이 보기]" 줄이 있다.
  새로고침한 뒤에도 이 줄에서 같은 대안의 차이 살펴보기를 다시 연다. 목록에 `frozen_alternatives`
  (대안 ID·수정본·범위·고정 시각)가 더해졌다. 고정한 수정본이 지금 저장된 최신 수정본이면 두 내용을 다시
  읽어 부분을 보인다. 앞선 수정본이면 내용을 다시 읽지 않고 관측 설명만 보인다고 적는다.
- **같은 수정본 다시 고정:** 서버는 설계상 부를 때마다 새 대안을 만든다. 그래서 화면에서 막는다. 같은 수정본과
  범위가 이미 고정돼 있고 편집이 없으면 새로 고정하지 않는다. "이 수정본(수정본 N)은 이미 고정했습니다. 같은
  대안의 차이를 다시 엽니다."와 "새 대안은 만들지 않았습니다"를 적고 기존 대안을 연다.
- **피드백 이력:** 저장된 피드백 아래 "이전 기록 N건" 접힘이 있다. 열 때 한 번 읽고, "수정본 1 · 확인 필요 ·
  메모 “…”"처럼 앞 수정본을 시각과 함께 보인다. 지운 수정본은 "수정본 N · 지움"이다.
- **덤으로 고친 경합 두 가지(기존 동작 유지):** 차이 보기가 "관측함"을 말하기 전에 탐구 칸이 먼저 그려진다.
  G-14 성장 효과 테스트는 네트워크가 조용해진 뒤 요청 수를 적는다.

### 14.6 미룬 것과 알려진 한계

- **환경 버전 열:** 실행 목록과 `run-trace-v1` 모두 실행의 환경 버전을 싣지 않아 늘 "—"다. 채우려면 트레이싱
  또는 스냅샷에 필드가 더해져야 한다.
- **기간 거르기:** 서버 거르기가 아니다. 오래된 사건을 보려면 [다음 기록 보기]로 더 불러와야 한다.
- **업무 거르기:** 실행 사건은 업무 ID를 싣지 않아 업무 거르기에 나오지 않는다. 실행으로 거르면 나온다.
- **기록 화면의 해시 변경:** 같은 문서 안에서 해시만 바뀌면(뒤로 가기 등) 새로 읽지 않는다. 새로고침하면 따른다.
- **업무 목록:** `work.created` 사건 20쪽(2,000건)까지, 바꾸기 목록은 최근 30개까지다. "이 업무의 실행"은 최근
  실행 50개 안에서만 찾는다.
- **작업 모델 복원:** 최근 25개 모델만 읽는다. 대화 칸은 작업 모델이 있어야 보인다.
- **② 건너뛴 번호:** 이해 없이 설계 요청이 있으면 번호가 1·3·4로 보인다. 운영 경로에서는 이해 없이 설계 요청을
  만들 수 없으므로 테스트 행위자 fixture에서만 보인다.
- 단계 6(좁은 화면·키보드·스크린리더 점검표)과 T078 자체 점검은 남았다. 소유자 화면 검토 기록은 아직 없다.

### 15.1 점검 방법

- **자동 점검(내부 구현):** axe-core는 이 환경에서 오프라인으로 쓸 수 없어 들여오지 않았다. 대신
  `app/tests/helpers/a11y-audit.mjs`가 페이지 안에서 점검한다. 접근 가능한 이름과 역할은 Chrome 자체 계산
  (`computedName`/`computedRole`, 테스트 브라우저를 `ComputedAccessibilityInfo`로 띄움)을 쓴다. 점검 항목:
  - 조작 요소의 이름, 이미지·SVG의 역할과 이름(또는 숨김), 입력칸의 진짜 라벨(placeholder만으로는 불가)
  - 제목 단계 건너뛰기, 랜드마크 이름 중복과 main 하나, aria-* ID 참조, 중복 ID
  - 이름을 붙일 수 없는 역할의 aria-label, 라이브 영역 중첩, aria-pressed·aria-selected의 역할, 양수 tabindex
  - 상태 칩의 글자(색만으로 표시하지 않음)
  - 렌더링된 글자 대비(AA: 보통 4.5:1, 큰 글자 3:1)와 토큰 쌍 대비(밝게·어둡게), 초점 링 대비 3:1
  - Tab으로 모든 초점 위치를 돌며 `:focus-visible`과 윤곽선(2px 이상) 또는 그림자 확인
  - 가로 넘침: 320px과 1280px 200% 확대(640 CSS px, 2배 픽셀)에서 페이지 가로 스크롤 없음. 가로로
    스크롤해도 되는 것은 그래프·표·코드 칸뿐이다.
  - `prefers-reduced-motion: reduce`에서 전환·애니메이션이 사라짐
- **교차 확인(커밋하지 않음):** pip으로 받은 axe-core 4.12.1 사본을 작업 공간에서 한 번 돌렸다. 고친 뒤 52개
  화면·상태 조합에서 위반 0개다. 제품이나 테스트에 들여오지 않았다.
- **키보드 여정(마우스 없이, `browser-a11y.test.mjs`):** (a) 새 업무를 쓰고 저장. (b) 실행 목록에서 실행을
  열고, 그래프 노드를 화살표로 옮기고, 시도를 바꾸고, 상세 탭을 화살표로 바꿈. (c) 내 버전을 제자리에서 열고,
  쓰고, 차이 살펴보기를 연 뒤 닫으면 초점이 연 단추로 돌아옴. (d) 확인 필요 표시와 저장. (e) 390px 메뉴
  서랍에서 초점이 갇히고 닫으면 돌아옴. (f) 설정의 모든 칸.
- **스크린리더 의미:** 여정 동안 모든 라이브 영역의 글 변화를 기록해 같은 글을 되풀이하지 않는지,
  assertive가 없는지 본다. 그래프는 같은 내용의 노드 목록(상태를 글로)을 가진다.

### 15.2 고친 것

- **대비:** 밝은 테마 강조색 `#087f83`은 바탕(4.42), 흐린 판(4.29), 강조 바탕(4.16), 메뉴(4.21)에서
  4.5:1이 안 됐다. `#07777b`로 바꿨다(밝은 바탕들 위에서 4.55:1 이상). 설정 왼쪽 목록의 현재 항목이 여기에 걸렸다.
  입력칸·선택 상자의 테두리는 1.77:1이라 칸이 잘 안 보였다. `--color-field-line`(밝게 `#7a8f95`,
  어둡게 `#5f7b85`)으로 3:1을 넘긴다(WCAG 1.4.11).
- **랜드마크와 이름:** 맥락 줄은 이름 있는 영역(`region`, "현재 맥락")이 됐다. 예전에는 어떤 랜드마크에도
  속하지 않았다. 설정의 계정·실행 한도 칸은 바깥 칸과 같은 이름의 영역이 겹쳐 안쪽 이름을 뺐다.
  실행 머리 영역은 불러오는 동안 없는 제목을 가리켜 "선택한 실행"이라는 이름을 직접 가진다. 업무 바꾸기,
  실행 명령 묶음, 내 버전의 원본 칸은 이름을 붙일 수 없는 `div`에 이름이 있어 `role="group"`을 줬다.
  시작 화면 로고의 불필요한 aria-label을 뺐고, 메뉴의 DeepTwin 링크 이름은 "Deep Twin"으로 읽혀
  "DeepTwin"으로 고정했다. 실행 목록에서 같은 업무의 두 실행은 링크 이름이 같아, 링크가 자기 줄
  ("실행 1d05fd7a · 업무 수정본 1")로 설명된다(`aria-describedby`).
- **제목 단계:** 최종 결과가 없는 실행의 "이 실행 전체" 피드백 제목이 h2 다음 h4였다. 피드백 제목 단계가
  놓인 자리를 따른다(결과 전체 h3, 단계 h4).
- **그래프:** 그림의 노드 상자(SVG `g`)에 있던 `aria-pressed`를 뺐다. 선택은 `data-selected`로 그린다.
  목록 단추는 그대로 `aria-pressed`를 가진다. 노드 목록 단추 사이를 화살표·Home·End로 옮긴다
  (모든 단추는 계속 Tab 정지점이다).
- **초점을 잃던 곳:**
  - 시도·수행 고르기를 바꾸면 고르기가 다시 그려지며 초점이 페이지 본문으로 떨어졌다. 이제 같은 고르기에
    남는다.
  - "실행 전체 보기"는 누르면 스스로 사라진다. 이제 초점이 새 선택 제목으로 간다.
  - 피드백 저장·지우기 뒤 단추가 비활성·숨김이 되며 초점이 본문으로 떨어졌다. 이제 눌린 표시로 간다.
  - 내 버전 편집기와 차이 살펴보기는 열면 제목으로 초점이 가고, 닫으면 연 단추로 돌아온다. 연 단추가
    없어졌으면 실행 제목으로 간다.
- **메뉴 서랍(1024px 미만):** 열려 있는 동안 건너뛰기 링크도 inert가 된다. Tab과 Shift+Tab이 서랍 안에서
  돈다. 예전에는 마지막 링크 뒤에 페이지 밖으로 나갈 수 있었다.
- **라이브 영역 소음:** 업무 설명을 칠 때마다 "저장되지 않은 변경 …"이 다시 쓰여 글자마다 다시 읽힐 수
  있었다. 산출물 수("산출물 3개")와 피드백 상태("아직 남긴 피드백이 없습니다.")도 단계를 고를 때마다 같은
  글로 다시 쓰였다. 셋 다 글이 바뀔 때만 쓴다.
- **좁은 화면:** 선택 칸의 상세 탭(입력·산출물·전달·도구·모델·기록)이 320px에서 옆으로 스크롤해야 보였다.
  이제 줄을 바꾼다.

### 15.3 단계 2–5 비평에서 남은 손질

- **기록(좁은 화면):** 사건 기록이 내보내기 안내보다 먼저 나온다. 거르기는 두 선택 상자가 들어갈 자리가
  있으면 두 열이다(320px 포함). 넓은 화면은 네 열이다.
- **기록의 해시 변경:** 해시만 바뀌어도(뒤로 가기, 같은 화면 링크, 주소 고침) 새 해시의 조건으로 기록을
  다시 읽고, 거르기 막대도 따라간다(§14.6의 한계 해소).
- **"실행 준비 다시 읽기":** 조용한 단추의 안쪽 여백 때문에 글이 위 문단보다 들여 써 보였다. 여백을 빼 글
  시작을 맞췄다.
- **설정 > 백업·보존(왼쪽 목록):** 상태 줄을 짧게 했다. 예: "백업 2개"(워커 연결됨), "백업 워커 없음",
  "정리 가능 1개 · 자동 삭제 없음". 긴 설명은 칸 안에 그대로다.
- **전송 매니페스트 SHA-256(설정 > 모델 연결):** 앞 12자와 "…"로 보인다. 전체 값은 바로 아래
  "기술 정보"에 있다(§11.2의 한계 해소).
- **맥락 줄의 모드 표식:** `run-trace-v1`에 `run_mode`를 더했다. 원장이 실행 명세에 고정한 모드이며
  추론하지 않는다(`docs/release/api-compatibility.md` §3e). 실행 상세는 `live`이면 **운영**,
  `isolated-comparison`이면 **격리 실험** 표식을 보인다. `replay`·`snapshot`·기록 없음은 표식을 비운다.
  다른 화면은 모드를 알지 못하므로 표식이 없다.
- **설정 > 서비스 클라이언트(T025 경로):** 새 칸(`service-clients.mjs`).
  - 목록: 이름, 상태(사용 중·만료됨·폐기됨, 글과 기호), 허용 읽기, 만료 시각과 남은 시간, 만든 시각.
    클라이언트 ID·수정본·범위 원문은 기술 정보에 있다.
  - 만들기: 이름, 허용할 읽기(서버가 Bearer에 허락하는 `snapshot.read`·`events.read`만), 만료
    (1·8·23시간). 기기 시계가 서버보다 빠를 수 있어 24시간은 고르지 않는다. 고른 범위가 조합된 경로의
    Bearer 범위와 같은지는 `test_service_client_bearer.py`가 확인한다.
  - 비밀 값은 딱 한 번 보인다. 읽기 전용 칸, [복사], 경고("지금 한 번만 보입니다 …"), [다 옮겼습니다 ·
    숨기기]가 있다. 값은 그 칸과 모듈 안에만 있고 localStorage·sessionStorage·속성·주소·제목에 쓰지 않는다
    (단위·브라우저 테스트). 숨기면 칸을 비운다. 새로 고치면 다시 볼 수 없다.
  - 비밀 값 다시 만들기와 폐기는 먼저 확인을 묻는다. 취소하면 아무것도 보내지 않고 초점이 돌아온다. 요청은
    읽은 수정본을 `expected_revision`으로 보내고, 먼저 바뀌었으면(409) 목록을 다시 읽고 그렇다고 말한다.
  - 거절: HTTP로 연 화면(loopback 배포)에서 만들면 서버가 422로 거절한다. 화면은 "이 배포에서는 서비스
    클라이언트를 만들 수 없습니다"라고 말하고, 기술 정보에 응답 코드, 서버 코드(`invalid_state`), 서버
    메시지, 상관 ID, 화면의 주소 방식을 보인다. HTTPS 화면에서의 422는 이유를 단정하지 않고 "서버가 이
    클라이언트를 만들지 않았습니다"와 서버가 만드는 조건을 적는다. 세션 어댑터는 이를 위해 거절의 서버
    코드와 상관 ID를 오류에 싣는다(`session.mjs`).
  - 브라우저 테스트(`browser-service-clients.test.mjs`)는 portable HTTPS fixture에서 실제로 만들고, 복사하고,
    그 비밀로 Bearer 읽기(200)를 하고, 회전 뒤 옛 비밀 401·새 비밀 200, 폐기 뒤 401을 확인한다.

### 15.4 미룬 것과 알려진 한계

- **실제 스크린리더 사용자 검사**(NVDA·VoiceOver·TalkBack)와 **소유자 수용**은 없다. 자동 점검과 키보드
  여정은 그 대신이 아니다.
- T078 자체 점검 가운데 IME, 세 보기·모드 사용성, 확장 화면(T087), 동결된 T081 후보 위에서의 최종 검사는
  남았다. T078은 체크하지 않았다.
- 초점 링 순회는 밝은 테마에서만 돌렸다. 어두운 테마의 초점 링은 토큰 대비로만 계산했다.
- 글자 대비 점검은 그라디언트·이미지 위 글과 SVG 그래프 안 글을 직접 재지 않는다. 그래프 색은 토큰 쌍으로
  계산했다. 강제 색상 모드(Windows 고대비)는 확인하지 않았다.
- 200% 확대는 640 CSS px·2배 픽셀로 흉내 냈다. 브라우저의 확대 조작 자체는 아니다.
- 타임라인 항목과 "받은 단계로 이동" 같은 조용한 단추는 그대로다. 타임라인 항목은 모두 Tab 정지점이다.
- 모드 표식은 실행 상세에만 있다. 설계 검토·과거 기록 표식을 붙일 근거는 아직 어느 화면에도 없다.
- 서비스 클라이언트: 명령·산출물·확장 읽기 범위는 소유자 결정 전이라 고를 수 없다. 사용 기록(마지막 사용
  시각)은 목록 경로가 싣지 않아 보이지 않는다.
