# 제품 화면 재설계 — 여정 중심 구조 (2026-09-26)

상태: **설계안 (소유자 검토 대기)**. 구현·사용성 수용 증거가 아니다.
기준 계약: `specs/001-autonomous-release/contracts/experience.md`(UX-001) §4·§7·§8·§10·§12,
`docs/superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md` §10,
`control-prototype/`(2026-09-06 시제품, 합성 데이터).

## 0. 왜 다시 설계하는가

2026-09-26 실제 서버를 합성 데이터로 띄워 모든 화면을 캡처하고 조작해 본 결과는 이렇다.

- **결과·과정 피드백을 줄 곳을 찾기 어렵다.** "내 버전"은 관제 화면 맨 아래에 있고, 어떤 산출물을
  고치는지 표시되지 않는다. 최종 결과물이 따로 구분되지 않는다. 과정(역할·전달·도구·순서)에 대한
  피드백은 입력할 곳이 없다.
- **트레이싱이 사실상 불가능하다.** 노드마다 `완료, 수행 1회, 산출물 1건`만 보인다. 시도별 입력,
  출력, 전달, 도구·모델 호출, 시간, 비용을 볼 수 없다. 기록 화면은 실행별로 거를 수 없고
  `work.revised · 성공 · 관련 기록 1개` 같은 줄만 반복된다.
- **노드와 산출물이 연결되지 않는다.** 그래프에서 n05를 골라도 산출물 칸에는 n15의 것이 남아 있다.
- **정보 구조가 없다.** 공통 메뉴가 없다. 관제 화면은 실행 목록, 텍스트 노드 목록, 제어, 승인,
  그래프, 노드 버튼, 상세, 산출물, 전체 산출물, 내 버전이 위계 없이 세로로 쌓여 있다.
  기록 화면에는 Claude 키, API 자격증명, 실행 한도 같은 설정이 섞여 있다.
- **내부 용어와 원시 값이 드러난다.** `dispatch`, `block_dependants`, `{"handler_id":…}`,
  `text/plain (선언)`, UUID, 해시, 마이크로초 시각, 이벤트 이름, 영어 서버 사유가 그대로 나온다.

**원인:** 태스크를 백엔드 계약 단위로 진행하면서 화면에는 부품만 붙였다. 여정과 정보 구조 설계는
마지막 태스크(T078)로 미뤄졌다. 브라우저 테스트는 "문구·버튼이 있는가"만 확인했다.
9월 초 시제품(`control-prototype/`)과 UX-001 계약에는 올바른 구조가 이미 있었지만, 별도 시제품이라
제품으로 옮겨지지 않았다.

## 1. 소유자 결정 (2026-09-26)

- **화면 기술:** 빌드 없는 브라우저 기본 ES 모듈을 유지한다(plan.md). 그 위에 디자인 시스템(토큰,
  레이아웃 부품, 표시 규칙)을 먼저 만든다. 조합이 번거로워지면 빌드 없이 쓰는 작은 라이브러리
  (예: Preact+htm, 파일로 들여와 CSP `script-src 'self'` 유지)를 그때 따로 검토한다.
  Next.js와 Vite+React는 채택하지 않는다. 다음 세 가지와 충돌하거나 비용이 크다.
  - 인라인 스크립트와 CSP
  - 인스턴스별 무작위 경로(`/<32hex>/`)와 빌드 시점 경로
  - 배포 구성과 SBOM
- **과정 피드백:** 산출물·전달물 대안(내 버전)에 더해 **선택 표시와 선택 메모**를 허용한다.
  설명은 어떤 단계에서도 필수가 아니다(FR-016).
- **목업 방식:** 별도 목업을 만들지 않는다. 실제 앱 안에서 실제 서버와 합성 데이터로 화면을 만든다.
  확인받은 화면이 곧 제품이다.

## 2. 원칙

1. **한 화면 한 목적.** 그 화면에서 할 일이 첫 화면 높이 안에 보인다. 부가 정보는 접거나 옆 패널로 뺀다.
2. **선택이 따라간다.** 노드를 고르면 그 노드의 수행·시도·입력·산출물·전달·도구 기록이 함께 바뀐다.
   예전 선택을 다른 대상의 기록처럼 보이지 않는다(UX-001 §4).
3. **사람 언어.** 내부 ID·해시·스키마 이름은 "기술 정보" 접힘 안에만 둔다. 시각은 "3분 전"과 절대
   시각(초 단위)으로 표시한다. 상태는 색만이 아니라 글과 아이콘으로 구분한다.
4. **없는 것은 없다고.** 빈 상태는 무엇이 없는지와 다음에 할 일을 한 문장으로 말한다. 미래 단계를
   비활성 설명문으로 나열하지 않는다.
5. **정직한 표시는 유지한다.** 전달됨, 활용 근거, 영향은 다른 주장이다. 추정은 추정으로 표시한다.
   시뮬레이션은 시뮬레이션으로 표시한다. 기존 증거 규칙(헌법 IX)은 바뀌지 않는다.

## 3. 정보 구조 (앱 셸)

```
┌──────────────┬──────────────────────────────────────────────────────────────┐
│ DeepTwin     │ [업무: 화요일 공간 안내] · [환경 v3 운영] · (운영|설계 검토|실험|과거 기록) │
│              ├──────────────────────────────────────────────────────────────┤
│ 업무         │                                                              │
│ 실행         │                     주작업면 (화면별)                           │
│ 버전·실험    │                                                              │
│ 기록         │                                                              │
│ ─────        │                                                              │
│ 설정         │                                                              │
└──────────────┴──────────────────────────────────────────────────────────────┘
```

- 왼쪽 메뉴는 모든 인증 화면에 공통이다. 좁은 화면(< 1024px)에서는 상단 메뉴 버튼으로 접힌다.
- 상단 맥락 줄에는 현재 업무 이름, 환경 버전, 모드 표식(UX-001 §4)을 둔다. 긴 ID는 상세에 둔다.
- 화면과 기존 파일의 대응은 다음과 같다. 파일 이름은 바꾸지 않는다.
  - 업무 → `work.html`
  - 실행 → `observe.html` (목록과 상세)
  - 버전·실험 → `versions.html`
  - 기록 → `records.html`, 로그와 내보내기만 둔다.
  - 설정 → `settings.html`. 계정, Claude 연결, API 자격증명, 실행 한도, 백업·보존, 업데이트,
    확장을 모두 여기로 옮긴다.
- 시작·로그인(`start.html`)만 셸 밖에 둔다. "개발 미리보기" 배너는 모두 없앤다.

      │
      ▼
차이 살펴보기 ─▶ 경쟁 설명·질문 ─▶ 변경 후보 ─▶ 버전·실험(이전 업무 재평가) ─▶ 사람 승인·적용·롤백

## 5. 화면 명세

### 5.1 업무 (`work.html`)

단계형 작업면이다. 이미 도달한 단계만 펼쳐 보인다.

```
┌ 업무: [이름 편집] ───────────────────────────── 저장됨 3분 전 ┐
│ ① 설명·자료        [설명 입력칸……………………]  [자료 추가] [마이크]     │
│    자료 3개: 요약.pdf (전체 읽음) · 표.csv (일부 읽음: 1–200행) · …    │
│ ② 업무 이해        [업무 이해하기]  또는 이해 결과 카드 + 대화           │
│ ③ 환경 제안        [환경 제안받기]  또는 후보 비교(그래프 한 개 크게 +   │
│                    같은 초점 요약) + [이 안 선택]                     │
│ ④ 준비·시작        준비된 환경 요약 + [업무 시작]                      │
└──────────────────────────────────────────────────────────────┘
오른쪽 접힘 패널: 이 업무의 실행 목록, 내보내기, 원본 삭제
```

- 다음 단계를 할 수 없으면 이유를 한 문장으로 보인다. 예: "자격을 갖춘 렌즈가 없어 환경을 제안할 수
  없습니다." 서버 원문은 "기술 정보" 접힘 안에 둔다.
- 내보내기와 원본 삭제는 업무 메뉴(⋯)로 옮긴다. 매 업무의 필수 단계가 아니다(US7-3).

### 5.2 실행 목록 (`observe.html` 기본)

| 업무 | 환경 버전 | 상태 | 시작 | 걸린 시간 | 비용(추정) | 사람 대기 |
|---|---|---|---|---|---|---|

행을 누르면 실행 상세(`observe.html#run=<id>`)로 간다. 상태는 글과 아이콘으로 표시한다.
완료, 진행 중(미완료), 실패, 사람 승인 대기, 취소됨을 구분한다.

### 5.3 실행 상세 — 가장 중요한 화면

```
┌ 화요일 공간 안내 · 실행 #12 · 완료 · 14:02–14:09 (7분) · 약 $0.42 ─ [이어서][중단][복구] ┐
├──────────────────────────────────────────────────────────────────────────┤
│ 최종 결과                                                                  │
│ ┌ 안내문.pdf (3쪽) — "안내문 작성" 역할이 만듦 ────────────── [미리보기][내려받기] ┐ │
│ │  [미리보기 영역]                                                          │ │
│ │  [내 버전 만들기]   이 결과 전체: ( ) 괜찮음  ( ) 확인 필요   [메모(선택)]      │ │
│ └──────────────────────────────────────────────────────────────────────┘ │
├───────────────────────────────┬──────────────────────────────────────────┤
│ 과정                          │ 선택: 근거 확인 (에이전트) · 수행 1 / 시도 2 ▾ │
│ [그래프 | 타임라인] 전환        │ [입력] [산출물] [전달] [도구·모델] [기록]      │
│                               │                                          │
│  근거 확인 ─▶ 초안 ─▶ 검토 ─▶ 안내문 │  입력: 요약.pdf v1 (앞 단계 "자료 수집" 시도 1) │
│   ✓        ✓      ⚠      ✓    │  산출물: 근거표.csv (12행) [열기][내 버전]      │
│                               │  도구·모델: 모델 호출 2회 · 입력 8.1k/출력 1.2k  │
│  타임라인:                     │           토큰 · 41초 · 약 $0.05             │
│  14:02 자료 수집 시도1 완료       │           웹 읽기 1회 (허용된 출처) 3.2초      │
│  14:03 근거 확인 시도1 실패(시간초과)│  기록: 이 시도의 사건 5개 [전체 기록에서 보기]   │
│  14:04 근거 확인 시도2 완료       │                                          │
│  …                            │  이 단계에 대해: ( ) 괜찮음 ( ) 확인 필요 [메모] │
└───────────────────────────────┴──────────────────────────────────────────┘
```

- **최종 결과:** 그래프의 출구 역할이 만든 산출물과, 저장·보고 단계가 받은 산출물이다.
  여러 개면 모두 보인다. 최종 결과가 없으면 "아직 최종 결과가 없습니다"와 멈춘 지점을 표시한다.
- **과정:** 그래프와 타임라인은 같은 선택을 공유한다. 노드를 고르면 오른쪽 상세가 그 노드의
  수행·시도로 바뀐다. 기본값은 가장 최근 시도이고, 과거 시도를 고를 수 있다. 과거 시도에 최신
  산출물을 붙이지 않는다(UX-001 §7).
- **상세 탭:** 입력, 산출물, 전달, 도구·모델, 기록. 모두 같은 수행·시도를 기준으로 한다.
  - 입력: 앞선 산출물의 정확한 버전.
  - 전달: 보낸 버전, 받은 수행·시도, 수신 확인. 전달됨과 활용 근거는 다른 주장으로 구분한다.
  - 도구·모델: 호출마다 제공자·모델, 토큰, 시간, 비용(추정 표시), 오류·재시도, 결과 파일.
    숨은 추론은 저장하지 않으므로 보이지 않는다고 명시한다.
- **내 버전:** 산출물 옆 [내 버전]을 누르면 같은 자리에 원본 | 내 버전 | 차이 분할 작업면이 열린다
  (§5.4). 페이지 맨 아래로 내려가지 않는다.
- **승인 대기:** 사람 승인이 필요한 노드는 그래프에 표시하고 상단에 한 줄 배너를 띄운다.
  [승인 화면 열기]로 간다.
- **통계 줄:** 걸린 시간, 모델·도구 호출 수, 추정 비용. 제공자가 확인하지 않은 비용은 "추정"으로
  표시하고, 모르면 "미확인"으로 표시한다.

### 5.4 내 버전 작업면

```
┌ 내 버전 — 근거표.csv (근거 확인 · 시도 2) ─────────────── 자동 저장됨 ┐
│ [원본 | 내 버전 | 차이]  (넓은 화면에서는 원본과 내 버전을 나란히)          │
│  …편집기(형식별: 텍스트·표·파일 올리기)…                                 │
│ 바꾼 줄·칸만 내 근거로 기록합니다. 나머지는 검토하지 않은 영역입니다.         │
│ [ ] 전체를 검토했습니다            [차이 살펴보기]   [닫기]              │
└──────────────────────────────────────────────────────────────┘
```

- 제목에 어떤 산출물, 역할, 시도인지 항상 보인다.
- "분석용으로 고정"은 UX-D07에 맞춰 **"차이 살펴보기"**로 바꾼다. 동작(정확한 수정본 고정 후 차이
  관찰)은 같다.
- 이유·지시 칸은 없다. 메모는 과정 피드백의 선택 메모와 같은 것이며 대안이 아니다.

### 5.5 차이 살펴보기

UX-001 §8을 따른다. 첫 화면은 관찰 차이와 관련 실행 구간이다. 차이를 고르면 원본·대안 부분,
입력·전달·도구 근거, 경쟁 설명이 함께 나온다. 현재 `inquiry.mjs`의 기능(설명 제안, 질문, 증거,
변경 후보 제안)은 유지하고 이 화면으로 옮긴다.

### 5.6 버전·실험 (`versions.html`)

현재 운영 버전 카드, 후보 목록(게이트·검증 상태), 실험(회차 쌍 비교·정지 이유), 승인·적용·롤백을
각각 탭으로 나눈다. 기존 `versions.mjs`와 `experiments.mjs`의 기능은 유지한다.

### 5.7 기록 (`records.html`)

- 사건 로그에 필터(업무, 실행, 종류, 기간)와 사람 문장 요약을 둔다.
  예: `work.revised` → "업무 설명을 고쳤습니다 (수정본 4)". 원 이벤트 이름은 상세에 둔다.
- 실행 상세의 [전체 기록에서 보기]는 이 화면을 해당 실행·시도로 걸러서 연다.
- 내보내기(범위 선택 → 미리보기 → 파일)는 유지한다. 제작자에게 보낼 피드백 메모 칸을 추가한다.
  자동 전송은 없고 파일 안에만 들어간다(US7).

### 5.8 설정 (`settings.html`)

왼쪽 하위 메뉴: 계정과 세션, 모델 연결(Claude API, API 자격증명), 실행 한도, 백업·보존, 업데이트·복구,
확장, 서비스 클라이언트(Bearer, T025 연결 뒤). 기록 화면에 있던 설정 항목을 모두 여기로 옮긴다.

## 6. 과정 피드백 데이터 (새로 필요)

| 항목 | 내용 |
|---|---|
| 대상 | 실행 전체, 또는 노드의 정확한 수행·시도 (`run_id`, `node_id`, `visit`, `attempt`) |
| 표시 | 선택: `ok`(괜찮음) · `needs_attention`(확인 필요). 없으면 표시하지 않음 |
| 메모 | 선택, 길이 제한 있는 평문. 이유나 지시를 요구하지 않음 |
| 성격 | **대안이 아니다.** UX-AC05에 따라 대안 수로 세지 않는다. 탐구의 "사용자 표시" 관찰로만 쓰고 정답으로 쓰지 않는다 |
| 기록 | 새 불변 레코드와 공개 사건. 소유자 명령이며 CSRF를 거친다. 바꾸면 새 수정본이 생기고 이전 것은 유지된다 |

산출물·전달물의 내 버전은 기존 대안 경로(drafts → freeze → difference)를 그대로 쓴다.

## 7. 트레이싱 조회 (새로 필요)

- `GET /api/v1/runs/{run_id}/trace`는 읽기 전용이고 브라우저 세션 전용이다. 다음을 반환한다.
  - 노드별 수행·시도 목록과 시각
  - 시도별 입력 산출물의 정확한 버전과 출처 시도
  - 출력, 전달(보냄·받음)
  - 도구 호출(도구, 작업, 시간, 결과, 오류, 결과 파일)
  - 모델 호출(제공자·모델 표시값, 입출력 토큰, 시간, 비용 추정과 그 근거, 오류)
  - 승인 기록
  - 기록되지 않은 항목(`not_recorded`)
- 숨은 추론과 비밀은 포함하지 않는다.
- `GET /api/v1/events`에 `run_id`, `work_id` 필터를 추가한다.
- 이미 저장된 사실만 모아서 보인다. 없는 값을 계산해 채우지 않는다.

## 8. 디자인 시스템

- **토큰** (`styles.css` 앞부분): 색(밝게·어둡게, 상태색 4종 + 글자), 간격 4px 단위, 글꼴 크기 6단계,
  모서리, 그림자, 초점 링.
- **레이아웃 부품** (`ui/` 모듈): 앱 셸, 페이지 머리, 카드, 분할 화면(크기 조절), 탭, 타임라인,
  상세 목록, 서랍, 빈 상태, 상태 칩, 버튼 위계(주·보조·위험), 접힘 "기술 정보", 알림 줄.
- **표시 규칙** (`ui/format.mjs`):
  - 시각: 상대 + 절대(초)
  - ID: 앞 8자 + 복사
  - 바이트, 토큰, 비용(추정·미확인)
  - 매체 종류: `text/plain` → 텍스트, `text/csv` → 표
  - 내부 용어 사전(예시):

    | 내부 용어 | 화면 표시 |
    |---|---|
    | `block_dependants` | 실패하면 뒤 단계 멈춤 |
    | `dispatch` 중단 | 새 작업 보내기 중단 |
    | `deterministic` | 정해진 처리 |
    | `human_gate` | 사람 승인 |
- 모든 문자열은 계속 `textContent`로 넣는다. 마크업 삽입은 없고 CSP도 그대로다.

## 9. 검증 방식

- **여정 테스트:** 사람이 목적을 끝까지 달성하는지 브라우저로 확인한다. 예:
  "실행 상세에서 n05를 고르면 n05의 산출물이 보이고, 내 버전을 만들어 차이를 살펴볼 수 있다."
  "시도 2의 입력과 모델 호출이 보인다." 문구가 있는지만 보는 확인은 보조로만 둔다.
- **스크린샷 검토:** 단계마다 1280px, 390px, 어두운 테마를 캡처해 소유자에게 보내고 확인받는다.
- **기존 보장 유지:** 보안(CSP, textContent, CSRF), 정직한 표시, 시뮬레이션 표기 테스트는 유지한다.
  배치가 바뀌어 달라지는 기대값만 고친다.
- 자동 검사 통과는 사용성 수용이 아니다. 소유자의 화면 확인을 따로 기록한다.
