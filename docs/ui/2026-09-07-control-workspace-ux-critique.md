# 수정 관제 UI 비평 — 이해도와 정보 우선순위

작성일: 2026-09-07 · 대상: `control-prototype/`, 검토 시 HEAD `f9ea189`(UI 코드 `4954450`).

## 결론

**연결 구조를 확인하는 시제품으로는 진전이 있지만, 비개발자가 설명 없이 사용하는 관제 UI로는 아직 미흡하다.** 그래프·산출물·대안·실행 쌍이 존재하는 것과 사용자가 그 관계를 쉽게 읽는 것은 다르다. 색·여백을 다듬는 수준보다 정보 우선순위와 작업면 연결을 먼저 고쳐야 한다. 제품 정체성을 버리거나 문서 카드형 UI로 되돌아가자는 판정은 아니다.

사용자의 “맞는듯?”은 방향의 잠정 확인이며, “너무 복잡해서 이해가 어려워서”는 현재 사용성의 명시적 문제 제기다. 최종 화면 승인으로 합산하지 않는다. 이번 제품 UX 의견을 업무 대안 산출물이나 DeepTwin 학습 증거로 재분류하지 않는다.

## 방법과 한계

- 설치된 `frontend-design`의 정보 구조·절제·사용자 관점 문구·스크린샷 자기 비평 기준을 사용했다. 미설치 `Impeccable`을 실행한 것으로 기록하지 않는다.
- 주 에이전트는 사용자 탭과 분리된 Chrome headless context에서 실제 노드·산출물·모드·작업 영역·합성 사례·감사 탐색을 수행했다. 1440×1000과 1024×768 화면 캡처 10개를 생성해 모두 직접 확인했다. 사용자 입력을 수정하거나 모델·도구·학습 기능을 실행하지 않았다.
- 두 별도 검토자가 실행/자기 버전과 설계/탐구/평가 영역을 나누어 독립 비평했다. 이후 주 에이전트가 중복 지적과 관찰 근거를 대조했다. 이것은 오류 독립성의 통계적 보증이나 실제 초보 사용자 실험이 아니다.
- 판정 근거는 [기존 수용·거부 기준](/Users/soonseekyang/Documents/Deeptwin/docs/acceptance-cases.md), [제품 의도](/Users/soonseekyang/Documents/Deeptwin/docs/product-intent.md), [UI 명세 §10–11](../superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md#10-환경-맥락-유지형-작업대--채택된-연결-구조)와 실제 화면이다. 이번에 논문 원본 PDF를 새로 독해하거나 엔진 효과를 검증한 것은 아니다.
- 앞선 79개 시험과 시각 검사 결과는 취소하지 않는다. 연결·보관·실패 처리·가독성의 해당 검사 범위에서 유효하지만, 사용자 이해도 합격의 근거는 아니다.
- 아래 위치는 해당 화면의 문서 위쪽부터 잰 CSS 픽셀이다. 사용자가 반드시 그만큼 스크롤한다는 행동 측정이나 소요 시간 측정이 아니다. 개선 사례의 최종 위치는 모든 이미지 해독 완료 후 재측정했다.

## 먼저 보존할 것

1. 설계 후보의 실제 구조 차이와 공통 비교 초점, 관제 그래프에서 정확한 수행·시도·입출력·수신자로 이어지는 관계.
2. 텍스트 외 PDF·표·이미지 원본과 부분 자기 대안. 일부 증거가 전체 검토·승인이 되지 않으며, 영향 범위가 대안 크기로 제한되지 않는 원칙.
3. 현재 시험 입력과 별도 합성 예시의 분리, 경쟁 설명과 미확인 증거, 이전 큐 반복 비교·악화·최종 근거 부족·정확한 후보의 사람 승인, 선택적 로그 공유.

이 기준을 유지한 채 **같은 맥락을 유지하는 것과 모든 정보를 늘 펼쳐 두는 것을 구별**해야 한다(AC-004, §10.1).

## 주요 지적

### UX-01 · 높음 — 그래프 선택과 결과 작업면이 시각적으로 끊긴다

**관찰:** 1440×1000 첫 화면에서 그래프는 y310–894, 수행/산출물 작업면은 y960부터 시작한다. ‘안내문 검토’ 노드를 선택하면 상태·아래 내용은 바뀌지만 스크롤 위치는 0으로 유지돼 결과 내용이 보이지 않는다. 원래 PDF 대상의 자기 버전 입력은 y2148이다. 1024×768에서는 작업면이 y967부터 시작한다. 노드에는 주로 이름과 종류가 있고, 선택 색은 진행 상태가 아니다.

**영향 판단:** 사용자는 무엇이 바뀌었는지, 어디에서 결과를 읽는지, 현재 어떤 작업을 살펴봐야 하는지 직접 찾아야 한다. ‘그래프 중심’이 ‘그래프만 먼저 보이고 작업은 아래에서 하는 구조’로 구현됐다.

**개선:** 넓은 화면은 읽을 수 있는 그래프와 선택 산출물의 작업면을 함께 유지하고, 좁은 화면은 현재 대상과 그래프로의 복귀를 유지하는 상세 작업면으로 연결한다. 필요한 경우 실제 관찰 기록에 근거한 상태·출력·검토 필요를 요약한다. 작은 그래프에 전부 압축하거나, 기록에 없는 실시간 상태·성공을 만들지 않는다.

### UX-02 · 높음 — 원본과 ‘나의 버전’의 소유 구분이 늦고, 현재 파일 선택이 표시되지 않는다

**관찰:** ‘같은 상태에서 나의 버전’ 제목 바로 아래에 시스템 원본이 크게 표시되고, 실제 빈 입력칸과 ‘아직 자기 버전 없음’은 그 뒤에 있다. 두 번째 출력 `brief-note-j1-origin`을 누르면 원본 표시가 바뀌지만 입력/출력 선택 버튼 다섯 개 모두 `aria-pressed=false`로 남는다. 새 입력의 개선 화면에는 원본 표시 없이 메타데이터와 자기 버전만 있다.

**영향 판단:** 무엇이 에이전트 산출물이고 무엇이 내가 남길 비교군인지, 지금 어느 파일을 대상으로 작성하는지 재해석해야 한다. 이는 DeepTwin의 핵심 입력 의미에 직접 닿는 문제다.

**개선:** ‘선택한 원본’과 ‘같은 조건에서 내가 만든 버전’을 분명히 구획하고, 현재 파일을 목록·작업면 양쪽에 일관되게 표시한다. 부분 선택 시 해당 원문/영역과 대안 작성·첨부를 가까이 두고, 개선 영역에서도 이 쌍을 확인할 수 있게 한다. 입력 파일이면 누가 만들어 어느 수행에 전달한 것인지 밝힌다. 원본 전체·실제 형식 접근은 유지한다. 코칭 코멘트나 이유를 필수로 요구하지 않는다.

### UX-03 · 높음 — 설계 비교가 세 후보를 기억하며 왕복하는 작업이 된다

**관찰:** 설계 그래프 보기의 전체 문서 높이는 4,914px이다. 후보 A/B/C는 각각 y310/1318/2366에서 시작하고, 선택한 설계가 y3397에서 전체 그래프로 다시 나온다. 공통 초점 전환은 있지만 해당 계약 설명은 각 그래프 아래에 있다. 첫 화면에서는 후보 A가 대부분을 차지한다.

**영향 판단:** 노드가 잘 읽혀도 후보 간 차이는 멀리 떨어져 있어 사용자가 기억으로 비교해야 한다. 이미 선택한 구조를 또 보여 주는 중복이 수정·승인 대상의 발견도 늦춘다.

**개선:** 현재 비교 질문과 후보별 핵심 구조 차이를 유지한 채, 같은 초점의 그래프를 즉시 대조할 수 있게 한다. 고정 기준안·대조안 전환이나 초점별 비교면은 후속 설계 후보이며 이번에 배치를 확정하지 않는다. 짧은 비교 요약은 그래프의 관련 노드·연결을 가리켜야 한다. 세 그래프를 읽을 수 없게 축소하거나 텍스트 카드로 구조 비교를 대체하지 않는다. 선택본의 중복 전체 표시는 줄인다.

### UX-04 · 높음 — 개선 탐구와 평가에서 중요한 판단 근거가 전체 자료 뒤에 묻힌다

**관찰:** 고정 사례 첫 화면은 큰 원본 PDF가 차지한다. 실제 차이 선택은 y1545, 경쟁 설명은 y2416, 비교 회차는 y3062다. 기본 `round-j1-1`에서 이미지 해독 완료 후 문서 높이는 12,827px이며, 기준/후보 실행 상세가 각각 y3318/y7669부터 이어진다. 부분 밖 영향 표는 y12055다. 회차 앞에 짧은 결과 문장은 있지만, 문구만 바뀌고 후속 시간표가 남았다는 구체적 근거는 이 표에서 읽게 된다.

**영향 판단:** 사용자는 ‘무엇이 달랐나’, ‘두 설명을 무엇으로 구별하나’, ‘어떤 부분이 나아지거나 나빠졌나’를 알기 전에 원본과 두 실행의 모든 파일을 읽게 된다. 깊은 탐구 역량과 상세 자료의 기본 펼침이 혼동돼 있다.

**개선:** 관찰 차이와 대응 부분을 먼저 제시하고 전체 원본은 즉시 열 수 있게 한다. 경쟁 설명은 짧은 주장·미확정 상태·판별에 필요한 증거를 우선 보여 주고 지지/반대 근거를 펼친다. 이전 큐 비교에서는 업무·회차·후보 변경·국소/후속 결과 요약을 먼저 두고 정확한 그래프·파일로 연결한다. 실패/악화·최종 근거 부족을 종합 점수로 가리지 않으며, 사람이 승인할 정확한 버전과 실제 적용은 계속 구별한다. 이 제안은 새로운 필수 승인 단계나 전용 제출 버튼을 추가하는 것이 아니다.

### UX-05 · 중간 — 세 보기의 차이가 작업 방식보다 정보 추가·접힘 차이로 보인다

**관찰:** 같은 영역의 본문을 공통 출력하고 대화 보기에서는 그 앞에 메모 입력창을 붙인다. 실행에서 그래프→대화로 전환하면 기존 그래프가 유지되고 상세 맥락이 펼쳐져, 선택 결과 작업면은 y960에서 y1410으로 더 내려간다. 대화의 자동 응답 미연결은 명시돼 있다.

**영향 판단:** 사용자는 ‘이 일을 하기에는 어느 보기가 편한가’를 배우기 어렵다. 대화 보기조차 원본과 떨어진 큰 메모칸으로 시작한다. 이는 LLM 미연결 자체의 결함이 아니라, 현재 시제품으로 세 작업 방식의 유용성을 검토하기 어렵다는 지적이다.

**개선:** 작업공간은 산출물 다루기, 그래프는 연결·상태 살피기, 대화는 현재 대상에 대한 대화라는 중심을 갖도록 한다. 같은 대상·버전·작성 상태를 공유하되 모든 내용을 매번 전부 반복하지 않는다. 세 모드를 삭제하거나 대화를 필수 개선 입력으로 바꾸지 않는다.

### UX-06 · 중간 — 정확성 고지와 내부 식별자가 업무 언어를 압도한다

**관찰:** 수신자 버튼은 `run-j1-origin-review-2` 같은 ID가 주된 이름이다. ‘실행·수행·시도’, ‘업무 모델’, ‘현재 맥락’이 별도 설명 없이 반복되고 `synthetic UI fixture`가 파일명마다 붙는다. 한국어 UI의 원 자료는 긴 영문 합성 문서다. ‘전체’와 ‘산출물 전체’가 함께 나오는 텍스트 범위 선택도 차이를 알기 어렵다.

**영향 판단:** 사용자는 업무 내용을 판단하기 전에 시스템 용어와 자료 언어를 해독해야 한다. 시제품/미연결 구별은 필요하지만 반복 고지는 중요한 대상·행동과 경쟁한다.

**개선:** 업무명·역할·파일명·읽을 수 있는 개정 이름을 먼저 보이고 정확한 ID는 보조 상세로 유지한다. 재시도와 새 수행의 의미는 필요한 자리에서 설명한다. 한국어 비개발자의 검토에 맞는 독립 합성 자료를 사용한다. 전역 시제품 표지와 실제 위험/미지원 고지는 남기되 중복을 정리한다. 원본/파생 구별, 첨부 소멸, 실제 미연결 상태를 감추는 방식은 허용하지 않는다.

### UX-07 · 중간 — 내부 탐구 감사가 현재 판단과 연결된 설명보다 전체 로그처럼 읽힌다

## 추천 수정 순서 — 아직 구현 승인/착수 아님

1. **실행 작업면 한 구간부터:** 노드 선택 → 특정 수행의 원본 → 부분 자기 버전 → 원본/대안 쌍 확인. UX-01·02를 우선 수정하고, 그래프·전체 산출물·이력·전달 연결이 손상되지 않는지 확인한다.
2. **설계 비교와 개선 판단의 정보 순서:** UX-03·04. 구조 차이/관찰 차이/국소·후속 결과가 먼저 읽히고, 전체 그래프·원자료가 바로 연결되도록 한다.
3. **세 보기·용어·감사 정돈:** UX-05–07. 상세를 숨기는 목적은 삭제가 아니라 각 작업에서 필요한 순간에 찾을 수 있게 하는 것이다.

이 순서는 개발자의 수정 우선순위다. 사용자 업무를 새 고정 직렬 절차로 바꾸거나 내부 탐구마다 승인 버튼을 추가하는 요구가 아니다. 기존 상태·계보·비교 근거는 재사용하고 화면을 전면 폐기하지 않는 것을 우선 제안한다.

## 다음 검토에서 확인할 행동

- 설명 없이 선택한 에이전트의 결과 작업면을 찾고, 현재 파일이 입력인지 출력인지와 어떤 수행의 버전인지 확인할 수 있는가.
- 두 번째 산출물을 고르면 목록과 작업면의 현재 대상이 일치하며, 원본과 자기 버전을 혼동하지 않는가.
- 일부 대안만 남기고도 원본의 해당 부분과 짝을 확인할 수 있으며, 이유 설명이나 전체 작성·승인을 요구받지 않는가.
- 같은 비교 질문으로 후보 그래프 간 차이를 오랜 화면 왕복 없이 확인하고, 전체 구조로 복귀할 수 있는가.
- 이전 큐의 한 회차에서 국소 수정과 후속 악화·미확인을 먼저 파악하고 그 근거 파일/실행 쌍에 도달할 수 있는가.
- 보기 전환 시 작업 초점은 달라지지만 대상·버전·초안·원위치가 유지되는가.

자동 검사는 위 행동의 상태 연결과 표시를 확인한다. 이해하기 쉬워졌다는 판정은 별도의 휴리스틱 재검토와 실제 사용자 관찰을 구별해 남긴다. 가상의 사용자 역할을 수행하는 에이전트가 실제 초보자 검증을 대신했다고 기록하지 않는다.
