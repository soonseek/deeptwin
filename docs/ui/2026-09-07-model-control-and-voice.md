# 모델 선택·에이전트별 관리·실시간 음성 입력 — 추가 요구 기록

> **현재 제품 경계:** 모델 선택·에이전트별 관리·실시간 음성 요구는 유지한다. 다만 제품은
> 자체 호스팅 웹 기반 오픈소스 프레임워크이고 브라우저 UI가 공식 표면이다. 음성은 현재
> 브라우저에서 캡처해 인스턴스 소유 worker가 전사하며, Claude는 API-only, Codex 구독은
> 서버 소유 관리형 실행기로 연결한다. 아래 상충하는 과거 통합 상태 문구는 역사다.

상태: 2026-09-07 사용자 직접 추가 요구를 반영한 구축 기준. 모델 목록·업무별 선택과 로컬 STT를
현재 첫 사용 브라우저 개발 슬라이스에 연결했다. 에이전트별 관제는 아직 완료되지 않았다. 이 문서 아래의 추론 차단·
320개 회귀는 모델·음성 단계 당시 기록이다. 후속 실제 구독 업무 이해와 최신 검증은
[실제 업무 이해 기록](2026-09-07-live-understanding.md)을 따른다.
기존의 최종 사용자 구독 지원, CLI 없는 이용, 그래프 기반 관제, DeepTwin 비교·재평가 원칙을 확장한다.
논문에서 새로 추출한 요구나 사용자 대안 산출물로 분류하지 않는다.

## 사용자가 직접 요구한 것

- 연결한 LLM 제공자에 따라 사용자가 모델을 선택할 수 있어야 한다. 모델 예시는 Claude Fable 5.1과 GPT-6 Astra다.
- 개별 에이전트를 실행할 때 어떤 모델을 사용하는지 모두 관리할 수 있어야 한다.
- 최초 업무 설명 입력에 말하는 동안 글자가 들어오는 실시간 STT가 있어야 한다.

## 모델 관리가 사용자에게 나타나는 위치

| 위치 | 필요한 경험 |
| --- | --- |
| 제공자 연결 | 사용 가능한 모델 목록과 구독·추가 과금·접근/지원 상태를 확인하고 기본 모델을 고른다. |
| 업무 입력 | 업무 이해·환경 제안에 사용할 모델을 확인·변경한다. 매 입력마다 설정을 다시 요구하지 않는다. |
| 환경 설계·관제 그래프 | 각 에이전트의 제공자·모델이 보이며, 노드에서 바꾸거나 전체 배정을 한 번에 관리한다. |
| 실행 상세·산출물 | 해당 실행에서 실제 사용한 모델·지원 설정과 변경/재시도 이력을 확인한다. |

### 구현 시 지킬 계약

1. 모델 목록은 제품에 박아 둔 몇 개 이름이 아니라 연결 경로에서 확인한 목록과 기능을 기반으로 한다.
   새로운 모델 발견, 목록 갱신, 권한 소멸과 모델 종료를 처리한다. 목록 조회 성공은 추론 성공이나
   구독 포함 과금의 증명이 아니다. 접근 권한·실행기 지원·과금 확인 상태를 별개로 둔다.
2. 환경 기본값과 에이전트별 개별 설정을 구분한다. 생성자·감독자·크리틱·DeepTwin 분석/평가
   등 내부 에이전트도 예외 없이 실제 실행 설정을 추적한다. 상세 설정을 첫 사용 필수 설문으로 만들지 않는다.
3. 추론 강도 등은 선택한 모델이 실제 지원하는 값만 제공한다. 모델 변경 시 이전 모델의
   지원되지 않는 설정을 묵시적으로 유지하거나 임의 다른 값으로 바꾸지 않는다.
4. 화면의 선택, 실행 요청, 제공자 응답의 실제 모델을 연결한다. 설정·모델 목록의 확인 시점과
   실행기 버전도 남긴다. 공급자가 정확한 모델 리비전을 주지 않으면 미확인으로 기록하며 재현을 보장하지 않는다.
5. 실행 중인 호출은 시작 당시의 설정을 보존한다. 변경은 적용할 다음 실행/새 시도와 명시적으로
   연결하고, 진행 중인 다른 에이전트나 과거 기록을 조용히 바꾸지 않는다. 기존 전역 Codex/Claude 설정도 변경하지 않는다.
6. 사용자가 고른 모델을 실패 시 몰래 교체하거나 API·추가 크레딧 과금으로 전환하지 않는다.
   자동 대체가 필요하다면 허용한 후보·조건·비용 한도의 사전 정책과 실제 대체 기록이 있어야 한다.
7. 같은 모델의 생성자와 크리틱을 허용한다. 모델 선택 기능으로 크리틱 독립성 설계 요구를 대신하지 않는다.
8. 운영 환경의 모델 변경은 구성 변경으로 추적한다. 변경된 모델로 이전 업무 큐를 재평가하는
   비교에서는 모델/설정 변화도 드러낸다. 좋아진 결과를 렌즈·지식 흡수만의 효과로 오인하지 않는다.
   후보 시험과 개선 근거를 바탕으로 한 사람의 최종 운영 버전 승격을 구분한다.
9. 사용량·지연·실패·한도는 제공자가 실제 알려 주는 범위에서 표시한다. 구독 사용량을 API 요금표로
   환산해 실제 청구액처럼 표시하지 않는다. 모델 선택·실행·변경 기록은 로컬 로그/선택적 내보내기에 연결한다.

## 실시간 STT: 입력 수단이지 피드백 엔진이 아님

- 원 업무 입력 옆에서 마이크를 켜고, 말하는 동안 인식 중인 글자가 보이며 확정된 글자를 수정할 수 있어야 한다.
  녹음을 끝낸 뒤에야 전체 전사가 나타나는 기능만으로 실시간 요구를 충족했다고 하지 않는다.
- 잠정 전사와 확정 전사를 구별한다. 잠정 결과가 바뀌어도 중복 삽입되지 않고, 한글 조합/동시 타이핑을
  덮어쓰지 않는다. 업무 전환·취소 뒤 늦게 온 결과를 다른 업무에 넣지 않는다.
- 마이크 시작은 명시 조작과 기기 권한 허용 뒤에만 수행하며 녹음 상태·정지를 쉽게 보여 준다.
  전사 완료는 모델 전송·환경 실행 동의가 아니다. 텍스트·파일 입력은 음성 실패와 독립적으로 사용할 수 있다.
- 발화를 자동 요약·교정해 사용자의 원 의도인 것처럼 저장하지 않는다. 인식 결과와 이후 사용자 수정본을 구분한다.
  업무를 설명한 발화는 DeepTwin의 대안 수행/학습 정답으로 재분류하지 않는다.

**구현 추천(사용자의 직접 기술 선택은 아님):** 구독 LLM과 분리된 로컬 음성 엔진을 기본으로 검증한다.
프레임워크가 설치/언어 모델 준비를 안내하며 사용자에게 CLI 설치를 요구하지 않는다. 원음은 기본적으로
영구 보관하지 않고, 확정 전사·수정 이력·엔진/언어/오류 등의 동작 기록을 남기는 방향이다.
외부 STT와 원음 보관이 필요하면 전송·보관 범위를 별도로 알리고 선택받는다. 숨은 유료 API 대체는 하지 않는다.

한국어 정확도·부분 전사 지연·확정 지연·긴 발화·정지/재개·동시 타이핑을 실제 지원 기기에서 검증해야 한다.
엔진/지원 OS와 수치 목표는 성능 검증 뒤 확정하며 아직 충족했다고 주장하지 않는다.

## 현재 코드의 누락과 구축 순서

아래는 최초 요구를 받았을 때 정한 구축 순서다. 현재의 실제 구현·검증 범위는 다음 절에 구분한다.
실제 Codex 추론은 별도의 native-tool 격리 미충족으로 계속 차단한다.

1. 제공자별 실제 모델 목록·접근/과금 상태·선택 저장을 연결한다.
2. 업무 이해 요청부터 선택 모델/설정과 입력 수정본을 함께 고정하고 실행 시 검증한다.
3. 실시간 음성 입력을 현재 원 입력/저장 흐름에 독립적으로 연결해 검증한다.
4. 환경 그래프·실행기 구축에 에이전트별 모델 배정/변경/실제 실행 기록을 처음부터 포함한다.
5. 이전 큐 재평가·환경 버전 승격·로그 내보내기에서도 동일 모델 설정 이력을 사용한다.

## 이번 구현과 실제 확인 범위

### 모델 목록과 선택

- `model/list`를 명시 조회하며 모델별 추론 수준을 읽는다. 모델 이름을 고정 목록으로 만들지 않는다.
  조회만으로 추론이나 로그인 변경을 시작하지 않는다. Claude는 실제 구독 통합 미준비 상태로
  표시하며 공개 Fable 이름을 계정 조회 결과처럼 넣지 않는다.
- 업무 입력 가까이에 접을 수 있는 모델 설정을 둔다. 선택은 업무별 불변 설정 버전으로 저장한다.
  입력 수정본과 별개이므로 모델 변경이 원 설명·파일을 덮어쓰지 않는다.
- 업무 이해 요청에는 선택 모델·추론 수준·설정 버전·원래 목록·최근 재검증 목록을 고정한다.
  같은 계정의 목록을 새로 읽은 것만으로 유효한 기존 선택을 강제 재저장하지 않는다.
  계정 변경·현재 목록의 모델/설정 소멸·조회 실패는 새 요청의 검증을 통과하지 못한다.
- 요청의 실제 응답 모델이 선택과 다르면 성공으로 인정하지 않는다. 과거 요청과 진행 중인 요청은
  이후 선택 변경으로 재작성하지 않는다. API나 다른 모델로 자동 대체하지 않는다.
- 실제 설치된 Codex 0.144.4에 임시 개발 인스턴스 보관함으로 읽기 전용 조회를 수행했다. 반환 모델은
  `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`, `gpt-5.5`, `gpt-5.4-mini`,
  `gpt-5.3-codex-spark` 6개였다. **Astra는 이 연결 경로의 반환 목록에 없었다.**
  이를 제품 전체 모델 부재나 사용자 계정 권한 부족으로 단정하지 않는다. 실제 추론은 0회다.

### 로컬 음성 입력

- 현재 개발 기기(Apple Silicon macOS)에 whisper.cpp 1.8.7과 다국어 `base` 모델을
  개발 인스턴스 전용 `speech-runtime`에 준비했다. 다운로드한 공개 아카이브와 모델을 고정 SHA-256으로
  검증한다. 총 약 199 MB이며 전역 Python/Codex/Claude 설정을 바꾸지 않았다.
- 로컬 Python 서버와 개발 인스턴스 소유 C++ worker 사이에 크기가 제한된 PCM 스트림을 전달한다.
  음성을 LLM 구독이나 외부 전사 API로 보내지 않는다. 준비 상태 조회는 마이크나 엔진을 켜지 않는다.
- 브라우저는 사용자의 명시 마이크 조작 후에만 PCM을 만들고, 말하는 동안 잠정 전사를 표시한다.
  확정 구간은 현재 입력에 합치며 기존 타이핑과 한글 조합을 보존한다. 확정 전사는 음성 인식 결과이지
  사람의 승인·정답 표시가 아니며, 모델 전송 동의도 아니다.
- 세션·구간 순서·원음 해시·전사 결과·종료 이력을 로컬 DB에 보관한다. **원음 bytes는 디스크에
  남기지 않는다.** 전사 본문은 비공개 감사 테이블에 있으며 일반 이벤트에는 넣지 않는다.
  업무 전환/취소 뒤 늦은 결과는 적용하지 않고, 재시작은 진행 중 녹음/전사를 자동 재개하지 않는다.
- 세션은 128개 요청, 요청은 0.25–8초 PCM으로 제한한다. 5분 유휴 세션은 다음 시작/전사 요청에서
  만료 처리한다. 이는 정시 백그라운드 종료 보장이 아니다. 이 제한은 초기 구현의 제한이다.
- 실제 로컬 엔진에 새 합성 한국어 음성을 넣어 호출을 확인했다. 설치된 Yuna 음성의 문장
  “오늘은 파란 공 세 개를 상자에 넣습니다.”를 `base`가 “오늘은 파란 공세기를 상자에 넣습니다.”로
  인식했다. 준비 후 전사 시간은 해당 짧은 샘플에서 약 257–534 ms였지만 **숫자 구절 오류가 있었다.**
  첫 엔진 준비에는 약 8.6초가 관찰됐다. 실제 사람의 마이크·소음·장문·한국어 정확도 검증은 아니다.
- 정확히 0인 PCM의 환각은 빈 문자열로 처리하도록 회귀 시험을 추가했다. 이것이 일반 배경 소음이나
  모든 무음 환각을 해결했다는 증거는 아니다. 지원 배포 프로필의 격리 worker·고품질 VAD·정확도 목표는 남아 있다.

### 완료로 간주하지 않는 것

실제 구독 LLM의 업무 이해 추론, Claude 구독 통합, 생성된 환경 그래프에서의 에이전트별 배정,
실제 에이전트 실행·재평가·환경 승격 및 로그 내보내기는 아직 구현/검증되지 않았다.
선택/요청/기록의 버전 계약을 해당 단계에 재사용할 기반을 만든 것이지, 그래프 관제 요구의 완료가 아니다.
STT 설치 스크립트는 개발자 준비용이다. 최종 사용자가 CLI에서 이를 실행하도록 요구하는 제품 설계가 아니다.

### 검증과 UX 원칙

- OpenAI Docs로 공식 모델 조회·설정 계약을 확인하고, Frontend Design으로 첫 입력 화면을 유지하며
  모델 상세 설정을 접는 방식으로 배치했다. Superpowers TDD에 따라 동작 부재/오류를 재현하는
  실패 시험을 먼저 두고 구현했다. 독립 리뷰에서 발견한 경쟁·종료 오류도 회귀 시험으로 남겼다.
- Python 최신 전체 회귀는 **259 passed**, 실패/건너뜀 0이며 기존 Starlette/AnyIO deprecation 경고 1건이 있다.
  모델 요청의 고정/검증, 계정 변경과 catalog 게시 경쟁, SQLite 저장 실패, PCM 제한,
  세션 중지 뒤 늦은 결과, 캐시 손상, 자동 저장 중 받아쓰기를 검사했다.
- 기존 브라우저 회귀 **48/48**, 새 음성 프런트 시험 **13/13**(오디오 worklet 단위 시험 1개 포함)이
  통과했다. 실제 가짜 오디오 기기→WebAudio/worklet→PCM HTTP→실제 SpeechSessions→통제된 전사 엔진으로
  잠정/최종 반영·동시 타이핑/한글 조합·중복 방지·즉시 트랙 종료·다른 업무/화면의 늦은 응답 폐기를 검사했다.
  무음·권한 거절·동시 창·느린 전사 시 대기열 제한·종료 확인 실패·저장 freeze 해제·마이크 시작 중 타이핑도 포함한다.
  서버와 프런트 시험 합계는 **320개**, 실패/건너뜀 0이다. 실제 사용자 마이크 품질 통과 수치가 아니다.
- 부하를 준 통합 실행에서 RPC 시험의 50 ms **하위 프로세스 초기화** 전제가 한 번 실패했다.
  제품 타임아웃을 늘리지 않고, 정상 초기화 후 해당 차단 호출에만 짧은 시험 예산을 적용하도록
  테스트를 고쳤다. 대상 세 시험 5회 반복과 전체 회귀가 통과했다.
- 실제 로컬 STT 엔진을 새 합성 WAV→PCM→HTTP→세션 관리 경로로 호출해 200 응답과 전사를 확인했다.
  원 입력은 변하지 않았다. 이것은 마이크 기기/한국어 정확도 검증을 대신하지 않는다.
- 주 에이전트가 실제 첫 화면과 모델 선택 390/1024 px, 음성 입력 390 px 어두운 화면 및
  1024 px 밝은 화면을 직접 시각 검토했다. 음성 입력 장면은 합성 오디오 기기·통제된 엔진의
  검증 화면이다. 실제 모델/사용자 음성 결과를 보여 주는 스크린샷으로 분류하지 않는다.
- 실제 개발 서버는 기존 보관함을 유지한 `http://127.0.0.1:4193/`이다. 최초 화면 GET에서
  마이크 준비됨·LLM 실행 버튼 비활성·스크립트 오류 없음·POST 없음, 업무 전후 0개를 확인했다.
  실제 사용자 마이크와 사용자 업무 자료를 자동 시험에 사용하지 않았다.
- 기존 `control-prototype/`, 이전 두 superpowers 계획의 변경과 메인 작업 트리는 건드리지 않았으며,
  커밋·스테이징·푸시를 하지 않았다. 추가 파일은 실제 `app/`와 그 구현 기록에 한정했다.
