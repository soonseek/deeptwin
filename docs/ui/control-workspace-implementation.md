## 검증 원칙

최종 코드 검증 대상은 `4954450c6560a94ec4bf875030442afb9b8647af`이다. 주 에이전트가 7개 시험 파일을 함께 실행해 **79개 통과, 실패 0, 건너뜀 0**(46.16초)을 확인했다. 순수 코드·파일 57개와 실제 Chrome 브라우저 22개이며, 최종 캡처도 같은 코드에서 재생성했다. Task 6은 별도 명세 검토자의 두 수정 재검토 후 다른 담당자의 품질 검토를 통과했다. Task 7은 작성자와 다른 두 담당자가 명세와 품질을 순서대로 검토했고, 최종 SHA·검사 수의 기록 보정도 재검토 통과했다. 자동 검사와 아래 시각 관찰은 사용자 수용이나 엔진 효과를 뜻하지 않는다.

인계 상태: `http://127.0.0.1:4183`에서 시제품 서버를 실행 중이다. Codex 패널 열기 요청은 `queued`를 반환했고, 이후 화면 확인은 Mac 잠금으로 차단됐다. 브라우저 시제품 화면 표시·사용자 조작 확인은 잠금 해제 후 진행해야 한다. 사용자에게 CLI 조작을 요구하지 않는다. 작업 브랜치와 worktree는 유지하며 병합·푸시·정리하지 않는다. 실제 모델·도구·탐구·평가·운영 기능은 연결하지 않았다.

각 작업의 최초 실패, 수정 뒤 실제 통과, 독립된 명세 검토와 그 이후 품질 검토를 구별한다. 스크린샷은 실제 브라우저에서 캡처하고 직접 확인한다. 실제 한국어 IME나 사용자 수용을 자동 입력 테스트로 대체해 판정하지 않는다. 고정 합성 예시의 개선 수치는 엔진 성능 근거가 아니다.

기존 시제품 기준선: 번들 Playwright를 `PROTOTYPE_PLAYWRIGHT_MODULE`로 지정해 `node --test prototype/tests/prototype.test.mjs` 실행. 실제 32개 통과, 실패 0, 건너뜀 0. 브라우저 환경 없이 먼저 수행한 검사는 14개 통과·3개 건너뜀이었으며, 이후 완전 실행으로 구별해 기록한다. 이 결과는 코드 보존의 기준선이지 과거 정체성 실패 해소 근거가 아니다.

Task 1: 최초 `fixtures.mjs` 부재와 다음 `build-assets.mjs` 부재로 의도된 실패를 확인한 뒤 8개 검사 통과(실패·건너뜀 0). 가져오기와 검사만으로는 파일을 쓰지 않음. 최초 빌드 105개 생성, 재실행 105개 불변. PDF 생성 표식 1회(20개 예상), 20개 PDF와 파생 미리보기 렌더링, 고유 내용 12종·도식 10개 점검. 원본/파생 차이는 형식 표지뿐이며 c1의 의도된 업무 오류는 보존. PDF의 정규 xref 공백 120줄은 Git 공백 경고와 구별했고 나머지 파일 공백 검사는 통과. Task 1 독립 검토: `spec_fixture` 명세 통과 이후 `quality_fixture` 품질 검토 통과. 중대·중요 지적 없음. 파일 생성기의 차이 파일/심볼릭 링크 거부 경로는 읽기 전용 코드 점검으로 확인했으며, 재실행 불변성은 수동 빌드로 확인했다. 거부 경로를 실제 실행한 것으로 기록하지 않는다. 체크인된 자동 시험에 파일시스템 회귀 검사가 없다는 비차단 보완 의견을 기록한다.

Task 2: `361b2ee`, 상태 16개 검사·자료 포함 24개 검사 통과, 실패·건너뜀 0. 초기 누락 모듈 실패와 수정별 회귀 실패 후 통과를 기록했다. 주 에이전트 코드 점검으로 상속된 잘못된 실행 ID 처리, 실제 방문한 실행만 선택 기록으로 유지, 수행이 없는 서로 다른 자원의 대화 메모 분리 문제를 찾아 수정했다. 독립 검토는 별도다.

Task 2 명세 검토 지적을 `912c415`에서 수정했다. 배열을 실행 ID로 받아들이는 암묵적 변환, 현재 키 구조로 도달할 수 없는 자원 메모, 실제 텍스트가 아닌 PDF 때문에 실행되지 않던 텍스트 범위 검사, 보관 가능 크기와 복원 가능 크기의 불일치를 각각 회귀 검사 후 수정. 상태 18개·현재 전체 41개 검사 통과. 독립 명세 재검토 통과, 품질 검토는 다른 담당자에게 배정했다.

Task 3 품질 검토 통과. 비차단 보완 의견: 저장소의 그래프 회귀 시험은 설계 4종 중심이며 별도 명세 검토는 실행 포함 14종을 확인했다. 현재 실행 그래프는 같은 검증된 기본 구조를 재사용한다.

Task 2 품질 검토는 새 입력의 개선 영역 메모가 실제 원본 대신 고정 사례 회차를 키로 사용함을 재현했다. 다른 실행으로 옮기면 이전 메모가 보이고, 고정 사례에서 회차를 바꾼 뒤 돌아오면 같은 원본의 메모가 사라지는 문제다. 실제 원본 맥락과 고정 사례 맥락을 별도 키로 나누는 수정·회귀 검사를 진행한다. Task 5 독립 명세 검토는 104개 원본/미리보기 바이트와 포트 충돌 시 기존 서버를 종료하지 않는 동작도 확인했다.

Task 2 후속 `9d3e9c1`: 새 입력 메모는 실제 원본 맥락, 고정 사례 메모는 해당 차이·회차를 기준으로 분리했다. 실제 이동·자원 전환·고정 사례 왕복·보관 복원을 회귀 검사했다. 상태 21개·전체 44개 통과, 독립 명세 변경 재검토 통과. 원 품질 검토자가 지적 사항 해소 여부를 재검토한다.

Task 4 `27753bf`에 세 영역/보기와 정확한 고정 사례 상세를 연결했다. 긴 실행 선택 목록은 접을 수 있도록 하되 기존 실행 버튼과 정확한 참조를 유지했다. 주 에이전트·명세 검토에서 일반 화면의 ‘렌즈’ 표현과 빈 문자열 초안을 실제 자기 버전으로 표시하는 문제를 확인했다. `1fdc0cb`, `c88be9d`에서 회귀 실패 후 수정: 내부 용어는 감사에만 남고, 지운 초안은 부재로 표시하며 공백·줄바꿈은 원문 그대로 유지한다. 자체 11개·전체 55개 검사 통과. 아직 브라우저 조작이나 화면 관찰 결과는 아니다.

Task 4 수정 후 독립 명세 재검토와 후속 품질 검토를 모두 통과했다. 품질 검토자는 추가로 실행·시도·보기 228개 조합과 고정 사례 시도·수신 30개 조합을 읽기 전용으로 확인했다. DOM 입력·모달 복귀·실제 가독성은 Task 6–7의 별도 브라우저 검증 대상으로 남긴다.

Task 6 독립 명세 검토는 자동 검사 통과와 별개로 두 문제를 실제 브라우저에서 재현했다: 사용자가 접은 그래프가 같은 보기의 선택 변경에 다시 열리고, 파일만 있는 자기 버전을 문자 대안의 부재와 구별하지 않는 표시였다. `4954450`에서 실패 회귀 뒤 수정했다. 명세 재검토와 후속 품질 검토는 별도다. Task 7은 독립 명세 검토를 통과했고 품질 검토를 진행한다.

화면 관찰: 주 에이전트는 `00`–`07`의 주요 캡처 26개를 직접 확인했다. 별도 검토자는 화면 조합 54개와 좁은 그래프 보조 캡처 6개를 모두 확인했으며, 수정 뒤 밝은 범례 6개와 390px 어두운 선택 노드 캡처를 재확인했다. 작은 화면은 그래프·원 파일 내부 탐색을 사용하며 본문 밖 넘침이나 글자를 축소해 끼워 넣는 방식으로 처리하지 않는다. 캡처는 로컬에서 재생성 가능한 검사 출력이며 아직 Git에 추가하지 않았다. 실제 물리 한국어 IME·OS 수준 BFCache 이동·사용자 정체성 수용·실제 DeepTwin 효과는 검증되지 않았다.

진행 방식의 도구 제약: Task 2의 새 구현 담당 배정 후 추가 신규 에이전트 생성이 `agent thread limit reached`로 두 번 거절됐다. 이후 필요하면 기존 담당자를 새 한정 과제에 재사용한다. 구현자와 검토자는 분리하며 명세 통과 뒤 품질 검토 순서를 유지한다. 새 담당자를 매 작업에 배정했다고 허위 기록하지 않는다.

## 시각 구현 기준

승인된 작업대 구조를 유지한다. 서명 요소는 문서 카드가 아니라 선택 대상·정확한 산출물·전달 관계로 이어지는 관제 그래프다. 실행 캔버스 `#111c23`, 패널 `#17232a`, 본문 `#e1edf0`, 연결선 `#6cadb8`, 활성 `#56d7d3`, 주의 `#f4cb73`을 기본 어두운 팔레트로 삼는다. 한국어 제목은 Apple SD Gothic Neo의 굵기·크기 대비, 본문은 시스템 산세리프, 실행 참조는 monospace로 역할을 구별한다. 외부 폰트 요청은 하지 않는다.

구조: 왼쪽 환경 영역 → 상단 현재 버전·보기 → 읽을 수 있는 그래프 → 정확한 수행·산출물 작업면. 세 후보는 작은 그래프 카드로 축소하지 않고 같은 기능 초점으로 연결된 넓은 그래프를 비교한다. 선·번호·배지는 실제 관계·시도·상태에만 사용한다. 장식용 지표·가짜 진행·성공 표시는 넣지 않는다.

## 구현 전 발견한 구체적 검증 위험

읽기 전용 UI 점검에서 제안 코드의 두 위험을 찾았다. 이는 구현 완료 판정이 아니다.

- Task 3: 모든 그래프 선에 같은 아래→위 곡선을 쓰면 작성↔검토의 정방향과 되돌아감이 겹치고 노드 안을 통과한다. 방향별 포트·경로를 나누고 선택/라벨 가독성을 실제 화면에서 확인한다.
- Task 6: 전체 화면 재렌더링이 그래프 가로 탐색 위치와 펼친 상세를 잃게 할 수 있다. 동일 대상에서 위치·펼침을 유지하고 선택 노드를 다시 화면 밖으로 보내지 않는 브라우저 회귀 검사를 추가한다.
- Task 4/6: 고정 사례의 관련 실행 상세가 최신 시도의 출력만 보여 주면 탐구 맥락의 정확한 입력·시도·수신 기록을 확인할 수 없다. 해당 상세에서도 실제 시도를 선택하고 입력·출력·수신을 확인하되 현재 시험 초안의 대상을 바꾸지 않는다.

이 보완은 승인된 관계 가독성·맥락 보존의 구현 수정이며 새 제품 기능이나 실제 엔진 동작을 추가하는 것이 아니다.
