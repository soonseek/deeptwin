# 초기 UI 설계 검토 사례

작성일: 2026-09-06

검토 대상: [초기 UI 정보 구조·화면 흐름 설계][design] §1–11. 대조 근거: [기존 수용·거부 사례][ac]. [§7 화면 구조와 남은 결정][d7]은 기존 §1–6의 요약 대조 범위다. [§8 독립 제품의 도구 준비·실행·복구][d8]와 AC-035–037에 대한 UI-13–UI-15를 추가했던 이력과 UI-01–UI-12의 당시 문서 관찰을 보존한다. UI-01–UI-15 전체는 과거 §1–8 관찰 행으로 유지하고 §6 조작·§9의 V-01–V-08은 아래 [화면 검토 절차](#화면-검토-절차)에 별도로 기록한다. 후속 §10의 한정된 사용자 확인과 §11 통합 문서의 검토 대기는 ‘환경 맥락 유지형 작업대 채택’에 기록한다.

수용·거부 사례 링크는 원 작업 폴더의 로컬 근거다. 이 파일에 복사하지 않았으며 독립 배포물에 포함되지 않는다.

범위: 실제 문서의 출발 대상·도착 대상·상태·권한 연결을 따라 읽는 UI 설계 검토다. 사용자 대안, 실행 로그, 학습 점수, 기능 시험 데이터를 생성하지 않는다.

시작 이력: UI-01–UI-12 모두 **미검토 — 화면 설계 작성 후 확인**으로 기록했다. 이후 각 사례를 문서에서 추적한 관찰로 현재 판정을 갱신한다.

추가 검토 이력(2026-09-06): UI-13–UI-15는 **미검토 — §8 작성 후 실제 문구 추적 대기**로 시작했다. §8 작성 뒤 §8.1–8.6 전체와 §1의 도구 작업 참조·§4의 준비/실행/복구 연결·§5의 새 상태를 직접 읽어 아래 관찰을 갱신했다. 도구 준비·관제 정보·안전한 복구의 세 원칙은 사용자 확인됨, 이를 통합한 설계 문서는 사용자 미검토, 실제 UI·도구·파일·복구 동작은 미시험으로 구별한다. 기존 12개 사례의 관찰을 새 요구의 검토 완료로 소급하지 않는다.

보완 이력: UI-12는 최초 정본 `5bc9c17`에서 공유 검토 취소의 복귀·미추출·미전송 경로를 찾지 못해 ‘설계 누락’으로 기록했다. 원저자가 `f887eaa`에서 §4를 보완했고 명세·품질 재검토 완료를 전달받았다. 보완된 취소/닫기 → 원 업무·대상·버전·작성 상태의 연결을 다시 직접 읽어 현재 판정을 갱신했다.

판정 의미: ‘설계에 표현됨’은 해당 연결과 거부 경계가 문서에 있다는 뜻이다. ‘설계 누락’은 필요한 표현을 찾지 못했다는 뜻이다. 어느 판정도 프로그램 동작·품질·효과 통과나 사용자 승인을 의미하지 않는다.

현재 시제품은 제품 의도에 맞는 UX 기준선으로 채택하지 않는다. 아래 에이전트 검사는 자체 코드 범위의 동작 증거로 보존하며 이번 사용자 검토 실패를 뒤집는 근거가 아니다. 원 영상 관찰 기록과 상위 설계에서 요구했던 관제·실행·산출물 관계가 클릭 계획의 문서 편집·상태 보존 중심 검증으로 축소됐다. 다음 단계는 상위 대상·연결·합격 기준의 재검토다. 이 기록만으로 새 화면 설계나 구현을 승인하지 않는다.

2026-09-06 사용자는 “우선 이 환경 맥락 유지형 작업대를 기준으로 상세 설계를 진행하는 것이 맞을까요? 이번 확인은 연결 구조에 대한 것이며, 세부 기능이나 구현 전체의 승인은 아닙니다.”에 “맞아”라고 답했다. [UI 설계 §10](../superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md#10-환경-맥락-유지형-작업대--채택된-연결-구조)에 확인된 구조와 다음 검토 제안을 분리했다.

확인 범위는 같은 환경의 설계 비교·실행 관제·개선 실험을 연결하고 작업공간·대화·그래프에서 환경 버전·업무·실행·단계/시도·산출물 맥락을 유지하는 방식이다. 대상에 직접 들어갈 수 있어야 하며 필수 순차 탐색으로 만들지 않는다. 표시용 시각 자료의 가상 기록·미리보기는 실제 파일 생성·렌즈 수행·평가 증거가 아니다. 기존 V02/V03 실패, 나머지 장면 미승인과 과거 UI-01–15 문서 관찰을 그대로 보존한다.

당시 첫 확인은 새 상세 패널·기본 펼침·지원 형식/편집·자동 저장/대안 인식/시험 시작 정책·새 시제품·엔진·계정/도구 연결까지 승인한 응답이 아니었다. 실행 그래프와 개별 수행·시도의 실제 입력·다형식 출력·전달 이력을 이어 보는 경험은 아래 후속 확인으로 구별한다.

문서 통합 점검(첫 확인 당시): 기존 UI-01–15의 15행은 당시 HEAD와 동일하며 장면 정의·관찰 표는 각각 8행/6열을 유지했다. UI 정본·이 기록·원 작업 폴더의 제품 의도/진행 기록에서 로컬 참조 65개를 확인했다. 자체 검토와 별도 읽기 전용 검토에서 승인 범위 확대·기존 실패 은폐·논문과 UI 제안의 혼동·수행/시도별 입출력 맥락 누락에 관한 중요한 결함을 발견하지 못했다. 이는 문서 일관성 점검이며 그 자체가 사용자 확인·제품 동작·엔진 효과 검증은 아니다.

후속 실행·산출물 탐색 확인(2026-09-06): 사용자는 “전체 그래프를 유지하면서, 선택한 수행·시도의 정확한 입출력과 전달 이력을 펼쳐 보는 이 방식으로 상세 설계를 이어가면 맞을까요?”에 “응”이라고 답했다. UI 정본 §10.3의 핵심 탐색 방향을 확인 상태로 바꿨다. 전체 관계와 개별 수행/재시도, 실제 입출력·전달 버전, 다형식 열람·확장과 맥락 유지를 연결하되, 구체 접힘 규칙·패널·형식별 편집/비교·대안 식별/저장/시험 시작·새 구현은 미결로 유지한다. V02/V03의 기존 시제품 실패를 통과로 바꾸지 않는다.

당시 다음 검토로 §10.4의 공통 산출물 작업 영역에서 형식에 맞게 원본과 자기 버전을 다루는 경험을 제시했다. 논문 §4.5–4.6·§6.2를 다시 읽고 원본/파생 표시/실제 대안, 검토 범위/영향 범위, 편집·대안 수용·비교 지원을 구별했다. 그 시점에는 사용자 미확인이었고 새 UI·파일 변환·실제 대안·렌즈 수행·효과 평가를 생성하거나 시험하지 않았다.

후속 문서 점검: 기존 UI15행의 동일성과 장면/관찰 각각 8행·6열, 네 문서의 로컬 참조 66개 및 공백 오류 없음을 확인했다. 자체 검토와 별도 읽기 전용 검토에서 범용 편집 약속·부분 대안의 전체 승인 변환·코칭 회귀·승인 확대에 중대한 결함을 발견하지 못했다. 기존 UI 계획의 별도 미커밋 내용은 변경하지 않았다. 점검 결과는 문서 일관성에 한정한다.

후속 다형식 작업면 확인(2026-09-06): 사용자는 “이처럼 같은 작업면에서 원본과 자기 버전을 함께 다루되, 열람·작성·비교 방법은 산출물 형식에 맞추는 방향이 맞을까요?”에 “응”이라고 답했다. UI 정본 §10.4의 경험 방향을 확인 상태로 바꿨다. 구체 지원 형식·편집기·부분 매칭·저장·대안 식별·시험 시작·새 구현까지 승인한 응답은 아니다. 기존 시제품 실패와 UI15행의 과거 문서 관찰은 그대로 보존한다.

당시 다음 검토로 §10.5의 관찰 차이 중심 연결 상세를 제시했다. 원본/대안 비교와 관련 실행 구간, 경쟁 설명별 지지·반대 근거·미설명 부분, 필요한 새 증거와 감사 이력을 함께 읽는 경험이다. 논문 §4.7–4.8.5(21–28쪽)를 다시 확인했으며 그래프 강조를 원인 판정, 렌즈 해석을 학습 정답, 사용자의 설명 동의를 새 수행 증거로 바꾸지 않았다. 그 시점에는 사용자 미확인이었고 실제 진단·렌즈·평가·구현은 수행하지 않았다.

이번 문서 점검: UI15행 보존, 장면/관찰 각각 8행·6열, 로컬 참조 67개와 공백 오류 없음을 확인했다. 자체 검토와 별도 읽기 전용 검토에서 조사 강조/인과 판정·관찰/가설/새 증거·렌즈 감사/후보 근거·부분 반복/승인 범위 구별에 중요한 결함을 발견하지 못했다. 기존 UI 계획의 별도 미커밋 내용은 변경하지 않았다. 문서 일관성 점검이며 진단·렌즈 효과의 검증은 아니다.

후속 차이 중심 탐구 확인(2026-09-06): 사용자는 “차이를 선택하면 관련 실행 구간과 경쟁 설명·근거가 함께 따라오는 이 탐구 방식으로 잡으면 맞을까요?”에 “응”이라고 답했다. UI 정본 §10.5를 확인 상태로 바꿨다. 확인은 조사 상세의 조직 방향에 한정되며 구체 패널·표시 규칙·질문 정책·자동 실행·진단/렌즈 효과·새 구현의 승인 또는 검증은 아니다. 기존 시제품 실패와 UI15행의 과거 관찰은 보존한다.

당시 다음 검토로 §10.6의 이전 업무 큐에서 업무·회차를 선택해 기준/후보 실행 쌍을 함께 보는 경험을 제시했다. 논문 §4.9–4.10(28–30쪽)과 사용자의 이전 큐 반복·사람 최종 환경 버전업 요구를 대조했다. 과거 원 실행/비교 기준/후보 실행, 조건 일치/차이, 국소 전달/후속 산출물, 반복 큐/별도 최종 근거, 검증·승인·실제 적용 버전을 구별했다. 그 시점에는 사용자 미확인이었고 실제 재실행·평가·승인·계정 연결·구현은 수행하지 않았다.

이번 문서 점검: UI15행 보존, 장면/관찰 각각 8행·6열, 로컬 참조 68개와 공백 오류 없음을 확인했다. 자체 검토와 별도 읽기 전용 검토에서 실제 비교 조건·국소/후속 영향·반복/최종 자료·검증 조합·외부 권한·승인 범위 구별에 중요한 결함을 발견하지 못했다. 기존 UI 계획의 별도 미커밋 내용은 변경하지 않았다. 이는 문서 일관성 점검이며 실제 개선 효과의 검증은 아니다.

후속 반복 평가 작업면 확인(2026-09-06): 사용자는 “업무와 회차를 고르면 기준·후보의 그래프·산출물·평가 근거가 함께 열리는 이 비교 작업면을 반복 평가의 기본 화면으로 잡으면 맞을까요?”에 “응”이라고 답했다. UI 정본 §10.6을 확인 상태로 바꾸고 V-06의 목표 경험에 실제 실행 쌍과 맥락 연결을 반영했다. 확인은 비교 작업면의 조직 방향이며 구체 배치·평가식·회차 수·예산·자동 실행/승인 조작·개선 효과·새 구현의 승인 또는 검증은 아니다. 과거 시제품 실패와 UI15행의 기존 관찰은 보존한다.

당시 다음 검토로 §10.7의 초기 후보 그래프들을 같은 검토 초점으로 연결해 읽는 경험을 제시했다. 논문 §4.2–4.4(16–18쪽)·§6.4(40쪽)와 초기 렌즈 생성·별도 크리틱의 사용자 확장을 구별했다. 후보 간 구조 차이, 예정 계약/실제 기록, 렌즈 조합/구조 병합, 수정 버전의 재검토·승인/구성 상태를 분리한다. 그 시점에는 새 상세가 사용자 미확인이었으며 실제 후보 생성·크리틱 평가·모델 호출·구현은 수행하지 않았다.

이번 문서 점검: UI15행 보존, 장면/관찰 각각 8행·6열, 로컬 참조 69개와 공백 오류 없음을 확인했다. 자체 검토와 별도 읽기 전용 검토에서 구조 다양성·후보 부족·렌즈 조합/구조 병합·설계/실행·새 버전 재검토·독립성 미검증과 승인 범위 구별에 중요한 결함을 발견하지 못했다. 기존 UI 계획의 별도 미커밋 내용은 변경하지 않았다. 문서 일관성 점검이며 실제 설계 생성·크리틱의 효과 검증은 아니다.

후속 초기 그래프 비교 확인(2026-09-06): 사용자는 “비교 초점을 고르면 각 후보 그래프의 관련 구조와 검토 근거가 함께 따라오는 방식으로 잡으면 맞을까요?”에 “응”이라고 답했다. UI 정본 §10.7을 확인 상태로 바꾸고 V-02에 같은 초점·새 버전 재검토 연결을 반영했다. 확인은 후보 탐색의 조직 방향이며 구체 배치·생성/평가식·자동화·독립성 검증·새 구현의 승인이 아니다.

통합 문서 검토 제시: [UI 정본 §11](../superpowers/specs/2026-09-06-deeptwin-ui-structure-design.md#11-통합-검토본--다음-ui-계획의-범위)에 확인된 구조의 읽기 기준과 다음 UI 계획의 한정된 검토 계약을 묶었다. 새로운 상위 원칙 질문을 추가하지 않으며 사용자 문서 검토 뒤 수정 UI 전용 계획을 작성하는 방향을 제시한다. 실제 조작/다형식 시험 파일과 표시용 생성·렌즈·평가 상태를 구별하고, 계획 수립·재제작 착수·실제 엔진을 일괄 승인하지 않는다. 현재 통합본·후속 계획 범위는 사용자 검토 대기다. 아래 역사적 장면 관찰 칸을 새 시제품의 통과로 갱신하지 않는다.

통합본 점검(2026-09-06): UI15행 보존, 장면/관찰 각각 8행·6열, 로컬 참조 72개와 공백 오류 없음을 확인했다. 자체·별도 읽기 전용 검토에서 중요한 의도 이탈이나 승인 확대를 발견하지 못했다. 읽기 전용 검토의 주의점을 반영해 새 시험 입력에 사전 합성 탐구 이력을 분석 결과처럼 붙이지 않는 경계를 명시했다. 별도 미커밋 UI 계획은 그대로 보존했다. 이는 문서 검토이며 새 화면·실제 파일 생성·렌즈/크리틱·개선 효과 검증은 아니다.
