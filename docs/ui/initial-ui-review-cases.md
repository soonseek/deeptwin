# 초기 UI 설계 검토 사례

작성일: 2026-09-06

검토 대상: [초기 UI 정보 구조·화면 흐름 설계][design] §1–9. 대조 근거: [기존 수용·거부 사례][ac]. [§7 화면 구조와 남은 결정][d7]은 기존 §1–6의 요약 대조 범위다. [§8 독립 제품의 도구 준비·실행·복구][d8]와 AC-035–037에 대한 UI-13–UI-15를 추가했던 이력과 UI-01–UI-12의 당시 문서 관찰을 보존한다. UI-01–UI-15 전체는 과거 §1–8 관찰 행으로 유지하고 새 §6 조작·§9의 V-01–V-08은 아래 [화면 검토 절차](#화면-검토-절차)에 별도로 기록한다.

수용·거부 사례 링크는 원 작업 폴더의 로컬 근거다. 이 파일에 복사하지 않았으며 독립 배포물에 포함되지 않는다.

범위: 실제 문서의 출발 대상·도착 대상·상태·권한 연결을 따라 읽는 UI 설계 검토다. 사용자 대안, 실행 로그, 학습 점수, 기능 시험 데이터를 생성하지 않는다.

시작 이력: UI-01–UI-12 모두 **미검토 — 화면 설계 작성 후 확인**으로 기록했다. 이후 각 사례를 문서에서 추적한 관찰로 현재 판정을 갱신한다.

추가 검토 이력(2026-09-06): UI-13–UI-15는 **미검토 — §8 작성 후 실제 문구 추적 대기**로 시작했다. §8 작성 뒤 §8.1–8.6 전체와 §1의 도구 작업 참조·§4의 준비/실행/복구 연결·§5의 새 상태를 직접 읽어 아래 관찰을 갱신했다. 도구 준비·관제 정보·안전한 복구의 세 원칙은 사용자 확인됨, 이를 통합한 설계 문서는 사용자 미검토, 실제 UI·도구·파일·복구 동작은 미시험으로 구별한다. 기존 12개 사례의 관찰을 새 요구의 검토 완료로 소급하지 않는다.

보완 이력: UI-12는 최초 정본 `5bc9c17`에서 공유 검토 취소의 복귀·미추출·미전송 경로를 찾지 못해 ‘설계 누락’으로 기록했다. 원저자가 `f887eaa`에서 §4를 보완했고 명세·품질 재검토 완료를 전달받았다. 보완된 취소/닫기 → 원 업무·대상·버전·작성 상태의 연결을 다시 직접 읽어 현재 판정을 갱신했다.

판정 의미: ‘설계에 표현됨’은 해당 연결과 거부 경계가 문서에 있다는 뜻이다. ‘설계 누락’은 필요한 표현을 찾지 못했다는 뜻이다. 어느 판정도 프로그램 동작·품질·효과 통과나 사용자 승인을 의미하지 않는다.

대상: [설계 §9 화면별 상세 검토안][d9]과 §6.1–6.6의 장면 연결 추천 조작. 상태: 첫 시제품 기본 골격 A와 §9.3 제작 범위 사용자 확인, 시제품 제작 중. 장면별 세부 조작은 실제 화면 검토 전이다. 기존 UI-01–UI-15는 과거의 문서 관찰 행으로 보존하고 아래 기록을 추가한다.

골격 선택 기록(2026-09-06): “첫 시제품의 기본 배치는 이 A안으로 잡는 것이 맞을까요?”에 사용자가 “응”이라고 답했다. 왼쪽 환경·업무 탐색, 상단 대상·버전, 중앙 세 모드 전환만 첫 시제품의 기본 배치로 확인했다. 아래 V-01–08의 사용자 확인 칸은 장면별 세부 조작을 뜻하므로 일괄 완료로 바꾸지 않는다. 기본 진입·저장/대안 식별·자동화·승인 조작과 실제 제작·제공자/도구 연결은 이 응답으로 확인하지 않았다. 제작 범위는 UI §9.3의 제안으로 따로 검토한다.

제작 범위 후속 확인(2026-09-06): 다음 질문 “이 범위로 첫 클릭 시제품을 만드는 것이 맞을까요?”에 사용자가 “응”이라고 답해 UI §9.3 범위의 구현 계획·제작을 시작했다. 장면 이동·원문/선택·시험용 편집과 표시용 시스템 결과를 구별하며 실제 AI·도구·학습은 연결하지 않는다. 제작 승인을 장면별 사용성 확인이나 엔진 효과 검증으로 기록하지 않는다.

기록 시작(2026-09-06): 아래 여덟 장면의 다섯 기록칸을 모두 미실시로 작성했다. 앞으로 수행한 단계만 날짜·대상 버전·실제 근거·관찰/한계를 남겨 갱신한다. 준비전은 사용할 대상·자료·접근 조건을 점검하는 별도 단계이며 문서검토 완료나 사용자 확인을 대신하지 않는다. 문서 작성에 착수했다는 사실만으로 준비전이나 다른 칸을 완료로 바꾸지 않는다.

문서검토에서는 각 장면의 출발 대상에서 보이는 영역·선택·상태 변화·복귀까지 직접 읽고, §9.1의 동일 산출물 추적과 §6의 추천 조작에 맞춰 권한·원본/대안/후보 버전을 대조한다. 시제품관찰에서는 사람이 화면에서 실제로 경로를 찾는지, 사용자확인에서는 A/B·첫 진입·복귀·대안 식별·승인 표시 등 개별 추천을 선택했는지, 실제연결시험에서는 도구·PDF 실물·후속 입력·저장/복구가 실제로 작동하는지 각각 별도 근거를 남긴다. 이 절은 그 실행을 이번 작업에서 수행했다는 뜻이 아니다.

화면을 관찰할 때에는 사용할 자료가 없다는 이유로 사용자 업무 설명에서 콘텐츠나 자기 대안을 만들어 채우지 않는다. 외부 연결이나 실행 없이 가능한 문서검토만 먼저 남길 수 있다. ‘문서에서 연결 확인’은 사용성·기능·학습 효과의 시험 통과가 아니며 수행하지 않은 단계는 미실시로 둔다.

문서 관찰 갱신(2026-09-06): 기준 커밋 `7e0f0cf`의 두 문서 전체를 읽은 뒤 이번 §6 장면 연결 조작·§9 전체와 아래 절차를 다시 직접 읽었다. 아래 문서 검토 칸은 이 추가 본문의 출발/복귀·권한·버전 연결을 관찰한 기록이다. 실제 연결 자료의 준비 점검·시제품 관찰·새 추천의 사용자 확인·동작 시험은 수행하지 않았으므로 각각 미실시로 유지한다.
