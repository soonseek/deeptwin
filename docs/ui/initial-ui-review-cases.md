# 초기 UI 설계 검토 사례

작성일: 2026-09-06

검토 대상: [초기 UI 정보 구조·화면 흐름 설계][design] §1–7. 대조 근거: [기존 수용·거부 사례][ac]. [§7 화면 구조와 남은 결정][d7]을 기존 §1–6의 요약 대조 범위로 추가하며 사례 수와 기존 관찰의 의미는 유지한다.

수용·거부 사례 링크는 원 작업 폴더의 로컬 근거다. 이 파일에 복사하지 않았으며 독립 배포물에 포함되지 않는다.

범위: 실제 문서의 출발 대상·도착 대상·상태·권한 연결을 따라 읽는 UI 설계 검토다. 사용자 대안, 실행 로그, 학습 점수, 기능 시험 데이터를 생성하지 않는다.

시작 이력: UI-01–UI-12 모두 **미검토 — 화면 설계 작성 후 확인**으로 기록했다. 이후 각 사례를 문서에서 추적한 관찰로 현재 판정을 갱신한다.

보완 이력: UI-12는 최초 정본 `5bc9c17`에서 공유 검토 취소의 복귀·미추출·미전송 경로를 찾지 못해 ‘설계 누락’으로 기록했다. 원저자가 `f887eaa`에서 §4를 보완했고 명세·품질 재검토 완료를 전달받았다. 보완된 취소/닫기 → 원 업무·대상·버전·작성 상태의 연결을 다시 직접 읽어 현재 판정을 갱신했다.

판정 의미: ‘설계에 표현됨’은 해당 연결과 거부 경계가 문서에 있다는 뜻이다. ‘설계 누락’은 필요한 표현을 찾지 못했다는 뜻이다. 어느 판정도 프로그램 동작·품질·효과 통과나 사용자 승인을 의미하지 않는다.

‘승인’은 설계 §1·5·6.6과 AC-011·023에서 대상·버전·효력을 가진 결정이며 검사 성공·실제 적용과 구별된다. UI 검토 판정에도 운영 승인 효력을 부여하지 않는다.

‘대안’은 설계 §1·4·6.4와 AC-029–031·033에서 선행 원본 뒤 실제 제공한 자기 버전이며 이유 설명·시스템 추정·업무 설명이 아니다. ‘실험’은 설계 §4·5와 AC-005·010·011·026·027·030에서 기준·후보를 구별한 재수행 비교이며 튜닝·최종 증거·운영 적용을 구별한다. 네 용어의 의미 충돌은 발견하지 못했다.

§7 대조 관찰: 두 골격·세 모드 연속성은 UI-03·04 및 §1–3과, 업무 설명에서 실제 구조·산출물로 이어지는 흐름은 UI-01·02 및 §4와 일치한다. 실제 부분 대안·탐구·격리 실험의 반복은 UI-05·06, 전체 회차·별도 최종 근거는 UI-08, 실패·보류·정확한 후보 승인·운영/롤백은 UI-09·10의 기존 연결을 보존한다. 세 탐구 경로와 업무 표현·권한 있는 감사는 UI-07, 각각의 구독·선택 API는 UI-11, 독립 기록 추출·공유 취소 복귀는 UI-12와 직접 대조했다. §6의 여섯 선택도 확인된 원칙과 미합의 조작으로 구별되어 요약과 본문 사이의 의미 충돌을 발견하지 못했다. 이 대조는 새 실행 사례가 아니며 사용자 미검토·실제 동작 미시험 상태를 바꾸지 않는다.

검사 기록: 지정 `rg` 패턴으로 UI-01–UI-12 정확히 12행을 확인하고, 7열·행 순서·전 사례의 검토 한계와 로컬 링크 10개 정의의 파일·절 앵커를 검사했다. 설계 §1–7 존재와 §7의 본문·사례 연결, 이번 요약 보완의 변경 범위가 두 설계 문서뿐인지 확인했다. `git diff --check`로 공백 오류를 확인했다. 형식 검사는 각 사례의 의미 검토를 대신하지 않는다.
