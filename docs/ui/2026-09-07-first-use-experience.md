## 이번 설계의 중심

인스턴스에 처음 들어온 사람은 자신의 업무를 설명하거나 자료를 넣는다. 프레임워크가 그 업무를 수행할 환경을 제안하고, 사용자는 그 결과를 이해·조정·승인해 첫 업무를 시작한다. 기능 목록이나 논문의 내부 객체가 화면 순서를 결정하지 않는다.

첫 사용의 주체는 일반 사용자이며, 첫 화면의 일은 **업무를 맡길 수 있게 하는 것**이다. 관제 그래프는 사용자가 먼저 조립해야 할 빈 편집기가 아니라 업무 요청에 대한 구성 결과다. 운영에 들어가면 같은 그래프가 실제 진행·전달·산출물을 보여 주는 관제면이 된다.

## 같은 업무 공간이 바뀌는 다섯 장면

### 처음 실행했을 때

- 지원 배포물은 운영자가 인스턴스를 가동하고 사용자가 공식 브라우저 UI에 들어갈 수 있는
  안내와 상태를 제공해야 한다. 인스턴스가 준비된 뒤의 DeepTwin 업무에 CLI·개발자 설정이나
  Docker/Portainer 화면 조작을 사용자 과제로 넘기지 않는다. 구체 지원 호스트·배포 방식은
  최신 운영 계약에서 별도로 고정·검증한다.
- 화면 중심에는 “어떤 일을 맡기고 싶으세요?”와 업무 설명/자료 추가가 있다. 빈 관제 그래프, 분석 메뉴, 학습 설정부터 보여 주지 않는다.
- Codex 구독 또는 Claude API 연결을 DeepTwin 브라우저 UI 안에서 안내한다. 설명·자료 준비는 먼저 할 수 있고, 실제 모델이 필요한 시점에는 연결 상태와 복귀 경로를 제공한다. Codex API는 별도 명시 선택이다. 공식 통합의 기술적 적합성을 이번 시각 초안이 증명하지 않는다.
- 기록 기반은 배포·최초 설정 중 프레임워크가 제어권을 가진 최초 사건부터 작동해야 하지만, 로그 추출을 첫 업무의 필수 절차로 만들지 않는다. 수집 범위·보관/공유 안내는 별도 책임으로 남긴다.

### 설명하거나 자료를 넣었을 때

- 자료가 추가됐는지, 읽을 수 있는지, 아직 처리 중인지 개별 자료 옆에서 알 수 있다.
- 프레임워크가 이해한 업무와 예상 결과를 짧게 보여 준다. 사용자는 틀린 부분만 말로 바로잡는다. 자료만 넣은 경우에는 목적처럼 중요한 빈칸만 묻는다.
- 목적·완료 조건·권한·위험 등의 모든 필드를 사용자에게 작성시키는 설문으로 바꾸지 않는다. 충분한 정보가 있으면 매 항목 승인 없이 제안을 준비한다.
- 업무 설명과 자료는 환경 설계의 입력이다. 아직 없는 산출물의 사용자 대안·학습 정답으로 재분류하지 않는다.

### 환경 제안이 준비됐을 때 — 첫 그래프가 등장하는 시점

- 입력한 업무와 자료를 그대로 유지한 작업 공간에 제안된 환경이 나타난다. 다른 전문 메뉴를 찾아갈 필요가 없다.
- 기본 3안은 실제 구조로 비교한다. 권장안과 차이를 업무 언어로 설명하며, 다른 안도 그래프로 대조할 수 있다. 작은 장식 그래프나 이름만 다른 카드로 대체하지 않는다.
- 누가 무엇을 만들고 누구에게 전달하는지부터 읽힌다. 감독·통제·도구·기억·평가도 같은 환경 구성에 연결하고, 필요한 상세를 펼칠 수 있게 한다.
- 사용자가 말로 수정을 요청하면 영향을 받은 역할·연결과 새 제안이 함께 바뀐다. 직접 노드 편집·YAML 작성을 필수로 요구하지 않는다.
- 내부에서는 렌즈 단독/하이브리드 탐색과 별도 크리틱을 수행하고 생성·탈락·수정 이력을 남긴다. 일반 사용자가 철학 용어나 독립성 설계를 이해해야 다음으로 갈 수 있게 하지 않는다. 검토한 후보가 부족하면 세 안을 가짜로 채우지 않는다.

### 선택한 환경으로 업무를 시작할 때

- 무엇을 구성하고 어떤 첫 업무를 수행할지 이해할 수 있는 요약에서 승인 범위를 확인한다. 화면 수와 승인 효력의 수를 일치시키지 않는다.
- 프레임워크가 구성을 맡고 필요한 연결/권한만 해당 작업에서 안내한다. 모든 외부 서비스 연결을 설계 전에 강제하지 않는다.
- 준비가 끝나면 같은 환경에서 실행을 시작한다. 그래프는 새 메뉴가 아니라 제안에서 실행 상태로 이어진다. 막힌 역할에는 필요한 사용자 행동이 보인다.
- 설계 승인만으로 외부 게시·발송이나 미래의 모든 운영을 허가한 것으로 처리하지 않는다.

### 첫 산출물을 받았을 때

- 완성된 결과가 우선 보이며, 그래프에서 개별 역할의 단계별 산출물과 전달도 바로 확인할 수 있다. PDF·표·이미지 등 형식을 텍스트로 평준화하지 않는다.
- 사용자는 필요한 산출물 전체/일부에 “내가 만든 버전”을 남길 수 있다. 별도 개선 메뉴에서 원인을 해설하거나 모든 부분을 채울 의무가 없다.
- 실제 대안 이후 내부 차이 탐구·렌즈·후보 변경·이전 업무 큐 반복 평가가 연결된다. 부분 대안의 영향은 그 부분에 갇히지 않는다. 사람이 개선 근거와 정확한 환경 버전을 보고 최종 승인한다.
- 세 보기(작업공간·대화·그래프)는 같은 업무를 살펴보는 방식으로 유지한다. 시작 전에 모드를 이해·선택하는 문제를 풀게 하지 않는다. 로그 추출/공유는 언제든 선택하는 별도 행위다.

이 장면들은 경험을 설명하는 구분이다. 제품에 다섯 단계 마법사나 고정 완료 버튼을 추가하라는 명세가 아니다.

## 시각 초안의 범위

대화 속 클릭형 초안은 **주간 자료 브리핑이라는 새 합성 업무**의 사전 작성 장면이다. 실제 사용자 자료를 받거나 읽지 않고, 로그인·그래프 생성·검토·실행·파일 생성·학습을 하지 않는다. 장면 선택은 검토 도구이며 제품의 고정 메뉴가 아니다. 실제 모델 결과와 사용자 대안이 없으므로 DeepTwin 효과 검증도 아니다.

시각 방향: 기존 제품의 청록 관제 언어를 유지하되, 첫 화면은 입력 작업에 여백을 배분한다. 밝은/어두운 화면의 배경은 #f4f7f7 / #10191e, 패널은 #ffffff / #18262d, 본문은 #1b3037 / #e5eff0, 보조 글자는 #53676e / #acc0c6, 선은 #cfdddf / #3c535d, 강조는 #087f83 / #62d2ce를 쌍으로 사용한다. 제목/본문은 시스템 한국어 산세리프, 파일/연결의 보조 표시는 시스템 고정폭. 고유 요소는 **업무를 입력하던 같은 공간에서 환경 그래프가 만들어지고 그 그래프가 관제로 이어지는 연속성**이다.

자기 비평: 새 랜딩 페이지나 일반 챗봇처럼 보이는 것을 피하기 위해 설계 장면에 실제 역할·통제·자원 관계를 표시한다. 반대로 처음부터 운영 상세를 노출해 다시 검사 도구가 되는 것을 피하기 위해 최초 화면에는 업무 입력만 전면화한다. 깊은 관제 기능의 삭제가 아니라 등장 시점의 재조직이다.

## 이번에 확인할 것

1. 처음 켰을 때 별도 설명 없이 할 일을 알 수 있는가?
2. 자료가 어떤 업무와 구성에 반영됐는지 이해할 수 있는가?
3. 사용자가 에이전트 설계자가 되지 않아도 환경을 이해·수정할 수 있는가?
4. 제안에서 첫 실행·산출물까지 같은 업무를 이어 간다고 느끼는가?
5. 실패/연결 부족에서도 내용을 잃지 않고 다음 행동을 알 수 있는가?

이 흐름을 먼저 검토하며, 현재 시제품의 세부 배치나 과거 기능별 “응”을 새 경험의 최종 승인으로 승계하지 않는다. 근거는 사용자 직접 정정, 제품 의도 INT-003/008/015/025/034, 수용 기준 AC-001/008/019, 통합 설계 §1–3이다. 논문 원본을 이번 턴에 새로 독해한 것으로 기록하지 않는다.

검토용 장면의 로컬 확인: 1024/736/360px × 밝은/어두운 화면 × 5장면, 총 30개 조합에서 페이지 가로 넘침과 스크립트 오류가 없음을 확인했다. 후보 전환·역할 선택·산출물 종류 전환·세 보기·연결 안내 복귀도 확인했다. 주 에이전트가 첫 입력·업무 이해·설계 그래프·산출물 화면을 직접 시각 검토했다. 이 결과는 장면 전환 검사이며 실제 설치·인증·자료 처리·생성·사용자 이해도 또는 이전 관제 시제품의 최종 검증이 아니다.
