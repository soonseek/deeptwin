상태: **입력·자료 보관 슬라이스 구현 및 검증 완료 / 전체 첫 사용 여정 미완료**.
2026-09-07 사용자의 “좋아”는 첫 사용 경험 방향의 수용, 이어진 “응”은 실제 연결 착수로 해석했다.
최종 제품·배포·모델 통합 완료나 변경된 공급자 조건의 승인을 받은 것은 아니다.

이 문서는 첫 입력/보관 구현 당시 기록이다. 후속 계정 연결·업무 이해 서비스·모델 선택·음성
입력의 현재 범위는 `app/README.md`와 [모델·음성 기록](2026-09-07-model-control-and-voice.md)을 따른다.

## 작업 범위

`app/`에 별도 실제 로컬 서버와 입력 화면을 만들었다. 기존 `control-prototype/`의 합성
업무/산출물/그래프를 실제 입력 결과로 재사용하지 않는다. 오래된 상세 UI 수정과
기존 두 superpowers 계획 파일의 미완료 변경은 보존했다. 이번 턴에서 그 파일은 수정하지 않았다.

첫 화면은 업무 설명과 자료 추가가 중심이다. 입력·자료를 저장하기 위해 모델이나
모든 외부 도구 연결을 미리 요구하지 않는다. 전체 첫 사용 여정은 계속 다음 흐름을 목표로 한다.

업무 설명/자료 → 이해 확인 → 실제 구조가 다른 후보 그래프 → 수정/승인 → 첫 실행/타입별 산출물.

이번에 실제 연결한 것은 위 흐름의 **입력/자료 보관과 버전이 고정된 설계 요청 기록**까지다.
엔진이 연결되지 않아 설계 요청은 명시적으로 blocked이며, 실행 중/승인됨/완료로 위장하지 않는다.

## 실제 동작과 기록

- 자유 입력, 여러 파일 업로드, 파일별 성공/실패와 원본 다운로드.
- 로컬 SQLite의 설명/파일 bytes/읽기 결과/불변 수정본/메타데이터 이벤트.
- 텍스트 자동 저장·수동 저장, 서버 저장 성공 후 상태 표시, 다시 열기/업무 선택.
- 한글 IME·앞뒤 공백·줄바꿈·HTML처럼 보이는 문자열을 입력 데이터로 보존.
- 서버의 compare-and-swap 수정본 검사로 오래된 탭의 텍스트 수정과 파일 추가를 거절.
  업로드 응답은 그 업로드가 커밋한 정확한 불변 수정본이며 더 최신의 다른 탭 수정본을 섞지 않는다.
- 명시 선택한 공급자/구독 모드/수정본에 묶인 설계 요청. 동일 요청 재시도는 중복 기록하지 않는다.
- 이벤트에는 ID·시각·수정본·해시·크기·읽기 상태·요청 결과를 기록한다. 일반 이벤트에
  본문/파일명/인증정보를 중복 기록하지 않는다. 원문과 bytes는 업무 저장소에 별도로 있다.

TXT/MD/CSV/JSON UTF-8 원문과 DOCX 본문/표 일부를 읽는다. PDF는 로컬 `pdftotext`가 있을 때만
제한된 텍스트 추출이 가능하다. **현재 실행 환경에는 없어 PDF는 원본만 보관한다.**
이미지/OCR/조판 해석, 의미 분석은 수행하지 않는다. HTML/SVG는 실행하지 않는다.
실행 가능한 네이티브 PDF 파서를 배포하기 전에는 제한된 헬퍼/OS 샌드박스와 업데이트 정책을
정해야 한다. 입력 크기·시간 제한은 네이티브 파서 취약점에 대한 격리를 대신하지 않는다.

## 검증 결과

루트가 최신 코드에서 직접 재실행:

- Python: 63 passed / 0 failed / 0 skipped.
- 브라우저: 13 passed / 0 failed / 0 skipped, 실제 Python 서버와 매번 분리된 임시 DB 사용.
- IME 검사는 composition 이벤트와 실제 저장 요청으로 수행했다. 물리 키보드/OS 입력기로 직접 입력하는 검사는 아직 하지 않았다.
- Python 실행 시 설치된 Starlette의 AnyIO 타입 별칭 deprecation warning 1건. 테스트 실패는 아님.
- 구문 검사와 `git diff --check` 통과. 커밋·스테이징·푸시하지 않음.

TDD에서 먼저 실패시킨 핵심 사례: API 부재, 실제 저장/복원, 파일별 실패,
누락된 요청 보호, 잘못된 요청 타입, 비ASCII CSRF, 오래된 수정본 업로드,
저장 중 시작된 한글 조합, 저장 실패 후 업무 선택 표시 불일치, 다른 탭의 원문 덮어쓰기.

독립 검토에서 발견된 마지막 두 UI 상태 결함도 회귀 검사로 수정 확인했다.

## 다음 결정과 남은 구축

Claude·Codex 구독을 모두 지원한다는 요구는 변경하지 않는다. 하지만 현재 공식 문서상
Claude 제3자 구독 통합은 Anthropic의 사전 승인이 필요하므로, 두 구독을 즉시 제공할 수 있다는
이전 판단은 확정 근거가 부족하다. 설치/로그인과 제품 통합 허용 여부를 구분해야 한다.
근거와 계약은 `2026-09-07-provider-integration-findings.md` 참조.

**API 방식으로 대체하거나 자동 과금 경로를 열지 않았다.** 사용자 선택 없이 공급자 요구를
축소하지 않는다. Codex 우선 연결과 Claude 승인 경로를 별도로 진행할지 다음 사용자 판단이 필요하다.

남은 단계: 공식 공급자 인증/과금 격리/권한 UI → 실제 업무 이해 → 내부 철학 렌즈와 독립 크리틱을
통한 후보 그래프 → 수정/승인 → 프레임워크 소유의 도구 실행과 타입별 산출물 → 사용자 대안과
차이 탐구 → 이전 업무 큐 재평가 → 인간의 정확한 버전 승격 승인.
배포 후 프레임워크가 관측 가능한 첫 제어 사건부터의 전체 이벤트 체계와 선택적 로그
내보내기/공유도 아직 추가해야 한다.
위 기능을 이번 저장 기반 테스트로 검증한 것으로 승계하지 않는다.
