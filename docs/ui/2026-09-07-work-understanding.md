# 입력에서 실제 업무 이해까지 — 구현 범위와 검증 기록

> **역사적 호스트-로컬 개발 실험 기록입니다.** 아래 설치된 Codex CLI 연결은 현재 웹 릴리스
> 경로가 아닙니다. 현재 제품은 서버가 소유·격리하는 관리형 Codex 구독 실행기와 브라우저 UI를
> 사용하며, 그 실제 배포 적격성은 T088에서 별도로 검증합니다.

상태: 2026-09-07 서비스·UI 구현 뒤 환경 없는 Codex generation 경계를 추가했고,
**합성 입력 2건의 실제 구독 추론과 UI 연결을 사전 출시 웹 슬라이스에서 확인했다.**
사용자의 “다음”에 따라 계정 연결 다음의 업무 이해 흐름을 구현했다.
아래는 제품 전체 완료 선언이나 렌즈 정책의 승인 기록이 아니다.

## 이 범위로 나눈 이유

통합 제품 설계 §3·4.3·9와 제품 의도 INT-021–023을 다시 확인했다.
입력에 근거한 업무 이해 → 출처 기반 단독/하이브리드 렌즈 후보 → 격리된 크리틱 →
구조적으로 다른 기본 3안은 유지한다. 그러나 최초 렌즈 목록·원자적 생성 규칙·하이브리드
충돌 처리·호출 예산·점수/선별 기준은 아직 상세 미결이다. 이를 패키지 기본값이나
과거 수동 리허설로 확정하지 않는다. 다음 그래프 구현 전에 근거와 추천안을 제시해 검토받는다.

이번에 구현한 흐름은 **실제 읽은 입력 → 구독 모델의 업무 이해 초안 → 출처/빈칸 →
원 입력을 정정하고 같은 업무에서 다시 확인**이다. 모델 응답 이후는 통제된 모델 대역으로
검증했다. 이후 합성 설명 단독 1건과 UI 설명·파일 입력 1건을 실제 추론했으며, 업무 설명과 정정을 사용자 대안이나
학습 정답으로 바꾸지 않는다. 일반 사용자에게 고정 설문이나 기술 객체를 채우게 하지 않는다.

## 계약

- 명시적인 ‘업무 이해하기’ 전에 보내는 설명·파일명·실제로 읽은 글자를 확인한다.
  원본 파일 bytes는 전송하지 않는다. 부분 읽기·미지원/OCR 미수행 상태를 보존한다.
- 기존 추출 제한(파일별 20,000자)과 별개로 이번 호출은 합계 60,000자 제한을 가진다.
  초과하면 몰래 자르거나 일부 파일을 누락하지 않고 호출 전에 멈춘다. 최종 제품 한도는 아니다.
- 요청의 저장본·입력 해시·프롬프트 버전·제공자·구독 방식·상태 이력을 로컬에 보존한다.
  생성된 요약·산출물 형식·명시 제약·중요 빈칸·추정을 구분한다.
- 근거의 source_id와 정확한 인용문을 전송 원문과 대조한다. 출처 문자열 검사가
  의미적 타당성·완전성·사용자 의도 일치를 증명하지는 않는다.
- 명시 동작 외에는 모델을 호출하지 않는다. GET·새로고침·입력 자동 저장은 재실행하지 않는다.
  응답을 못 받은 동일 요청의 재전송은 멱등 처리한다. API로 자동 전환하지 않는다.
- 요청 후 원 입력이 바뀌어도 원 요청은 해당 저장본에 남는다. 결과는 원문을 덮어쓰지 않는다.
  취소 후 늦은 응답은 적용하지 않는다. 서버 재시작 시 진행 중 요청을 자동 재전송하지 않는다.
- `understanding=true`는 업무 이해 서비스 구현 여부다. 실제 제공자 준비 여부는 별도로
  구분한다. 검증된 실행기 버전·환경에서 UI를 활성화하고 요청마다 완전한 사전 점검을 반복한다.
  `design_generation=false`, `execution=false`는 아직 연결하지 않은
  설계/운영 기능이다. 이해 성공을 환경 승인이나 운영 준비 완료로 표시하지 않는다.

## 도구 경계

OpenAI Docs와 설치된 0.144.4 JSON 스키마로 app-server의 구조화 응답과 취소 계약을 확인했다.
`thread/start` 설치 스키마에는 `ephemeral`, `baseInstructions`, `developerInstructions`,
`config`가 있다. `turn/start.outputSchema`는 현재 턴에 적용된다.
`readOnly`만으로 native tools나 전역 MCP·skills가 모두 차단되는 것은 아니다.
공식 계정 저장소는 기존 로그인과 공유하되 자격 증명 파일을 읽거나 복사하지 않는다.
입력 전송 전 격리가 확인되지 않으면 실패폐쇄한다.

### 최초 점검에서 발견한 경계 — 후속 환경 없는 방식으로 해소

- 공식 Codex CLI 0.144.4에서 계정은 ChatGPT 방식임을 확인했다. 설정/스킬 조회와
  프로세스별 재설정으로 활성 MCP와 스킬을 0개로 만든 뒤 재조회하는 경로를 점검했다.
  사용자 전역 설정·로그인 상태를 변경하거나 자격 증명을 읽고 복사하지 않았다.
- 그러나 이 버전의 `ToolsToml`에는 `view_image` 차단 옵션이 없다. 도구 구성은 환경이
  존재하면 `ViewImageHandler`를 등록한다. `tools.view_image=false`는 유효한 격리
  근거가 아니므로 제거했다. 이미지 읽기 이벤트를 받은 뒤 중단하는 것도 사전 차단이 아니다.
- 이 단계에서 `_native_tool_isolation_supported`는 항상 false였고 사전 점검은
  `isolation_unavailable`로 끝났다. 당시 `thread/start`·`turn/start`·모델 추론은 0회였다.
  이 문장은 후속 환경 없는 경계가 구현되기 전의 역사적 결과다.
- 프로세스 자식 수가 점검 시점에 0이었던 것은 인프로세스/HTTP 부작용 부재의 증명이 아니다.
  이 결과로 모든 전역 도구/외부 연결이 완전히 격리됐다고 주장하지 않는다.
- 후속 구현은 단순히 차단 조건을 제거하지 않았다. 0.144.4의 experimental
  `thread/start.environments`와 `turn/start.environments`를 빈 목록으로 고정해 환경 의존 도구를
  등록 전에 제외하고, 독립 도구·지시·연결 설정을 별도로 실패폐쇄한다. 상세 실측은
  [실제 업무 이해 확인 기록](2026-09-07-live-understanding.md)에 있다.

[도구 등록](https://github.com/openai/codex/blob/rust-v0.144.4/codex-rs/core/src/tools/spec_plan.rs),
[이미지 읽기 처리](https://github.com/openai/codex/blob/rust-v0.144.4/codex-rs/core/src/tools/handlers/view_image.rs),
[thread 환경 계약](https://github.com/openai/codex/blob/rust-v0.144.4/codex-rs/app-server-protocol/src/protocol/v2/thread.rs),
[turn 환경 계약](https://github.com/openai/codex/blob/rust-v0.144.4/codex-rs/app-server-protocol/src/protocol/v2/turn.rs).

LangChain ecosystem-primer와 LangGraph fundamentals를 검토했다. 이번 독립적인
업무 이해 호출에는 복잡한 그래프를 억지로 넣지 않는다. 후속 렌즈 생성·격리 크리틱·
조정 흐름은 계약 검토 뒤 LangGraph의 해당 상태/분기/영속성 스킬로 연결한다.
외부 LangSmith/OTEL 추적이나 API 키 의존성을 자동 추가하지 않는다.

Frontend Design은 기존 청록색·한국어 시스템 서체를 유지하면서 이해 결과를
업무 입력 바로 아래로 연결하는 데 사용했다. 근거는 접어 두고 MIME 표기는 PDF 등
읽기 쉬운 이름으로 표시한다. 별도 관리 대시보드나 중복 CTA를 추가하지 않았다.
Superpowers TDD에 따라 실패 시험 → 구현 → 회귀 확인을 수행한다.

## 검증 상태

아래 160/41 회귀 수치는 모델·음성 요구 이전 경계의 기록이다. 후속 모델 선택 구현은
선택 모델·추론 수준·설정 버전·목록 재검증 근거를 요청에 함께 고정하고, 응답 모델 불일치를
실패로 기록한다. 최신 구현/검증 범위는 [실제 업무 이해 기록](2026-09-07-live-understanding.md)을 따른다.

- 최종 회귀: Python 160/160, 브라우저 41/41 통과(실제 모델 대역 사용).
  외부 Starlette의 AnyIO deprecation 경고 1건, 실패/건너뜀 없음. 구문 검사와 diff 검사 통과.
- 실제 4193 화면을 기존 보관함으로 재시작했다. 업무 개수는 전후 0개이며, 읽기 전용
  브라우저 확인에서 준비 중 표시·전송 버튼 비활성을 확인했다. POST·외부 요청은 없었다.
- 후속으로 모델 선택·에이전트별 모델 관리·실시간 음성 입력 요구가 추가됐다.
  이 검사 결과가 해당 기능의 구현/검증을 포함하는 것은 아니다.
  [추가 요구 기록](2026-09-07-model-control-and-voice.md)을 다음 구축 기준으로 함께 따른다.
- 루트 첫 경계 시험 11개: 기능 부재로 실패 확인 뒤 통과.
- 진행 중 중복 요청에 새 요청 키가 붙은 경우, 완료 후 그 키를 재전송하면 다시 호출될 수 있는
  문제를 추가 실패 시험으로 재현했다. 키 별칭도 원 요청에 묶어 수정했다.
- SQLite COMMIT 실패 시 미실행 작업이 남는 문제와 취소 상태 저장 전에 worker를 중단해
  running이 남는 문제를 실제 DB 실패로 재현했다. 작업 등록·중단 신호를 COMMIT 뒤로 옮겼다.
- 취소 UI는 로컬 결과 미적용과 공급자 중단 요청을 뜻한다. 원격 실행의 즉시 종료나
  구독 사용량 종료를 보장하지 않는다.
- 실제 0.144.4 사전 점검에서 모델 입력 전 차단을 확인했다. 성공 경로 단위 시험은 native
  guard를 대역으로 바꾸며, 별도 시험은 당시 false guard가 유지되는지 확인했다. 이 항목은
  환경 없는 generation 구현 전의 역사적 검사다.
- 독립 최종 코드 검토에서 현재 도달 가능한 critical bug는 발견되지 않았다. 차단 아래의
  생성/취소 경로를 앞으로 활성화해도 안전하다는 인증은 아니다.
- 통제된 모델 대역의 시험은 요청/저장/화면 상태 검사이며 실제 모델 품질 검증이 아니다.
- 사용자 업무 자료는 자동 시험에 사용하지 않는다. 후속 실제 모델 확인도 새 합성 입력 2건으로
  제한했으며, 사용 모델·호출 성공과 제품 품질/렌즈 효과를 별도로 보고한다.
