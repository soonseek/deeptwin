# MANUAL-001: 선행 산출물과 실제 대안의 사전 점검

날짜: 2026-09-06
상태: 종료 — 사용자가 기준 기획안을 대안을 남길 수 없을 정도로 부적합하다고 판단하여 비교 전에 중단했다. 사용자 대안 없음. 차이 분석·렌즈 적용·재수행·효과 검증 미실시.

## 종료 기록

사용자 원문: “피드백을 줄 수가 없을 정도로 처참하게 말도 안 되는 기획안이라서 내가 보기엔 이번 단계는 이런 식의 검증은 아예 수행 자체를 할 수가 없을 것 같다. 내 의도 자체는 네가 제대로 파악할 수 있었다라는 점? 그거는 그 정도의 의미는 있을 것 같아 그래도.”

이번 방식의 검토는 성립하지 않았다. 기준 산출물의 입력 충실도 점검은 사용자가 자기 대안을 만들며 검토할 수 있는 업무 적합성·품질을 보증하지 못했다. 사용자의 발언은 이 시도를 종료하는 절차 평가이지 같은 과업의 대안 산출물·판단 차이·학습 데이터가 아니다. 구체적으로 무엇이 잘못됐는지나 사용자의 원하는 기획안을 이 발언에서 추정하지 않는다.

대화를 통해 의도를 이해하는 데 의미가 있었다는 사용자의 평가는 설계 대화의 성과로만 남긴다. 제품 경험 일치, 렌즈 효용, 흡수·재실행 개선, 크리틱 독립성, 전체 설계 승인 또는 구현 권한으로 확대하지 않는다. 실제 엔진 효과는 검증하지 않았으므로 효과가 없다고 판정한 것도 아니다.

같은 방식의 재시도나 새 기준 기획안 생성, 대안 제출 요구는 진행하지 않는다. 기존 입력·산출물·수동 카드·해시는 절차 이력으로 그대로 보존하고, 미실시 단계는 미실시로 남긴다. 아래 준비 절차는 종료된 시도의 이력이며 현재 대기 중인 요청이 아니다.

## 실행 범위와 근거

사용자는 에이전트 환경·렌즈 엔진이 없는 상태의 PoC 실효성에 의문을 유지하면서 가능하다면 한 번 해보라고 했다. 전체 설계에 대한 동의나 효과 기대의 확인이 아니다. 직전 제안한 수동 리허설 중 선행 산출물 준비만 수행했다.

현재 제품의 실행 소스는 `src/deeptwin/__init__.py`의 hello 함수뿐이다. 의존 패키지 설치는 에이전트·렌즈·평가기의 구현이 아니다. Eval Engineering의 discovery/task-design 기준에서 실제 Harness·Environment·Verifier가 없어 정식 성능 평가를 진행할 수 없다. Harbor 작업, 점수식 평가, 새 World Skill, 서비스·API 연결은 이 제한된 시도의 범위를 넘어 만들거나 실행하지 않았다. 기존 제품 의도·검토 절차 문서를 맥락으로 유지한다.

여기서 새로 확인할 수 있는 것은 사용자가 주어진 원본에 자기 대안을 남길 수 있는지, 실제 차이에서 반박 가능한 설명·판별 질문이 나오는지, 렌즈 없는 탐구와 어떤 실질적 차이가 있는지다. 아직 어느 것도 확인하지 않았다. 자동 엔진의 흡수, 이전 큐 성능, 시청 성과, 모델/오류 독립성, 제품의 두 구독 실행은 평가하지 않는다.

## 입력과 실제 생성

- `baseline-input.md`: 작성 에이전트에 보낸 과업 메시지 원문. 모든 관찰 수치는 실존 연구가 아닌 준비자가 만든 가상 사례다. 사용자 개인의 실제 업무·시청자 데이터가 아니다.
- `baseline-output.md`: `/root/rehearsal_baseline_writer`가 반환한 원문. 재작성·개선·선별하지 않았다.
- 작성 문맥: `fork_turns=none`. 해당 작성 에이전트에는 기존 사용자 대화나 배제된 업무 설명, 논문·렌즈 카드·다른 평가를 전달하지 않았다. 파일/도구/웹/다른 에이전트 접근을 금지했고 관찰된 실행은 텍스트 반환뿐이었다.
- 생성 경로: 현재 Codex 작업의 협업 에이전트 1회. DeepTwin 실행기나 최종 사용자 구독 어댑터가 아니다. 모델 설정은 부모 기본값 상속이며 응답에서 정확한 해결 모델 ID·토큰 사용량은 확인하지 못했다.
- 준비자·검토자는 이전 대화를 이미 보았다. 문맥 전달 제한은 완전한 실험 블라인드나 판단 오류의 통계적 독립성을 보증하지 않는다. 앞서 제외한 설명의 세부 조건을 사용자 기준·선호·정답으로 넣지 않는다.
- 작업 관계: 준비자가 만든 가상 관찰 자료 → 기획 역할의 실제 생성 → 대본 작성 역할로의 전달 예정. 대본 작성 역할은 실행하지 않았다. 전체 멀티에이전트 실행을 모사한 추적을 만들지 않는다.

## 원본 적합성 확인

메인 에이전트가 제공한 입력과 반환 원문을 대조했다. 6명/12건, 검색 7건/질문 5건, 표현 3건/권한 2건, 후속 참여 2명, 노트 재사용 두 번과 미측정 항목이 입력에 대응한다. 제안과 관찰을 구별하고 가상 사례임을 명시한다. 출처는 F1–F6으로 반환됐다. 이것은 입력 충실도 확인이며 콘텐츠 품질 점수·시청 성과·크리틱 독립성 검증이 아니다. F4의 업무 3개가 참여자별인지 합계인지 명시되지 않은 모호성은 원본에서 추가 수치 해석하지 않았고 한계로 남긴다.

## 당시 계획한 다음 증거와 멈출 조건 — 비교 전 종료

1. 원 자료와 원본 기획안을 먼저 사용자에게 제시한다. 실험 과제의 적합성이나 사용자의 원문 만족을 미리 가정하지 않는다.
2. 사용자가 같은 상황에서 남긴 실제 전체/부분 대안만 비교한다. 이유·수정 지시·전체 완료 선언은 필수가 아니다. 대안 미제공은 실패 점수가 아니며 대안이 없으면 비교를 진행하지 않는다.
3. 차이 정렬 후에만 `lens-rules-v0.1.md`의 후속 점검을 고려한다. 카드는 논문을 바탕으로 준비한 수동 질문 규칙이며 설치된 철학 엔진이 아니다. 카드의 적합성·판별력은 아직 검증되지 않았다.
4. 관찰 차이, 가설, 질문과 사전 예측, 이후 실제 응답은 별개로 보존한다. 설명을 만들었다는 이유로 효과를 선언하지 않는다. 변경 후 원문 복사·현재 대화 재작성은 독립 흡수 증거가 아니다.
5. 사례가 부적합하거나 렌즈가 구별할 예측을 만들지 못하거나 추가 질문이 부담이면 중단하고 실효성을 확인하지 못했다고 기록한다. 사용자에게 시연 성공을 위한 답을 요구하지 않는다.

기준 파일은 사용자 대안 이후 덮어쓰지 않는다. 수정이 필요하면 이유를 기록하고 별도 버전을 만들며 비교 대상 변경을 알린다. 원본 내용 해시는 별도 manifest에 기록한다. 내용 해시는 순서·원문 대조를 돕는 것이지 실행 재현 또는 인과 입증이 아니다.
