후속 확인 및 다음 주제(B5, 세 모드): 작업공간·대화·그래프가 같은 환경·산출물·성장 이력을 다른 방식으로 다룬다는 관계에 사용자가 ‘응’이라고 답했다. INT-024와 전체 여정의 상태를 확인됨으로 갱신하고 AC-018에 연결했다. 기본 모드·기능 동등성·저장·전환·그래프 직접 편집·구현은 미정이다. 다음은 설치 직후 전 과정 기록과 제작자에게 선택적으로 전달하는 증거 묶음의 경계다. 논문 4.4절·6.2절·6.5절을 직접 확인하고, 사건/계보 기록과 원문 공개 범위, 가림에 따른 진단·재현 한계, 전체 렌즈 탐색의 예상/실측 구분, 사용자 환경 학습과 제작자 프레임워크 개선의 분리를 검토 제안으로 기록했다. 아직 상세 수집·보존·내보내기 정책을 승인 또는 활성화한 것은 아니다.

후속 확인 및 다음 주제(B5, 증거 묶음): 사용자가 공개 범위를 확인한 관련 맥락·재현 한계를 담은 공유용 증거 묶음이라는 설명에 ‘응’이라고 답했다. 전체 여정과 제품 의도에 원칙 확인을 기록하고 AC-032를 연결했다. 세부 수집·보관·파일 형식·가림/전달·자동화는 미정이다. 다음은 자동/사람 개입 반복 개선의 권한·중단 경계이며 전체 여정 7.1절에 검토 제안으로 작성한다. 논문 4.8.3절·4.9–4.10절·6.2절에 근거해 허용 실험 안의 자동 진행, 필요한 새 사람 수행/선택·권한에서의 국소 대기, 한도·진전 없음·안전 조건의 보류와 사람 최종 승격을 구별한다. 각 내부 단계의 승인 버튼·새 제출 절차·침묵 동의·렌즈 보류에 따른 전체 중단으로 해석하지 않는다. 아직 구체 한도·시작/재개 트리거·운영 자동화 또는 현재 프로젝트의 실제 실행 권한을 확정하지 않는다.

후속 확인 및 다음 주제(B5, 자동 실험 경계): ‘허용된 실험은 자율 진행, 새로운 사람 판단·권한에서 개입, 운영 승격은 사람 결정’이라는 설명에 사용자가 ‘응’이라고 답했다. 전체 여정 7.1절·제품 의도에 핵심 원칙 확인을 기록하며 한도 수치·시작/재개·조작·외부 실행 권한은 미정으로 유지한다. 다음은 추상 원칙 확인을 실제 반복 업무 한 종류의 기준 사례로 통합 검토하는 단계다. 논문 4.2절·6.6절에 근거해 사용자가 직접 품질을 판단할 수 있는 업무를 추천하되 구체 업무는 자료로 확정할 수 없어 한 가지를 묻는다. 전체 입력/과거 큐/대안 준비를 선행 의무로 두지 않는다. 가상 제안서·유튜브 업무를 임의 선정하지 않고, 한 사례 검토를 범위 축소·효과 증명으로 보지 않는다. 두 구독 경로와 같은 모델 크리틱 독립성은 별도 미검증 과제로 유지한다. UI 제작·구현은 시작하지 않는다.

검토 절차 직접 정정(B5): 실제 기준 업무를 묻자 사용자는 유튜브 콘텐츠 기획을 설명하면서 이를 피드백으로 가공하려는지 문제를 제기했다. 이어 선행 상황·산출물을 먼저 제시한 뒤 대안을 받아야 하며 이번 턴은 피드백 실험으로 무효라고 정정하고 ‘검토 절차를 다시 잡아봐’라고 요청했다. 이전 설명은 피드백·학습·효과 검증 근거 및 그에 맞춘 원본/평가표의 우회 개인화에서 제외한다. 기존 통합 검토 절은 철회 상태와 새 절차로 교체하고 INT-033 정정 및 AC-033–034에 연결했다. 새 절차는 개발자가 먼저 상황·자료·역할·완결 선행 산출물을 제시·고정, 이후 실제 전체/부분 대안, 차이/가설/필요한 렌즈·새 증거, 변경 가설과 가능한 재수행을 검토하는 수동 리허설 제안이다. 구현 후 실제 엔진/이전 큐/별도 최종 증거/사람 승격 검증과 구별한다. 이전 설명 노출을 지웠다고 하거나 문맥 분리로 오류 독립성을 증명하지 않는다. 현재는 절차 문서만 수정했으며 예시 생성·피드백 수집·실험·UI/구현을 시작하지 않았다.

제한 시도 시작(B5, MANUAL-001): 사용자는 환경·렌즈 엔진이 없는 작은 PoC의 실효성에 의문을 유지하면서 가능하다면 한 번 해보라고 했다. 이를 전체 검토 절차의 효과 승인이나 제품 구현 요청으로 확대하지 않는다. 코드가 hello 함수뿐임을 확인하고 Eval Engineering의 실제 Harness·Environment·Verifier 요건에 비춰 정식 성능 평가는 불가능하다고 구별했다. 수동 절차 리허설의 기준 준비만 수행했다. 기존 대화를 전달하지 않은 작성자에게 새 가상 관찰 자료로 기획안 1건을 생성하게 했고 입력·응답·해시를 docs/rehearsals/manual-001에 보존했다. 논문 24–28쪽의 소수 미세렌즈를 수동 질문 규칙 초안으로 준비했으나 적용·효과는 미검증이다. 사용자 대안 이후 필요하면 렌즈 없는 탐구와 질문의 실질적 차이를 비교하고, 판별력이 없거나 부적합하면 실효성 미확인으로 멈춘다. 대안 없이 해석하지 않는다. 모델/코드/전체 워크플로 재실행, 제품 구독 경로, 운영 승격은 수행하지 않았다.

제한 시도 종료(B5, MANUAL-001): 사용자는 기준 기획안이 자기 대안을 남길 수 없을 정도로 부적합하여 현 단계에서 이런 방식의 검증은 수행할 수 없다고 판단했다. 비교 전에 종료했으며 원본·생성 조건은 보존한다. 사용자 대안·차이 탐구·렌즈 적용·재수행·효과 검증은 모두 없고, 이번 거절을 대안 산출물이나 학습 증거로 변환하지 않는다. 사용자가 인정한 의미는 대화를 통한 의도 이해이며 제품 경험 일치·엔진 효과·전체 설계 승인과 구별한다. 재시도·새 기획안·추가 대안 요청은 진행하지 않는다. ## B4 화면 구성 접근법 — 비교 후 세 모드 모두 제공으로 결정

공통 범위: 업무 설명/자료 → 업무 모델 확인 → 내부 후보 탐색/크리틱 → 설계 비교·수정·승인 → 실제 환경 구성·관제 → 피드백과 필요한 SPLI → 이전 큐 반복 평가 → 사람 최종 승인·환경 버전업. 로그 내보내기는 별도의 선택 행위다. 어느 접근법도 엔진 기능을 생략하는 축소안이 아니다.

논문 4.3–4.4절(17–18쪽)은 구조 비교·선택과 실제 실행 설계·기록 연결을 정하지만 화면 배치까지 정하지 않는다. 아래 추천은 비개발자 사용, 실제 관제 환경, 업무/버전 맥락 유지라는 확인된 의도와 실패 사례에 따른 제품 경험 제안이다.

- **업무 작업공간 중심(비교 당시 추천):** 업무 환경과 선택한 업무 건의 맥락을 유지하며 대화·자료, 실제 에이전트 흐름, 산출물/검토를 연결한다. 설계 비교와 개선 실험은 해당 환경의 같은 버전 계보 안에서 열고, 단계별로 필요한 정보를 펼친다. 장점은 구성·운영·개선의 연속성이고 위험은 정보 과밀이므로 모든 패널의 상시 노출을 요구하지 않는다.
- **대화 중심:** 대화 흐름에서 자료 제출·질문·설계 카드·승인을 이어 간다. 진입은 쉽지만 여러 실행·산출물·버전의 동시 관제가 어려울 수 있어 영속적인 작업 목록·결과/평가 보기가 함께 필요하다. 대화만 제공하는 축소안이 아니다.
- **그래프 캔버스 중심:** 역할·연결·병렬 흐름을 중심으로 설계와 실행을 탐색한다. 구조 가시성은 높지만 비개발자에게 그래프 편집을 필수로 요구하면 의도와 어긋난다. 자연어 변경과 결과·평가 검토를 함께 제공해야 한다.

사용자 결정: **“3가지 모드 모두 제공”**. 작업공간 중심만 채택하지 않고 세 모드를 제품 범위에 포함한다(INT-024). 공통 업무·버전·권한·기록을 유지하는 방향은 기존 연속성 요구에 근거한 설계 해석이며, 기본 진입·자동 전환·동시 다중뷰·모드별 기능 동등성·직접 그래프 편집은 미결이다. 기존 목업의 메뉴·배치 전체를 승인된 UI로 복제한다는 뜻은 아니다.

- 선택한 역할에서 해당 실행의 지원되는 실제 도구 화면/결과·입력·출처·오류·재시도·전달 근거를 필요시 연다. 모든 역할의 원시 로그나 브라우저 화면을 항상 펼치지는 않는 방향을 추천하되, 숨은 추론을 제공하겠다는 약속은 아니다. 실시간 화면·당시 저장된 화면·기록 재생·미확인을 구별한다. 특정 패널·배치·지원 방식과 갱신 주기는 미정이다.

- 미지원 기능을 자동 도구 개발·설치 또는 숨은 유료 API 전환으로 메우지 않는다. 오류 복구는 이번 실행을 이어 가는 것이며, 운영 지식을 바꾸는 개선 실험·이전 큐 평가·사람 최종 승인·환경 버전업과 구별한다. 현행 허용 범위를 바꾸는 후보가 필요하면 그 변경에 맞는 검토·검증 경로에 연결한다.
